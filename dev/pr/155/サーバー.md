## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 待ち受けポート | 指定があればそのポートで `127.0.0.1` に待ち受け、無ければ今と同じくポート 0。待ち受けられなければ `ServeFailedError` | 置き場所は `config.yaml` の `preview.port` |
| `Host` の確かめ | `127.0.0.1:{ポート}`・`localhost:{ポート}` に加え、ポートを外したホスト名の部分が許可するホスト名と同じ要求を受ける | 大文字と小文字を区別しない今の比べ方に揃える。許可の値はホスト名だけで、入口のポート（既定でないポートのリバースプロキシを含む）を問わない |
| `Origin` の確かめ | 今の 2 つに加え、スキームが `https` か `http` で、ポートを外したホスト名の部分が許可するホスト名と同じものを受ける。`Origin` が無いときは今と同じく通す | 書き込みのエンドポイント 7 つが同じ判定を使う |
| MCP サーバーへの渡し方 | 環境変数に置く設定は、起動スクリプトが呼び出し元で設定されているキーだけを MCP の設定の `mcpServers.mindstella.env` に書いて渡す | tmux のサーバーの有無に依らず MCP サーバーにだけ届き、フックのコマンドを Claude Code の全体の環境へ広げない |
| 起動時のフック | 配信を立てた直後に、ポートとワークスペースの名前を渡して呼ぶ。同じワークスペースで呼び直して配信を立てなかったときは呼ばない | `MINDSTELLA_PREVIEW_START_HOOK` のコマンドの末尾に、ポートとワークスペースのフォルダの名前を引数で足す |
| 終了時のフック | 配信を止めるとき（MCP サーバーが終わるとき）に、立てた配信ごとに同じ値を渡して呼ぶ | 標準入力が閉じたときと SIGTERM を受けたときのどちらでも呼ぶ。1 つの配信に 1 回だけ |
| フックの呼び方と失敗 | フックのコマンドは新しいセッションで立て（`start_new_session`）、標準入出力をつながず、終わりを待たない。立てられない（コマンドが見つからない・引数を分けられない）ときは、配信の起動と終了は止めずに標準エラーに記録する | 待たないため、待つ時間の上限は持たない。終了の待ちは下の「Claude Code の終わらせ方」 |
| 既存機能への影響 | どれも未設定なら、待ち受け・`Host`・`Origin`・`preview_url` の結果が今と同じ | |
| セキュリティ | 待ち受けるアドレスは `127.0.0.1` のまま。外から開く画面の認証は外の入口に任せる | 非機能要件『待ち受けの範囲』の根拠に書く |

Claude Code の終わらせ方（2026-10-08 に Claude Code 2.1.294 で測った）:
- `/exit`（tmux の中の対話）と `claude -p` の終わりのどちらも、標準入力を閉じずに SIGTERM を送り、約 0.3〜0.4 秒後に MCP サーバーのプロセスが消える
- tmux のセッションが閉じると、MCP サーバーと同じプロセスグループの子も消える。新しいセッションで立てた子は残る

このため終了時のフックは SIGTERM でも呼び、新しいセッションで立てて終わりを待たない。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 待ち受けポート | 指定があればそのポートで `127.0.0.1` に待ち受け、無ければ今と同じくポート 0。待ち受けられなければ `ServeFailedError` | 置き場所は `要件.md` の `未確定` |
| `Host` の確かめ | `127.0.0.1:{ポート}`・`localhost:{ポート}` に加え、ポートを外したホスト名の部分が許可するホスト名と同じ要求を受ける | 大文字と小文字を区別しない今の比べ方に揃える。許可の値はホスト名だけで、入口のポート（既定でないポートのリバースプロキシを含む）を問わない |
| `Origin` の確かめ | 今の 2 つに加え、スキームが `https` か `http` で、ポートを外したホスト名の部分が許可するホスト名と同じものを受ける。`Origin` が無いときは今と同じく通す | 書き込みのエンドポイント 7 つが同じ判定を使う |
| MCP サーバーへの渡し方 | 環境変数に置く設定は、起動スクリプトが呼び出し元で設定されているキーだけを MCP の設定の `mcpServers.mindstella.env` に書いて渡す | tmux のサーバーの有無に依らず MCP サーバーにだけ届き、フックのコマンドを Claude Code の全体の環境へ広げない |
| 起動時のフック | 配信を立てた直後に、ポートとワークスペースの名前を渡して呼ぶ。同じワークスペースで呼び直して配信を立てなかったときは呼ばない | 渡し方は `要件.md` の `未確定` |
| 終了時のフック | 配信を止めるとき（MCP サーバーが終わるとき）に、立てた配信ごとに同じ値を渡して呼ぶ | `未確定`: SIGTERM で終わるときも配信を止めて終了時のフックを呼ぶか（決める段: インターフェース定義設計。インターフェース定義『MCP サーバーの起動』に書く） |
| フックの失敗 | コマンドが見つからない・0 以外で終わっても、配信の起動と終了は止めず、標準エラーに記録する | 待つ時間の上限は、Claude Code が標準入力を閉じてから SIGTERM を送るまでの待ちを測り、それより短くインターフェース定義設計で決める |
| 既存機能への影響 | どれも未設定なら、待ち受け・`Host`・`Origin`・`preview_url` の結果が今と同じ | |
| セキュリティ | 待ち受けるアドレスは `127.0.0.1` のまま。外から開く画面の認証は外の入口に任せる | 非機能要件『待ち受けの範囲』の根拠に書く |

`未確定`: SIGTERM で終わるときの終了時のフック（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | SIGTERM を受けたときも配信を止め、終了時のフックを呼んでから終わる | Claude Code が待ちきれずに SIGTERM を送っても、外の入口に登録が残りにくい | SIGTERM の受け口を足す |
| B | 終了時のフックは標準入力が閉じたときだけ呼ぶ | 今の終わり方のまま | SIGTERM で終わると外の入口に登録が残る |

推奨: A

立てては消す使い方では、終了時のフックが呼ばれないと外の入口に使わないポートの登録が溜まるため。

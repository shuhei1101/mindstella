## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 保存待ちの編集を待つ判定 | `/api/edits` を読む非同期の処理と、`window` に置いた結果を返す同期の判定に分け、`page.wait_for_function` には同期の判定を渡す（[#382](https://github.com/shuhei1101/mindstella/pull/382) の `test_add_item_with_options` の待ち方に統一する） | helper と `test_workspace_settings_screen.py` のゴールの中身の判定の両方 |
| 待つようになって fail する呼び出し | 判定を同期にした後に `test_detail_panel_screen.py`・`test_workspace_settings_screen.py` を流し、fail した呼び出しの待つ値・順番を修正する | 画面の不具合と分かった箇所は原因を切り分けて要件へ戻す |
| コメントの一覧を開き直したときの位置 | `SETTLED_SCROLL_TOP_JS` が、待つたびにセレクタで要素を引き直して位置を読む | 描き直しで要素が差し替わっても、差し替え後の要素の位置を読む |
| 毎回 pass することの確認 | 修正した 2 つのテストのファイルを負荷を掛けた状態（他の画面のテストと一緒に流す）で繰り返し流し、全回 pass したログを置く | 回数は結合テスト作成で決め、ログに記載する |

#428 の原因の調査の結果（画面の `.comments-body` への `scrollTop` の書き込みと scroll のイベントを記録する一時のテストを、CPU に負荷を掛けて 12 回流した）:

| 時点 | `.comments-body` の要素 | `scrollTop` |
| --- | --- | --- |
| 開き直した直後の描き直し（`openList`） | 要素 3 | 500 を当てる |
| `open_list` が `.open` を待ち終え、`SETTLED_SCROLL_TOP_JS` が要素を取る | 要素 3 | 500 |
| スレッドの読み直しの後の描き直し（約 110 ms 後） | 要素 4 に差し替え | 要素 4 に 500 を当てる。要素 3 は外れて 0 |
| `SETTLED_SCROLL_TOP_JS` が 150 ms ごとに読む | 要素 3 を読み続ける | 0 が 2 回続いて 0 を返す（fail した 4 回とも、直後に引き直した要素 4 は 500） |

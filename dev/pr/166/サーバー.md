## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| メンバー | `config.yaml` の `members` に ID・表示名・役割（`owner` / `admin` / `member`）・種類（`human` / `ai`）を持つ。登録したら `owner` がちょうど 1 人いること、ID が重ならないことを検査する。種類が `ai` の表示名は「AI」 | 検査は起動時と設定の再読み込みの両方。キーの名前は ER 図の設計で決める |
| 役割の確かめ | 書き込む口ごとに要る役割を決め、足りなければ 403 で断る。既定の書き換えと設定の再読み込みとメンバーの管理は管理者とオーナー、管理者の任命と解任はオーナーだけ。オーナーを消す・降格する要求は役割に関係なく断る | メンバー未登録のワークスペースは今と同じく確かめない |
| ログイン | メンバーを登録したワークスペースでは、ログインの口と画面だけをログインなしで返し、ほかの全ての口（画面・記録・書き換えの知らせ・書き込み）はログインしていなければ 401 にする。画面の要求はログインの画面へ送る | ログインの保つ時間は非機能要件に決定値を置く（規約『資源の値の決め方』で導く） |
| パスワードのハッシュ | Argon2id で作り、使えなければ bcrypt にする。ライブラリは単一ユースケース設計の後のライブラリ選定で決める | 依存の確認と動作環境に足す |
| 利用者のファイル | `~/.config/mindstella/users.yaml` に、メンバーごとのハッシュ・仮のパスワードかの印・失敗の回数・ロックの終わりの時刻を置く。作るときと書くときに権限を `0600` にし、読むときに `0600` より広ければ起動時にエラーにする | ワークスペースとメンバー ID の組で引く形は ER 図の設計で決める |
| 失敗が続いたとき | メンバーごとに続けて失敗した回数を数え、上限を超えたらロックの時間だけ断る。成功したら回数を戻す | 上限とロックの時間は非機能要件に決定値を置く |
| Cookie | ログインの印はサーバーのメモリに持ち、Cookie には推測できない値だけを入れる。HttpOnly・SameSite=Strict・Path=/ を付け、公開して HTTPS の外の入口の内側で使うときは Secure も付ける | サーバーを立て直すとログインし直す |
| CSRF | 書き込む口は、今の `Origin`・`Content-Type` の確かめに加え、ログインで渡したトークンを要求ヘッダーで受けて合わなければ 403 にする | メンバー未登録のワークスペースは今の確かめのまま |
| 公開範囲 | `config.yaml` の設定で、待ち受けのアドレスを `127.0.0.1` からほかのマシンへ開くアドレスへ広げる。オーナーがいないのに公開する設定なら、配信を立てる時（`preview_url`）と設定の再読み込みのときにエラーにし、足りないもの（オーナー）を出す | 待ち受けは今と同じく配信を立てるときだけ読み、再読み込みでは変えない。再読み込みで公開とオーナーの組み合わせが合わなければ前の設定のまま |
| 公開したときの `Host` と `Origin` | 公開したときは、待ち受けたアドレスと公開の設定で受けるホスト名を `Host`・`Origin` で受ける | 受けるホスト名の書き方はインターフェース定義の設計で決める |
| 仮のパスワード | 管理者がメンバーの仮のパスワードを発行すると、そのメンバーのハッシュを置き換えて仮の印を付ける。仮の印のあるメンバーはパスワードの変更の口だけを使える | 仮のパスワードは発行した画面に 1 回だけ出す |
| オーナーの再設定のコマンド | サーバーのマシンで、ワークスペースのフォルダとオーナーの ID を受けて新しいパスワードを標準入力から読み、ハッシュを書き直してロックを解く | 起動スクリプトのサブコマンドか別のコマンドかはインターフェース定義の設計で決める |
| 既存機能への影響 | メンバー未登録なら、待ち受け・`Host`・`Origin`・各口の結果が今と同じ | E2E の実行のみの行で確かめる |
| セキュリティ | 公開はオーナーがいてログインを求めるときだけにし、ログインなしでほかのマシンへ開く経路を作らない | 非機能要件『待ち受けの範囲』の根拠に書く |

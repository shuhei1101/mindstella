# 要件

## 要望

親 [#365](https://github.com/shuhei1101/mindstella/issues/365) の決定（D-8・D-13・D-14・D-16・D-20〜D-23）に従い、React 移行の土台を配置してトップバーと概要の画面を移行する。
子 6（[#371](https://github.com/shuhei1101/mindstella/issues/371)）で切り替えるまで、今の画面（`/mindstella.html`）とその部品・ストーリー・テストはそのまま配信し、動かし続ける。

<!-- table: data -->

| 対象 | 要件 |
| --- | --- |
| ビルド | Vite（React + TS）でビルドし、tsc は型検査（`--noEmit`）だけに使う。React Compiler を入れ、新しいコードで `useMemo`・`useCallback` を記載しない |
| スタイル | Tailwind v4 を使い、トークンを `:root` の 3 ティアで持って `@theme inline` で割り当てる。`--color-*: initial` で色の標準のパレットを削除する |
| UI 部品 | shadcn/ui（Base UI 版）だけを使う |
| ルーター | TanStack Router にし、URL の状態は `validateSearch` + Zod で持つ |
| サーバーのデータ | TanStack Query にし、Provider と QueryClient は 1 つにする |
| 配信 | ビルドした SPA の `index.html` をサーバーが配信する。今の画面のパスは変えず、SPA は別のパスで配信する |
| Storybook | `@storybook/react-vite` の設定を、今の `.storybook/` とは別に配置する。データは MSW と props で差し込む |
| lint・検査 | eslint-plugin-better-tailwindcss（任意値の禁止）・eslint-plugin-boundaries（`app・routes → features → shared` の向き）・react-hooks・jsx-a11y・複雑さの lint を error で入れる。Storybook の addon-a11y と Playwright の axe で画面を検査する |
| Git フック | lefthook と、リポジトリの直下の `package.json` の npm scripts で、lint・型検査を commit の前に実行する |
| トップバー・概要 | 部品設計『トップバー』と画面設計『概要』の要素と操作を全て再現する。見た目は shadcn/ui・Tailwind に合わせて一新してよい |

<!-- /table -->

配信と API の定義の方式: `serve.py` を維持し、SPA を `/spa/` の下で配信する（インターフェース定義『SPAの配信』）。
React の側が呼ぶ配信の API は、インターフェース定義から OpenAPI の定義を記載し、orval で TanStack Query の hook・Zod・MSW のモックを生成する。
OpenAPI に載せるのは、トップバーと概要が読む `GET /api/records`・`GET /api/comments`・`GET /api/edits`・`GET /api/threads` で、書き換えの知らせ（`GET /api/events`、Server-Sent Events）は生成の外で記載する。
親の決定 D-14 の FastAPI は使わず、利用者の端末の依存（PyYAML・jsonschema・mcp）を増やさない。

フロントのソースの置き場所: knowledge の規約『ビルド構成』のとおり、ソースをリポジトリの直下の `frontend/` に置き、ビルドの出力を `plugins/mindstella/skills/mindmap/preview/spa/` へ書いて commit する（モジュール構成『プレビュー / React』）。React の側の `tsconfig.json` だけは `frontend/` に置く。

単体テストのランナー: React の部品と画面は Vitest + Testing Library で確かめ、テストのファイルを対象の横に置く（knowledge の規約『Unit / Component テスト』『フォルダ構成』）。

Git フック: lefthook の設定（`lefthook.yml`）をリポジトリの直下に置き、`npm ci` の postinstall で共有の `.git/hooks/` へ入れる。設定を持たない worktree の commit では、lefthook は警告を出すだけで止めない（PoC 検証の所見）。

TypeScript のバージョンと型情報つきの lint: 今の画面も React の側も、typescript-eslint が対応するバージョンの TypeScript で型検査と `.js` の生成をする（PoC 検証で、今の画面の生成物に差分が出ないことを確認した。プレビュー.md の `## PoC 結果`）。

# 要件

## 要望

資料の HTML の本文を描く枠（部品『HTMLの本文の枠』）の中のリンクを押したとき、枠の中では移らず、リンク先を新しいタブで開く。

- 枠の中の `href` を持つリンクを押すと、リンク先が新しいタブで開き、枠の中の本文は描いたまま残る
- `target="_blank"` を持つリンクも、同じく新しいタブで開く
- リンクにフォーカスして Enter を押したときも、押したときと同じに働く
- 新しいタブは、開いた先のページから元のプレビューの画面を操作できない形（`noopener`）で開く
- 枠を使う全ての場所で同じに働く（詳細パネル・詳細の全画面の HTML の本文、Markdown の本文の中の `html` のコードブロック、HTML の本文の差分の「描いた結果」、配る書き出し）
- 枠の中で文を選んでコメントの入口を出す操作は、リンクの文を選んだときも今までどおり働き、選んだだけではリンク先を開かない
- 同じ本文の中の場所を指すリンク（`href` が `#` で始まる）は、新しいタブで開かず、本文のスクロール領域をその場所（`id` が一致する要素）まで送る。一致する要素が無ければ移らず、プレビューの URL のハッシュは変えない

`未確定`: 新しいタブで開くリンクの範囲（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `http:`・`https:`・`mailto:` の URL を指すリンクだけを開き、ほかのリンク（相対の URL・`javascript:` など）は押しても移らない | 資料に無いページやプレビューの画面を誤って開かない。`javascript:` を動かさない | 資料どうしを相対の URL でつないだリンクは働かない |
| B | `href` を持つリンクを全て開く | 開けないリンクが無い | 相対の URL が配信の URL を基準に解かれ、無いページやプレビューの別の画面が開く |

推奨: A

HTML の本文は 1 つの資料の中身だけを `srcdoc` で描いており、相対の URL が指す先のファイルを配っていない。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| HTML の本文の中へ、用語・項目の ID のツールチップとリンクを出す | 要望は HTML に元から書かれたリンクの押下だけを扱う | [#212](https://github.com/shuhei1101/mindstella/issues/212) |
| Markdown の本文の外へのリンクを新しいタブで開く | Markdown の本文のリンクは画面の文書にあり、押すと同じタブで移るが、ブラウザの戻るで本文へ戻れ、本文が消えたままになる事象に当たらない | 予定なし |
| 枠の中のフォームの送信 | `sandbox` に `allow-forms` が無く今も送信されず、本文が消える事象に当たらない | 予定なし |

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 書き込みのタグの確かめ | `add`・`update`・`batch`・`new_thread`・`update_thread`・保存待ちの編集の保存は、語彙に無いタグをエラーにせず書き込む | 空・重なりのタグを弾く既存の検査は残す |
| 書き込みの結果 | 結果に `candidate_tags`（`tag`・付けた項目かスレッドの `ids`・字面の近い語彙のタグ `similar`）を返す。`batch` は最上位にタグごとにまとめたものと、操作ごとの結果の両方に持つ | 近いタグは `similar_tags` を使い、件数の上限は今の `CANDIDATE_LIMIT` のまま。インターフェース定義設計で決めた |
| `find` のタグ | 語彙に無いタグでも、項目が使っているタグなら絞り込める。どの項目も使っていないタグはエラーでなく 0 件を返し、近い語彙のタグを案内する | 単一ユースケース『記録の検索』で決めた |
| `check` | 語彙に無いタグを未登録の候補として返し、採否の手段（`update_settings` で語彙へ登録・`tag_map` で既存のタグへ付け替え）を案内する | - |
| `update_settings` の語彙の置き換え | 古い語彙から外したタグを対応なしで持つ項目が残るときだけエラーにする。古い語彙に無かった未登録の候補は、対応なしで残してよい。語彙を変えずに `tag_map` だけを渡して候補を既存のタグへ付け替えられる | 単一ユースケース『設定の更新』『発言の取り込み』で決めた |
| `check` の結果 | 未登録の候補は問題でなく `warnings`（`kind: candidate_tag`・`similar` つき）として返し、候補だけなら `ok` を真にする。採否の手段は `hint` で案内する。`problems` の `unknown_tag` は無くす | 単一ユースケース『ワークスペースの点検』とインターフェース定義設計で決めた |
| 語彙の説明の 3 点 | 設定のスキーマの `tags` の 1 件に任意のキー `include`（str）・`exclude`（str）・`examples`（list[str]）を追加し、`tags`・`update_settings` で読み書きする | インターフェース定義設計で決めた |

# 要件

## 要望

knowledge の規約『タグと用語の登録』に合わせて、次の 3 つを満たす。

| 要望 | 終わりの条件 |
| --- | --- |
| 付ける条件と付けない条件 | 取り込みの手順（`steps/取り込み.md`）と session の `SKILL.md` に、タグ・用語・エイリアスそれぞれの付ける条件と付けない条件が例つきで書かれている。「合うタグが無い新しい話題のときだけ登録してから付ける」「一般的な技術の言葉は、利用者が指定したときだけ足す」の書き方が無くなっている |
| 未登録の候補の受け付け | `add`・`update`・`batch`・`new_thread`・`update_thread` と画面からの保存待ちの編集の保存が、語彙に無いタグをエラーにせず書き込み、結果に未登録の候補のタグと字面の近い語彙のタグを返す。`check` が未登録の候補を洗い出し、`update_settings` で語彙へ登録するか `tag_map` で既存のタグへ付け替えるかで採否を決められる |
| 語彙の説明の 3 点 | 設定のタグの語彙の 1 件が「含める / 含めない / 例」を持てる。`tags` がそれを返す |

`未確定`: 語彙の説明の 3 点の持ち方（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今の `summary` を残し、任意のキー `include`・`exclude`・`examples` を追加する | 今のワークスペースを移し替えずに読める | 説明が `summary` と 3 点の 2 か所に分かれる |
| B | `summary` を `description`（`include`・`exclude`・`examples` を持つオブジェクト）に置き換える | 規約の `description` と同じ名前になる | 版の移し替えが要り、破壊的変更になる |

推奨: A

Issue の受付で破壊的変更を不要と判断しており、キーの追加で要望を満たせる。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 項目とタグの組ごとの主題（`main: true`）と、`tags` の `query` | 同じ話し合いの別の直しで Issue がある | [#335](https://github.com/shuhei1101/mindstella/issues/335) |
| 用語・エイリアスの一致の前の NFKC・大文字小文字の正規化 | 同じ話し合いの別の直しで Issue がある | [#334](https://github.com/shuhei1101/mindstella/issues/334) |
| タグの語彙の `group`・タグ自体の `aliases`・`deprecated` と振り替え先 | 規約がタグに持たせるキーだが、Issue の要望（付ける条件・未登録の候補・説明の 3 点）に含まれない。今回の語彙のスキーマに足して持つ前提で中身が決まるため、レビューで含めるかを確定する（今の判断は含めない） | 起票予定 |
| 画面（詳細パネルの編集・設定の画面）での未登録の候補の見せ方と、説明の 3 点の入力 | 要望は AI の取り込みと MCP のツールが対象で、画面の見た目と操作を変えない。設定の画面は語彙の 1 件をそのまま保つので、追加したキーは画面からの保存で失われない | 起票予定 |
| 記録の読み取りを dev-docs の `search_docs` に任せる・設定の共通のキーを dev-docs.yaml にそろえる | 別の Issue で扱う。語彙のスキーマを変えるときは互いの変更を突き合わせる | [#345](https://github.com/shuhei1101/mindstella/issues/345)・[#346](https://github.com/shuhei1101/mindstella/issues/346) |

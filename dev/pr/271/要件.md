# 要件

## 要望

差分の表示の E2E テスト `test_normal_when_added_then_removed_since`（`tests/e2e/単一ユースケース/test_diff_view.py`）を、同じコードなら毎回同じ結果にする。

| 項目 | 要件 |
| --- | --- |
| 原因 | ファイル全体を続けて流して fail を再現し、fail した回の「前回開いてから」の始まりの日時・まとまりの日時・画面の件数と印を記録して、揺れる箇所を突き止める |
| 直し方 | 突き止めた原因を取り除く。待ちの時間を延ばすだけで時刻の境目を避ける直し方にしない |
| 結果の揃い方 | 直した後、`test_diff_view.py` の全体を 10 回続けて流して 10 回とも pass する |
| 確かめる中身 | 「前回開いてから」の件数が消した N-2 の 1 件で、N-2 が消した印で出て、新規の印の項目が無く、N-1 に印が無いことを確かめ続ける。確かめる操作と期待値を減らさない |

`未確定`: 直す場所（決める段: 単一ユースケース設計）

| 案 | 内容 |
| --- | --- |
| A | 原因がテストの準備・待ち方にあれば、テストだけを直す |
| B | 原因がプレビューかサーバーの「前回開いてから」の決め方にあれば、その実装と設計書を直す |

推奨: A

単独では 3 回とも pass し、ファイル全体を流したときだけ落ちるため、先に流したテストの残す状態に左右される準備の側を先に調べる。
再現の記録で原因が実装にあると分かれば B にする。

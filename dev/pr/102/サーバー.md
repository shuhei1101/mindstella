## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 記録の置き場所 | ワークスペースの中のファイルとフォルダを全てサブフォルダ `.mindstella/` で引く。サブフォルダの名前は 1 か所の定数に持つ | `release/` も含める（[確認ログ](./確認ログ.md)） |
| ワークスペースの見分け | サブフォルダの `config.yaml` があればワークスペース。無く、直下に `config.yaml` か `mindmap.yaml` があれば、今の `mindmap.yaml` と同じく移し替えを案内するエラーにする | 各ツールの `workspace` の制限とエラーを揃えて改める |
| 直下の画面 | 直下には何も書かない。画面はサーバーの配信で開く | [確認ログ](./確認ログ.md) |
| 全ての種類の本文 | タスク・用語集・メモのスキーマに `body` を足し、`has_body` を全ての種類で真にする（区別が要らなくなれば項目ごと外す）。`add`・`update` の本文を持てない種類のエラーを外す | 点検の本文のずれ・参照切れ、変更履歴の `body_diff`、`show` の `body_markdown` は種類を問わず今の仕組みに乗せる |
| 編集した人 | 共通のキーに `updated_by`（`ai` / `user`、任意）を足す。`add`・`update`・`adopt`・`edit_option`・`batch` の書き込みと、`update_settings` のフェーズ・対象・カテゴリーの付け替えで `updated` と一緒に `ai` を書き、`add`・`update` の `item` では渡せないキーにする | 変更履歴の `before` に入れないキーに足す |
| 変更履歴の編集した人 | 変更履歴の 1 回分に、書き換えた人（`ai` / `user`）のキーを足す | キー名はインターフェース定義設計で決める |
| 前回読んだ時点からの変更 | `changes_since_read` が返す項目と変更履歴の回に、編集した人が載る | 今の返す形に乗る |
| 移し替えの手順 | v0.6.0 の `steps.yaml` の改名の後に、直下のファイルとフォルダをサブフォルダへ移す手順を足す。無いファイルは飛ばす | 今の操作（`rename_file`・`move_dir`）で足りるかを、無いファイルの扱いと合わせて確かめ、足りなければ操作を足す |
| 版の読み取り | `migrate` は、サブフォルダの版のファイルが無ければ直下の版のファイル（移す前の形）を読む | 版のファイルが無いワークスペースは今のとおり版を記録する前の形式として扱う |

# 要件

## 要望

ワークスペースの記録の形を、直下には画面だけ・どの種類にも本文・項目ごとに最後に編集した人、の形に直す。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 記録の置き場所 | 設定（`config.yaml`）・種類ごとの YAML・本文の `docs/`・`release/`・`changes.yaml`・`comments.yaml`・`drafts.yaml`・`submissions.yaml`・版のファイル・ロック・前回開いた日時を、ワークスペースの直下の 1 つのサブフォルダ `.mindstella/` にまとめる |
| 直下の画面 | ワークスペースの直下には画面の HTML `mindstella.html` だけを置く |
| ワークスペースの見分け | サブフォルダの `config.yaml` があるフォルダをワークスペースとして扱う。ツールとスキルが受け取るワークスペースのフォルダは、今と同じく直下のフォルダ |
| 全ての種類の本文 | タスク・用語集・メモにも本文（`body`）を持たせ、検討事項・調査・資料・会話ログと同じく `add`・`update` の `body_markdown` で書け、変更履歴に本文の差分を積む。資料の本文は今と同じく必須、他の種類は任意 |
| 編集した人 | 項目ごとに、最後に編集したのが AI か利用者かを `updated_by`（`ai` / `user`）に持つ。項目を足す・値を変える書き込みで、更新日時（今の `updated`）と一緒に書き換える。MCP のツールの書き込みは `ai` |
| 変更履歴の編集した人 | 変更履歴の 1 回分に、その回を書き換えたのが AI か利用者かを持つ |
| 既存のワークスペース | v0.6.0 の移し替えの手順に、直下のファイルとフォルダをサブフォルダへ移す手順を足す。今ある項目の `updated_by` は足さず、無い項目は編集した人が分からないものとして扱う |

<!-- /table -->

記録をまとめるサブフォルダの名前は `.mindstella/` にする（複合ユースケース設計で、次の案から A を採った）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `.mindstella/` | ファイルの一覧で隠れ、直下に画面だけが見える。プラグインの名前で何のフォルダか分かる | 隠しフォルダを出さない設定だと、利用者が本文や `release/` を手で開きにくい |
| B | `data/` | どの端末でも見え、手で開きやすい | 直下に画面と並んで見える。他の道具のフォルダと名前がぶつかりやすい |

推奨: A

D-22 の理由は「利用者が見たいのは画面だけ」で、隠れるほうがその形に近い。手で開く必要がある `release/` の資料は、画面の資料の画面とゴール判定の案内から辿れる。

`未確定`: 直下の `mindstella.html` の中身と、書き出す契機（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 記録を埋め込んだ見るだけの画面（描画のライブラリは CDN から読む）を、ワークスペースを作ったときと、項目・設定を書き換えるツールのたびに書き直す | サーバーを立てていなくても、ファイルを開けば今の記録が見える | 書き換えのたびに画面を書き出す分だけ遅くなる。コメントと設定の保存は配信の URL でしか使えない |
| B | 配信を立てたとき（`preview_url`）に、配信の URL へ移るだけの HTML を書く | 開くと、コメントも使える配信の画面になる | サーバーが止まっていると開けない。起動のたびにポートが変わり書き直しが要る |

推奨: A

D-22 を決めたときの画面は直下の `preview.html` を開く形で、ファイルを開けば見える使い方をそのまま残せる。コメントは配信の URL で使う今の形を変えない。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 利用者が画面から項目を編集し、`updated_by` に `user` を書く | 画面からの編集は #48 が作る。この PR は値の置き場所と、MCP のツールの書き込みの `ai` を作る | [#48](https://github.com/shuhei1101/mindstella/issues/48) |
| 編集した人に利用者の名前（誰か）を入れる | ワークスペースにメンバーが無く、AI か利用者かの 2 つで見分ける。メンバーは #25 が足す | [#25](https://github.com/shuhei1101/mindstella/issues/25) |
| 利用者が YAML・本文を手で直したときの編集した人 | 書き込むのはツールと画面だけで、手の編集は書き換えた人を残せない | 予定なし |
| 画面に編集した人を出す | 要望は AI が利用者の編集を見分けるための記録で、画面に出すことを含まない | 予定なし |

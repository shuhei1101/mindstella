# 要件

## 要望

プレビューのコメントの入力と返信の入力に、録音して文字起こしするマイクのボタンを追加する。

| 項目 | 要件 |
| --- | --- |
| マイクのボタン | コメント・返信の入力欄の右の、「レビューに追加」と同じ並びにアイコンだけで置く |
| 録音中 | 「レビューに追加」とマイクの位置を、アイコンだけの × の「キャンセル」と ✓ の「文字起こし」に切り替え、文字を出さない。録音を終えたら元のボタンに戻す |
| キャンセル | 録音を破棄する。入力欄の文字は変わらない |
| 文字起こし | 録音を終えて文字起こしを依頼し、結果を設定の挙動で処理する |
| 文字起こし後の挙動（設定） | `send`（既定）: 結果をその書き込みとし、溜めずにその 1 件だけを Claude Code へ送信する。`insert`: 入力欄のカーソルの位置に挿入し、送信しない |
| 用語集のプリセット | MindStella の設定で 1 つ選び、文字起こしの依頼に渡す |
| 経路 | ブラウザが録音を MindStella のサーバーへ送信し、サーバーが文字起こしのインターフェース（抽象）経由で voice-paste の `POST /web/transcriptions` に渡し、`GET /web/transcriptions/{job_id}` で結果を待って画面へ返す。画面とサーバーの他の処理は voice-paste に直接依存しない |
| 名前 | 画面・設定のキー・画面の文言に voice-paste の名前を出さず、「文字起こしのサービス」と呼ぶ。サーバーの抽象に依存させ、別の文字起こしに切り替えられるようにする |
| 押せないとき | 次のどれかのとき、マイクのボタンを押せなくし、理由をツールチップで出す: voice-paste が停止している、voice-paste がブラウザの機能（`/web/`）を組み込まずに起動している（`/web/` の下が 404）、ブラウザが `getUserMedia` を使えない（HTTPS でない経路から外の端末で開いたとき） |

マイクのボタンは、今の画面（`preview/components/*.ts`）と React の画面の両方のコメント・返信の入力に置く（React への切り替え（#371）まで既定で開くのは今の画面のため）。

`未確定`: voice-paste の接続先（URL）の持ち方（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 常駐サーバーの環境変数で持ち、既定を voice-paste の既定の待ち受けにする |
| B | ワークスペースの `config.yaml` で持つ |

推奨: A

voice-paste は端末に 1 つで、ワークスペースごとに変わらないため。

# 要件

## 要望

`plugins/mindstella/skills/mindmap/references/文章の書き方.md` を、knowledge の規約『文章の書き方』（`convention-writing-style`、rev 7）の内容に合わせる。
ファイル名と見出しは確定版の名前と同じ `文章の書き方` のまま維持する。
`plugins/mindstella/files.yml` のこのファイルの行の `description` は、1 文目を合わせた本文に合わせて修正する。

コピー元との対応は次のとおり。

<!-- table: data -->

| コピー元の項目 | コピーでの扱い |
| --- | --- |
| 概要 | 対象を記録（検討事項の回答・資料の本文・リリースの資料・会話ログ）に置き換えて取り込む。出典の略号の文は取り込まない |
| 文章を追加した後の確認表 | 確認と理由の 2 列を取り込む。出典の列は取り込まない。プロジェクトの規約・起動プロンプトを前提にした用語（参照先・手順本文・注入）は、記録の用語（別の項目・資料・本文）に置き換える |
| 残してよい否定 | 1 文目だけを取り込む。AI Monitor の手順の例と規約『既存文章の維持』への参照は取り込まない |
| 文章でない所の用語の選び方 | 取り込む。判定フローチャート『用語の選び方』へのリンクは、判定の順（文章か → 対応表 → 用語集・公式ドキュメント → 訓読みの動詞・一字の語・比喩か）の 1 文に置き換える |
| 用語の選び方の原則表 | 原則・悪い例・良い例を取り込む |
| 動詞は「する」を付ける | 取り込む |
| ドキュメントの用語の対応表 | 対応表 `word-list-ai-slop` の NG と OK の 2 列を表で取り込む（プラグインは利用者の端末で knowledge を参照できないため、埋め込みを表に置き換える） |
| UI の操作の語の参照 | 取り込まない（スキルは画面の文言を記載しない） |

<!-- /table -->

現在のコピーの `## 語の選び方` の 4 行は、次のとおりコピー元の項目へ移し、セクションは削除する。

| 現在の行 | 移し先 |
| --- | --- |
| 呼び名を固定する | 確認表の「同じものを別の言葉で呼んでいないか」 |
| 造語を作らない | 原則表の「定着したカタカナ語を和語に訳さない」「新しい呼び名を作る前に…」 |
| 定番の操作語を使う | 「動詞は「する」を付ける」と対応表 |
| 値に軸の名前を添える | 原則表の「値を 1 文字だけで…表示しない」 |

# 要件

## 要望

mindstella を経由した話し合いでは、利用者は Claude Code のターミナルを確認しない前提にする。
画面から届いた発言に限らず、ターミナルに記載したことは利用者に届かないものとして扱う。

| 対象 | 要件 |
| --- | --- |
| 決めてほしいこと（ヒアリングの質問・方針転換の確認・範囲の見直しのたたき台の確認・ゴール判定の確定・記録を削除してよいか など） | ターミナルに記載せず、検討事項（未決定・案と推奨つき）として記録し、その検討事項を向けたスレッドを `new_thread` で立てて知らせる。利用者は画面のコメントで回答し、送信の取り込みで拾って記録する |
| 長いたたき台・比べた結果 | 資料に起こし、その資料を向けたスレッドで確認を求める |
| 検討事項にするほどではない質問・知らせ（リサーチを始めてよいか・起票してよいか・書き出す先のパス など） | スレッド（`new_thread`）で聞き、回答が届くまで、その質問の先の作業をしない |
| ターミナルに記載してよいもの | MCP のツールが使えないときの案内（準備のステップの、常駐サーバーが待ち受けていない旨）と、`new_thread` が失敗したときの同じ質問と、setup・upgrade のスキルの中の質問だけ |
| Claude Code が出すツールの許可の確認 | 話し合いの中でターミナルに許可の確認が出ないようにする。リリースの資料（`.mindstella/release/`）は、Write ツールでなく、サーバーの MCP のツールで書き出す |
| 決まりの置き場所 | session のスキル（SKILL.md と `steps/`）に加え、mindstella のセッションの起動時に必ず読み込まれる指示に入れる。起動時の指示は、起動スクリプト `bin/mindstella` が `claude` を `--append-system-prompt` 付きで立ち上げて渡す（画面のコメントが届くのは起動スクリプトが立てた tmux のセッションだけで、ターミナルを確認しない場面と一致する）。起動時の指示にも、setup・upgrade のスキルの中の質問はターミナルで聞く例外を入れる |

回答を待つ間も、回答に左右されない取り込み・記録は続ける。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| setup・upgrade のスキルの質問をターミナルから移す | setup はワークスペースと画面ができる前に、upgrade は版が合わず session が止まった後にターミナルで呼ぶスキルで、画面で回答できない | 予定なし |

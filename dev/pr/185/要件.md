# 要件

## 要望

インターフェース定義『記録の形式の移行』で、手順を当てた後のワークスペースを期待値・セットアップに書く箇所を、v0.6.0 の手順で `.mindstella/` へ移した後のパスで書く。
直した後の期待値・セットアップが、結合テスト `test_migrate.py` の対応するテストが確かめる内容と食い違わない状態を基準にする。

<!-- table: data -->

| 流れ | 要件 |
| --- | --- |
| `正常系（手順を当てる）`（`test_normal_when_apply`） | 資料の期待値を `.mindstella/docs.yaml` で書く。設定ファイルの期待値を「直下に `mindmap.yaml`・`config.yaml` が無く、`.mindstella/config.yaml` が `mindmap.yaml` の中身（`field` を `playbooks` に移した後）を持つ」と書く。`needs_values` の期待値を `.mindstella/config.yaml` の `summary`、版のファイルの期待値を `.mindstella/mindstella-version.ini` が無いまま、と書く |
| `異常系（手順が失敗する・StepFailedError）`（`test_error_when_step_fails`） | 版のファイルの期待値を `.mindstella/mindstella-version.ini` が無いまま、と書く |
| `異常系（点検に合わない・SchemaMismatchError）`（`test_error_when_schema_mismatch`） | セットアップを `summary` を持たない `.mindstella/config.yaml` のワークスペース、版のファイルの期待値を `.mindstella/mindstella-version.ini` が無いまま、と書く。エラーの本文の期待値（`config.yaml: ` で始まる行）は、点検がワークスペースの記録のフォルダからの相対パスで返す今の出力に合っているため変えない |
| 変えないもの | 写し（`backup.ref`）の中身の期待値は、手順を当てる前のワークスペースの複製のため直下のパスのまま残す。版を記録する前の形式で作るワークスペースのセットアップ（直下の `mindmap.yaml`）も変えない |

<!-- /table -->

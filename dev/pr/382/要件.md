# 要件

## 要望

プレビューの「項目を追加」で開いた検討事項の追加の入力で、「案を追加」で書いた案・採用・案の削除を、案の記号をキーにした属性ではなく案として溜め、保存で検討事項の案として書き込む。

終わりの条件:

- 追加の入力で案を書いて離れると、溜めた `item-add` の `value` に、案の記号をキーにした属性（例 `A: {content: ...}`）が入らない
- 追加の入力で書いた案・採用を選んだ案・削除した案が、追加の入力を開き直したときに案の区画へそのとおりに出る
- 保存すると、追加した検討事項が書いた案（採用を選んだ案は採用つき）を持つ
- 保存待ちの編集の件数は、案を書いても項目の追加 1 件のまま

`未確定`: 追加する項目の案の溜め方（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `item-add` の `value` に `options`（記号・中身・採用）を持たせ、追加の入力の案の操作は `value.options` を書き換えて送り直す | 足す項目 1 つで編集 1 件の数え方と、保存で項目を 1 回で追加する当て方をそのまま使える | `item-add` の `value` に渡せないキーから `options` を外し、案の形を確かめる処理が要る |
| B | 仮の ID（`new-*`）への `option-add`・`option-edit`・`option-remove`・`adopt` を受け付け、保存で項目の追加の後に当てる | 詳細パネルの案の操作と同じ編集を送れる | 足す項目 1 つで編集 1 件の数え方が崩れ、取り消し・印・書き込めなかった編集の扱いを仮の ID へ広げる変更が大きい |

推奨: A

保存待ちの編集の件数を「項目の追加は項目ごとに 1 件」と定めた単一ユースケース『画面で項目を編集して保存する』の数え方を変えずに済み、変更がサーバーの値の確かめと追加の入力の 1 関数に閉じるため。

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |
| --- | --- | --- | --- | --- |
| `app.ts` の `submitAddField` | [de3874f2](https://github.com/shuhei1101/mindstella/commit/de3874f2)（`利用者が画面から項目を編集・追加・削除し、まとめて保存できるようにする (#325)`） | 追加の入力のキーを、タイトルを書くまでは手元に持ち、書いたら同じ `item-add` の `value` を送り直して溜める | 2 回 | 案の操作（`option-*`・`adopt`）もキーと同じく `next[input.key]` に入れており、案を扱う分岐が無い |
| `app.ts` の `submitAddField` | [04e17634](https://github.com/shuhei1101/mindstella/commit/04e17634)（`編集を溜めた後の描き直しで書きかけの入力が失われる不具合を修正し、結合テストを安定させる (#378)`） | 仮の ID が振られたときに、振られる前の書きかけの案を仮の ID へ移す | 2 回 | 書きかけの案を保つ目的で、今回の直し方（案の操作を案として溜める）はこの目的を壊さない |
| `edits.py` の `item-add` の `value` に渡せないキー（`options`）と、仮の ID への編集を断る確かめ | [de3874f2](https://github.com/shuhei1101/mindstella/commit/de3874f2)（`利用者が画面から項目を編集・追加・削除し、まとめて保存できるようにする (#325)`） | 案は `option-*`・`adopt` で編集し、足す項目のキーは `item-add` の `value` を書き換える | 1 回 | 案 A は `options` を渡せないキーから外し、案 B は仮の ID への案の編集を受け付ける。どちらも「足す項目のキーは `item-add` の `value` を書き換える」目的は壊さない |

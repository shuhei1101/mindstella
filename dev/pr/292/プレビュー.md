## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 「前回開いてから」の範囲 | まとまりの `until_seq` が、前回開いた時点の通し番号より大きいまとまりと、まだまとめていない変更を範囲にする。日時は比べない | - |
| 範囲の始まりの表示 | `{日時} より後` は前回開いた日時で今までどおり出す | - |
| タブの中の保ち方 | 同じタブで読み込み直しても範囲を変えない（今までどおり）。sessionStorage に通し番号も持つ | - |
| 前回開いた時点が無い・呼べない | タブを開いた時点（読んだ記録の `last_seq`）を範囲の始まりにし、開く前の書き換えに印を付けない（今までどおり） | - |
| 配る書き出し | 端末の設定に、開いた日時と書き出した記録の `last_seq` を持ち、同じ決め方で範囲を決める | - |
| 前回開いた時点の通し番号が今の `last_seq` より大きい | ワークスペースを戻した・作り直したときに起こる。範囲の扱いは単一ユースケース設計で決める | `未確定`（決める段: 単一ユースケース設計） |

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 前回開いた時点が無いときと同じに扱う（範囲の始まりをタブを開いた時点にする） | 印が付かないだけで、誤った印を出さない | 戻した後の最初の 1 回は差分が出ない |
| B | 全てのまとまりを範囲にする | 戻した後も何かしらの差分が出る | 前回見た書き換えにも印が付く |

推奨: A

通し番号が戻ったときは前回開いた時点と今の記録の対応が取れないため、誤った印を出すより出さない方が読み手を迷わせない。

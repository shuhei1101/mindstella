## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 保存待ちの編集 | 利用者の編集・追加・削除を、確定させずに溜める | `.mindstella/edits.yaml`（ER 図『ワークスペース』） |
| 書き込みのエンドポイント | 保存待ちの編集の読み取り・追加・書き換え・取り消しと、まとめての保存を開ける | `GET`/`POST /api/edits`・`DELETE /api/edits/{id}`・`POST /api/edits/save` |
| まとめての保存 | 溜めた編集を、項目の追加・更新・削除・案の書き換え・採用の切り替え・設定の書き換えとして 1 回で当て、1 つでも書き込めなければ何も書かずに書き込めない編集と理由を返す | 今の `batch` と同じく全体を当てるか当てないかにする |
| 編集した人 | 保存で書く項目の `updated_by` と変更履歴の `by` を `user` にする。MCP のツールは今どおり `ai` で書く | 書き手を引数で受けるか、別の入口にするかはモジュール構成設計で決める |
| 削除 | 指されている項目の削除は書き込めない編集にし、指している項目を返す | MCP の `remove` と同じ確かめ |
| AI の書き換えとの衝突 | 編集を溜めた後に AI が同じ項目を書き換えたら、その編集を書き込めない編集にする | 溜めた時点の `updated` と比べる |
| 書き換えのまとまり | 保存で利用者の編集を 1 つのまとまりにし、AI のまだまとめていない変更は先に別のまとまりにする | |
| 書き換えの知らせ | 保存で書いた項目を、今の書き換えの知らせ（`/api/events`）で開いている画面へ知らせる | |
| 排他 | 保存は MCP のツールと同じ書き込みの順番を取ってから書く | 今のコメントの送信と同じ |
| 既存機能への影響 | MCP のツールの引数と結果は変えない | |

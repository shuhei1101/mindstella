# 要件

## 要望

詳細に出す文字列の値（画面設計『詳細パネル』の要素「文字列の値の描画」が描く値）の中の改行を、Markdown の段落の中の 1 つの改行も含めて、詳細パネル・詳細の全画面で改行として出す。
対象は検討事項の `lead` に限らず、文字列の値の描画が描く値の全て（検討事項の `answer`・`reason`・案の各値、タスクの `reason`、調査の `question`・`conclusion` など）にする。
これらの値は同じ 1 つの描き方で描いており、`lead` だけを分けると描き方が値ごとに分かれるため。
空行で区切った段落・箇条書き・強調など、今の Markdown の描き方は変えない。
marked か DOMPurify を読めず文字のまま出すときも、改行を改行として出す。

記録の形は変えない（`lead` ほかの値は文字列で、改行を既に持てる）。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 本文（`body`）の段落の中の改行 | 要望は詳細の文字列の値で、本文は Markdown の書き方どおり（1 文 = 1 行で書き、1 段落に結合する）に描くため変えない | 予定なし |
| 差分の表示の間の、キーの差分で文字で並べる前の値と今の値の改行 | 判断: 含めない。前後の値は語の差分の面と組で描いており、改行を出すと語の面の囲み方も見直しになるため、要望の背景の読みやすさとは分けて扱う | [#314](https://github.com/shuhei1101/mindstella/issues/314) |
| 結合テスト `tests/integration/preview/test_detail_panel_screen.py` の `test_diff_keys_when_inline_words` 系 4 件の fail（`preview_word_diff_helpers.py` の `build_key_word_diff_workspace` が語彙に無いタグの項目を足す） | 結合テストが全 pass であることから外れている。#308 のタグの語彙の後から develop でも fail し、要望（値の改行の表示）に含まれない | [#313](https://github.com/shuhei1101/mindstella/issues/313) |

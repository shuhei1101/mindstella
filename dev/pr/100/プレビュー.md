### 原因の調べ

E2E と同じ記録・幅 1280px のブラウザで、マップの枠を追った。

| 時点 | `scrollLeft` | 枠の幅（`clientWidth`） | `scrollWidth` | 倍率 |
| --- | --- | --- | --- | --- |
| D-3 を選んだ後（「全体を表示」） | 222 | 734 | 958 | 0.909 |
| 余白をドラッグした後 | 224 | 734 | 958 | 0.909 |
| 余白を押した後 | 0 | 1214 | 1214 | 1 |
| 「拡大」を 1 回押してから同じ操作をした後 | 99 → 0 | 734 → 1214 | 833 → 1214 | 0.75（保たれる） |

`mapState.scroll` は 224 のまま描き直しで戻されているが、詳細パネル（480px）が閉じて枠が広がり、マップ（`sizer`）が枠より小さくなって送れる幅が無くなるため、ブラウザが 0 に切り詰める。
倍率を固定しても同じで、実装の不具合ではなく、マップが広がった枠より小さいときに「位置が変わらない」が成り立たない期待値の書き方による。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| シナリオの期待値 | 余白を押した後のスクロールの位置を、縦・横それぞれ、押す前の位置と広がった枠で送れる端の位置のうち小さい方とする | 選んだ項目を中央へ送り直さないことは変えない |
| シナリオのセットアップ | 拡大を 150% にしてから D-3 を選び、余白を右へ 450px ドラッグして、押す前の横の位置を押した後に送れる端より手前（0 より大きく）にする | 「全体を表示」のままでは押した後の位置が縦・横とも 0 に潰れ、位置を戻さない実装でも pass する。150% で D-3 を選ぶと横の位置は 605、押した後に送れる端は 211 |
| 画面設計 | 要素「マップ」の `action` のスクロールの位置の書き方を、シナリオと同じ基準（選んだ項目を中央へ送り直さず、押す前の位置と広がった枠で送れる端の位置のうち小さい方）に直す | - |
| E2E テスト | `test_normal_when_background_pressed` の最後の検証を、押した後の `scrollWidth - clientWidth` / `scrollHeight - clientHeight` と押す前の位置の小さい方と比べる形に直し、流れに拡大を 150% にする操作と右へ 450px のドラッグを足す | - |
| 実装 | 変えない（外した後に `mapState.scroll` へ戻す今の処理で、直した期待値を満たす） | - |
| ドラッグ・押下の判定 | `enableDragScroll` の押下とドラッグの分け方は変えない | - |

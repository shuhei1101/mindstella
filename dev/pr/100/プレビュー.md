## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 原因の特定 | 選びを外した後の描き直しのどこで位置が 0 になるかを、ブラウザで `mapState.scroll` と `wrap` の `scrollLeft`・`sizer` の幅・枠の幅を追って特定する | 候補は、戻す前に `mapState.scroll` が 0 で上書きされるか、詳細パネルが閉じて広がった枠で倍率を求め直し横に送れる幅が縮むか |
| 位置を保つ | 選びを外したとき、余白を押す前のスクロールの位置へ戻す | `未確定`（決める段: モジュール構成設計） |
| ドラッグ・押下の判定 | `enableDragScroll` の押下とドラッグの分け方は変えない | - |
| 選んだ項目を中央へ送る | 選んだ項目が変わったときに節を中央へ送る動きは変えない | - |

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 押す前の位置を控え、選びを外した後の描き直しの最後にその位置へ戻す。「全体を表示」の倍率は今の書き分けどおり求め直す | シナリオ・画面設計の決めた振る舞いを変えない | 倍率を求め直して横に送れる幅が押す前の位置より狭くなると、位置を保てない |
| B | 選びを外した描き直しでは「全体を表示」の倍率も求め直さず、押す前の倍率と位置をそのまま保つ | 送れる幅が変わらず、位置を必ず保てる | 画面設計の「全体を表示のときは広がった枠に合わせて倍率を求め直す」を変える |

推奨: A

画面設計とシナリオが既に決めた振る舞いに実装を合わせる直しで済む。
原因が倍率の求め直しで送れる幅が縮むことにあり A で位置を保てないと分かったときだけ、単一ユースケース設計で B を検討する。

# タスクに予定・実績の記録を足す

## 概要

利用者が、タスクの予定（開始・期限）と実績（着手・完了）を記録に残し、プレビューで読み返せるようになる。

## 背景

[Issue #26](https://github.com/shuhei1101/mindstella/issues/26) の要望。
タスクは状態だけを持ち、いつやる予定で、いつ着手して終えたかが残らない。
ガントの表示（[#27](https://github.com/shuhei1101/mindstella/issues/27)）がこの予定・実績を読む。
起点 Issue の担当・レビュアーの範囲は、ユーザーの指示（[PR #166 のコメント](https://github.com/shuhei1101/mindstella/pull/166#issuecomment-6074073119)）で下書きの [#173](https://github.com/shuhei1101/mindstella/issues/173) へ移っている。

## 計画書

| ファイル | 中身 |
| --- | --- |
| [要件](./要件.md) | 要望の整理と影響する UC 一覧 |
| [サーバー](./サーバー.md) | タスクのスキーマと、状態の変更で実績を入れる計画書 |
| [プレビュー](./プレビュー.md) | 詳細パネルとタスクの表に予定・実績を出す計画書 |
| [スキル](./スキル.md) | 取り込みでタスクの予定を書く計画書 |

## タスク一覧

- [x] ~~初期構築~~（既存リポジトリのため対象外）
- [x] ~~リバースエンジニアリング~~（現状設計書が揃っている）
- [x] ~~方針決め~~（方針決めを依頼する Issue ではない）
- [x] ~~PoC 検証~~（未検証の技術機構に依存しない）
- [x] ~~複合ユースケース設計~~（影響なし: 既存の複合ユースケースの流れを変えない）
- [x] ~~デザインスタイル選定~~（デザイン方針があり、見た目の方向を変えない）
- [x] ~~画面一覧・画面遷移~~（画面の追加・削除と画面遷移の変更を含まない）
- [x] 単一ユースケース設計
- [ ] モック作成
- [ ] インターフェース定義設計
- [x] ~~部品設計~~（影響なし: 既存の表の部品へ渡す列を足すだけで、部品の引数・状態を変えない）
- [ ] 画面設計
- [ ] モジュール構成設計

- [ ] 実装

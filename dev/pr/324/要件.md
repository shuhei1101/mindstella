# 要件

## 要望

タスクに予定 `plan`（`start`・`due`）と実績 `actual`（`started`・`done`）を持たせる。
値はどれも日付（`YYYY-MM-DD`）で、どのキーも書かなくてよい。

- 予定は AI が `add`・`update`・`batch` の `item` の `plan` で書く。`start` が `due` より後なら書き込まずにエラーを返す
- 実績は `item` で渡させない（渡したら書き込まずにエラーを返す）。タスクの `status` を `進行中` にした書き込みで `started`、`完了` にした書き込みで `done` を、ツールがサーバーの端末のその日の日付で入れる。足すときの状態が `進行中`・`完了` のときも同じく入れる
- `started` は最初に入れた日付を書き直さない。`完了` にしたときに `started` が無ければ、`started` にも同じ日付を入れる
- `完了` から他の状態へ戻したら `done` を消す（ガントの表示 [#27](https://github.com/shuhei1101/mindstella/issues/27) が終わっていないタスクの帯を今日まで描けるように）
- 話し合いの中でタスクの日付が出たら、AI が取り込みで `plan` に書く（スキルの手順）
- プレビューの詳細パネルにタスクの予定と実績を出し、タスクの表に予定と実績の列を足す（見せ方はモック作成で決める）
- `plan`・`actual` を持たないタスクは今と同じに動き、既存のワークスペースは移し替えずにそのまま読める

## スコープ外

| 項目 | 理由 | 対応予定 |

| 担当・レビュアー（`assignees`・`reviewers`・レビュー中の状態とボードの列・「自分の担当」「自分のレビュー待ち」の絞り込み・D-41・D-42）と、実績の `review` | ユーザーの指示（[PR #166 のコメント](https://github.com/shuhei1101/mindstella/pull/166#issuecomment-6074073119)、案 A）で、メンバーとタスクの分担は需要が出るまで対応しない。task-planner の[判断](https://github.com/shuhei1101/mindstella/issues/25#issuecomment-6074194706)で下書きへ移した範囲（起点 Issue の本文には残っている） | [#173](https://github.com/shuhei1101/mindstella/issues/173) |

| ガントの表示（予定と実績の帯） | この PR の予定・実績を読む側の Issue が持つ | [#27](https://github.com/shuhei1101/mindstella/issues/27) |

## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 本文の形式の持ち方 | 資料の本文を Markdown か HTML のどちらか 1 つで持つ | `body` のファイル名の拡張子（`{ID}.md` / `{ID}.html`）で表し、入力は `body_html`、項目の表示は `body_html`・`body_format` を返す。画面には行の印を足した HTML を `marked_bodies` で渡す |
| 項目の追加・更新 | 資料だけ HTML の本文を受ける。資料以外の種類に HTML の本文を渡したときはエラーで返す | 形式を変えた更新は、前の形式の本文のファイルを消し、本文の差分は変更履歴に残す |
| 項目の表示・記録の取得 | HTML の本文も Markdown の本文と同じく返し、形式も読めるようにする | - |
| 項目の削除 | HTML の本文のファイルも消す | - |
| 点検 | `missing_body`・`orphan_body` の対象に HTML の本文を足す | - |
| 書き換えの知らせ | 見ているファイルの印に HTML の本文を足す | - |
| 行の印 | 画面へ渡す HTML の本文に、`html.parser.HTMLParser` で開きタグごとに中身が始まる原文の行の印（`data-line`）を足す | PoC で成立。記録の取得・配る書き出しが渡す本文 |
| 選んだ箇所の照らし合わせ | HTML の本文も本文の行の範囲で照らし、同じパーサーで `<style>`・`<script>` の中を外した描いた文と比べる | PoC で成立 |
| 配る書き出し | HTML の本文も埋め込む | 描き方はプレビューの計画書 |
| セキュリティ | HTML の本文はファイルに書くだけで、サーバーは中身を解釈・実行しない | 描くときの無害化はプレビューの計画書 |
| 既存のワークスペース | 今の Markdown の資料はそのまま読め、移し替えの手順を足さない | - |

結論: 成立。
詳細はプレビューの計画書の `## PoC 結果`。

最小再現コードの要点（`poc/html-body/annotate.py`）:

```python
def handle_starttag(self, tag, attrs):
    line, column = self.getpos()
    raw = self.get_starttag_text() or ""
    if tag in UNMARKED_TAGS:
        return
    offset = self._line_starts[line - 1] + column
    # 複数行にまたがる開きタグは、閉じた行から中身が始まる
    self.marks.append((offset, offset + 1 + len(tag), line + raw.count("\n")))

def selection_matches(source, start, end, selected):
    return normalize(selected) in normalize(text_of_lines(source, start, end))
```

# 要件

## 要望

### コメントをスレッドにする

プレビューでまとめて送ったコメントは、1 件ごとに 1 つのスレッドの最初の書き込みになる。
スレッドには利用者と AI の書き込みが書いた順に積まれる。
AI は利用者が書き込んだスレッドに必ず返信する。
返すことが無いときは受け取った旨だけの短い返信にし、資料・検討事項などを足したり直したりしたときは、その項目の ID を返信に書く（画面では項目を開くリンクになる）。
AI からもスレッドを立て、利用者に返事を求められる（Issue に起票してよいかの確認など）。
レビュー中のコメント（送る前に溜めるもの）とまとめて送る操作は今のまま残す。

まとめて送ったコメントはスレッドとして記録し、送信の記録（`submissions.yaml`）をスレッドへ置き換える。
AI が取り込んだかは、スレッドが AI の返信待ちか（最後の書き込みが利用者か）で決め、取り込み済みの印（`taken`）は持たない。
AI の既読はこれと分けて持つので、セッションを開いて未読に戻しても、返信したスレッドを取り込み直さない。
既存のワークスペースの送信は、移し替えの手順（`migrations/`）でスレッドへ移す（取り込み済みの送信はクローズ、取り込んでいない送信はオープンの返信待ち）。

利用者がスレッドへ返信する送り方は、モック作成で決める。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 返信をその場で送り、まとめて送ったときと同じく Claude Code へ入力して知らせる | 1 件ずつ返事を待つやり取りがすぐ進む | 返信のたびに Claude Code へ入力が入る |
| B | 返信もレビュー中のコメントに溜め、まとめて送る | 送る操作が 1 つにそろう | 返事を 1 件返すのにも、溜めて送る 2 つの操作が要る |

推奨: A

スレッドの返信は相手の返事を待つ 1 件ずつのやり取りで、溜めてまとめる理由が薄い。

### オープン・クローズ

スレッドはオープンとクローズの状態を持ち、利用者が画面でクローズにする。
AI は既定でオープンのスレッドだけを読み、要るときだけクローズのスレッドも読む。

クローズとオープンへの戻しは、利用者だけが画面で行う。AI はクローズにしない。

### タグ

スレッドにタグを付け、スレッドの一覧をタグで絞り込める。

タグは AI が MCP のツールで付け、画面はタグを表示してタグで絞る。利用者は画面でタグを付け外ししない。

### 要約

AI は返信のたびに、スレッドの要約（何の話で、どう決着したか。例: 「○○の質問。回答はこの方向で決まった」「取り下げになった」）を書き直す。
要約は本文と分けて持ち、一覧で本文を読まずに引ける。

### AI の既読・未読

スレッドの書き込みごとに、AI が読んだか（既読・未読）を持つ。
AI が MCP のツールでスレッドを読むと、読んだ書き込みが既読になる。
Claude Code のセッションを開いたときに、スクリプトで全ての書き込みを未読に戻す。

`未確定`: 未読に戻す契機（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | プラグインに Claude Code の `SessionStart` のフックを足し、新しい会話・再開・`/clear` のたびにスクリプトで戻す | 会話の文脈が変わるどの契機でも戻り、`session` を呼ばない会話でも戻る | プラグインに初めてフックを持たせる |
| B | 起動スクリプト（`bin/mindstella`）が Claude Code を立てる前に戻す | 今の起動の流れに足すだけで済む | `/clear`・再開と、既にあるセッションへつなぐときに戻らない |
| C | `session` の準備で MCP のツールを呼んで戻す | フックもスクリプトも足さない | `/clear` の後に `session` を呼び直すまで戻らない |

推奨: A

会話の文脈を失う契機（新しい会話・`/clear`）と未読へ戻す契機が一致するのは、Claude Code が会話の始まりに流すフックだけ。

### MCP のツール

- スレッドの一覧: 状態（オープンだけ・クローズだけ・全部。既定はオープンだけ）・タグ・未読だけか既読も含めるか・AI の返信待ちだけかで絞り、キーだけ（ID・状態・タグ・要約・未読の件数など、書き込みの本文を含めない）でも返す
- スレッド 1 件を読む: 未読の書き込みだけか全部かを選び、返した書き込みを既読にする
- 返信・スレッドを立てる・要約とタグの書き換え（ツールの分け方はインターフェース定義設計で決める）

### 画面

左から出すパネル（今のコメントの一覧）を、「レビュー中のコメント」と会話のタブで切り替える。
会話のタブはスレッドを並べ、押すと書き込みを読めて、返信とクローズができる。
AI の返信と AI が立てたスレッドは、開いている画面へ書き換えの知らせで反映する。

### AI から利用者への連絡のタブ（#206）との関係

AI から利用者への連絡は AI が立てるスレッドに寄せ、[#206](https://github.com/shuhei1101/mindstella/issues/206) は破棄の判断へ回す。
スレッドで聞くのは、ワークスペースの外へ書き込む前の確認と、話の流れと関係の無い知らせ。今の話の流れの中で答えが要る問いはターミナルで聞く。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 変更履歴の版を URL で指し、返信から版へのリンクを貼る | Issue が別の話として挙げている | [#210](https://github.com/shuhei1101/mindstella/issues/210) |
| 利用者の既読・未読（AI の返信が来たことを画面で印にする） | 要望は AI の既読だけで、スレッドが入ることを前提にした後続 | 起票予定 |
| AI の返信を Discord などの Webhook や OS の通知で知らせる | 外のサービスへ知らせる別の要望 | [#157](https://github.com/shuhei1101/mindstella/issues/157) |
| 配る書き出し（1 枚の HTML）にスレッドを載せる | 配る書き出しはコメントの一覧を持たない見るだけの画面で、返信も送れない | 予定なし |

# 要件

## 要望

コメントをまとめて送信した後、Claude Code の会話の記録に入力が入ったときは、応答を `entered: true` にし、画面に「{件数} 件を送り、Claude Code に入力しました（{HH:mm}）。」を表示する。

| 要件 | 終わりの条件 |
| --- | --- |
| 上限を実測から決め直す | 起動スクリプトで起動した Claude Code（今のバージョン）へ貼り、会話の記録に記載されるまでを、入力を待っているときと処理中（`enqueue`）で測る。非機能要件『ClaudeCodeへの入力を確かめる上限』の値・根拠・内訳を、測った最大と規約『資源の値の決め方』の余裕から記載し直す。報告の実測（約 0.8 秒・約 2.1 秒）が上限に収まる |
| 貼り付けの打ち切りと記録の確認の打ち切りを分ける | 生きているかの確認と tmux の 3 つのコマンドは、記録の確認とは別の上限で打ち切る。記録の確認の上限は、貼り終えた時点から数える |
| 届かないときの応答の遅れを上限で抑える | 届かないとき、`POST /api/comments/send` の応答は 2 つの上限の和を超えずに返り、送信した書き込みは残ったまま `entered: false` を返却する |
| 設計書とテストを新しい上限に合わせる | インターフェース定義『コメントをまとめて送る』の 0.5 秒の記述、モジュール構成『ClaudeCodeへの入力.py』の定数と打ち切りの手順、単体・結合テストの期待値が新しい上限と一致する |

`未確定`: 2 つの上限の値（決める工程: モジュール構成設計。実測から決める）

## 変更箇所の由来

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |
| --- | --- | --- | --- | --- |
| `claude_input.py` の `INPUT_DEADLINE_SEC`・非機能要件『ClaudeCodeへの入力を確かめる上限』 | [40b47046](https://github.com/shuhei1101/mindstella/commit/40b47046)（`画面から送ったコメントを、起動スクリプトが立てた tmux のセッションの Claude Code へすぐに入力する (#201)`） | 0.5 秒を初期値として入れた。Claude Code 2.1.296・tmux 3.4 で 62 回測った最大 0.245 秒に余裕 50% を加えて切り上げた値で、届かなくても送信は残るため外れたときの損は画面の文言だけとした | 1 回 | 実測の最大を測り直して値を変える修正は、上限を実測から決める目的を壊さない |
| `claude_input.py` の `enter_to_claude` の打ち切り | [3411fb8d](https://github.com/shuhei1101/mindstella/commit/3411fb8d)（`MCP サーバーを stdio から HTTP の常駐サーバーに移す（既定のポート 8784・MINDSTELLA_PORT） (#392)`） | 常駐サーバーへ移したため、貼る前に宛先の Claude Code が生きているかの確認（`is_session_alive` の `ps`・`tmux display-message`）を追加し、同じ 0.5 秒の期限の中に入れた | 2 回 | 0.5 秒の内訳（貼り始めから記録に記載されるまで）に、生きているかの確認の時間が入っていない。貼り付けと記録の確認の上限を分けると、確認の時間が記録の確認の上限を削らない |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 送信結果の文言と、送信している間の表示 | 文言と表示の条件は変えない。届かないときに送信している間の表示が上限の分だけ長く出る | 予定なし |
| 入力できなかったことの Webhook の通知 | 通知の新設で、この PR は判定の上限だけを変える | [#222](https://github.com/shuhei1101/mindstella/issues/222) |
| 送信のボタンの変更 | 送信の導線と画面の変更で、送信結果の判定は変えない | [#401](https://github.com/shuhei1101/mindstella/issues/401) |

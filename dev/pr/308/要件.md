# 要件

## 要望

エージェントが MCP でワークスペースを読むとき、少ない呼び出しと少ないトークンで目当ての項目にたどり着けるようにする。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| タグの語彙 | `config.yaml` に、使ってよいタグの一覧（名前と説明）を持つ。説明は任意 |
| 語彙の検査 | 項目の追加・更新（`add`・`update`・`batch`）とスレッドのタグ（`new_thread`・`update_thread`）で語彙に無いタグを弾き、字面の近いタグの候補を添えたエラーにする |
| 語彙の登録 | `update_settings` で、語彙へのタグの追加・説明の書き換え・削除ができる。消すタグ・名前を変えるタグは、対象・カテゴリーと同じく古いタグから新しいタグへの対応で項目とスレッドのタグを付け替え、対応の無いタグが残る書き換えはエラーにする。対応の値に null を渡したタグは、項目とスレッドから外す |
| `tags` | 語彙のタグごとに、名前・説明・持つ項目の数・使っている種類を返す。持つ項目の数が 0 のタグも返す |
| `find` のタグ | タグを複数渡せる。既定は全てのタグを持つ項目（AND）を返し、いずれかを持つ項目（OR）は別の引数で渡す |
| `find` の件数とページ分け | 条件の有無によらず、既定の件数（20 件。上限 100 件）で最初のページを返し、条件に合う全体の件数 `total` と、続きを取る値 `next_cursor`（不透明な文字列。最後のページでは null）を付ける。`next_cursor` を渡すと次のページを返す |
| `find` の返す中身 | 今の ID・種類・題名・状態にタグを足す。返す量を `response_format`（`concise` / `detailed`）で選べる。項目の中身は今どおり `show` で取る |
| 切り詰めたときの案内 | 全体の件数がページより多いとき、返事に絞り込める引数（`tags`・`kind`・`status` など）を案内する文を入れる |
| 空の結果のときの案内 | 語彙にあるタグ・種類・状態などの組み合わせで 0 件になったとき、空の `items` と `total: 0` に、外せる条件を案内する文を添える。案内の文は切り詰めたときと同じ仕組みで組み立てる |
| 登録外のタグで探したとき | 空の結果にせず、字面の近いタグの候補を添えたエラーにする |
| ツールの説明 | `find`・`tags` のツールの説明に、使える絞り込みと、先に `tags` を呼ぶことを書く |
| 点検 | `check` が、語彙に無いタグを持つ項目とスレッドを洗い出す |
| スキルの手順 | session の手順で `find` から一覧を読む箇所（ゴール判定の完了したタスク・リサーチの調査）は、`next_cursor` をたどって全件を読む。取り込みのタグは語彙から選び、新しい話題のときは語彙へ登録してから付ける |
| 既存のワークスペース | 次の版の移し替えの手順で、項目とスレッドが使っているタグを説明なしで語彙へ登録する |

<!-- /table -->

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| プレビューのタグの AND / OR の絞り込み | 画面の側の要望 | [#187](https://github.com/shuhei1101/mindstella/issues/187) |
| プレビューの全体の検索からの絞り込み | 画面の側の要望 | [#143](https://github.com/shuhei1101/mindstella/issues/143) |
| `find` 以外の読み取りのツールのページ分け | 件数で返事が膨らむのは条件なしの `find` で、`next` は件数の上限を持ち、`threads` は本文を返さない | 予定なし |
| 属性名（`attrs`）の語彙 | 要望に含まれない | 予定なし |
| 同じ決まりを他のリポジトリの規約・ツールへ入れる | 他のリポジトリの Issue が扱う | [shuhei1101/knowledge#15](https://github.com/shuhei1101/knowledge/issues/15)・[shuhei1101/aituber#48](https://github.com/shuhei1101/aituber/issues/48)・[shuhei1101/ai-monitor#2859](https://github.com/shuhei1101/ai-monitor/issues/2859) |

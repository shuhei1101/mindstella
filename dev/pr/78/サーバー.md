## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 送信の形 | 送信に箇所（本文は行の範囲と選んだ文、ほかの値はキーと選んだ文）を任意で持たせる。項目に紐づかないコメントは `target` を持たない | 既存の `submissions.yaml` はそのまま読める形にし、移し替えの手順を足さない。レビュー中のコメントと書きかけの置き場所（`comments.yaml`・`drafts.yaml`）も無ければ 0 件として読むため、#81 で v0.5.0 に上がった版の扱いに手順を足さない |
| レビュー中の置き場所 | レビュー中のコメントと書きかけを、送った送信と分けてワークスペースに置き、読み・足し・書き換え・削除を受け付ける | 置き場所は[要件](./要件.md)で決めた |
| まとめて送る | チェックしたレビュー中のコメントを 1 回で受け、全てを送信に足してからレビュー中から外す。1 件でも足せないときは何も書き換えない | - |
| 検証 | 本文の箇所は、行の範囲が本文の行数に収まり、その行の範囲の文に選んだ文が含まれるかを確かめる。値の箇所は、キーがその項目にあり、その値に選んだ文が含まれるかを確かめる。合わなければ 409 を返す | 選んだ文と raw の文の両方から記号 `*`・`_`・`~`・`` ` ``・`\`・`\|`・`#`・`>` と空白・改行を外して比べる。raw の側は先に、各行の行頭のリストの記号（`-`・`+`・`数字.`・`数字)`）・表の区切りの行（`\| --- \|`）・コードブロックのフェンスの行・画像（`![代わりの文](URL)` を丸ごと）を外し、リンク `[文](URL)` を `文` にし、文字参照を文字に戻す |
| 取り込んでいない送信 | MCP の `submissions` が箇所を返し、項目に紐づかない送信は `target` を空で返す | - |
| 同時の書き込み | レビュー中の書き換えも送信と同じロックを取ってから読み・書く | - |
| 二重に送らない | まとめて送るで `submissions.yaml` を書いた後、`comments.yaml` から消す前にプロセスが落ちても、次に送ったときに同じコメントを二重に送らない | 送信に元のコメントの ID（`comment`）を持たせ、まとめて送るときに同じ `comment` の送信があれば足さずにレビュー中から外す（モジュール構成『送信』の `append_submissions`） |
| 送り元の確かめ | 足すエンドポイントも、`Host`・`Origin`・`Content-Type` を今の送信と同じに確かめる | - |
| 本文の上限 | 今の送信と同じ 10000 文字。まとめて送る件数とリクエストの大きさの上限を非機能要件で決める | 本文と選んだ文がそれぞれ 10000 文字まで入るよう、リクエストの本文の上限を 64KiB から 128KiB へ上げた（非機能要件『送信の本文の長さ』）。まとめて送るは ID だけを送るため件数の上限を設けない |

# 要件

## 要望

全種類の項目の関連（`related`）の各要素に、相手（`to`）・関係の種類（`type`）・いつ読むか（`when`）を持たせ、片側だけ書いて逆向きはツールで出す。
合わせる規約は knowledge の『ドキュメント管理』の「関連」と判定フローチャート『関連の張り方』で、Issue 本文の原稿ではなく knowledge に入った方を正とする。

<!-- table: data -->

| 要望 | 終わりの条件 |
| --- | --- |
| 関連の要素 | 全種類の項目の `related` の 1 件が `to`（相手の項目の ID）・`type`・`when`（いつ読むか、1 文）を持つ。ID の文字列の要素は受け付けない（前の版の形式として移し替えへ案内する） |
| `type` の語彙 | `type` は `requires`・`references`・`replaces`・`part_of`・`change_together` のどれか |
| 書き込み | `add`・`update`・`batch`・保存待ちの編集の保存が関連を要素の形で受ける。`batch` の `$番号` は要素の `to` に書ける |
| 逆向き | `show`・`batch` の取得の `referenced_by` の `related` の行が、関連の `type`・`when` を返す。片側だけ書いた関連を相手の項目からたどれる |
| `change_together` の両側 | 点検が、片側だけに書いた `change_together` を返す |
| 件数の上限 | 1 項目の `related` の件数に上限を持ち、超えた書き込みを受け付けない |
| 張るときの決まり | session の手順に、関連を張る前に判定フローチャート『関連の張り方』に当てて `type` と片側・両側を決め、`when` を書けない関連と本文でリンクしている相手には張らないことが書かれている |
| プレビューの表示 | 詳細パネル・詳細の全画面の関連と参照元の欄で、関連ごとに種類と `when` が見える |
| プレビューの編集 | プレビューの項目の編集の関連の入力で、関連ごとに相手・種類・`when` を入れ、保存待ちの編集として保存できる |
| 既存のワークスペースの移し替え | upgrade が既存のワークスペースの `related` を要素の形へ移し替える |

<!-- /table -->

会話ログも同じ要素の形にし、この会話で更新した項目を `type: references` と、その項目のどの経緯を確かめるときに読むかの `when` で指す。

移し替えは、手順のスクリプトが ID の文字列を相手だけを持つ要素にし、点検の後に upgrade を回す AI が関連ごとに両方の項目を読んで判定フローチャート『関連の張り方』で `type` と `when` を決め、`batch` 1 回でまとめて書く。`when` を書けない関連は外し、外した関連を利用者に示す。

`未確定`: 1 項目の `related` の件数の上限（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 全種類で共通の上限を 1 つ持つ | 決まりが 1 つで、session の手順も 1 つで済む | 会話ログのように多くの項目を指す種類で足りなくなる |
| B | 種類ごとに上限を持つ | 種類ごとの使い方に合わせられる | 種類のスキーマごとに値を決めて保つ |

推奨: B

会話ログは 1 回の会話で更新した項目を指すため、他の種類と同じ上限では収まらない。
値はインターフェース定義設計で、既存のワークスペースの件数から決める。

| 関連の `paths`（glob） | 項目の関連の相手は項目で、機械で判定できるファイルのパスを持たない | 予定なし |
| 関連の相手の種類（文書・コード・ルール）を指す欄 | 相手はワークスペースの項目に限る | 予定なし |
| `impact` が `requires`・`change_together` の関連をたどること | 判断が分かれる。たどれば影響の洗い出しが関連の種類を使えるが、今の `impact` は関連をたどらない設計で、要望は関連に種類と `when` を持たせることに限る。この時点の判断はスコープ外で、レビューで確定する | 予定なし |
| 点検で、本文でリンクしている相手への関連を見つけること | 本文の ID の言及と関連の重なりを機械で判定する決まりが無い。重ねないことは session の手順で守る | 予定なし |
| 閲覧・修正の記録から関連を推薦すること（D-27） | 要望に含まれない | 予定なし |
| 記録の読み取りを dev-docs の `search_docs`・`trace_related` に任せること | 別の Issue で扱う。この PR の逆向きの関連を受け継ぐかは、その着手時に決める | [#345](https://github.com/shuhei1101/mindstella/issues/345) |
| `detect_screen_issues` の `target: mock` が、モックの操作列 `.mockbar` を axe の検査の範囲から外さないこと | ai-monitor の `MOCK_EXCLUDED_SELECTORS` が `.mock-bar` だけを外す不具合で、要望に含まれない | [ai-monitor#3138](https://github.com/shuhei1101/ai-monitor/issues/3138) |

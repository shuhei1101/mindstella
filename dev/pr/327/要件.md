# 要件

## 要望

プレビューが描く Markdown の本文に共通のスタイルを持たせ、表の列の固定・見出しの固定・しま模様・セクションの折りたたみを表示の設定でオン・オフできるようにする。
本文に独自のタグ・記法を書かせず、資料は普通の Markdown のまま見せ方だけを変える。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 共通のスタイル | 詳細パネル・詳細の全画面・本文の差分（インライン・左右に並べる）が描く Markdown の本文に、同じスタイルを当てる。配る書き出しの 1 枚の HTML にも同じスタイルが当たる |
| 表の列の固定 | 表示の設定でオンにすると、本文の表で選んだ列より左を固定し、表を横に送っても固定した列が見えたままになる |
| 表の見出しの固定 | 表示の設定でオンにすると、本文を縦に送っても表の見出しの行が本文の区画の上端に残る |
| 表のしま模様 | 表示の設定でオンにすると、本文の表の行を 1 行おきに色で塗り分ける |
| セクションの折りたたみ | 表示の設定でオンにすると、本文の見出しを押してその見出しの下（次の同じか上の階層の見出しまで）を畳み・開ける。本文の差分（インライン・左右に並べる）には当てない |
| 列の幅と折り返し | 本文の表の列ごとにセルの最大の文字数を数え、短い列は折り返さず、中くらいの列は折り返さないか区切りのよい所でだけ折り返し、長文の列は一定の幅で折り返す。表が本文の幅に収まらないときは表の中だけで横に送る（本文の区画は横に送らせない） |
| 切り替えの残し方 | 4 つの切り替えは、この端末だけの個人の上書きとして端末の保存領域に残し、表示の設定の「この端末で変えている項目」と「既定に戻す」の対象にする |
| AI Monitor の Pages から拾う見せ方 | Pages の本文のスタイルのうち、本文にタグを書かずに当たる見せ方を拾う |

<!-- /table -->

単一ユースケース設計で決めた論点。

| 論点 | 決定 | 設計書 |
| --- | --- | --- |
| 4 つの切り替えをワークスペースの既定（`config.yaml` の `display`）にも持たせるか | 持たせず、個人の上書きだけにする（差分のミニマップ・本文の差分の並べ方と同じ）。サーバー・ER 図・既定の保存の確かめは変えない | シナリオ『表示の設定を変える』の正常シナリオ（本文の表とセクションの見せ方を変える） |
| 4 つの切り替えの既定 | 表の列の固定・表の見出しの固定・セクションの折りたたみはオン、表のしま模様はオフ。列の固定は見出しに固定のボタンを出すだけで、押すまで列を固定しない。セクションの折りたたみは見出しを押せるようにするだけで、開いた状態で描く | シナリオ『項目の詳細を読む』の正常シナリオ（本文の表とセクションを読む） |

モック作成で決めた論点。

| 論点 | 決定 | 設計書 |
| --- | --- | --- |
| Pages から拾う見せ方 | 表を横に送れるときの右端のフェード・コードブロックの言語の札とコピーのボタン（`pre` の外の `div.md-code` に置く）・GitHub の Alert（`> [!NOTE]` 等）の囲み（見出しは補足・ヒント・重要・警告・注意）を拾う。見出しのアンカーは今の `#` のリンクが残るため足さない | モック『markdown-body』 |
| 列の幅と折り返しの境目 | 全角を 1、半角を 0.5 と数え、8 文字以下の列は折り返さず、25 文字以上の列は 24em で折り返す。その間の列は最小の幅を文字数の半分 + 2em（14em まで）にし、文節の区切りでだけ折り返す | モック『markdown-body』 |
| 幅 720px 以下での固定 | 列の固定と固定のボタンを外し、見出しの固定は残す | モック『detail-panel』 |
| セクションの開閉の押し方 | 見出しの頭の矢印（24px）だけをボタンにし、見出しの文言は選んでコメントできるまま残す。本文で使っている上位 2 つの階層の見出しにだけ置き、畳んだ中身は `hidden="until-found"` にして、リンク・ハッシュで飛んだときは開く | モック『detail-panel』 |
| 画面の文言 | 切り替えは「表の列の固定」「表の見出しの固定」「表のしま模様」「セクションの折りたたみ」 | モック『settings-panel』 |

## 変更箇所の由来

| 対象箇所 | commit | 目的 | 変更回数 | 影響 |
| --- | --- | --- | --- | --- |
| 本文の表を包む `.md-table-wrap` と、収まる表を本文の幅いっぱいに広げる書き方（画面設計『詳細パネル』の本文・`style.css` の `.md table`） | [32f4fa63](https://github.com/shuhei1101/mindstella/commit/32f4fa63)（`幅 320px でもプレビューのトップバー以外の画面を横にスクロールさせず、見切れなく操作できるようにする (#289)`） | 狭い幅で本文の区画ごと横に送らせず、表の中だけで横に送る | 1 回 | 列の幅を文字数で決めて表を本文の幅より広くしても、横に送るのは表の入れ物の中に閉じるため、この目的を壊さない |

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 本文にタグ・独自の記法を書いて見せ方を変える方式（Pages の `<!-- table: data -->` で有効にする並べ替え・絞り込み・列の表示・合計・コピー） | Issue の「やらないこと」。資料は普通の Markdown のまま保つ | 予定なし |
| スレッドの AI の返信を本文と同じ描画とスタイルで出す | 別の Issue が扱う。今回入れる共通のスタイルを使う | [#267](https://github.com/shuhei1101/mindstella/issues/267) |
| 資料の本文の見出しから目次を作る | 別の Issue が扱う | [#160](https://github.com/shuhei1101/mindstella/issues/160) |
| HTML の本文（`body` が `.html`）と `html` のコードブロックの見せ方 | 作者の HTML のスタイルをそのまま描く枠で、Markdown の本文のスタイルを当てない | 予定なし |
| コードブロックの中の Markdown の描画 | テンプレートの Issue が扱う | [#16](https://github.com/shuhei1101/mindstella/issues/16) |
| 結合テスト `test_workspace_settings_screen.py` と `test_options_edit` の不安定な落ち方 | 今回の差分と無関係で、develop でも落ちる | [#328](https://github.com/shuhei1101/mindstella/issues/328) |

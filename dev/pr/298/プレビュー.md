## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| アクセシビリティ | 表示の設定・絞り込み・コメントのボタンに幅の下限 `--target-min`（24px）を幅で区切らずに持たせ、幅 480px 以下の詰め方（389px 以下と、#290 の 390〜480px）が効く間も、件数の札を持たない間も 24px を割らない | 高さは今の 32px のまま。481px 以上はボタンの幅がもともと 24px を超え、見た目は変わらない |
| レスポンシブ対応 | 幅 320px・最大の中身（つながらない・差分あり・絞り込み 2 桁・コメント `99+`）でも、#263 の収め方（ボタンを隠さない・差分の札 `5.5em` 以上・`scrollWidth` が表示幅以下）を保つ | つながらない・差分ありの間だけ、印だけのボタンを幅 26px にして左右の余白 8px を保つ（[確認ログ](./確認ログ.md)） |
| 既存機能への影響 | 幅 481px 以上の見た目と、ボタンの読み上げの名前・押したときの動きは変えない。390〜480px は #290 の収め方（横にはみ出さない・差分の札 `5.5em` 以上）を保つ | - |
| 部品設計 | `FitNarrowest*` と #290 の `FitWide*` の説明にボタンの幅の下限を書き足し、件数の札を持たないボタンが並ぶ状態を確かめられるようにする | 件数なしの状態は `FitNarrowestNoCount`（320〜389px）と `FitWideOfflineDiffNoFilter`（390〜480px）として足す |
| 結合テスト | 表示幅 320・361・389px で `FitNarrowest*` の状態、390・480px で `FitWide*` の状態のトップバーに axe の `target-size` を当てて違反が無いこと、各ボタンの枠が縦横 24px 以上であることを確かめる | 既存の `scrollWidth` の確かめはそのまま流す |

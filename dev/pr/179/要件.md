# 要件

## 要望

プレビューの差分の表示で、選んだ時点に AI が `remove` で消した項目を、足した・変えた項目と見分けて読めるようにする。
取り下げた調査・資料・用語集・メモ・会話ログ（`withdrawn: true` と `reason` を持つ項目）に、取り下げの印を出す。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 消した項目の出し方 | 差分の表示の間、選んだ時点の `removed`（ID・種類・消したときのタイトル）を、その種類の画面に消した印つきで出す。消した項目は中身が残らないため、詳細パネルは開かない |
| タブの印 | 選んだ時点で消した項目だけを持つ種類のタブにも、足した・変えた項目と同じ点を付ける。タブの件数は今ある項目の数のまま変えない |
| 時点の件数 | 変更履歴の時点の件数 `points[].count` に、その時点で消した項目の数を含める |
| 同じ範囲で足して消した項目 | 「前回開いてから」のように複数のまとまりを合わせた範囲で、足した後に消した項目は、新規の印を付けず消した項目としてだけ出す |
| 取り下げの印 | 取り下げた調査・資料・用語集・メモ・会話ログに、差分の表示によらず、表・カード・ボード・詳細パネルで取り下げの印を出し、詳細パネルに取り下げた理由 `reason` を出す |
| 選んだ時点で取り下げた項目 | 差分の表示の間、選んだ時点で取り下げた項目は、変更の印と取り下げの印で、取り下げたことを読める |
| 既存の記録 | `removed` を持たないまとまりと、`withdrawn` を持たない項目は、今と同じ表示のまま |

<!-- /table -->

`未確定`: 消した項目を出す場所（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | その種類の画面の一覧（表・ボード・カード・マップ・字下げの一覧）の末尾に、消した項目の行・カードを薄く並べる | 足した・変えた項目と同じ場所で見つかる | 表示形式ごとに出し方を決める必要があり、マップでは置き場所が無い |
| B | その種類の画面の一覧の上に「消した項目」の帯を 1 つ置き、ID・タイトルを並べる | 表示形式によらず 1 つの出し方で済む | 足した・変えた項目と離れた場所に出る |

推奨: B

消した項目は押しても開く中身が無く、行やカードの形で並べる利点が薄い。表示形式ごとの出し方を増やさずに済む。

`未確定`: 取り下げの印の見た目（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | タイトルの右に「取り下げ」の札を付け、行・カードの文字を薄くする | 状態を持つ検討事項の `取り下げ` と同じく、一目で残っているだけの項目と分かる | 札の分だけ幅を取る |
| B | タイトルに取り消し線を引く | 幅を取らない | 消した項目の印と見分けにくい |

推奨: A

消した項目の印と取り下げの印を、同じ差分の表示の中で見分ける必要がある。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 検討事項・タスクを取り下げた（状態 `取り下げ`・`対象外`・`中止` にした）ときの専用の差分の印 | 要望に含まれない。状態の前後は今も詳細パネルの差分で読める | 予定なし |
| 変更履歴のモーダルを時系列の一覧にし、未読の印を付ける | 同じモーダルの並べ方を変える別の要望。件数に消した項目を含めることは、この PR で決める | [#156](https://github.com/shuhei1101/mindstella/issues/156) |
| 利用者が画面から項目を削除・取り下げる | 画面から書き込む口を作る Issue で扱う | [#48](https://github.com/shuhei1101/mindstella/issues/48) |

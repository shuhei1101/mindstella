# 要件

## 要望

ワークスペースの直下に README を置き、そのフォルダで使うコマンドの一覧（起動・接続・スキル）と、記録を見るプレビュー（起動スクリプトで立ち上げる MCP サーバーが配る画面）の URL を書く。

| 項目 | 要件 |
| --- | --- |
| 置く場所 | ワークスペースの直下の `README.md`。直下には `.mindstella/` と `README.md` が並ぶ |
| 書く内容 | プレビューの URL を先に置き、続けてコマンド（起動・接続・セッション・セットアップ・アップグレード。1 つごとに太字の見出し・短い説明・`bash` のコードブロック）、公開ドキュメント『プレビューを見る』『起動スクリプトで立ち上げる』へのリンク。コマンドは、そのフォルダの絶対パス・今のプラグインのフォルダ・tmux のセッションの名前を埋めた、そのまま叩ける形にする |
| 操作の名前 | `起動`・`接続`・`セッション`・`セットアップ`・`アップグレード` のように、アプリケーションの操作名で書く |
| 書く時点 | `init` がワークスペースを作るとき、`/mindstella:session` を始めるたび、プレビューの配信を立てたとき。プラグインを上げた後のパスと、起動のたびに変わる URL に追従する |
| 書く主体 | サーバー。スキルは MCP のツールを呼ぶだけで、README の中身を自分で書かない |
| 利用者が書いた README | 1 行目に自動で書いた印が無い `README.md` は書き換えない（利用者のファイルを残す） |
| 記録との関係 | `README.md` は記録ではない。自動で書いた印を確かめるほかにどのツールも読まず、点検しない。ワークスペースの見分け（`.mindstella/config.yaml` があるフォルダ）は変えない |
| 既にあるワークスペース | `/mindstella:session` を始めた時点で置かれる。移し替えの手順とプラグインの版の引き上げは足さない |

# 要件

## 要望

ワークスペースの直下に README を置き、そのワークスペースの記録を見るプレビュー（起動スクリプトで立ち上げる MCP サーバーが配る画面）の開き方を書く。

| 項目 | 要件 |
| --- | --- |
| 置く場所 | ワークスペースの直下の `README.md`。直下には `.mindstella/` と `README.md` が並ぶ |
| 書く内容 | 起動スクリプト（`{プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ}`）でこのフォルダを立ち上げ、`session` にプレビューを頼み、示された URL（`http://127.0.0.1:{ポート}/mindstella.html`）をブラウザで開くこと。ポートは起動のたびに変わる。手順を写すかリンクで済ませるかは下の `未確定` |
| 作るとき | `init` がワークスペースを作るときに書く |
| 既にある README | フォルダに `README.md` が既にあれば書き換えない（利用者のファイルを残す） |
| 記録との関係 | `README.md` は記録ではない。どのツールも読まず、点検しない。ワークスペースの見分け（`.mindstella/config.yaml` があるフォルダ）は変えない |

`未確定`: 既にあるワークスペースへ README を置くか（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 次の版の移し替えの手順で、直下に `README.md` が無ければ置く | 前から使っているワークスペースにも案内が揃う | 移し替えの手順が 1 つ増える |
| B | 置かない（新しく作るワークスペースだけ） | 移し替えに触れない | 前から使っているワークスペースには案内が無いまま残る |

推奨: A

版が変わると移し替えを通るまで `session` が止まるため、利用者の手間は増えず、全てのワークスペースで案内が揃う。

`未確定`: README の文面（決める段: インターフェース定義設計。利用者が読む文面のためユーザーへ確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 固定の文面にし、プラグインのフォルダはパスを埋め込まず調べ方（`claude plugin list --json` の `installPath`）を書く | プラグインを上げても文面が古くならない | 利用者がプラグインのフォルダを調べる手間がある |
| B | 作るときのプラグインのフォルダの絶対パスと tmux のつなぐコマンドを埋め込む | 書かれたコマンドをそのまま叩ける | プラグインを上げると版ごとのフォルダが変わり、書かれたパスが古くなる |
| C | 1〜2 行の要約と、公開ドキュメントの『プレビューを見る』へのリンクだけを書く | 手順が変わっても README を書き換えずに済む | 手順を読むのにリンク先を開く |

推奨: C

A・B は公開ドキュメントの手順の写しを各ワークスペースに配り、写しはプラグインを上げても書き換わらないため、ログイン（#25）・共有のサーバー（#14）で入り方が変わると古い文面が残る。C は手順の変更にも追従する。

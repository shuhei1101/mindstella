# 要件

## 要望

プレビューの Markdown の描画を、marked から mdmark v0.7.0 に置き換える。

- 描く対象は、資料ほか全種類の項目の本文（詳細パネル・詳細の全画面・本文の差分）、項目の文字列の値、スレッドの書き込み（利用者と AI の書き込み・レビュー中の書き込み）
- mdmark の CSS と JavaScript は、タグ `v0.7.0` を固定した jsDelivr の URL で読む。新しいバージョンへ上げるのはこの PR の外で行う
- スレッドの書き込みは、今の文字のままの表示をやめ、本文と同じく Markdown として描く。書き込みの中の項目の ID とまとまりへのリンクは、今と同じく押して開ける
- mdmark へ渡すのは Markdown だけにする。記録の YAML を画面に出すときは、mindstella の変換の処理で Markdown にしてから渡す
- 用語・エイリアスの一致（[#334](https://github.com/shuhei1101/mindstella/issues/334) の正規化を含む）は mindstella 側に残す
- 置き換えの後も、今の本文の次の機能を保つ
  - 選んだ箇所へのコメント（選んだ範囲から元の Markdown の行を求める）
  - 見出しのリンクと `#見出し`・`#diff=` のリンク
  - 用語・資料・調査のマーカーとツールチップ、項目の ID のリンク
  - 図の拡大・Raw・コピー、`html` のコードブロックの HTML の本文の枠、表の中だけで横に送る入れ物
  - 本文の差分（インライン・左右に並べる）
  - 読み込めなかったライブラリの名前を出す知らせ
  - 配る書き出しを、ネットにつながらない端末で開いても本文と図が描かれる
- 使わなくなった描画のライブラリ（marked ほか）は、プレビューと配る書き出しから外す。外すライブラリは PoC 検証の結果で決める

mdmark が持つ機能のうち今の画面と重なるもの（差分・コメント・用語のツールチップ・印刷）の扱い（PoC 検証で案 A に決めた）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mindstella 側の今の機能を使い続け、mdmark の重なる機能は設定で止める | 画面の操作と記録の形式が変わらず、範囲が描画の置き換えに収まる | mdmark の部品の見た目と操作にはそろわない |
| B | mdmark の機能へ寄せ、mindstella 側の同じ機能を外す | mdmark の部品にそろう | 記録の形式（変更履歴・コメント）とのつなぎ込みが要り、範囲と pt が膨らむ |

推奨: A

Issue の範囲は描画の置き換えで、用語の一致を mindstella 側に残すと決めている。
mdmark の機能へ寄せるのは、#212 と mdmark の追加の機能を待ってから別の Issue で行える。

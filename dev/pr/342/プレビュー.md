## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 読み込み | `template.html` で mdmark の `dist/index.css` と `dist/index.js` を、タグ `v0.7.0` を固定した jsDelivr の URL（`https://cdn.jsdelivr.net/gh/shuhei1101/mdmark@v0.7.0/dist/`）で読む | 今の名前空間のスクリプトから ES モジュールの `mount` を呼ぶ形は PoC 検証で決める |
| 本文の描画 | 本文・項目の文字列の値・本文の差分の塊を、`renderWithLines` の marked の描画から mdmark の描画に置き換える | 用語のマーカー（`linkBody`）は mindstella 側の一致のまま、mdmark の描いた本文に当てる |
| 行のマーカー | 選んだ箇所へのコメントが使う元の Markdown の行を、mdmark の描いた本文から引く | `未確定`（決める段: PoC 検証）。mdmark が出す行の属性で足りなければ、描いた後に mindstella 側で付ける |
| スレッドの書き込み | 書き込み・レビュー中の書き込みの本文を、文字のままの表示から mdmark の描画に替える | 項目の ID とまとまりへのリンクは今と同じく押して開ける |
| 図 | 図の拡大・Raw・コピーと図の差分を保つ | 図を mermaid で直接描き続けるか mdmark に任せるかは PoC 検証で決める |
| 重なる機能 | mdmark の差分・コメント・用語のツールチップ・印刷は使わない | 要件の `未確定` の推奨の案 A。設定で止められるかは PoC 検証で確かめる |
| 見た目 | 本文と書き込みに mdmark の共通スタイルを当て、ライト / ダークをプレビューのテーマに合わせる | デザイン方針を更新する |
| 読み込めないとき | mdmark が読めないときも、今と同じく読めなかったライブラリの名前と原文を出す | - |
| 動作環境 | 非機能要件のブラウザ（Chrome と Edge の最新版）は mdmark の対象（Chrome 99 以上）に入るため変えない | - |
| 既存機能への影響 | 本文の見出しのリンク・`#diff=` のリンク・`html` のコードブロックの枠・表の入れ物を保つ | 結合テストで確かめる |

行のマーカーの `未確定`（決める段: PoC 検証）:

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mdmark が描いた要素の行の属性（`data-line` ほか）を、選んだ箇所のコメントの行に読み替える | mindstella 側で Markdown を解析し直さない | mdmark の出す属性の範囲（表の行・リストの項目・コードの中）に左右される |
| B | mindstella 側で Markdown を解析して行を求め、mdmark の描いた要素へ付け直す | 今の行の求め方を保てる | Markdown の解析を mdmark と二重に持つ |

推奨: A

描画を mdmark に一本化する Issue の目的に合う。
足りない箇所が PoC 検証で見つかったときだけ、その箇所を B で補う。

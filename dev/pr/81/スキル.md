## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| セットアップ | 話題に合う進め方ガイドを 1 つ以上選び、選んだガイドをすべて読む。ゴールは候補を示したうえで「決めずに始める」も選べるようにし、題名（何について話し合うか）だけは必ず決める | 複数のガイドを選んだときは、各ガイドのフェーズから 1 本の並びのたたき台を作って確かめる |
| 話し合いの準備 | `playbooks` に並んだガイドをすべて読む | - |
| 範囲を見直すステップ | `session` にステップを足す。範囲が広がった・利用者が題名・ゴール・ガイド・呼び名を変えたいと言った・話の中身と呼び名が合わなくなったときに、AI が書き換えのたたき台を示して確かめ、設定を書き換えるツールで書く | - |
| ガイドの付け替え | ガイドを足す・外す・入れ替えてフェーズが変わるときは、古いフェーズから新しいフェーズへの対応の表を示し、利用者が確かめてから付け替える。対応の無い古いフェーズは、どの新しいフェーズへ移すかを尋ねる | - |
| 取り込み | ゴールの納品物に当たる資料を作ったら、設定を書き換えるツールで、同じタイトルの納品物があればその `doc` から資料を指し、無ければ行を足す | ゴールが無いときは足さない |
| 方針転換 | 要らなくなった納品物は、設定を書き換えるツールでゴールの納品物から外す。Edit ツールで `mindmap.yaml` を直す手順を消す | `allowed-tools` に設定を書き換えるツールを足す |
| ゴール判定 | ゴールが無いときは、リリースせず、ゴールを決めるかを利用者に尋ねる。決めると言われたら範囲を見直すステップでゴールを書く | - |
| システム開発の進め方ガイド | `## 最上位の軸の呼び名` を「機能」にし、対象に入れるのは機能の名前と概要、システムの違いはタグで分けると書く | - |

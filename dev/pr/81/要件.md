# 要件

## 要望

話し合いの途中で、題名・ゴール・プレイブック（進め方ガイド）・最上位の軸の呼び名を MCP のツールで書き換えられるようにし、ゴールを任意・プレイブックを配列にした設定の形で、同じワークスペースのまま範囲の広がった話し合いを続けられるようにする。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 題名 | 話し合いの途中で、題名（`summary`）を書き換えられる。範囲が広がったら、AI が状況に合わせて題名を書き換える。題名は今と同じく必須 |
| ゴールは任意 | 設定はゴールを持たなくてよい。ゴールを持たないワークスペースを作れ、読み書き・点検・プレビュー・ゴール判定がそのまま動く |
| ゴールの中身 | ゴールは 1 つで、どこで一区切りか（フェーズと概要）と納品物を持つ。話し合いの途中で、ゴールを足す・書き換える・外す、納品物を足す・外すことができる。範囲が広がったら、AI がゴールを状況に合わせて書き換える |
| プレイブックの配列 | 分野（`field`）を、プレイブックの名前の配列に変える。1 つ以上を並べ、AI は並べたガイドをすべて読む |
| プレイブックの付け替え | 話し合いの途中で、プレイブックを足す・外す・入れ替えられる。フェーズが変わるときは、古いフェーズと新しいフェーズの対応を利用者に示して確かめてから、設定と項目のフェーズを付け替える。新しいフェーズに無いフェーズを持つ項目を残したまま付け替えない |
| 話し合いの概要 | 設定に、何についての話し合いかを 1 文の短い文（60 字以内）で書く概要（任意のキー）を足す。AI がセットアップと範囲の見直しで書き、設定を書き換えるツールで書き換える。利用者は `mindmap.yaml` を直して書き換える。概要の画面の題名の上には、プレイブックの名前とゴールのフェーズの代わりにこの概要を出す |
| ゴールが無いときの概要の画面 | ゴールまでの進捗のタイルを出し、見出しを「フェーズ別の進捗」にして、下に「ゴールは決まっていません」と全フェーズの決着の数だけを出す（納品物は出さない） |
| フェーズの並び | 複数のプレイブックを並べても、フェーズはワークスペースの設定が 1 本の並びで持つ。プレイブックを選ぶ・足すときに、AI が並べた各ガイドのフェーズから並びのたたき台を作り、利用者の確認を取る |
| フェーズの付け替えの書き込み | 設定を書き換えるツールが古いフェーズから新しいフェーズへの対応を受け取り、設定と項目の `phase`・`goal.phase` を 1 回の書き込みで付け替える。対応の無いフェーズを持つ項目が残るときはエラーにし、どのファイルも書き換えない |
| フェーズの点検 | 点検（`check`）が、項目の `phase` と `goal.phase` を設定の `phases` と突き合わせ、設定に無いフェーズを問題として返す |
| 設定を書き換えるツール | 題名・ゴール（納品物を含む）・プレイブック・フェーズ・最上位の軸の呼び名を書き換える MCP のツールを足し、スキーマで検証してから書く。方針転換で納品物を外すのもこのツールで行い、Edit ツールで `mindmap.yaml` を直さない |
| 最上位の軸の呼び名 | システム開発の進め方ガイドの最上位の軸の呼び名を「システム」から「機能」にし、システムの違いはタグで分けると書く。話の中身と呼び名が合わなくなったら、AI が呼び名を書き換える |
| 既存のワークスペース | 今の版のワークスペースは、移し替え（`/mindstella:upgrade`）で `field` をプレイブックの配列へ移す。移し替えで、今のワークスペースの呼び名は書き換えない |

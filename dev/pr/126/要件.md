# 要件

## 要望

プレビューの画面を、次のとおりに変える。

- 絞り込み: 表で、列（ID・用語集の「用語」など）の値で行を絞り込める。ID でも絞り込める。入口は絞り込みのドロワーの列ごとの「文字を含む」の欄にし、列の見出しに絞り込みのボタンは置かない
- 全体の検索の並び: ID かタイトルが検索の言葉と完全に一致する項目を、結果の一番上に出す（大文字・小文字と前後の空白は区別しない）。続く結果は今の種類ごとのまとまりのまま
- 全体の検索のショートカット: `Ctrl+K`（macOS は `Cmd+K`）で開く。`/` では開かない。入力欄・テキストエリアに入力中でも `Ctrl+K` で開く。トップバーの検索の入口に出すキーの案内も `Ctrl+K` にする
- 画面のスクロール: どの画面も、ページ全体はブラウザのウィンドウの高さに収め、ページ全体の縦スクロールを出さない。スクロールが要る所（概要のタイル・ボード・マップ・カード・表・つながり）は、トップバーとタブの帯の下の領域の中で縦・横にスクロールさせる
- 上の帯: トップバーとタブの帯は、どの画面でもどこまでスクロールしても見えたままにする
- 本文の見出しのリンク: 詳細パネルと全画面の本文（Markdown）の見出しごとにリンクを付ける。本文の中の `[文言](#見出し)` のリンクと、URL のハッシュから、その見出しへ移れる
- 本文の中の用語: 詳細パネルと全画面の本文に、用語集の用語（用語の項目のタイトル）が出てきたら下線などで示す。カーソルを合わせる・フォーカスすると、その用語の意味をツールチップで出す。押すとその用語の詳細を開く。用語の項目自身の本文の中の、その用語自身は示さない
- 本文の中の項目の ID: 詳細パネルと全画面の本文に、記録にある項目の ID（`D-95` など）が出てきたら、その項目の詳細を開くリンクにする。記録に無い ID はリンクにしない
- 用語と ID のリンクは、本文の文中（インラインコードを含む）に付け、コードブロックと図には付けない。見出しの中の用語には印を付けない
- 全画面表示のボタン: 全画面表示の間もボタンの色を変えず、アイコンを縮小（矢印が内向き）に替える
- 検討事項のマップ: 中間の層（カテゴリー・フェーズ）のラベルに枠か背景を付け、線の上でも読める
- 詳細の全画面（モーダル）: 今より一回り大きくする。開いている間、モーダルの中でスクロールしても後ろの画面をスクロールさせない。本文（Markdown）の幅をモーダルの幅いっぱいまで広げる

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 種類・状態・タグでの絞り込み | [#89](https://github.com/shuhei1101/mindstella/pull/89) でドロワーとして入っており、要望もこの PR の対象から外している | 予定なし（対応済み） |
| 本文のコードブロックと図の Raw の横スクロールへキーボードで届かない | 同じ本文を触るが、キーボードで届かない不具合で目的が違う | [#93](https://github.com/shuhei1101/mindstella/issues/93) |
| 詳細パネルの外（表のセル・カード・ボードのカードの要約）に出る用語・項目の ID のリンク | 要望は資料・本文を対象にしている | 予定なし |

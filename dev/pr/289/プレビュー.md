## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 全体の検索 | 389px 以下で検索の入力欄を縮められるようにし、ダイアログの中を横に送らせず、「検索を閉じる」を窓の中に置く | 320 x 568 で入力欄が縮まず、ダイアログの中が横に送れて「検索を閉じる」が窓の外に出ていた |
| 図の拡大 | 389px 以下で「本文へ戻る」を印（‹）だけのボタンにし、名前は読み上げに残す | 320 x 568 で「本文へ戻る」が 3 行に割れて帯の上へ見切れていた。モックの案（2 段にする案と比べた） |
| 概要 | 389px 以下で「次に検討する項目」の見出しと「すべて表示（N 件）」をそれぞれ 1 行に保ち、収まらないときは「すべて表示」を次の行へ回す | 320 x 568 で見出しと「すべて表示」が途中で割れていた。モックの案（文言を縮める案と比べた） |
| 詳細パネル・詳細の全画面 | 本文の長い URL・インラインコードを本文の幅で折り返す（項目の ID のリンクは折り返さない）。本文の表は、表の画面の `.table-wrap` と同じく `overflow: auto` の要素で包み、表の中だけで横に送る。包む要素は `tabindex="0"`・`role="group"`・`aria-label="本文の表"` にし、キーボードで送れるようにする | 320 x 568・390 x 844 で本文の区画ごと横に送れていた（表は列の多いとき 1280 x 800 でも）。全ての幅で効かせる |
| 残りの画面と部品 | 変えない | 320 x 568 で横に送れる区画（表・カテゴリー別の進捗は要素の中で送る）・見切れ・押せないボタンが無かった |
| レスポンシブ対応 | 洗い出した箇所を、320px でページ全体が横にスクロールせず、要素が見切れない作りにする。中身が表示幅を超える表・マップ・ネットワーク・図・本文のコードブロックは、その要素の中でだけ横にスクロールさせる | はみ出す要素だけを 389px 以下で直す（詳細パネル・詳細の全画面の本文は全ての幅） |
| 既存機能への影響 | 幅 390px 以上の見た目（詳細パネル・詳細の全画面の本文の幅を超える URL・インラインコード・表の見せ方を除く）と、ボタンの読み上げの名前・押したときの動きは変えない | - |
| 画面設計 | 全体の検索の閉じる・図の拡大の閉じる・概要の次に検討する項目のすべて表示・詳細パネルの本文（詳細の全画面も同じ）に、幅 389px 以下（本文は全ての幅）の表示の仕方を書く | 部品の引数・状態は変わらないため、部品設計は変えない |
| モジュール構成 | 本文を描く `renderMarkdown`（`core/libs.ts`）で、描いた本文の表を横に送れる要素で包む | 詳細パネル・詳細の全画面の本文と、本文の差分の部品が共に使う |
| 結合テスト | 対象の画面ごとに 320 x 568 で開き、`document.documentElement.scrollWidth` が表示幅以下で、表・マップ・ネットワーク・図・本文のコードブロックのほかに `scrollWidth` が `clientWidth` を超える区画が無く、画面の主な操作のボタン・閉じるボタンが表示幅の中にあって押せることを確かめる。320px で変わる部品はストーリーを 320 x 568 で確かめる | 既存の 390 x 844 の確かめは残す |
| 動作環境 | 非機能要件『画面サイズ』の決定値（幅 320px 以上）と測り方は変えない | - |

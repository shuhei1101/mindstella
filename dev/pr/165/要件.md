# 要件

## 要望

### 起動スクリプトの alias と環境変数の登録

セットアップのスキル `/mindstella:setup` が、起動スクリプト（`bin/mindstella`）を呼ぶシェルの alias の登録と、起動スクリプトが読む mindstella の環境変数（`MINDSTELLA_VENV`・`MINDSTELLA_ALLOWED_HOSTS`・`MINDSTELLA_PREVIEW_START_HOOK`・`MINDSTELLA_PREVIEW_STOP_HOOK`）の設定を受け持つ。
登録と設定は MCP のツールを使わず、スキルの配下に置くスクリプトで行う。
MCP のツールが無い Claude Code（起動スクリプトで立ち上げる前）で `/mindstella:setup` を呼んでも、登録と設定を実行できる。
登録した後は、新しいシェルで alias にワークスペースのフォルダを渡すと、起動スクリプトを叩いたのと同じく立ち上がる。

alias と環境変数を書く先は、インターフェース定義設計で B に決めた（インターフェース定義『起動スクリプトの登録』）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ログインシェルの設定ファイル（`~/.bashrc`・`~/.zshrc`）に、mindstella の印で囲んだ範囲を書く | 置くファイルが増えない | 書き直す・消すたびに利用者の設定ファイルを書き換える |
| B | mindstella 専用のファイル（例 `~/.config/mindstella/shell.sh`）に書き、ログインシェルの設定ファイルには読み込む 1 行だけを足す | 書き直す・消すときは専用のファイルだけを置き換える | 置くファイルが 1 つ増える |

決定: B

設定を変えるたびに書き換えるのが専用のファイルだけになり、利用者が手で書いた設定ファイルの中身を壊さない。

alias は、叩くたびに `claude plugin list --json` から今の `installPath` を引いて `bin/mindstella` を叩く。
プラグインを上げて古い版のフォルダが消えた後も、登録し直さずに今の版で立ち上がる。

Claude Code のアカウントを複数持つ利用者は、`/mindstella:setup` でアカウントの名前と Claude Code の設定のフォルダを登録し、アカウントごとの alias `mindstella-{アカウントの名前}`（例 `mindstella-sub1` → `~/.claude-sub1`）で立ち上げる。
`mindstella-{アカウントの名前}` は、`installPath` を引く `claude plugin list --json` にも、起動スクリプトにも、そのアカウントの `CLAUDE_CONFIG_DIR` を渡す。
`mindstella` はシェルの既定のアカウントのまま立ち上げる。
起動スクリプトの tmux のセッションの名前はワークスペースのフォルダとアカウントで決め、同じフォルダを別のアカウントで開くと別のセッションになる。

### サーバーで使うときの絞り込みの保存

サーバーの配信でプレビューを開いたとき、絞り込みのドロワーで選んだ条件を保存し、読み込み直しても・開き直しても同じ条件で描く。
配る書き出し（見るだけの 1 枚の HTML）では保存しない。

条件は端末の保存領域（個人の上書きと同じ `localStorage` のキー）に画面ごとに持ち、同じワークスペースを見る他の人の表示を変えない。
表示の設定の「この端末で変えている項目」に出し、「既定に戻す」で外す。
URL のハッシュの `f.{列}` で開いたときはハッシュの条件で描き、保存した条件を書き換えない。

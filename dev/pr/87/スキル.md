## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 記録は確かめずに書く | 記録は状況が変わるたびに確かめずに足し・書き換え、確かめるのはワークスペースの外へ書き込むときだけ、という決まりを置く | 置く場所は `未確定`（要件.md） |
| 取り込み: 検討事項 | 検討事項を足すときに、AI が案（`key`・`content`・`pros`・`cons`）を書いて `options` に入れる。決めたこととして足すときは選ばれた案を `adopted: true` にする | 問いの形にならない未整理は、案を書けるようになった段階で書く |
| 取り込み: タスク | AI がやる作業も、利用者に頼む作業も、出た時点でタスクとして積む | 担当は #26 |
| 取り込み: 納品物の資料 | ゴールの納品物が決まったら資料を作り、本文に概要・背景・最終的な構成を先に置いてゴールの `doc` から指す。決まったことに合わせて本文を書き足す | 今の「図や文書を資料に残す」の納品物の扱いを広げる |
| 取り込み: 用語集 | 一般的でない言葉を、利用者が指定しなくても足す。一般的な技術の言葉は指定されたときだけ | 今の言い方のずれを正す決まりは残す |
| 取り込み: タスクの成果 | タスクで作った成果を 1 件ずつ資料にしてタスクの `related` から指し、完了にする前に 1 対 1 を確かめる | 調査のタスクは除く（要件.md のスコープ外） |
| ヒアリング | 検討事項が持つ案を案の表に出す。案の無い検討事項は、案を書き足してから聞く。答えを記録するときは選ばれた案を `adopted: true` にする | - |
| リサーチ | 調べた結果や読んだコード・ドキュメントにある固有の言葉を用語集に足す | - |
| 範囲の見直し | ゴールの納品物を足したら、取り込みの手順で資料を作って `doc` から指す | - |
| 準備 | ゴールの納品物のうち `doc` を持たないものがあれば、取り込みの手順で資料を作る | セットアップで決めたゴールの分。setup の `allowed-tools` は変えない |
| ゴール判定 | `goal` が届いたと返した後、確定を取る前に、完了したタスクの成果と資料が 1 対 1 で揃っているかを確かめ、欠けていれば資料を足してから確定を取る | `goal` の判定は変えない |
| 結合テスト | インターフェース定義の制約を変えた分を `test_session.py` に足す | 手順をモデルが読んで動かす振る舞いは確かめない |

# プレビューの項目を追加する入力で、続けて入力しても前の送信の値を失わないようにする

## 概要

利用者がプレビューの「項目を追加」の入力で、案やキーを続けて書いても、先に書いた案・値が失われずに溜まるようにする。

## 背景

[Issue #386](https://github.com/shuhei1101/mindstella/issues/386) の不具合。
release PR [#384](https://github.com/shuhei1101/mindstella/pull/384) の E2E で `tests/e2e/単一ユースケース/test_item_add.py::test_normal_when_options_written` が fail した（[実行の結果の報告](https://github.com/shuhei1101/mindstella/pull/384#discussion_r4433842741)）。
追加の入力の `submitAddField` は、保存待ちの `item-add` の `value` をコピーして書き換え、送信し直す。
`editState.edits` は送信の応答の後の `loadEdits()` で初めて更新されるため、前の送信の応答より前に次の入力が来ると、前の値を含まない `value` から組み立てて上書きする。
案の操作で起きる形は [#382](https://github.com/shuhei1101/mindstella/pull/382) で入り、キーの書き換えで起きる形は [#325](https://github.com/shuhei1101/mindstella/pull/325) からある。
どちらもまだリリースしていない。

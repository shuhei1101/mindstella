# 要件

## 要望

プレビューの「項目を追加」で開いた追加の入力で、`submitAddField` の送信を、前の送信の応答の後へ順に当てる。
前の送信の応答より前に次の入力が来ても、次の送信は前の送信の値を含む `value` から組み立てる。

終わりの条件:

- 検討事項の追加の入力でタイトルを書き、「案を追加」→ 案 A を書いて離れる → すぐに「案を追加」→ 案 B を書いて離れると、保存待ちの `item-add` の `value.options` が A・B の 2 件になり、追加の入力にも案 A・B が出る
- 追加の入力でキーを続けて書き換えると（例: タグを書いて離れ、すぐに影響度を変える）、保存待ちの `item-add` の `value` に両方の値が入る
- タイトルを書いた最初の `item-add` の応答より前に次の入力が来ても、`target` の無い `item-add` をもう 1 件送信せず、保存待ちの編集の件数は項目の追加 1 件のまま
- `tests/e2e/単一ユースケース/test_item_add.py::test_normal_when_options_written` が pass する

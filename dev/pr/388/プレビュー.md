## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 追加の入力の送信の順序 | 追加の入力を開くたびに送信の並び（`EditState.addSend`）を作り、`submitAddField` の送信を前の送信が終わってから順に当てる。次の送信の `value` は、並びが持つ最後に溜められた `value`（無ければ並びの `addDraft`）から組み立て、読み直し（`loadEdits()`）の結果は待たない。当て先は `editing` ではなく並びの仮の ID で引き、閉じた・別の追加を始めた後も積んだ入力はその仮の ID へ送る | 案の操作（`option-add`・`option-edit`・`option-remove`・`adopt`）もキーの書き換え（`set`）も同じ順序に載せる |
| 最初の `item-add` の応答の前の入力 | タイトルを書いた最初の `item-add` の応答より前に来た入力も、応答の後に、返った仮の ID の `item-add` の `value` へ当てて送信する。`target` の無い `item-add` を 2 件送信しない | 応答で `editing`・`adding` を書き換えるのは、その並びの追加の入力をまだ開いているときに限る |
| 送信が断られた・届かないとき | その送信の理由を今までどおり `errors` に入れ、後に続く入力は、断られた送信を除いた保存待ちの `value` から組み立てて送信する | 既存の `submitEdit` の扱いを変えない |

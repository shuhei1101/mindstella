## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| シナリオ『ワークスペースの移し替え』 | `test_normal_when_version_recorded_at_top` のフローと期待値を「`v0.5.0` より新しくプラグインの版までの手順（v0.6.0 の手順を含む）」、`test_normal_when_options_filled` のフローを「`v0.6.0` より新しくプラグインの版までの手順（v0.7.0 の手順を含む）」と書く | 個々の手順の中身を確かめる期待値（D-1 に採用した案を作る 等）は変えない |
| インターフェース定義『記録の形式の移行』 | `test_normal_when_plan` の `plugin_version` をプラグインの版、`steps` の版を `migrations/` にある全ての手順の版と書く。`test_normal_when_apply` の当てる手順を「プラグインの版までの手順」、`test_normal_when_record` の `recorded` と版のファイルの 1 行目をプラグインの版、`test_normal_when_version_file_at_top` の `steps` を「`v0.5.0` より新しくプラグインの版までの手順の版」と書く。`test_normal_when_answer_to_option` は `to_version` に `v0.7.0` を渡す形にする。版を並べた `summary` も「プラグインの版までの手順」と書く | `destructive` が v0.6.0 の手順だけ `true`・`v0.3.0` の手順の失敗・`to_version` を渡す流れは版のまま残す |
| 割り出しの補助 | `tests/workspace_fixtures.py` に、`version.ini` の 1 行目を返す関数と、`migrations/` の版のフォルダのうち渡した版より新しくプラグインの版までの版の集まりを返す関数（渡した版が無いときは版を記録する前の形式として全ての版）を置く | 版の大小は `v{major}.{minor}.{patch}` を数の組で比べる |
| E2E テスト | `test_workspace_upgrade.py`・`test_discussion_to_goal.py` の `_plugin_version` を消して補助を使い、`test_workspace_upgrade.py` の手順の版の比較を補助の結果と比べ、版を並べた docstring を「プラグインの版までの手順」と書く。`test_discussion_setup.py` は #176 のバックマージが develop へ入った後に、中の `_plugin_version`・`_step_versions_after` を消して補助を使う | E2E は作成だけで、実行はスプリントの release ブランチで行う |
| 結合テスト | `test_migrate.py` の `PLUGIN_VERSION`・`STEP_VERSIONS` を補助から割り出し、`test_normal_when_version_file_at_top` の `{"v0.6.0", "v0.7.0"}` を `v0.5.0` より新しい版の集まりと比べる。`test_normal_when_answer_to_option` の 2 回の呼び出しに `to_version` の `v0.7.0` を渡す。版を並べた docstring を「プラグインの版までの手順」と書く | `SUMMARY_STEP_VERSION` と v0.6.0 の手順だけが破壊的の確かめは版のまま残す |

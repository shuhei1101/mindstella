## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 入力の時点 | まとめて送る処理が `submissions.yaml` と `comments.yaml` を書き終えた後に、足した送信を tmux のペインへ入力する。書き込みの鍵を持ったまま tmux を待たない | 送り先は要件の `未確定`（インターフェース定義設計） |
| 複数行の本文 | 改行で入力が確定されないよう、ペーストとして貼ってから確定のキーを送る | 使う tmux のコマンドは PoC 検証で確かめる |
| 入力の失敗 | 送り先のペインが無い・tmux が失敗した・時間内に終わらないときは、送信を残したまま 201 を返し、入力しなかったことを応答に載せる。ログに理由を残す | 待つ上限はインターフェース定義設計で決める |
| 届いたかの確かめ | 入力の後、受け継いだ `CLAUDE_CONFIG_DIR` の `projects` の下で作業フォルダに当たるフォルダの jsonl のうち、入力した後に書き足されたものを引き、`cwd` がワークスペースのフォルダと一致する user のメッセージに送った送信の ID が入ったかを確かめる。会話の ID（`CLAUDE_CODE_SESSION_ID`）は `/clear` で変わるので使わない。入っていなければ入力できなかったときと同じに扱う | 待つ時間と待ち行列の扱いはインターフェース定義設計で決める |
| 応答 | `POST /api/comments/send` の 201 の本文に、Claude Code へ入力したかを足す | プレビューの「送った結果」の出し分けに使う |
| 二重の取り込み | 入力した送信も `taken` は空のまま残し、AI が取り込んだときに `take_submission` で取り込み済みにする。話し合いの最初の取り込みは `taken` が空のものだけを拾う | 既存の取り込み済みの仕組みを使う |

結論は不成立とする。
ペインが入力を待つ状態（入力欄が空・応答中）なら、送信の内容は欠けずに 1 回の入力として入り、送り先の決め方は案 A で成り立つ。
一方で、利用者が打ちかけているときは打ちかけごと送られ、選択の表示（許可の確認を含む）が出ているときは `Enter` が既定の項目を選んで文字列が失われるため、ペインの状態を見ずに入力する形では要件が成り立たない。
ユーザーがこの 2 つの崩れを利用者が tmux で気づいて直すものとし、ペインの状態を見ずに入力する形に要件を直した（[確認ログ](./確認ログ.md)）。
直した要件の下では、確かめた観点は全て成り立つ。

検証した Claude Code は 2.1.296、tmux は 3.4。
使ったアカウントはログインが切れていてモデルを呼べなかったため、応答中はシェルの実行で、許可の確認は `/mcp` の選択の表示で代えた。
入力欄の扱いは Claude Code の画面の側で決まり、モデルの応答の有無に依らない。
モデルを呼ばなかったため、従量課金の実費は 0 円（見積もりは Haiku 5.5 の単価で 1 回の実行あたり 100 円未満）。

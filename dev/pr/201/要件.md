# 要件

## 要望

### 送ったコメントを Claude Code へ入力する

プレビューのコメントの一覧でまとめて送ると、サーバーは `submissions.yaml` に足した後、その送信を起動スクリプトが立てた tmux のセッションの Claude Code へ文字列として入力する。
入力は送るたびに行い、話し合いの途中でも、利用者が Claude Code へ打ち込まずに送信が会話に入る。
Claude Code が応答している最中に送ったときも、入力は失われず、応答の後に会話へ入る。
本文が複数行の送信も、行の途中で入力が確定されず、1 回の入力として入る。
入力欄に打ちかけがあるときや、選択の表示（ツールの許可の確認など）が出ているときも、ペインの状態を見ずに入力する。
打ちかけとつながって送られたり、選択の表示で入力が失われたりしたときは、利用者が tmux のセッションを見て気づき、自分で直す。
Claude Code のフック（利用者の送信のたびに動くもの）は使わない。

入力する文字列の中身は、単一ユースケース設計で A に決めた（単一ユースケース『コメントを選んで送る』『送信の取り込み』）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 送信ごとの ID・向けた項目・箇所・本文を並べ、取り込んで取り込み済みにするよう添える | 会話を見るだけで何が届いたか分かり、AI が `submissions` を呼ばずに取り込める | 長い本文をまとめて送ると入力が長くなる |
| B | 「画面から送信が {件数} 件届いた」と取り込みを促す 1 行だけを入力し、中身は AI が `submissions` で読む | 入力が短く、本文の長さや改行に左右されない | 会話の上では何が届いたか見えない |

決定: A

Issue は送信の内容が文字列として入ることを求めており、利用者が会話の上で送ったものを確かめられる。
長い複数行の入力は貼り付けとして会話に入るため、Claude Code は入力された文字列をそのまま記録せず、並んだ ID を手がかりに取り込んでいない送信の一覧で読み直してから記録する。

`未確定`: 送り先の tmux のペインの決め方（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Claude Code から立った MCP サーバーが受け継ぐ `TMUX_PANE` のペインへ入力する | 起動スクリプトを変えずに、Claude Code が動くペインを指せる。利用者がウィンドウを分けても指す先がずれない | tmux の中で立てた Claude Code であれば、起動スクリプトを使わなくても入力される |
| B | 起動スクリプトがセッションの名前を MCP の設定の `env` で渡し、そのセッションへ入力する | 送り先が起動スクリプトの立てたセッションに限られる | 起動スクリプトと `launch.py` を変える。セッションの中でウィンドウやペインを増やすと、指す先が Claude Code でなくなる |

推奨: A

送り先は Claude Code が動いているペインそのもので、セッションの名前を経由するより取り違えが起きない。

### 届かないときの扱い

tmux の中で立てた Claude Code でないとき（送り先のペインが無いとき）や、tmux への入力に失敗したときも、送信は `submissions.yaml` に残し、まとめて送る操作は失敗にしない。
入力しなかった送信は、今までどおり話し合いの最初の取り込みで拾う。
同じ送信を、入力したときの取り込みと話し合いの最初の取り込みで 2 度取り込まない。

入力した後、Claude Code の会話の記録に送った送信が入ったかを確かめ、入っていなければ入力できなかったときと同じに扱う。
会話の記録は、MCP サーバーが Claude Code から受け継ぐ設定のフォルダ（`CLAUDE_CONFIG_DIR`、無ければ既定のフォルダ）の `projects` の下で作業フォルダに当たるフォルダから、入力した後に書き足された jsonl を引き、アカウントを使い分けていても、そのセッションのアカウントの記録を読む。
`/clear`・`/resume` で会話の ID が変わっても今の会話を拾えるよう、会話の ID には頼らない。
届いたかは、`cwd` がワークスペースのフォルダと一致する user のメッセージに、送った送信の ID が入ったかで見る。
同じフォルダで別の Claude Code を並べて動かしているときは、別の会話に入ったものも届いたと数える。
確かめるまで待つ時間と、応答中で入力が待ち行列にあるときの扱いは、インターフェース定義設計で決める。

コメントの一覧の「送った結果」で、Claude Code へ入力したかを出し分けるかは、モック作成で A に決めた（[確認ログ](./確認ログ.md)）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 入力できたときと、送信だけを残して入力できなかったときで文言を分ける | 「送りました」と出るのに Claude Code に入らない、という今回の事象を利用者が見分けられる | 送った結果の文言が増える |
| B | 今の「{件数} 件を送りました」のまま変えない | 画面を変えない | 入力できなかったときに、利用者が気づけない |

決定: A

今回の不具合は、画面が送れたと示すのに Claude Code へ届かないことで、届いたかを画面で見分けられないと同じ混乱が残る。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 共有サーバーで、送信を送り元の端末の Claude Code へ返す | 送り先を送り元ごとに分ける別の要望で、下書きにまとめられている | [#173](https://github.com/shuhei1101/mindstella/issues/173) |
| 入力できなかったことを Discord などの Webhook で知らせる | ユーザーが必須ではないとした。Webhook や OS の通知で状態を知らせる [#157](https://github.com/shuhei1101/mindstella/issues/157) と合わせて扱う | 起票予定 |

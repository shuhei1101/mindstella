## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| トランスポート | `main` は `MCPServer` の `streamable_http_app()` を `127.0.0.1` の `MINDSTELLA_PORT`（無ければ 8784）で待ち受ける。stdio の経路は削除する | ポートが使われていれば、使っているポートを示して終了コード 1 で終わる |
| 起動と管理 | `ensure_server.py` を置き、`GET /_admin/status` が mindstella を返さなければ仮想環境の Python で `server.py` をバックグラウンドで起動する。SessionStart のフックと起動スクリプトが呼ぶ。状態の確認と停止は管理のツール `server_status`・`server_stop` で行う | 要件.md の「常駐サーバーの起動と管理の仕方」の決定 B。systemd は使わない |
| ワークスペースの解決 | `resolve_workspace` は、フックが入れたセッションの作業フォルダを基準に相対パスを解決する。作業フォルダが無く相対パスのときはエラーにする | サーバーのプロセスの作業フォルダは使わない |
| ペインへの入力 | `InputTarget` はツールの引数 `session` から作り、配信の台帳がワークスペースごとに最後に受けた値を持つ。tmux へは `session.tmux` のソケットを `-S` で指して入力する | 引数が無い（tmux の外）ときは貼らない。今の挙動と同じ。貼る前に、`session.claude_pid` のプロセスが `session.claude_started_at` と同じ起動時刻で生きていて、ペインの `#{pane_pid}` の子孫かを確かめ、違えば貼らない |
| 配信の寿命 | 配信は常駐サーバーのプロセスに付く。常駐サーバーが止まるときに全ての配信を止め、終了時のフックを呼ぶ | SIGTERM の受け口は残す |
| 起動スクリプト | `--mcp-config` で渡すのをやめ、常駐サーバーが待ち受けていなければ起動してから Claude Code を立ち上げる | `launch.py` はプラグインのフォルダとセッションの名前だけを出す |
| 外から見る設定 | 外から見る設定の 3 つの環境変数を、常駐サーバーを起動する環境から読む | MCP の設定の `env` で渡す仕組みは削除する |
| 状態の持ち方 | セッションごとの値は引数で受け、モジュール変数に持たない | 書き換えの鍵はプロセスに 1 つのまま |
| 既存機能への影響 | 全てのツールの引数・返り値は変えない（フックが入れる引数 `session` の追加を除く）。Claude Code の中のツールの名前は、プラグインの `.mcp.json` から読むため `mcp__plugin_mindstella_mindstella__{ツール}` に変わる | 設計書・スキルの `allowed-tools`・公開ドキュメントのツールの名前を書き換える |

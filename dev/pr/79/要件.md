# 要件

## 要望

MCP のツールで項目を書き換えるたびに、変わったところを項目ごとの変更履歴としてワークスペースに残し、プレビューで前回からの差分を表示に切り替えて読めるようにする。

| 項目 | 要件 |
| --- | --- |
| 変更履歴 | `update`・`adopt` が項目を書き換えるたびに、変わったキーと本文の前回からの変更を、その項目の変更履歴として 1 回分積む。前回分を丸ごとは持たず、変わったところだけを持つ。変わったキーが無い書き換えは積まない |
| 保持する回数 | 何回分持つかを設定で決める。既定は 1、0 は履歴を持たず差分を出さない、上限は設けない。回数を超えた古い履歴は、次に積むときに消す |
| 変更履歴からの時点の選択 | トップバーの「変更履歴」ボタンでモーダルを開き、書き換えのまとまりを日時つきで新しい順に並べる（先頭は「前回開いてから」）。1 つ選ぶと、どの画面も同じ時点の差分の表示になる。項目ごとに比べる回を選ぶ形は持たない（[確認ログ](./確認ログ.md)） |
| Markdown の差分 | 本文を Markdown として描いたまま、足した部分と消した部分を見分けられる |
| 図の差分 | mermaid の図は描いたまま、変わったノード・辺を色で示す。対象は flowchart・sequenceDiagram・classDiagram・erDiagram・stateDiagram-v2 で、それ以外の種類は変わった図の枠に色を付け、Raw で記法の行の差分を見せる（[確認ログ](./確認ログ.md)） |
| Raw の差分 | Raw（元の記法）の表示では、行ごとの差分を読める |
| キーの差分 | 本文以外のキー（状態・答え・案 など）も、前回の値と今の値を見分けられる |
| 書き換えのまとまり | MCP のツール `commit`（一言の説明つき）が、最後のまとまりより後の書き換えを 1 つのまとまりにして日時と説明を付ける。`pending` はまだまとめていない変更の一覧を返す。書き換えは今と同じくすぐワークスペースと画面に反映する。スキル（`session`）はステップを 1 つ終えるたびに `commit` を呼び、まとめていない変更は変更履歴の一覧の先頭に出す（[確認ログ](./確認ログ.md)） |
| 新規の印 | 選んだ時点で足された項目に新規の印、変わった項目に変更の印を付ける。表・ボード・カード・マップ・概要のタイルの印は文言を付けず印だけにする（変更は ●、新規は +）。基準は端末に残る「前回開いた日時」で、タブを開いたときの値をそのタブの基準にし（無ければそのタブを開いた日時）、同じタブで読み込み直しても変えない。詳細パネルの差分は基準と関係なく、変更履歴の前回と比べる |
| タブの印 | 差分のある項目を持つタブに印を付ける。件数は残し、差分の表示の間だけタブの印の右上に点を重ねる（[確認ログ](./確認ログ.md)） |
| 配る書き出し | `export` が書き出す見るだけの 1 枚の HTML でも、同じ差分の表示を使える |
| 既存のワークスペース | 変更履歴を持たない既存のワークスペースはそのまま読み書きでき、差分が出ないだけにする。足すキーは任意のキーにし、移し替えの手順は足さない |

`未確定`: 保持する回数の設定の置き場所（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | ワークスペースの設定（`mindmap.yaml`）のキーにする |
| B | 環境変数にする |

推奨: A

ファイルの大きさはワークスペースごとに変わるうえ、[#24](https://github.com/shuhei1101/mindstella/issues/24) がワークスペースの既定と個人の上書きの 2 段へ広げるため。

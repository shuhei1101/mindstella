## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 変更履歴の形 | 全ての種類の項目に任意のキー（変更履歴）を足し、1 要素 = 1 回の書き換えとして、書き換えた日時・変わったキーの前の値・今の本文から前の版へ戻す行ごとの差分を持つ。新しい順に並べる | 本文の全文は持たない（#13 のメモのユーザーの求め） |
| 履歴を積む書き込み | `update`・`adopt` が `save_change` の前に、書き換える前の項目と後の項目を比べて 1 回分を積む。変わったキーが無ければ積まない。`add` は積まない（変更履歴の無い項目が新規） | `updated`・変更履歴そのものは比べる対象にしない |
| 保持する回数 | 積んだ後に、保持する回数を超えた古い要素を消す。0 のときは積まず、持っている変更履歴も次の書き換えで消す | 既定 1、上限なし |
| 保持する回数の設定 | 置き場所は要件の `未確定`（推奨: `mindmap.yaml` のキー）。無いときは既定の 1 として扱う | 決める段: インターフェース定義設計 |
| 記録の取得 | `GET /api/records` と `export` が変更履歴を項目に載せたまま返し、画面で前の版を組み立てられるようにする | `ビルド.py` の収集を共通に使う |
| 点検 | 変更履歴のキーをスキーマで点検する。本文を手で書き換えて前の版を組み立てられない変更履歴は、点検で知らせる | 本文の持ち方の決定に追従 |
| 既存のワークスペース | 変更履歴と設定のキーは任意にし、無いワークスペースをそのまま読み書きする。移し替えの手順は足さない | `mindstella-version.ini` の扱いは変えない |
| 書き込みの排他 | 変更履歴は項目と同じ YAML に持ち、今の `.mindstella.lock` の排他の中で一緒に書く | - |
| 非機能（大きさ） | 保持する回数を増やしたときの YAML と `GET /api/records` の大きさを非機能要件に置くかを、インターフェース定義設計で判断する | 上限を設けないため、決定値ではなく測り方を残す |

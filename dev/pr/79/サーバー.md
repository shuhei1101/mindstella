## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 変更履歴の形 | 全ての種類の項目に任意のキー（変更履歴）を足し、1 要素 = 1 回の書き換えとして、書き換えた日時・変わったキーの前の値・今の本文から前の版へ戻す行ごとの差分を持つ。新しい順に並べる | 本文の全文は持たない（#13 のメモのユーザーの求め） |
| 履歴を積む書き込み | `update`・`adopt` が `save_change` の前に、書き換える前の項目と後の項目を比べて 1 回分を積む。変わったキーが無ければ積まない。`add` は変更履歴を積まない。新規・変更の判定は変更履歴ではなく、まとまりの一覧から取る | `updated`・変更履歴そのものは比べる対象にしない |
| 書き換えのまとまり | まとまりへの所属は項目の変更履歴から切り離し、`changes.yaml` のまとまりの一覧で持つ。一覧の各要素は日時・説明・`until_seq` と、そのまとまりで足した項目の ID・変えた項目の ID を持つ。変更履歴の要素はワークスペースの通し番号 `seq` を持ち、まとまりの `until_seq` の範囲で引く。`add`・`update`・`adopt` は `pending` に ID を足す。MCP のツール `commit`・`pending` を足す | 形はインターフェース定義『書き換えのまとまり』『まだまとめていない変更』と ER 図『ワークスペース』。保持する回数を超えて消えた回でもまとまりの一覧に ID が残るため印は付けられる。巻き戻しは持たない |
| 保持する回数 | 積んだ後に、保持する回数を超えた古い要素を消す。0 のときは積まず、`pending.changed` にも足さず、持っている変更履歴も次の書き換えで消す | 既定 1、上限なし。0 では変更の印も付かない（単一 UC『前回からの差分を見る』の保持する回数が 0） |
| 保持する回数の設定 | `mindmap.yaml` の任意のキー `history_limit`。無いときは既定の 5 として扱う。保持する回数を超えて消した回の最大の `seq` を項目の `history_dropped_seq` に残す | ファイルの大きさはワークスペースごとに変わり、#24 が個人の上書きへ広げる |
| 記録の取得 | `GET /api/records` と `export` が変更履歴を項目に載せたまま返し、画面で前の版を組み立てられるようにする | `ビルド.py` の収集を共通に使う |
| 前回開いた日時 | プレビューのタブが開いたときに `POST /api/opened` で前回開いた日時を返し、ワークスペースの `.mindstella-opened` を今の日時に書き換える | 配信のポートは立てるたびに変わり、端末の保存領域ではセッションをまたいで残らないため |
| 点検 | `changes.yaml` をスキーマと参照切れで点検する。本文を手で書き換えて前の版を組み立てられない変更履歴は `stale_history` で知らせる | - |
| 既存のワークスペース | 変更履歴と設定のキーは任意にし、無いワークスペースをそのまま読み書きする。移し替えの手順は足さない | `mindstella-version.ini` の扱いは変えない |
| 書き込みの排他 | 変更履歴は項目と同じ YAML に持ち、今の `.mindstella.lock` の排他の中で一緒に書く | - |
| 非機能（大きさ） | 変更履歴は変わったキーと本文の差分だけを持つため、大きさの決定値は置かない。差分の表示の切り替えの時間を非機能要件に置く | 上限を設けないため、決定値ではなく PoC の規模を残す |

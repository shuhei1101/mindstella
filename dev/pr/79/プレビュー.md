## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 差分の表示の切り替え | 変更履歴のモーダルで選んだ時点を全ての画面で使い、端末の保存領域に残す。抜ける操作はトップバーの札の × とモーダルの「差分を出さない（今の内容）」。入れるときは今の版の図を使い回し、前の版だけを描く | 既定は差分を出さない |
| 前の版の組み立て | 項目の `history` を新しいものから選んだ時点の最初の `seq` まで当て、キーと本文を組み立てる | 足りなければ印だけ付けてその旨を出す |
| Markdown の差分 | 今の本文と前の版の行ごとの差分を取り、描いた段落・見出し・箇条書き・表の行へ、足した・消した印を付ける。消した行は描いた本文の中に消した印つきで差し込む | 印の見た目はモック作成 |
| 図の差分 | mermaid の記法の前後でノードと辺を突き合わせ、足した・変わったノードと辺を色で示す。消したものは図の外に一覧で示す | PoC で成り立った flowchart・sequenceDiagram・classDiagram・erDiagram・stateDiagram-v2 だけノード・辺に色を付け、それ以外の種類は変わった図の枠に色を付け Raw で記法の行の差分を見せる。消したものの見せ方はモック作成 |
| Raw の差分 | 図の拡大と詳細パネルの図の Raw で、記法の行ごとの差分（足した行・消した行）を出す | - |
| キーの差分 | 詳細パネルの各キーで、前の値と今の値を見分けられる形で出す | 見た目はモック作成 |
| 新規・変更の印 | 選んだ時点のまとまりの `added`・`changed` の項目に、表・カード・ボード・マップ・概要のタイルで印を付ける。「前回開いてから」は `POST /api/opened` が返す前回開いた日時より後のまとまりとまだまとめていない変更 | 差分の表示の間だけ出す |
| タブの印 | 印の付いた項目を持つタブに、件数を残したまま点を重ねる | - |
| 差分が無いとき | 変更履歴の無い項目・保持する回数が 0 のワークスペースでは、差分の表示に切り替えても今の内容をそのまま出す | - |
| 配る書き出し | 見るだけの 1 枚の HTML でも、埋め込んだ変更履歴から同じ差分を出す | 前回見た日時はその端末で持つ |
| 差分の計算 | 行ごとの差分と sequenceDiagram のメッセージの並びの突き合わせは、ブラウザで jsdiff 9.0.0 の `diffLines`・`diffArrays` に `timeout` を渡して計算する。打ち切ったら、本文は「本文の差分を計算しきれない旨」、図はその図だけを色付けの対象外の種類と同じ見せ方（枠に色・Raw で記法の行の差分）に落とす。jsdiff を読めないときは、本文の頭に `libraryNotice` を出し、本文・図・Raw を差分なしで描く | 外部ライブラリ『jsdiff』。描画のライブラリと同じく配信元から版を固定して読み、配る書き出しには埋め込む |
| アクセシビリティ | 足した・消したを色だけで示さず、記号か下線・取り消し線を併せる | - |

結論: 成立。
確かめた 5 種類はどれも、公開の `mermaid.render` だけで、変えた・足したノードと辺に色を付け、消したノードを一覧で取り出せた。
差分の表示の切り替えは、今の版の図を使い回して前の版だけを描く形にする（前後とも描き直すと、ノード 50 で 200 ミリ秒を超える）。
200 ミリ秒を 2 回とも満たした最大の規模は、図のノード 50・本文 1000 行。インターフェース定義設計で非機能要件の値の案にする。
計測の端末は WSL の Playwright の Chromium 151.0.7922.34。端末の空きメモリは約 40GB あった。MCP `get_capacity` の空き枠は 0 のまま計測しており、他のエージェントの処理と重なったため、2 回の値に 1.5 倍ほどの開きがある。

最小再現コードの要点（`poc/diagram-diff/diagdiff.js` の突き合わせ）:

```js
// ノード: g.node の id から「{描画の id}-」と末尾の「-{連番}」を外したものを鍵にする
function nodeKey(el, prefix) {
  let id = el.id.startsWith(prefix + "-") ? el.id.slice(prefix.length + 1) : el.id;
  return id.replace(/-\d+$/, "");
}
// 辺: data-id から端点を引き、同じ端点の辺は出てきた順の番号で分ける
base = did.replace(/^(L_|id_)/, "").replace(/_\d+$/, "").replace(/-\d+(?=_|$)/g, "").replace(/_/, ">");
// 前後の鍵で比べる: 今にだけある鍵は足した、文字が違えば変わった、前にだけある鍵は消した
for (const [k, n] of newX.nodes) {
  const o = oldX.nodes.get(k);
  if (!o) result.added.push({ kind: "node", key: k, els: n.els });
  else if (o.text !== n.text) result.changed.push({ kind: "node", key: k, els: n.els });
}
for (const [k, o] of oldX.nodes) if (!newX.nodes.has(k)) result.removedNodes.push(o.text || k);
```

diff の見どころ: `diagdiff.js` の `extract`（図の種類ごとの鍵の取り方）と、`run.py` の `toggle_reuse`（今の版の図を使い回す切り替えの計測）。
既知の限界: ノードの id に `_` を含む flowchart では、辺の `data-id` から端点を引く処理が区切りを取り違える。設計で、端点をノードの鍵の一覧と突き合わせて決める形にする。

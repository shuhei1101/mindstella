# 要件

## 要望

#342 で mdmark v0.7.0 に置き換えたプレビューの描画の上で、次を mdmark の機能で実現する。

- Markdown の資料に埋め込んだ HTML を、プレビューで描いた結果のまま見られる
- 埋め込んだ HTML の中の図・チャートを描き、チャートは拡大・縮小とドラッグでの移動ができる。普通の HTML には拡大・縮小のボタンを付けない
- 埋め込んだ HTML の中でも、用語・資料・調査のマーカーとツールチップ、項目の ID のリンクを出す
- 操作できる部品（スライダー・グラフ・今の値をコピーするボタン）が、資料の中でも埋め込んだ HTML の中でも動く。ボタンで動かした値を JSON にしてクリップボードへコピーし、利用者がコメントに貼って AI へ返せる
- 変更履歴の差分に、埋め込んだ HTML の変更を出す。既定はソースの行と文字の色分けにし、描いた結果の前と後にも切り替えられる
- 資料 1 件を書き出せる
  - Markdown で書き出す: 書き出す前に、埋め込んだ HTML が消えることと共通のスタイルが外れることを警告する
  - HTML で書き出す: 共通のスタイル（CSS）と用語のツールチップを中に持ち、mindstella が無くても開ける 1 枚の HTML にする。ほかの項目へのリンクは切れてよい
- AI が資料に HTML・図・操作できる部品を埋め込むときに読む、作り方の資料をスキルに持たせる
- 用語・エイリアスの一致を mindstella 側の処理から mdmark へ移し、mindstella 側の一致の処理を外す
  - 移した後も、全角半角・英字の大文字小文字・前後の空白の違いで用語・エイリアスが一致する（#334 から統合）
  - 正規化を持つ mdmark#102 を含むバージョンの mdmark へ上げる。mdmark#102 は v0.7.0 に入っておらず、v0.8.0 のリリースの PR（[shuhei1101/mdmark#144](https://github.com/shuhei1101/mdmark/pull/144)）が Draft で開いている

`未確定`: 埋め込んだ HTML と操作できる部品の描き方（決める段: PoC 検証）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mdmark の `<!-- html -->` の範囲と部品（`<mdmark-chart>`・`<mdmark-param>` ほか）で描く。資料に書いたスクリプトは動かさない | mdmark の記法・見た目・無害化にそろい、mdmark に追従する Issue の方針に合う | 部品で表せない動き（任意の計算式）は書けない。今の `html` のコードブロックの HTML の本文の枠と描き方が変わる |
| B | mindstella の HTML の本文の枠に `allow-scripts` を持たせ、資料に書いたスクリプトを枠の中で動かす | 任意の動きを書ける | mdmark の部品・ツールチップが枠の中に届かない。スクリプトを動かす安全の決め方が要る |

推奨: A

Issue は mdmark に追従する形へ書き直されており、操作できる部品は mdmark#21 が持つ。

`未確定`: チャートの拡大・縮小とドラッグでの移動（決める段: PoC 検証）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mdmark の `<mdmark-chart>` の図の拡大・移動を使い、足りなければ mdmark へ起票する | 外部ライブラリを増やさない | mdmark の拡大・縮小はボタンとキーで、Issue の追記のドラッグでの移動を満たすかを確かめる必要がある |
| B | Chart.js と chartjs-plugin-zoom を入れる | 追記の例のとおりに動く | 埋め込んだ HTML のスクリプトは動かないため、mdmark の部品の外で描く仕組みが要る |

推奨: A

`未確定`: 資料の書き出しを作る場所（決める段: PoC 検証）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | プレビューの画面で、mdmark のブラウザの API で描いた HTML と mdmark の CSS を 1 枚にまとめ、ブラウザでダウンロードさせる | 動作環境に Node を足さない。描いた結果と書き出しがそろう | mdmark のブラウザの API で 1 枚の HTML を作れるかを確かめる必要がある |
| B | サーバーで、配る書き出しの組み立て（`scripts/builder.py` の mdmark の CSS と JavaScript を中に持たせる処理）を資料 1 件に使う | 動作環境を変えずに済む。組み立ての処理を 1 か所にまとめられる | 描いた結果と書き出しの描画が、ブラウザとサーバーの 2 か所に分かれる |
| C | サーバーの MCP のツールから mdmark の CLI（`mdmark export`）を呼ぶ | mdmark の書き出しをそのまま使える | 動作環境に Node 24 以降が要る（非機能要件の動作環境の変更） |

推奨: A

`未確定`: AI が読む HTML の作り方の資料の置き場所（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `skills/mindmap/references/` に mindstella の資料としての書き方を置き、記法の詳細は mdmark の採用バージョンの資料（`docs/リファレンス/HTMLの書き方.md` ほか）を指す | mdmark の MCP を入れていない利用者でも読める | mdmark の版を上げるたびに指す先を確かめる |
| B | mdmark の MCP の `read_guide` を読むよう案内する | 記法の正本を 1 か所にできる | mdmark のプラグインを入れていない端末では読めない |

推奨: A

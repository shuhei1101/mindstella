# 要件

## 要望

リポジトリの直下に rule-inject の索引 `rules.yaml` を追加し、mindstella でファイルを記載する・ツールを呼ぶ前に、ヒットする規約が案内されるようにする。

| 要件 | 終わりの条件 |
| --- | --- |
| 直下に索引を配置する | `rules.yaml` が直下にあり、rule-inject の索引のチェック（スキル `rule-inject:setup`）がエラーを返却しない。master へ入った後、rule-inject のログに `/mnt/c/Users/shuhe/repo/mindmap/rules.yaml` の `read_index` の `FileNotFoundError` が出なくなる |
| プロジェクト固有のテンプレート・規約を掲載する | AI Monitor の索引 `rules.global.yaml` が適用していない、このリポジトリのテンプレート（`dev/テンプレート/` の `部品設計.schema.yaml` など）と規約が、適用する先のパスの glob つきで掲載されている |
| 使用しているスタックの knowledge の規約を掲載する | knowledge の `rules.yaml` に無い、このリポジトリのスタック（React・TypeScript・Python・Vite・Tailwind CSS など）の knowledge の規約のうち、このリポジトリの設計書と食い違わないものが、適用する先のパスの glob つきで掲載されている |
| 掲載の基準と書き方 | 掲載する行は knowledge の規約『ルール索引への登録』の強制注入の 4 つの基準を満たし、`paths` は同規約の書き方（`**/` で始める・拡張子の後ろに `*` を付けない）に従う。`rule` が指すファイルが全て実在する |

書式は knowledge の [rules.yaml](https://github.com/shuhei1101/knowledge/blob/develop/rules.yaml) と AI Monitor の [rules.yaml](https://github.com/shuhei1101/ai-monitor/blob/develop/rules.yaml)（`default_on`・`rules[].rule`・`paths`・`exclude`）に合わせる。

AI Monitor の `rules.global.yaml` と同じパスにヒットする、このリポジトリのテンプレートのコピー（`dev/テンプレート/シナリオ.schema.yaml` など）は掲載しない（同じファイルへほぼ同じ書式が 2 件案内されるため）。設計書は dev-docs の `write_docs` がこのリポジトリの Schema で検査するため、ずれた分は書き込みの検査で止まる。

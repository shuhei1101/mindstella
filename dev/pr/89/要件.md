# 要件

## 要望

1 つのワークスペースで関連する複数の話題を扱えるよう、AI が話題ごとのタグを作って項目に付け、プレビューの今ある画面を 1 つの絞り込みのボタンとドロワーで種類・状態・タグで絞り込めるようにする。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 話題のタグ | 話題は項目のタグ（今の `tags`。自由な文字列の配列）で分ける。AI が話題ごとにタグを作り、1 項目に複数付けられる。記録の形は変えない |
| 取り込みの決まり | 取り込みの手順に、発言を記録するときに話題ごとのタグを付ける決まりを足す。AI はタグの一覧を引き、既にある話題のタグを使い回し、新しい話題のときだけタグを作る |
| タグの一覧のツール | ワークスペースで使っているタグを、件数と付いている種類つきで返す MCP のツールを足す |
| タグで絞り込む検索 | 項目の検索（`find`）の `tag` で、そのタグを持つ項目を返す（今の `find` が持つ。変えない） |
| 絞り込む画面 | 検討事項（マップ・ボード・表）・タスク（ボード・表）・資料（カード・ボード・表）・記録の表（調査・用語集・メモ・会話ログ）・つながりで絞り込める |
| 絞り込みの条件 | 種類・状態・タグで絞り込める。同じ条件の中で複数の値を選ぶと、どれかに合う項目を出し、条件どうしは全てに合う項目を出す |
| 絞り込みのボタンとドロワー | どの画面も絞り込みのボタンを 1 つだけ置き、押すとドロワーが開いて条件を選べる。表の列の見出しの絞り込みのボタン、資料のカード・ボードの絞り込みのポップオーバー、マップの状態の帯とつながりの種類の帯の表示 / 非表示の切り替えは、このドロワーにまとめる |
| 件数のバッジ | 絞り込み中は、ボタンに件数のバッジを付ける。絞り込んでいないときはバッジを出さない |
| 表示形式の切り替え | 同じ画面のマップ・ボード・カード・表を切り替えても、選んだ条件を保つ |
| 開いたときの絞り込み | 概要のタイルなどから URL のハッシュの絞り込み（`f.{列}`）で開いたときも、ドロワーの条件として効き、バッジが付く |
| 配る書き出し | 配る書き出しの 1 枚の HTML でも、同じドロワーで絞り込める |

<!-- /table -->

`未確定`: 件数のバッジに出す数（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 選んでいる条件の値の数 | どの画面でも同じ意味になり、条件を外し忘れに気づける | 何件に絞れたかはバッジから読めない |
| B | 絞り込んだ後の項目の数 | 何件に絞れたかが分かる | マップ・つながりでは画面の中の数と重なり、条件の数が分からない |

推奨: A

ボタンは条件の入口で、絞り込み中であることと条件の多さを示すほうが役に立つ。
絞り込んだ後の件数は、画面の中（表の件数・ボードの列）が既に出している。

`未確定`: 各画面の「種類」の条件が指すキー（決める段: 画面設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | つながりは項目の種類（検討事項・タスク・資料 など）、他の画面はその種類の `kind`（タスクの作業・調査 など。持たない種類は種類の条件を出さない） | 画面に並ぶ項目に合った値で絞れる | 画面によって種類の意味が違う |
| B | どの画面も項目の種類 | 意味が揃う | 1 種類だけを並べる画面では種類の条件が意味を持たない |

推奨: A

1 種類だけを並べる画面で項目の種類を出しても絞り込めず、今の表の「種類」の列も `kind` を指している。

# 要件

## 要望

シナリオ『前回からの差分を見る』の `正常シナリオ（保持する回数が 0）` と、それを確かめる `test_normal_when_history_limit_zero` で、準備に置く検討事項と、後から足す検討事項の ID を揃える。

- 後から足す検討事項の ID は、`add` が種類の連番の最大 + 1 で決める（D-3 だけのワークスペースでは D-4）。プレビューとスクリプトの振る舞いは変えない
- 満たす基準は、直したシナリオの期待値を確かめる `test_normal_when_history_limit_zero` の pass
- 同じシナリオの期待値（足した検討事項に新規の印が付き、D-3 には変更の印が付かない・D-3 の詳細パネルに差分の印が無く今の本文だけが出る）と、同じファイルのほかのテストは変えない

`未確定`: 揃え方（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 準備の記録を検討事項 D-1〜D-5（D-3 だけ本文を持つ）にし、足した検討事項を D-6 のままにする | `正常シナリオ` と準備・`COMMIT_SUMMARY`・`NEW_DECISION` を共有でき、テストは準備と表の印の期待値を直すだけで済む | 表の印の期待値に D-1・D-2・D-4・D-5 の行が増える |
| B | 準備を D-3 だけのまま、足した検討事項を D-4 にする | 準備が最小のまま | `正常シナリオ` と共有している `COMMIT_SUMMARY`（「D-6 を足す」）と `NEW_DECISION` のコメントを、このテスト用に分ける必要がある |

推奨: A

`正常シナリオ` と同じ記録の前提に揃えると、共有している定数の記述（D-6）がこのテストにもそのまま当てはまり、直す箇所が準備と期待値に閉じる。

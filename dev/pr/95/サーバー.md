## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定ファイルの名前 | `SETTINGS_FILE` を `config.yaml` にし、ワークスペースを見分ける・作る・読む・点検する全ての処理がこの名前を使う | `mindmap.yaml` だけがあるフォルダは、移し替えを案内するエラーにする。ただし `migrate` のワークスペースの見分けだけは、`config.yaml` か `mindmap.yaml` のどちらかがあれば通す |
| 既定のキー | `config.yaml` のスキーマに、ネットワークの見た目の既定（`glow`・`starlight`・`constellation`・`deep`・`dust` の列挙）と表示する種類の既定（種類の名前の配列）を任意のキーとして足す | キーは `display` の `network_look`（見た目）と `visible_kinds`（表示する種類）（ER 図『ワークスペース』） |
| `update_settings` | 書き換えられるキーに見た目の既定・表示する種類の既定を足す | `history_limit` は今のまま書き換えない |
| 既定の書き換えのエンドポイント | 画面の明示的な操作から、見た目の既定・表示する種類の既定を `config.yaml` へ書くエンドポイントを配信に足す。書く前にスキーマで検査し、書いたら書き換えの知らせを送る | 誰でも書ける（役割で絞るのは #25） |
| 配信の起動時の検査 | `preview_url` が配信を立てる前に `config.yaml` をスキーマで検査し、合わなければ違う箇所（キーと理由）を並べたエラーを返して立てない | 既に立っている配信には効かない（再読み込みで効かせる） |
| 設定の再読み込み | 配信は今のとおり `/api/records` のたびに `config.yaml` を読み、検査に通った設定を「最後に通った設定」として持つ。読んだ `config.yaml` が検査に通らなければ、最後に通った設定で返して違う箇所を添える。再読み込みのエンドポイントは検査の結果を返し、通れば書き換えの知らせを送る | `update_settings`・既定の書き換え・別のプロセスの書き換えは、今のとおり次の読み込みで効く。書き換えの監視（`workspace_signature`）は `config.yaml` を見続ける |
| 画面のファイル名 | 配信の画面を `/mindstella.html` で返し、`/` は `/mindstella.html` へ送る。`preview_url` は `/mindstella.html` の URL を返す | `export` は今のまま `out` を受け取る |
| 移し替えの手順 | 次の版の `migrations/{版}/steps.yaml` に、`mindmap.yaml` を `config.yaml` へ改める `rename_file` を足す | 前の版の手順（`v0.3.0/steps.yaml` の `set_default` の `file: mindmap.yaml`、`v0.5.0/scripts/field_to_playbooks.py` の `SETTINGS_FILE = "mindmap.yaml"`）は改名より前に当たるため `mindmap.yaml` のまま残す |

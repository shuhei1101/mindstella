# 要件

## 要望

ワークスペースの設定を、ワークスペースの既定（`config.yaml`）と個人の上書き（ブラウザの localStorage）の 2 段にし、各自の表示の好みが他の人の表示に影響しないようにする。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| 設定ファイルの名前 | ワークスペースの設定ファイルを `mindmap.yaml` から `config.yaml` に改める。今のキー（題名・概要・プレイブック・フェーズ・対象とカテゴリー・ゴール・関連する場所・`history_limit`）はそのまま持つ |
| ワークスペースの既定 | `config.yaml` に、ネットワークの見た目の既定と表示する種類の既定を足す。どちらも任意のキーで、無ければ組み込みの既定（見た目は `deep`、表示する種類は全ての種類）を使う。変更履歴の回数は今の `history_limit` のまま持つ |
| ネットワークの見た目 | 選べる値は `glow`・`starlight`・`constellation`・`deep`・`dust` の 5 つ。既定は `deep`（深宇宙）。この PR は値の置き場と選び方を作り、値ごとの描き分けは [#28](https://github.com/shuhei1101/mindstella/issues/28) が作る |
| 表示する種類 | 画面のタブに出す種類（検討事項・タスク・調査・資料・用語集・メモ・会話ログ）を選ぶ。概要とネットワークは常に出す |
| 個人の上書き | ブラウザの localStorage に、見た目・ライト / ダーク・表示する種類・表の列を持つ。端末ごと・ブラウザごとに持ち、サーバーへ送らない |
| 値の決め方 | 項目ごとに、localStorage に値があればそれを、無ければ `config.yaml` の値を、それも無ければ組み込みの既定を使う。ライト / ダークは `config.yaml` に持たず、上書きが無ければ今と同じく端末のライト / ダークに従う |
| 既定に戻す | 個人の上書きを外し、ワークスペースの既定の表示に戻せる |
| `config.yaml` の書き換え | 書き換えるのは MCP のツール（`update_settings`）と、画面の明示的な操作（見た目の既定・表示する種類の既定を、ワークスペースの既定として保存する操作）だけにする。画面の個人の上書きの操作は `config.yaml` を書き換えない |
| 配信の起動時の検査 | サーバーがワークスペースの配信を立てるとき（`preview_url`）に `config.yaml` をスキーマで検査し、合わなければ違う箇所（キーと理由）をエラーで返して配信を立てない |
| 設定の再読み込み | 配信に設定の再読み込みのエンドポイントを置く。検査に通れば新しい設定を使い、開いている画面に知らせる。通らなければ最後に検査に通った設定のまま動き続け、違う箇所をエラーで返す |
| 画面のファイル名 | 配信の画面のパスを `mindstella.html` にする |
| 既存のワークスペース | 次の版の移し替えの手順で、`mindmap.yaml` を `config.yaml` に移す。移していないワークスペースは、移し替えを案内するエラーにする |

<!-- /table -->

表示の設定は、トップバーから開き、コメントの一覧と同じく見ている画面に重ねて左から出すパネル（幅 900px 以下では画面の幅いっぱい）に置く（[プレビュー](./プレビュー.md) の `### 画面一覧`）。

`未確定`: ワークスペースの既定として保存する操作の見せ方（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 個人の上書きの欄の下に「ワークスペースの既定にする」ボタンを置き、押すと確かめてから今の選びを `config.yaml` へ書く | 個人の操作と取り違えにくく、明示的な操作になる | 押す前に確かめの一手間が要る |
| B | 個人の上書きとワークスペースの既定を別の区画に分け、区画ごとに選ぶ | 既定と上書きの値を並べて見比べられる | 同じ項目が 2 回並ぶ |

推奨: A

`config.yaml` を書き換えるのは明示的な操作に限るため、個人の選びとは別のボタンにしたうえで確かめを挟む。

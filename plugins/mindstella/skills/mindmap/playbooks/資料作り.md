# 資料作りの進め方ガイド

資料の目的と読み手を決め、構成を組んでから、本文を書いて仕上げるまでの進め方。

## 最上位の軸の呼び名

資料

対象には、作る資料の名前と概要を入れる。

## カテゴリーの分け方

対象の中の分け方。話し合いの中身に合わせて、利用者と決める。
例: 本編・図表・データ・付録。

## フェーズと観点

| フェーズ | 観点 |
| --- | --- |
| 目的 | 何のための資料か・読んだ後に読み手にしてほしいこと・使う場面（読む・発表する・配る）・載せないこと |
| 読み手 | 誰が読むか・既に知っていること・知りたいこと・読む時間と場面・判断に要る根拠 |
| 構成 | 章立てと順序・各章の役割・結論を置く位置・分量の配分・図表を使う場所 |
| コンテンツ | 章ごとの本文・主張と根拠・図表・数字と出典・用語の統一 |
| 仕上げ | 表記と用語のゆれ・数字と出典の突き合わせ・読み手の目での通読・体裁 |

後のフェーズの問いは、前のフェーズの検討事項に `depends_on` で繋ぐ。
目的や読み手が変わったら、構成以降の検討事項が要見直しになる。

## 必ず調べるもの

| 調べるもの | 調べ方 | 積む調査 |
| --- | --- | --- |
| 資料に載せる数字・事実 | 公式の資料 | 一次情報の出典つきの事実の調査 |
| 同じ種類の資料（企画書・提案書・報告書など）の型と書き方 | 実践者の知見 | 型・言い回しの調査 |
| 主張を覆しうる反対の事実 | 公式の資料 | 反証の調査 |

数字と事実には、出典を付ける。

## ゴールの候補

| ゴール | `goal.phase` | 納品物（`goal.deliverables`） | 選ぶとき |
| --- | --- | --- | --- |
| 構成まで | 構成 | 構成案 | 本文を書く前に、章立てと順序だけを固めたい |
| コンテンツまで（既定） | コンテンツ | 構成案・資料の本文 | 読める形の資料を作りたい |
| 仕上げまで | 仕上げ | 構成案・資料の本文・点検の記録 | 渡せる状態まで整えたい |

納品物は資料（`kind`: 文書 / 図、`deliverable: true`）として作り、できたら状態を `完成` にして、`goal.deliverables[].doc` から指す。

## リリースの形

`.mindstella/release/` に次を書き出す。

| ファイル | 中身 |
| --- | --- |
| `決定事項.md` | ゴールのフェーズまでの決まった検討事項の一覧（ID・タイトル・答え・理由）をフェーズの順に並べる |
| `{納品物のタイトル}.md` | 納品物の資料（`deliverable: true`）ごとの本文。数字と事実には出典を添える。本文を HTML で持つ資料は `{納品物のタイトル}.html` |

# システム開発の進め方ガイド

作るものの目的から、要件・構成・インターフェース・中身までを、前のフェーズで決めたことを土台にして順に決めていく進め方。

## 最上位の軸の呼び名

機能

対象には、作る機能の名前と概要を入れる。システムの違いは、タグで分ける。

## カテゴリーの分け方

対象の中の分け方。話し合いの中身に合わせて、利用者と決める。
例: 機能・データ・画面・外部連携・運用。

## フェーズと観点

| フェーズ | 観点 |
| --- | --- |
| 目的 | 何のために作るか・誰が使うか・うまくいった状態は何か・やらないこと |
| 要件 | 利用者ができること・守る条件（性能・費用・運用・セキュリティ）・優先順位・制約・用語 |
| 構成 | 分け方（サブシステム・データストア・外部サービス）・依存の向き・使う技術の選定 |
| インターフェース | 各部の入口と出口（入力・出力・エラー・データの形）・呼び出す順 |
| コンテンツ | モジュール構成・画面・文面・初期データなど、中身 |

後のフェーズの問いは、前のフェーズの検討事項に `depends_on` で繋ぐ。
要件が変わったら、構成以降の検討事項が要見直しになる。

## 必ず調べるもの

| 調べるもの | 調べ方 | 積む調査 |
| --- | --- | --- |
| 外部ライブラリ・外部 API を決める検討事項 | 技術の選定 | ベストプラクティスの調査と、候補の比較の調査 |
| 似た既存のシステム・サービス | 公式の資料 | 何を真似て何を変えるかの調査 |
| 動かす環境の制約（OS・版・権限・費用） | 公式の資料 | 制約の調査 |

## ゴールの候補

| ゴール | `goal.phase` | 納品物（`goal.deliverables`） | 選ぶとき |
| --- | --- | --- | --- |
| 要件まで | 要件 | 要件定義書 | 作る前に何を作るかだけを固めたい |
| インターフェースまで（既定） | インターフェース | 要件定義書・構成図・インターフェース定義書 | 実装に入れる設計を固めたい |
| モジュール構成まで | コンテンツ | 要件定義書・構成図・インターフェース定義書・モジュール構成書 | 実装の分け方まで固めたい |

納品物は資料（`kind`: 文書 / 図、`deliverable: true`）として作り、できたら状態を `完成` にして、`goal.deliverables[].doc` から指す。

## リリースの形

`release/` に次を書き出す。

| ファイル | 中身 |
| --- | --- |
| `決定事項.md` | ゴールのフェーズまでの決まった検討事項の一覧（ID・タイトル・答え・理由）をフェーズの順に並べる |
| `{納品物のタイトル}.md` | 納品物の資料（`deliverable: true`）ごとの本文 |

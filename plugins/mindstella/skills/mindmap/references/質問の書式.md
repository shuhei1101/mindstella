# 質問の書式

利用者に問いを出すときの書式。
ヒアリングでも、たたき台の確認でも、リサーチの確認でも同じ書式で書く。

## 書式

1 つの問いは、次の順で書く。

1. タイトル（何を決める問いか）
2. 冒頭の文（なぜ今その問いが要るか。前提と、決まると何が進むか）
3. 案の表と推奨（選択肢があるときだけ）

選択肢が無い論点は、案の表を作らず、たたき台を出して直してもらう。

## 案の表と推奨

```
| 案 | 内容 | メリット | デメリット | 備考 |
| --- | --- | --- | --- | --- |
| A | 先に PoC を挟む | 核心の機構が成り立つかを早く確かめられる | 着手が 1 サイクル遅れる | - |
| B | PoC なしで実装に入る | 最短で着手できる | 成り立たなければ手戻りが大きい | 既存の技術の組み合わせ |

推奨: A

同期の性能が成立条件になっており、実装を進めてから成り立たないと分かると、設計から作り直しになる。
```

| 項目 | 書き方 |
| --- | --- |
| 第 1 列 | 記号（A / B / C ...）だけを入れる。列見出しは `案` |
| 内容列 | その案が何をするかを書く |
| メリット / デメリット | 対で書く。書けない論点では両方とも置かない |
| 備考 | 任意 |
| 使わない列 | 列ごと落とす（全行が空の列を並べない） |
| 推奨 | 表の下に記号だけを書き、理由は空行を挟んだ次の段落に書く |

案の記号と内容は、検討事項の `options`（`key`・`content`・`pros`・`cons`・`note`）に、表の下の推奨の記号は、写す先の案の `recommended`（推奨の印）に、そのまま写せる形にする。

## 複数の問いをまとめるとき

ヒアリングで 1 ラウンドに複数の問いを出すときは、問いごとにこの書式で書き、問いの順に番号を付けて並べる。
答えが他の問いに左右される問いは、同じラウンドに入れず次のラウンドに回す。

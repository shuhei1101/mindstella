# 文章の書き方

文章を追加する前に、既存の行を修正・削除することで足りないかを確かめ、足りるなら追加しない。

検討事項の回答・資料の本文・リリースの資料・会話ログに文章を追加したら、書き終えた直後に次を確認して、当てはまる行を削除する。
追加した分は、読み手が読む量をそのまま増やす。

## 確認する項目

<!-- table: data -->

| 確認 | 当てはまったら削除する理由 |
| --- | --- |
| 書いていない操作を禁じていないか | 書いていない操作は実行されない |
| そう書く理由・背景・経緯を説明していないか | 読み手の判断が変わらないなら要らない |
| 同じ内容を別の項目・資料が持っていないか | 参照を 1 行残せば足りる |
| 直前の正の指示の裏返しになっていないか | 「〜する」の後の「〜しない」は情報量が無い |
| 本文にあることを、冒頭の文や概要で言い換えていないか | 冒頭の文は 1〜2 行 |
| 冒頭の文・概要に後から情報を追加していないか | 対象そのものが変わったときだけ書き換える |
| 後から増えうるものの個数を書いていないか | 増減のたびに数だけを修正する差分が出る。数を削除しても文は成立する |
| 1 つの説明が 3 行を超えていないか | 決めきれていないと言葉で埋めたくなる。内容を確定させれば短くなる |
| 削除しても読み手の動きが変わらない行を残していないか | 変わらない行は、ほかの内容を埋もれさせる |
| 読み手が既に知っている一般の知識を説明していないか | 書くのは、この話し合いで決めたことだけ |
| 実装のコード例を載せていないか | 文で足りる。例は古い書き方に引っ張る。書式を示す例は、文より短く伝わるときだけ残す |
| バージョン・価格・閾値・モデル名など、時期で古くなる値を書いていないか | 古くなっても修正されないまま残る。公式の参照先を書く |
| 同じものを別の言葉で呼んでいないか | 別のものと読まれる。既出の呼び名に統一する |
| 選択肢を並べたまま、既定を決めていないか | 読み手が選べない。既定を 1 つ書き、例外だけ添える |
| 強調（必ず・絶対・重要・太字）を追加していないか | 重ねると、どれも目立たなくなる |
| 推量やぼかし（〜と思われる・〜かもしれない）で書いていないか | 決めて書く |
| 冗長な言い回し（することができる・を行う）を使っていないか | 省いても意味が変わらない |
| 同じファイルの中で同じ説明を繰り返していないか（概要・まとめのセクションを含む） | 最も適切な 1 か所に置く |

<!-- /table -->

残してよい否定は、実行しうる操作を止めるものだけ。

## 用語の選び方

文章でない所（見出し・表の列名・項目名・タイトル・分類の値）は、IT の分野で定着した単語で書く。
漢語でもカタカナ語でもよい。
文章は自然な文でよい。話し言葉の動詞は使用しない。

定着したかは、Microsoft の用語集・Android の日本語文字列・その技術の公式ドキュメントで使われている単語かで判断する。
迷ったときは、下の対応表 → 用語集・公式ドキュメント → 原則の順に判断する。

### 原則

対応表に無い単語は、次の原則で判断する。

| 原則 | 理由 | 悪い例 | 良い例 |
| --- | --- | --- | --- |
| 訓読みの動詞・一字の語をラベル・表のセル・分類の値に使わない | 意味の範囲が広く、短いラベルでは意味を特定できない。周りに文が無い値では、文中よりも和語が目立つ | 送る・足す・題 | 送信・追加・タイトル |
| 比喩で呼ばない | 比喩は正確さを損なう | 口・形・段 | インターフェース・スキーマ・レイヤー |
| 定着したカタカナ語を和語に訳さない | 「造語を作らない」を「日本語に訳す」と読むと、和語の造語が増える | 写し・印 | コピー・マーカー |
| 新しい呼び名を作る前に、辞書の語と、既存の製品・方法論での呼び名を探す。和語を名詞にした造語（〜事・〜もの・〜さ）を作らない | 辞書にも他の製品にも無い語は、読み手が意味を推測できない | 決め事・確からしさ | 検討事項・確信度 |
| 値を 1 文字だけで、何の値かを添えずに表示しない | 1 文字では何についての値か分からない | 大 | 影響度 大 |

# 範囲の見直し

話し合いの範囲が変わったとき、題名・話し合いの概要・プレイブック・フェーズ・最上位の軸の呼び名・ゴールを、利用者が確かめてから書き換える。
問いは `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/質問の書式.md` の書式で書き、文章は `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/文章の書き方.md` に従う。

## 手順

### 書き換えるものを決める

次のどれかのとき、書き換えるものを決める。

- 話の範囲が広がった
- 利用者が題名・話し合いの概要・ゴール・プレイブック・最上位の軸の呼び名を変えたいと言った
- 話の中身と最上位の軸の呼び名が合わなくなった
- ゴール判定でゴールが無く、利用者がゴールを決めると言った

今の設定は `{ワークスペースのフォルダ}/mindmap.yaml` を Read で読む。
プレイブックを足す・入れ替えるときは、足す進め方ガイド（`${CLAUDE_PLUGIN_ROOT}/skills/mindmap/playbooks/{プレイブック}.md`）を Read で読む。

### たたき台を作って確認する

書き換えるキーのたたき台を作る。

| キー | たたき台の作り方 |
| --- | --- |
| `summary` | 今の話に合わせた、何についての話し合いかの 1 文 |
| `description` | 今の話に合わせた、1 文の短い文（60 字以内）。消すときは `null` |
| `playbooks` | 足す・外す・入れ替えた後の、進め方ガイドの名前の並び（1 件以上） |
| `phases` | プレイブックを変えるとき、並べた各ガイドの `## フェーズと観点` から作る 1 本の並び |
| `target_label` | 話の中身に合う、最上位の軸の呼び名 |
| `goal` | ゴールの候補（`## ゴールの候補`）から。納品物の足し引きも含める。外すときは `null` |

`phases` を変えるときは、新しい `phases` に無い古いフェーズごとに、移す先の新しいフェーズを決め、対応の表（古いフェーズ・新しいフェーズ・該当する項目の ID）を作る。
新しい `phases` にも同じ名前があるフェーズは、対応に入れない。
どこへ移すか決められない古いフェーズは、移す先の案を表にして尋ねる。

たたき台と対応の表を示し、確定を求める。
利用者が確定するまで、設定も項目も書き換えない。

### 設定を書き換える

確定した内容で `update_settings` を呼ぶ。

- `settings`: 書き換えるキーだけを渡す。`goal` は丸ごと置き換わるので、`mindmap.yaml` の今のゴールから、変えない納品物も含めて渡す
- `phase_map`: `phases` を変えるときだけ、確定した対応（古いフェーズ → 新しいフェーズ）を渡す

```json
{"workspace": "{ワークスペースのフォルダ}", "settings": {"summary": "家計簿アプリの要件を決める", "playbooks": ["壁打ち", "システム開発"], "phases": ["目的", "発散", "要件"], "goal": {"phase": "要件", "summary": "要件が決まる", "deliverables": [{"title": "要件定義書"}]}}, "phase_map": {"問い": "目的", "結論": "要件"}}
```

`update_settings` がエラーを返したときは、本文のエラーを示して止まる。
対応の無いフェーズが残るというエラーなら、本文の残る項目を示し、移す先を尋ね直す。

### 会話ログを書き足す

`add`（`kind: log`）で会話ログを 1 件足す。
`related` に、フェーズを付け替えた項目（`update_settings` の `remapped`）を指し、`body_markdown` に書き換えの内容を書く。

### 書き換えを示す

`changed`・`remapped`・`files` から、書き換えた設定のキーと、フェーズを付け替えた項目を示す。

# ヒアリング

前提が揃った未決定の検討事項を選び、1 ラウンドの検討事項ごとにスレッドを立てて利用者に聞き、スレッドで届いた答えを記録する。
問いは `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/質問の書式.md` の書式で書き、文章は `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/文章の書き方.md` に従う。

## 手順

### 聞く問いを選ぶ

`next` を呼び、前提が揃った未決定を読む（利用者が話題を指しているときは、`find`（`text`: 話題）で合う検討事項に絞る）。
次の順で、このラウンドの問いを選ぶ。

1. 候補のうち、答えが他の候補の答えに左右されない問いを選ぶ。左右される問いは、次のラウンドに回す
2. 事実で分かる問いは、利用者に聞かず、自分で調べて答えを出す。調べるのに手間が掛かるものは、リサーチのステップに回す
3. 決めることだけを聞く

### スレッドで聞く

聞く前に、`edit_option` で案の推奨の印を案の表の推奨に揃えて記録する。
選んだ問いごとに、`new_thread`（`target`: 検討事項の ID）でスレッドを立て、本文に質問の書式で問いを書く。
検討事項が持つ案（`options`）は案の表に出し、推奨を付ける。
ターミナルには問いを書かない。答えが届くまで、答えに左右されない取り込み・記録を続ける。

### 答えを記録する

答えはスレッドへの返信で届く（届いたスレッドの取り込みで読む）。利用者の答えごとに、検討事項を次のようにする。

- `adopt` で選ばれた案を採用する（状態が `決定済み` になる）
- `update` で、`answer` に決まった答え、`reason` に決めた理由を書く
- 答えが新しい問いやタスクを生むときは、取り込みの手順で派生を積む

決めきれなかった問いは、状態を変えず、次のラウンドに回す。
記録したら、そのスレッドへ `reply` で、直した検討事項の ID を書いて返す。

### 会話ログを書き足す

`add`（`kind: log`）で会話ログを 1 件足し、`related` にこのラウンドで直した検討事項を指す。
決めた検討事項には、`update` で `sources` に会話ログの ID を入れる。

### 書き換えをまとめる

記録を書き換えたら、このステップで何をしたかを一言の説明（1〜200 文字）にして `commit`（`summary`）を呼ぶ。

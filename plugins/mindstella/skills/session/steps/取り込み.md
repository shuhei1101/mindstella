# 取り込み

利用者の発言を、対象・カテゴリー・フェーズに振り分けて記録し、進め方ガイドの観点と照らして派生の検討事項・未整理・タスクを積む。
文章は `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/文章の書き方.md` に従う。
項目の中身のキーは、`.mindstella/config.yaml` と各項目の書式（検討事項・タスク・資料・用語集・メモ・会話ログ）に合わせる。

## 手順

### 発言を振り分ける

発言を内容ごとに分け、次の記録にする。

| 発言の内容 | 記録 |
| --- | --- |
| 決めたこと | 検討事項。状態 `決定済み`・`answer`・`reason`・採用した案 |
| まだ決めていない問い | 検討事項。状態 `未決定`・案・推奨の印 |
| 問いの形にならない考えの断片 | 検討事項。状態 `未整理` |
| 後でやること・決めるための作業（AI がやる作業も、利用者に頼む作業も、出た時点で積む） | タスク。`kind`（`作業`・`調査`・`検証`）・状態 `未着手` |
| 言葉の意味を尋ねた脱線した質問 | 用語集。`meaning` に意味 |
| それ以外の脱線した質問 | メモ。タグ `topic:脱線`。タスクにしない |
| 会話で出した図・文書 | 資料。`kind`・`deliverable`・`status`・本文 |

検討事項・タスク・調査・用語集・メモ・会話ログは、経緯や補足があれば `body_markdown` で本文に書く。

記録する項目には、`.mindstella/config.yaml` の対象（`target`）・カテゴリー（`category`）・フェーズ（`phase`）を付ける。
迷うときは、進め方ガイドの観点に当てはめて決める。

### 話題のタグを付ける

記録を書く前に、`tags` で使われているタグを件数つきで全件引く。
記録する項目の `title`・本文の見出し・`description` から語を書き出して単語まで分け、その語で探した人にこの項目が出てほしい語だけを `tags` に付ける。
用語集にある複合語と、一語として定着した複合語は分けずに残し、構成語も付ける。
付ける数の上限は持たない。
対象（`target`）は作るものの区分として使い、話題には使わない。

タグの名前は `facet:value` にする。

| facet | 付ける語 | 例 |
| --- | --- | --- |
| `action:` | 行為の語。名詞形にする | `action:検索` |
| `tool:` | 道具の公式の名前。小文字・ハイフン区切りにする | `tool:claude-code` |
| `topic:` | それ以外の 1 概念の名詞 | `topic:通知` |

使われているタグに、同じ概念の言い方・活用の違いのタグがあれば、その表記を使う（例: `topic:用語集` があれば `topic:glossary` を作らない）。
無ければ新しいタグをそのまま付け、その語を `find` の `text` に渡す。
当たった既存の記録のうち同じ主題を持つものにも、同じ `batch` の `update` で付ける。
上位の広いタグがあれば、一緒に付ける。
関数名・ファイル名は、概念の語にしてから付ける。

| 付けない語 | 例 |
| --- | --- |
| それだけでは何の話か決まらない評価・状態の語 | 「重要」「ベストプラクティス」 |
| 状態・フェーズなど別のキーで表せるもの | 「決定済み」は `status` |
| 見出しによく出る一般語 | 背景・案・一覧・前提・補足 |
| 例として名前が出ただけの語 | 1 段落だけ例に出した「Mermaid」 |

### 検討事項に案を書く

`未整理` を除く検討事項は、案（`options` の `key`・`content`・`pros`・`cons`）を書いて足す。案を持たない検討事項は書き込めない。
未決定なら、AI が推す案 1 つに `recommended: true` を付ける。
決めたこととして足すときは、選ばれた案を `adopted: true` にし、状態を `決定済み` にする。
問いの形にならない未整理は案を持たずに足し、未決定へ変えるときに案を書く。
次の「派生を積む」で足す検討事項も同じ。
既にある検討事項の案と推奨の印を足す・直す・消すときは、`edit_option` を使い、`update` で案の配列を丸ごと渡さない。
採用している案を消すときは、先に `adopt` で採用をほかの案へ移す。

### 派生を積む

決めたことを、進め方ガイドの観点と照らす。
決めたことから新しく生まれる問いは、検討事項（状態 `未決定`）として足し、`parent` に元の検討事項を指す。
先に決まっている必要がある検討事項は `depends_on` で指す。
問いを決めるための作業は、タスクとして足し、`for` に検討事項を指す。
外部ライブラリ・外部 API を決める検討事項には、ベストプラクティスと候補を調べるタスク（`kind`: `調査`）を積む。

### 保留・解除・中止

- 後回しにするときは、`update` で状態を `保留` にし、`reason` を書く。決まるのを待つ相手があれば `depends_on` で指す
- 保留を戻すときは、`update` で状態を `未決定`（タスクは `未着手`）にする
- やめるときは、項目を消さずに取り下げる。検討事項は `update` で状態を `対象外` か `取り下げ`、タスクは `中止` にし、調査・資料・用語集・メモ・会話ログは `update` で `withdrawn: true` を書く。どの種類も `reason` を書く
- 誤って足した項目・重複した項目だけを `remove` で消す。消す前に、消す項目（ID・タイトル）と消すと戻せないことを利用者に示して確かめ、許しを得てから呼ぶ
- ほかの項目が指しているときは、`remove` のエラーに返った指している側の参照を、先に `update` で付け替えるか外してから消す

### 図や文書を資料に残す

会話で図や文書を出したら、`add`（`kind: doc`）で資料にする。
図や文書の本文は、主な中身がモックや図のような見た目のあるものなら `body_html` に HTML で、文章が主なら `body_markdown` に Markdown で入れる。`kind`（`図`・`文書` など）・`deliverable`・`status: 下書き`・`related`（関係する検討事項）・`aliases`・`description` を書く（`aliases`・`description` の書き方は SKILL.md の「記録の書き方」）。
Markdown の本文に、図・チャート・値を動かして確かめる部品などの HTML を埋め込むときは、書く前に `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/HTMLの書き方.md` を読む。
利用者がコメントに貼った、部品の今の値の JSON は、同じ資料の「値を受け取る」のとおり取り込む。
ゴールの納品物に当たるときは、`deliverable: true` にし、`update_settings` で設定のゴールにつなぐ。
`goal` は丸ごと置き換わるので、`{ワークスペースのフォルダ}/.mindstella/config.yaml` を Read で読んだ今のゴールを元に、同じタイトルの納品物があればその `doc` から資料の ID を指し、無ければ `{"title": …, "doc": 資料の ID}` の行を足して渡す。
ゴールが無いときは、納品物につながない。

### 納品物の資料を育てる

ゴールの納品物に `doc` を持たないものがあれば、`add`（`kind: doc`）で資料にする。
セットアップで決めたゴールの分は、話し合いの最初の取り込みで作る。
`deliverable: true`・`status: 下書き` にし、`body_markdown` に概要・背景・最終的な構成（見出しの並び。Issue などテンプレートのあるものはその見出し）を先に置く。
作った資料は、前の節と同じ手順で `update_settings` を呼び、納品物の `doc` から指す。
決まったことが出るたびに、`show` で今の本文を読み、書き足した全文を `update` の `body_markdown` で渡す。

### タスクの成果を資料に残す

作業・検証のタスクで作った成果は、1 件ずつ `add`（`kind: doc`）で資料にし、タスクの `related` から指す。`aliases`・`description` も書く。
ゴールの納品物に当たるときだけ `deliverable: true` にし、前の節の手順で納品物の `doc` から指す。
調査のタスクの成果は調査の記録に書き、資料にしない。
タスクを `完了` にする前に、成果と資料が 1 対 1 で揃っているかを確かめ、欠けていれば資料を足す。

### 用語を育てる

利用者の言い方が、用語集の言葉とずれていたら、その場で用語集の言葉に正す。
次の言葉は、利用者が指定しなくても `add`（`kind: term`）で用語集に足す（`meaning`・`aliases`・やめた言い方は `avoid`）。

| 足す | 足さない |
| --- | --- |
| システムの名前・業務や製品の固有の言葉・話し合いで決めた呼び名 | 一般的な意味のまま使っている技術の言葉（例: 「JSON」「正規表現」） |
| 一般的な語でも、この話し合いで一般と違う・狭い意味で使う語 | 1 項目の中だけで使い、ほかに出ない語 |
| リサーチで調べた外部ライブラリ・外部サービスの名前 | |
| 同じものに 2 つ以上の言い方が出たときの正式な語（残りの言い方は `aliases` に入れる） | |

### 会話ログを書き足す

発言ごとに、`add`（`kind: log`）で会話ログを 1 件足す。
`date` に今日の日付（`YYYY-MM-DD`）、`related` に今回足した・直した項目の ID、`body_markdown` に会話の要約と残しておきたい言葉を入れる。
決めた検討事項には、`update` で `sources` に会話ログの ID を入れる。

### 発言ごとにまとめて書く

利用者の 1 つの発言から出た記録（上の節で作った項目の追加・更新と会話ログ）は、`batch` の `operations` に並べて 1 回で書く。
同じ発言で足す項目を指すとき（`parent`・`depends_on`・`for`・`related`・`sources` など）は、その項目を足す `add` の番号（1 始まり）を `$1` の形で書く。
`update_settings` と `adopt` は `batch` に含めず、別に呼ぶ。

```json
{"workspace": "{ワークスペースのフォルダ}", "operations": [
  {"op": "add", "kind": "decision", "item": {"title": "記録の単位", "status": "決定済み", "answer": "月ごとに分ける", "options": [{"key": "A", "content": "月ごとに分ける", "adopted": true}, {"key": "B", "content": "1 つにまとめる"}]}},
  {"op": "add", "kind": "task", "item": {"title": "月ごとの集計を試す", "kind": "検証", "status": "未着手", "for": ["$1"]}},
  {"op": "add", "kind": "log", "item": {"title": "記録の単位を決めた", "date": "2026-10-05", "related": ["$1"], "body_markdown": "月ごとに分けると決めた"}}
]}
```

### 書き換えをまとめる

記録を書き換えたら、このステップで何をしたかを一言の説明（1〜200 文字）にして `commit`（`summary`）を呼ぶ。

### 記録を示す

記録した項目の ID とタイトル、積んだ問いを短く示す。

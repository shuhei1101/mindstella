# 方針転換

検討事項の採用する案を切り替え、依存をたどって影響を受ける項目を要見直しにし、見直しのタスクを積む。
文章は `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/文章の書き方.md` に従う。

## 手順

### 影響を示して確認を取る

`trace_related`（`from_ids`: 検討事項の ID・`direction: in`）を呼び、種類 `depends_on`・`parent`・`for` の関連で指している項目を、影響を受ける項目として読む。
切り替える案と、要見直しにする決定済みの検討事項を、`new_thread`（`target`: 検討事項の ID）で示して確認を取る。ターミナルには書かない。
確認はスレッドへの返信で届く。承認されるまで切り替えない。

### 採用する案を切り替える

利用者が選んだ案の記号で、`adopt`（`id`: 検討事項の ID・`key`: 記号）を呼ぶ。
`adopt` は採用する案を切り替え、状態を `決定済み` にする。答え（`answer`）は変えない。

### 影響を洗い出す

切り替えた後に `trace_related`（`from_ids`: 検討事項の ID・`direction: in`）を呼び直し、影響を受ける項目を読む。

### 要見直しにして見直しのタスクを積む

影響を受けた項目のうち、状態が `決定済み` の検討事項を、それぞれ次のようにする。

- `write_docs` の `update` で状態を `要見直し` にし、`reason` に見直す理由（どの検討事項の案がどう変わったか）を書く（採用した案は持ったまま）
- `next_id` で ID を取り、`write_docs` の `create` で見直しのタスクを積む（`kind`: `作業`・状態 `未着手`・`related` に検討事項を種類 `for` で・`reason` に見直す点）

### 本文を今の正だけに直す

切り替えた検討事項の `answer` を、採用した案の内容だけに `write_docs` の `update` で直す。
検討事項が本文（`body`）を持つときは、本文も今の正だけで書き直す（`set` の本文）。
前の案の記述は残さない。

### 納品物が要らなくなったとき

スコープが変わって納品物が要らなくなったら、次の順で資料へ格下げする。

1. `write_docs` の `update` で、その資料の `deliverable` を `false` にする
2. `update_settings` で、ゴールの納品物からその行を外す（`goal` は丸ごと置き換わるので、`{ワークスペースのフォルダ}/.mindstella/config.yaml` を Read で読んだ今のゴールから、その納品物の行だけを除いて渡す）
3. `check` で、参照切れが無いことを確かめる

### 会話ログを書き足す

`next_id` で ID を取り、`write_docs` の `create` で会話ログを 1 件足し、`related` に今回足した・直した項目を種類 `see_also` で指す。

### 書き換えをまとめる

記録を書き換えたら、このステップで何をしたかを一言の説明（1〜200 文字）にして `commit`（`summary`）を呼ぶ。

### 影響を示す

要見直しにした項目と、積んだタスクの ID を、確認を取ったスレッドへ `reply` で示す。
納品物を格下げしたときは、格下げした資料を `target` にした `new_thread` で知らせる。

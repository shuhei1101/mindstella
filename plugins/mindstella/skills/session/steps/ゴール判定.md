# ゴール判定

ゴールのフェーズまでの検討事項と納品物が揃ったかを確かめ、利用者の確定を取って、`.mindstella/release/` にリリースの資料を書き出す。
問いは `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/質問の書式.md` の書式で書き、文章は `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/文章の書き方.md` に従う。

## 手順

### ゴールに届いたかを確かめる

`goal` を呼ぶ。

- `has_goal` が偽のとき、ゴールが無いことと、`remaining_decisions`（全フェーズの決着していない検討事項）を示し、ゴールを決めるかを質問の書式で尋ねる。`.mindstella/release/` には何も書かない。決めると言われたら、範囲の見直しのステップへ進み、ゴールを書いてから `goal` を呼び直す。決めないと言われたら、ここで終える
- `reached` が偽のとき、`remaining_decisions`（ID・タイトル・フェーズ・状態）と `remaining_deliverables`（タイトル・資料）を示し、次に決める検討事項を推奨する。`.mindstella/release/` には何も書かず、ここで終える
- `reached` が真のとき、「タスクの成果と資料を揃える」へ進む

### タスクの成果と資料を揃える

`find`（`kind: task`・`status: 完了`）で完了したタスクを読み、作業・検証のタスクの成果と資料が 1 対 1 で揃っているかを確かめる。
`related` に成果の資料を持たないタスクは、`result` の成果を本文にした資料を `add`（`kind: doc`）で足し、`update` でタスクの `related` から指す。
調査のタスクは、成果を調査の記録に書くため除く。
資料を足したら、「確定を取る」で足した資料を示す。

### 確定を取る

決まった検討事項（ゴールのフェーズまでのもの。`.mindstella/decisions.yaml` を Read で読み、ID・タイトル・`answer`・`reason`）と、ゴールの納品物（`.mindstella/config.yaml` の `goal.deliverables` のタイトルと、`doc` が指す資料）を示す。
確定してよいかを質問の書式で尋ねる。

- 確定されたら、「リリースの資料を書き出す」へ進む
- 直すと言われたら、取り込みの手順で直し、`goal` を呼び直す

### リリースの資料を書き出す

先に `clear_release` を呼んで、`.mindstella/release/` の中身を消す。ツールのエラーが返ったら書き出さず、エラーの本文を利用者に示して終える。
続けて進め方ガイドの `## リリースの形` のとおり、`{ワークスペースのフォルダ}/.mindstella/release/` に Write ツールで書く（利用者に書き込みの確認が出る）。

- `決定事項.md`: 決まった検討事項の一覧をフェーズの順に並べる
- `{納品物のタイトル}.md`: 納品物の資料ごとに、`show`（`id`: 資料の ID）の `body_markdown` を本文にする

### 会話ログを書き足す

`add`（`kind: log`）で会話ログを 1 件足し、`related` に納品物の資料を指す。

### 書き出したファイルを示す

`.mindstella/release/` に書いたファイルを示す。

# ゴール判定

ゴールのフェーズまでの検討事項と納品物が揃ったかを確かめ、利用者の確定を取って、`.mindstella/release/` にリリースの資料を書き出す。
問いは `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/質問の書式.md` の書式で書き、文章は `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/文章の書き方.md` に従う。

## 手順

### ゴールに届いたかを確かめる

`goal` を呼ぶ。

- `has_goal` が偽のとき、ゴールが無いことと、`remaining_decisions`（全フェーズの決着していない検討事項）を示し、ゴールを決めるかを `new_thread` で質問の書式で尋ねる（検討事項は作らない）。`.mindstella/release/` には何も書かない。決めると言われたら、範囲の見直しのステップへ進み、ゴールを書いてから `goal` を呼び直す。決めないと言われたら、ここで終える
- `reached` が偽のとき、`remaining_decisions`（ID・タイトル・フェーズ・状態）と `remaining_deliverables`（タイトル・資料）と、次に決める検討事項の推奨を `new_thread` で知らせる。`.mindstella/release/` には何も書かず、ここで終える
- `reached` が真のとき、「タスクの成果と資料を揃える」へ進む

### タスクの成果と資料を揃える

`search_docs`（タスクに絞り、`status` が `完了`）を続きの `cursor` が無くなるまでたどって、完了したタスクを全て読み、作業・検証のタスクの成果と資料が 1 対 1 で揃っているかを確かめる。
`related` に成果の資料を持たないタスクは、`result` の成果を本文にした資料を `write_docs` の `create` で足し、同じ呼び出しの `update` でタスクの `related` から種類 `see_also` で指す。
調査のタスクは、成果を調査の記録に書くため除く。
資料を足したら、「確定を取る」で足した資料を示す。

### 確定を取る

決まった検討事項（ゴールのフェーズまでのもの。`.mindstella/decisions.yaml` を Read で読み、ID・タイトル・`answer`・`reason`）と、ゴールの納品物（`.mindstella/config.yaml` の `goal.deliverables` のタイトルと、`doc` が指す資料）を示す。
確定してよいかを、`new_thread` で質問の書式で尋ねる（検討事項は作らない）。ターミナルには書かない。確定はスレッドへの返信で届く。

- 確定されたら、「リリースの資料を書き出す」へ進む
- 直すと言われたら、取り込みの手順で直し、`goal` を呼び直す

### リリースの資料を書き出す

先に `clear_release` を呼んで、`.mindstella/release/` の中身を消す。ツールのエラーが返ったら書き出さず、エラーの本文を確定を求めたスレッドへ `reply` で示して終える。
続けて進め方ガイドの `## リリースの形` のとおり、ファイルごとに `write_release`（`path`: `.mindstella/release/` からのファイル名・`content`: 本文）で書く。Write ツールは使わない。

- `決定事項.md`: 決まった検討事項の一覧をフェーズの順に並べる
- `{納品物のタイトル}.md`: 納品物の資料ごとに、`search_docs`（`id` で絞り `view: full`）の本文を本文にする。`body` が `.html` の資料は `{納品物のタイトル}.html` に、本文のまま書く

### 会話ログを書き足す

`next_id` で ID を取り、`write_docs` の `create` で会話ログを 1 件足し、`related` に納品物の資料を種類 `see_also` で指す。

### 書き出したファイルを示す

`.mindstella/release/` に書いたファイルを、確定を求めたスレッドへ `reply` で示す。

# プレビューを外から見る

プレビューを、トンネル・リバースプロキシを通して端末の外から開くときに実行する。

## 前提

- [起動スクリプトで立ち上げる](./起動スクリプトで立ち上げる.md)
- [プレビューを見る](../プレビューを見る.md)で、端末のブラウザでプレビューを開ける
- 外のホスト名への要求を、端末の `127.0.0.1` の配信のポートへ渡す外の入口（トンネル・リバースプロキシ）を用意している

配信は `127.0.0.1` だけで待ち受けたまま変わらず、認証を持たない。
外から開く画面の認証は、外の入口で付ける。

## 手順

使い方を次の 3 つから 1 つ選ぶ。

### ローカルだけで見る

何も設定しない。
[プレビューを見る](../プレビューを見る.md)のとおり、示された `127.0.0.1` の URL を端末のブラウザで開く。

### 固定の URL で見る

ワークスペースが少なく、外の入口にポートを 1 回だけ登録して使いたいときの手順。

#### 待ち受けのポートを固定する

ワークスペースの `.mindstella/config.yaml` に `preview.port` を足す。

```yaml
preview:
  port: 47800
```

1〜65535 の整数で、ワークスペースごとに別のポートにする。
そのポートを別のプロセスが使っていると、プレビューの URL がエラーを返し、配信は立たない。

#### 許可するホスト名を渡す

外の入口のホスト名を、環境変数 `MINDSTELLA_ALLOWED_HOSTS` に設定する。
[起動スクリプトを登録する](./起動スクリプトを登録する.md)で、`MINDSTELLA_ALLOWED_HOSTS` に `preview.example.com` のようなホスト名を答えて登録する。

ホスト名だけをカンマで区切って並べ、大文字と小文字は区別しない。
スキーム・ポート・`/` を含む要素と空の要素は使われず、MCP サーバーが立つときに標準エラーへ記録される。
配信は、`Host` がこのホスト名の要求と、`Origin` がこのホスト名の `https://` か `http://` の要求も受ける。
ポートを外したホスト名で比べるので、外の入口のポートは問わない。
指定していないホスト名は、`Host` を 403 で返し、`Origin` を断る。

#### 外の入口にポートを登録する

外のホスト名の要求を `http://127.0.0.1:47800` へ渡すよう、外の入口に 1 回だけ登録する。
Cloudflare Tunnel の登録は[外の入口の例](#外の入口の例)。

#### 立ち上げ直す

登録した後に開いた新しいシェルで、[起動スクリプトで立ち上げる](./起動スクリプトで立ち上げる.md)を実行する。
同じフォルダのセッションが既にあると、新しい値は効かない。
Claude Code を閉じてから叩き直す。

### 立てては消す

複数のワークスペースで使い、プレビューを立てるたびに外の入口へ登録し、止めるたびに削除したいときの手順。
ポートは固定せず、起動のたびに空きポートが選ばれる。

#### 許可するホスト名を渡す

[固定の URL で見る](#許可するホスト名を渡す)と同じ。
外の入口が割り当てうるホスト名を全て並べる。

#### 登録と削除のコマンドを渡す

登録のコマンドを `MINDSTELLA_PREVIEW_START_HOOK`、削除のコマンドを `MINDSTELLA_PREVIEW_STOP_HOOK` に設定する。
[起動スクリプトを登録する](./起動スクリプトを登録する.md)で、登録のコマンド（例 `my-gateway add`）と削除のコマンド（例 `my-gateway rm`）を答えて登録する。

どちらも、コマンドの末尾にポートとワークスペースのフォルダの名前を足して呼ぶ（`my-gateway add 47800 家計簿`）。
コマンドはシェルを通さずに、シェルの書き方で分けて呼ぶ。

- 起動時のフックは、配信を立てた直後に呼ぶ。同じワークスペースで呼び直して配信を立てなかったときは呼ばない
- 終了時のフックは、Claude Code を閉じるときに、立てた配信ごとに 1 回呼ぶ
- どちらも終わりを待たない。コマンドが見つからないなど呼べないときは、標準エラーに記録し、配信の起動と終了は止まらない

#### 立ち上げ直す

[固定の URL で見る](#立ち上げ直す)と同じ。

### 外の入口の例

Cloudflare Tunnel で固定の URL を作る例。
認証は Cloudflare Access などで付ける。

`~/.cloudflared/config.yml` に、ホスト名と渡し先を書く。

```yaml
tunnel: {トンネルの ID}
credentials-file: ~/.cloudflared/{トンネルの ID}.json
ingress:
  - hostname: preview.example.com
    service: http://127.0.0.1:47800
  - service: http_status:404
```

ホスト名をトンネルへ向け、トンネルを動かす。

```bash
cloudflared tunnel route dns {トンネルの名前} preview.example.com
cloudflared tunnel run {トンネルの名前}
```

## 反映

`再起動`（[起動スクリプトで立ち上げる](./起動スクリプトで立ち上げる.md)）。
`preview.port` は配信を立てるときだけ読むので、[設定を再読み込みする](../../リファレンス/コマンド.md#設定を再読み込みする)では待ち受けが変わらない。

## 確認

#### 配信が許可したホスト名を受ける

`session` にプレビューを頼み、示された URL のポートへ、許可したホスト名を `Host` に付けてつなぐ。

```bash
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: preview.example.com' http://127.0.0.1:{ポート}/mindstella.html
```

`200` と出る。
許可していないホスト名を `Host` に付けると `403` と出る。
固定の URL で見るときは、示された URL のポートが `preview.port` と同じになる。

#### 外のホスト名で開ける

端末の外のブラウザで `https://preview.example.com/mindstella.html` を開く。
概要が出て、コメントを送れる。

#### フックが呼ばれる

立てては消すときだけ。
登録のコマンドが外の入口へ登録するものなら、プレビューを立てるとその登録にそのポートの行があり、Claude Code を閉じるとその行が無くなる。

## 元に戻す

[起動スクリプトを登録する](./起動スクリプトを登録する.md)で環境変数を外し、`config.yaml` の `preview` を消し、Claude Code を閉じて起動スクリプトで立ち上げ直す。

戻した後に残るものは、次のとおり。

| 残るもの | 扱い |
| --- | --- |
| 外の入口の登録 | 外の入口の側で消す。削除のフックを設定していた場合は、Claude Code を閉じたときに消えている |

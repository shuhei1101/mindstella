# 起動スクリプトを登録する

起動スクリプトを短い名前で叩きたいとき、外から見る設定などの環境変数を毎回打たずに済ませたいとき、Claude Code のアカウントごとに立ち上げたいときに実行する。

## 前提

- [プラグインをインストールする](./プラグインをインストールする.md)
- システムの `bash` と `python3` が入っている（mindstella の仮想環境と MCP のツールは要らない）
- ログインシェルが `bash` か `zsh`

## 手順

### 登録する

#### セットアップのスキルを呼ぶ

起動スクリプトで立ち上げていない Claude Code でも呼べる。

```
/mindstella:setup {ワークスペースのフォルダ}
```

MCP のツールが載っていないと、ワークスペースには何も書かず、登録を読んで分かれる。
未登録なら、起動スクリプトの登録を持ちかける。
登録済みなら、新しいシェルで alias にフォルダを渡して立ち上げ直すよう案内して止まる。

#### 設定したい環境変数を答える

設定したいものだけを答える。

| 環境変数 | 設定する値 |
| --- | --- |
| `MINDSTELLA_VENV` | MCP サーバーを動かす仮想環境のフォルダ |
| `MINDSTELLA_ALLOWED_HOSTS` | プレビューの配信が受ける外のホスト名（[プレビューを外から見る](./プレビューを外から見る.md)） |
| `MINDSTELLA_PREVIEW_START_HOOK` | 配信を立てた直後に呼ぶコマンド |
| `MINDSTELLA_PREVIEW_STOP_HOOK` | 配信を止めるときに呼ぶコマンド |

値に改行は入れられない。
答えなかった環境変数は、書かれない。

#### 新しいシェルを開く

登録は、`~/.config/mindstella/`（`XDG_CONFIG_HOME` があればその下の `mindstella/`）の `registration.json` と `shell.sh` に書かれる。
ログインシェルの設定ファイルには、`# >>> mindstella >>>` と `# <<< mindstella <<<` で囲んだ `shell.sh` を読み込む 1 行だけが足される。
設定ファイルは `bash` なら `~/.bashrc`（macOS では `~/.bash_profile`）、`zsh` なら `~/.zshrc`。
開いているシェルには効かないので、新しいシェルを開く。

#### alias で立ち上げる

```bash
mindstella {ワークスペースのフォルダ}
```

叩くたびに `claude plugin list --json` から今の `installPath` を引いて、`{プラグインのフォルダ}/bin/mindstella` に引数をそのまま渡す。
プラグインを上げて古い版のフォルダが消えた後も、登録し直さずに今の版で立ち上がる。
引けないときは、標準エラーに `[mindstella] エラー:` で始まる行を出して 1 を返す。
立ち上がった後は[起動スクリプトで立ち上げる](./起動スクリプトで立ち上げる.md)と同じ。

### 登録を変える

`/mindstella:setup` で、起動スクリプトの登録を変えたいと伝える。
登録済みの値が示されるので、変えたい環境変数だけを答える。
答えた環境変数だけが書き換わり、登録済みのほかの値は残る。
外したい環境変数は、外したいと答える。
登録し直しても登録は重ならず、設定ファイルの印の範囲は 1 つのまま。

### アカウントを足す

Claude Code のアカウントを複数持つときに、アカウントごとの alias `mindstella-{アカウントの名前}` を足す。
`/mindstella:setup` で、アカウントを足したいと伝え、次を答える。

| 答えること | 例 |
| --- | --- |
| アカウントの名前（英小文字・数字・`-` の 1〜32 文字で、英小文字か数字で始まる） | `sub1` |
| そのアカウントの Claude Code の設定のフォルダ | `~/.claude-sub1` |

新しいシェルを開いて、足した alias で立ち上げる。

```bash
mindstella-{アカウントの名前} {ワークスペースのフォルダ}
```

`installPath` を引く `claude plugin list --json` にも、起動スクリプトにも、そのアカウントの設定のフォルダを `CLAUDE_CONFIG_DIR` で渡す。
シェルの `CLAUDE_CONFIG_DIR` は変わらず、`mindstella` はシェルの既定のアカウントのまま立ち上がる。
tmux のセッションの名前はフォルダとアカウントで決まり、同じフォルダを別のアカウントで開くと別のセッションになる。

### 書き込めないとき

設定ファイルか登録の置き場所に書き込めないとき、`bash`・`zsh` 以外のシェルのときは、どのファイルも書き換えずに止まる。
書き込めない理由と、手で書けば同じ登録になる行（印の範囲と alias `mindstella` の定義）が示される。
その行を、ログインシェルの設定ファイルに自分で書く。

## 反映

`再起動`（新しいシェルを開く）。

## 確認

#### alias が定義されている

```bash
type mindstella
```

関数として定義されていると出る。
アカウントを足したときは、`type mindstella-{アカウントの名前}` も同じように出る。

#### 環境変数が入っている

```bash
echo $MINDSTELLA_ALLOWED_HOSTS
```

答えた値が出る。

#### 登録を読み返す

```bash
python3 {プラグインのフォルダ}/skills/setup/scripts/register.py show
```

標準出力の JSON の `registered` が `true` で、`aliases`・`env`・`accounts` が登録した値になっている。
何も書かない。

## 元に戻す

`/mindstella:setup` で、起動スクリプトの登録を外したいと伝える。
`registration.json` と `shell.sh` と、設定ファイルの印の範囲だけが消え、利用者が書いた行はそのまま残る。
アカウントだけを外したいときは、そのアカウントの名前を伝える。
`mindstella-{アカウントの名前}` だけが消える。
外した後は、新しいシェルから効く。

戻した後に残るものは、次のとおり。

| 残るもの | 扱い |
| --- | --- |
| 開いているシェルの alias と環境変数 | そのシェルを閉じると消える |
| 立ち上げ済みの tmux のセッション | 登録とは別に残る。要らなければ Claude Code を閉じる |

# ワークスペースを今の版へ移し替える

プラグインを上げた後に、`/mindstella:setup`・`/mindstella:session` がワークスペースの版が古いと案内したときに実行する。

## 前提

- [プラグインをインストールする](./プラグインをインストールする.md)
- [起動スクリプトで立ち上げる](./起動スクリプトで立ち上げる.md)で立ち上げた Claude Code
- 移し替えるワークスペース（`mindmap.yaml` があるフォルダ）

## 手順

### スキルを呼ぶ

起動スクリプトで立ち上げた Claude Code で、ワークスペースのフォルダを渡して呼ぶ。

```
/mindstella:upgrade {ワークスペースのフォルダ}
```

スキルが、ワークスペースの版とプラグインの版を比べる。
同じなら、移し替えるものが無いと示して終わる。
ワークスペースの版の方が新しいときは、プラグインの更新を案内して止まる。

### 当てる手順を確かめる

スキルが、当てる手順を版の順に示す。
ファイル名の変更・フォルダの移動・削除を含むときだけ、当ててよいかを聞かれる。
示された手順を読んでから答える。

### 手順を当てる

スキルが写しを取ってから、手順を当てる。
写しは、ワークスペースが git の管理下ならコミット、そうでなければ隣のフォルダ `{フォルダ名}.before-{版}` への複製になる。
途中で失敗すると、写しから自動で元に戻り、失敗した版・手順・理由が示される。

v0.5.0 の手順で、設定の `field` が、同じ名前 1 件のプレイブックの配列 `playbooks` へ移る（例: `field: システム開発` → `playbooks: [システム開発]`）。
最上位の軸の呼び名（`target_label`）は書き換わらない。

### 値を答える

手順の後に値が要るキー（設定の `summary` など）があれば、スキルが聞く。
答えた値がワークスペースに入る。
値が要るキーが無ければ、聞かれない。

### 話し合いへ進む

スキルが、移し替えた版と写しの場所を示す。
案内のとおり、話し合いを進めるスキルを呼ぶ。

```
/mindstella:session {ワークスペースのフォルダ}
```

## 反映

即時。

## 確認

#### 版が書き換わっている

```bash
head -n 1 {ワークスペースのフォルダ}/mindstella-version.ini
```

プラグインの版（例: `v0.3.0`）が出る。

#### 問題が無い

Claude Code に、mindstella の `check` ツールを、`workspace` にワークスペースのフォルダを渡して呼ぶよう頼む。

結果の `ok` が `true` になる。

## 元に戻す

移し替えた後に戻すときは、示された写しから戻す。

#### 写しが git のコミットのとき

```bash
git -C {ワークスペースのフォルダ} restore --source {写しのコミットの ID} --staged --worktree -- .
git -C {ワークスペースのフォルダ} clean -fd -- .
```

ワークスペースのパスが写しのコミットの中身に戻り、コミットに無いファイルが消える。

#### 写しがフォルダの複製のとき

ワークスペースのフォルダの中身を消してから、複製したフォルダの中身を書き戻す。

戻した後も、写しは残る。
要らなくなったら消す。

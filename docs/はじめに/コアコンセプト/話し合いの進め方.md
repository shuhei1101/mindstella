# 話し合いの進め方

話し合いの記録を 4 段の軸で整理し、分野ごとの進め方ガイドに沿ってステップを回し、ゴールまで進める仕組み。
記録を置くフォルダは [ワークスペース](./ワークスペース.md)。

## 記録の軸

記録は 対象 > カテゴリー > フェーズ > 検討事項 の 4 段で分ける。

| 軸 | 中身 | 持つ場所 |
| --- | --- | --- |
| 対象 | 話し合うものの最上位のまとまり。呼び名は進め方ガイドの既定から始まり、途中で書き換えられる | 設定の `targets`・`target_label` |
| カテゴリー | 対象の中の分け方 | 設定の `categories` |
| フェーズ | 浅い順に進める段階 | 設定の `phases` |
| 検討事項 | 問いと答えの 1 件 | `decisions.yaml` |

細かいものは軸を増やさず、派生（`parent`）・依存（`depends_on`）・タグ（`tags`）で表す。

## 進め方ガイド

分野ごとに、フェーズの並び・フェーズごとの観点・必ず調べるもの・ゴールの候補・リリースの形を決めた手引き。
新しい話し合いを始めるとき、分野を 1 つ以上選ぶと、選んだ手引きから設定のたたき台が作られる。
複数選んだときは、各手引きのフェーズから 1 本の並びを作り、設定がその並びを持つ。
手引きは、話し合いの途中で足す・外す・入れ替えられる。

| 分野 | 最上位の軸の呼び名 | フェーズ |
| --- | --- | --- |
| システム開発 | 機能 | 目的 → 要件 → 構成 → インターフェース → コンテンツ |
| 調査 | 調査対象 | 問い → 観点 → 事実 → 評価 → 結論 |
| 資料作り | 資料 | 目的 → 読み手 → 構成 → コンテンツ → 仕上げ |
| 壁打ち | テーマ | 問い → 発散 → 整理 → 絞り込み → 結論 |

システム開発のゴールは、要件まで・インターフェースまで（既定）・モジュール構成までから選ぶ。
ゴールは任意で、決めずに始めてもよい。

## ステップ

話し合いは、次のステップを場面に応じて回して進める。

| ステップ | スキル | することと残る記録 |
| --- | --- | --- |
| セットアップ | `setup` | 新しいワークスペースを作るか、既存のワークスペースの状況を読んで続きを推奨する |
| 取り込み | `session` | 発言を対象・カテゴリー・フェーズに振り分けて記録し、派生の検討事項・未整理・タスクを積む。保留・解除・中止もここで行い、会話ログを書き足す。話し合いの最初に、プレビューから送られて取り込んでいない回答・意見を拾い、送った順に同じ手順で記録して取り込み済みにする |
| ヒアリング | `session` | 前提が揃った未決定を選び、1 ラウンドにまとめて聞く |
| リサーチ | `session` | 調べるものを示して確認を取り、サブエージェントで調べ、結果を調査に書いて検討事項に繋ぐ |
| 方針転換 | `session` | 採用する案を切り替え、影響を受ける項目を要見直しにし、見直しのタスクを積む |
| 範囲の見直し | `session` | 題名・話し合いの概要・ゴール・進め方ガイド・最上位の軸の呼び名を、確かめてから書き換える |
| プレビュー | `session` | サーバーが配るプレビューの URL を示す |
| ゴール判定 | `session` | ゴールに届いていれば、検討事項と納品物を見せて確定をもらい、`release/` に書き出す。ゴールが無ければ、決めるかを尋ねる |

## 聞き方と調べ方

- ヒアリングは前提が揃った問いだけを 1 ラウンドにまとめる。答えが他の問いに左右される問いは次のラウンドに回す
- 事実は自分で調べ、決めることだけを聞く
- 選択肢があるときは、案の表（案・内容・メリット・デメリット・備考）と推奨を添える。選択肢が無い論点はたたき台を出す
- 脱線した質問は、言葉の意味なら用語集、それ以外ならメモに残し、タスクにはしない
- 外部ライブラリ・外部 API を決めるときは、ベストプラクティスと候補の調査を必ず積む
- サブエージェントの起動前に「何を・どの観点で・何体で」を示して確認を取る。利用者が自分から調べるよう頼んだときは省く

## 方針を変えたとき

採用する案を切り替えると、その検討事項に依存する決定済みの項目が要見直しになる。
切り替えた検討事項の本文は今の正だけを書き、古い方針を残さない。
スコープが変わって納品物が要らなくなったときは、その資料の `deliverable` を外して、納品物から資料へ格下げし、ゴールの納品物からも外す。

## 範囲が広がったとき

同じワークスペースのまま、題名・話し合いの概要・ゴール・進め方ガイド・最上位の軸の呼び名を書き換えて続ける。
`session` が書き換えのたたき台を示し、利用者が確かめてから書き換える。
フェーズが変わるときは、古いフェーズから新しいフェーズへの対応の表も示し、設定と項目のフェーズを一度に付け替える。
新しいフェーズに無いフェーズを持つ項目は、残したまま付け替えない。

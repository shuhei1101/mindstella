# ワークスペース

1 つの話し合いの記録を、YAML と Markdown で置いたフォルダ。
ファイル構成と各 YAML のキーは [ワークスペースの書式](../../リファレンス/ワークスペースの書式.md)にある。

## YAML が正本

検討事項・タスク・調査・資料・用語集・メモ・会話ログは、種類ごとの YAML に 1 項目ずつ記録する。
`docs/` の本文のファイルは本文だけを持ち、メタデータ（タイトル・状態・参照）は持たない。
項目の `body` が `docs/{ID}.md` を指して、項目と本文が結び付く。
本文はどの種類の項目も持てる。
資料の本文は、Markdown（`{ID}.md`）か HTML（`{ID}.html`）のどちらか 1 つで持ち、どちらで書いたかは `body` の拡張子で分かる。
ほかの種類の本文は Markdown だけ。

## 記録は `.mindstella/` にまとまる

ワークスペースのフォルダの直下には、サブフォルダ `.mindstella/` と `README.md` が並ぶ。
設定・種類ごとの YAML・本文の `docs/`・`release/`・書き換えのまとまり・スレッド・ロック・前回開いた日時は、全て `.mindstella/` の中に置く。
`.mindstella/config.yaml` があるフォルダが、ワークスペースになる。
画面はサーバーが配るもので、フォルダの直下には置かない。

`README.md` は記録ではなく、そのフォルダの起動・接続のコマンドとスキルの呼び方、プレビューの URL を書いたもの。
サーバーが、ワークスペースを作るとき・`session` を始めるとき・プレビューの配信を立てたときに書き直す。
1 行目に自動で書いた印が無い `README.md` は、利用者が書いたものとして書き換えない。

YAML の形は JSON Schema（`skills/mindmap/schemas/`）で決まり、書き込む MCP のツールは書き込む前に全ての YAML をスキーマと突き合わせる。
合わないときは何も書き換えない。

## 1 つの常駐サーバーが複数のワークスペースを扱う

ワークスペースを読み書きするのは、端末に 1 つの mindstella の常駐サーバー。
並行する複数の Claude Code のセッションが同じ常駐サーバーを共有し、ツールの引数 `workspace` で指したワークスペースをそれぞれ読み書きする。
相対パスの `workspace` は、ツールを呼んだセッションの作業フォルダから読む。
プレビューの配信もワークスペースごとに常駐サーバーが持ち、セッションを閉じても止まらない。
同じワークスペースへ同時に書いても、ロックで順に書くので、書き換えを失わない。

## ID の頭の文字で種類が決まる

項目の ID は、種類の頭の文字に連番を続けた形になる。
`D-12` なら検討事項、`T-3` ならタスクで、頭の文字から書き込む YAML が決まる。
消した番号は使い回さない。消した項目の ID は `changes.yaml` に残り、新しい項目の ID を振るときに避ける。

## 依存と採用する案

検討事項は、先に決まっている必要がある検討事項を `depends_on` で、派生元を `parent` で指す。
タスクは、進める検討事項を `for` で指す。
検討事項は複数の案を持ち、採用する案を 1 つに切り替えられる。
`未整理`・`対象外`・`取り下げ` のほかの状態は、案を 1 つ以上持つ。
AI が推す案には、未決定のうちに推奨の印を付ける。

`adopt` は案を採用して、状態を `決定済み` にする。答えと推奨の印は変えない。
`決定済み` の検討事項は採用した案を 1 つ持ち、採用した案を持つ検討事項は `未決定` にならない。
方針転換で `要見直し` にした検討事項は、前に採用した案を持ったままになる。
影響を受ける項目は `impact` が、`depends_on`・`parent`・`for` を逆向きにたどって洗い出す。
`related`（関連）は向きを持たないので、たどらない。

## 話題はタグで分ける

1 つのワークスペースで、関連する複数の話題を扱える。
話題は、項目の `tags` で分ける。
`session` は取り込みで、記録に話題ごとのタグを付ける。
タグはマスター（語彙）を持たない自由な文字列で、どのタグも書き込める。比べるときは NFKC と小文字にそろえる。
先に `tags` で使われているタグを引き、同じ意味のタグがあれば使い回し、無ければそのまま新しいタグを付ける。
1 項目に複数の話題が当たるときは、全て付ける。
付けたタグのうち、その項目が主に扱う話題のタグには主題のマーカー（`main: true`）を付け、触れているだけの話題のタグと分ける。
主題のタグは 1 項目に複数持てる。
タグで探すと、そのタグを主題として持つ項目が上に並ぶ。
プレビューでは、絞り込みのドロワーのタグで話題ごとに項目を絞れる（[絞り込みのドロワーで絞り込む](../../使い方/プレビューを見る.md#絞り込みのドロワーで絞り込む)）。

## 書き換えのたびに変更履歴が残る

項目は、`update`・`adopt`・`edit_option` が書き換えるたびに、変わったキーと本文の書き換える前の値を、その項目の変更履歴（`history`）として 1 回分積む。
前の版を丸ごとは持たず、変わったところだけを持つ。
何回分持つかは `config.yaml` の `history_limit` で決め（既定は 5、0 は変更履歴を持たない）、超えた古い分は次に積むときに消える。

AI が最後に読んだ時点は、`changes.yaml` の `read_seq` に持つ。プレビューの前回開いた日時とは別のものになる。
`session` は準備で `changes_since_read` を呼び、`read_seq` より後に足された・変わった・消された項目を、変わったキーと前の値つきで読み、`read_seq` を今の時点に書き換える。
AI が MCP のツールで書いた分も、次に呼ぶまでは読んでいない変更に数える。
`read_seq` より後の回は、保持する回数を超えても消えない。AI が読んだ後の書き換えで、超えた古い回を消す。

`commit` は、最後のまとまりより後の書き換えを、日時と一言の説明を付けた 1 つの書き換えのまとまりにする。
まとめる前の書き換えは `changes.yaml` に残り、`pending` で読める。
`add` が足した項目は変更履歴を持たず、まだまとめていない変更に入る。
`remove` が消した項目は、ID・種類・消したときのタイトルが、まだまとめていない変更の消した項目に入り、`commit` でまとまりに残る。
`session` はステップを終えるたびに `commit` を呼ぶ。

プレビューは、変更履歴と書き換えのまとまりから、前回からの差分を出す（[前回からの差分を読む](../../使い方/プレビューを見る.md#前回からの差分を読む)）。
変更履歴を持たない既存のワークスペースは、そのまま読み書きでき、差分が出ないだけになる。
`read_seq` を持たない既存のワークスペースも、移し替えずにそのまま読み書きでき、最初に `changes_since_read` を呼んだときに今の時点を記録する。
キーは [ワークスペースの書式](../../リファレンス/ワークスペースの書式.md#変更履歴)にある。

## 編集した人を項目ごとに残す

項目は、最後に足した・書き換えたのが AI か利用者かを `updated_by`（`ai` / `user`）に持ち、更新日時と一緒に書き換える。
MCP のツールの書き込みは `ai`、プレビューの画面から保存した書き込みは `user` になる。
変更履歴の 1 回分も、その回を書き換えたのが AI か利用者かを `by` に持ち、画面から保存した回は `user` になる。
`session` が呼ぶ `changes_since_read` は、項目の今の編集した人と、読んだ時点より後の回の `by` を返すので、AI は利用者が直した項目を見分けられる。
編集した人を持たない項目（このキーを入れる前に書いたもの・移し替えたもの）は、次に書き換えるまで、編集した人が分からないものとして扱う。

## 画面の編集は保存待ちに溜めてまとめて保存する

プレビューの画面で直した項目と設定は、その場では書かず、保存待ちの編集として `edits.yaml` に溜める。
溜めた編集は、保存待ちのパネルでまとめて保存するまで、項目・設定・変更履歴を変えない。
保存すると、サーバーが全ての編集を 1 回で当てる。1 件でも書き込めないものがあれば、何も書かずに、書き込めない編集と理由を返す。

書き込めない編集は、次のものになる。

- 溜めた後に AI が同じ項目を書き換えた編集（溜めた時点の項目の `updated` と今の `updated` が違う。設定は今の値が溜めた時点と違う）
- 編集する項目が無くなった編集
- 消す項目をほかの項目が指している編集（同じ保存で指している項目も消すか、参照を外すときは当たらない）
- 当てた後の項目・設定が、スキーマ・検討事項の案と状態の決まり・参照の指す先に合わない編集

保存した書き込みは、項目の `updated_by` と変更履歴の `by` が `user` になり、変更履歴の 1 回分は項目ごとにまとまる。
保存のときに AI のまだまとめていない変更があれば、先に説明「まとめる前の AI の書き換え」の 1 つのまとまりにする。その後、利用者の編集を説明「画面からの編集」の別の 1 つのまとまりにする。
保存の後は、保存待ちの編集が 0 件で、まだまとめていない変更も空になる。

AI は、次の `session` の準備で `changes_since_read` を呼ぶと、保存した変更を `by` が `user` の変更として読む。
キーは [ワークスペースの書式](../../リファレンス/ワークスペースの書式.md#保存待ちの編集)、操作は [プレビューを見る](../../使い方/プレビューを見る.md#項目と設定を編集して保存する)にある。

## 設定はワークスペースの既定と個人の上書きの 2 段

プレビューの見た目・表示する種類は、ワークスペースの既定と、見る人ごとの個人の上書きの 2 段で決まる。
ワークスペースの既定は `config.yaml` の `display` に持ち、同じワークスペースを見る全員に効く。
個人の上書きはブラウザの `localStorage` に持ち、ネットワークの見た目・ライト / ダーク・表示する種類・表の列を、端末ごと・ブラウザごとに残す。
サーバーへは送らず、ほかの人の表示には影響しない。

値は項目ごとに、個人の上書きがあればそれを、無ければ `config.yaml` の既定を、それも無ければ組み込みの既定（ネットワークの見た目は `deep`、表示する種類は全ての種類）を使う。
ライト / ダークは `config.yaml` に持たず、上書きが無ければ端末のライト / ダークに従う。
個人の上書きは、プレビューの表示の設定の「既定に戻す」で外れ、ワークスペースの既定の表示に戻る。

`config.yaml` を書き換えるのは、MCP のツール `update_settings` と、プレビューの「ワークスペースの既定にする」と、設定の画面で溜めた編集の保存だけで、画面の個人の上書きの操作は書き換えない。
手で直した `config.yaml` は、設定の再読み込みで開いている画面に効かせる。
キーは [ワークスペースの書式](../../リファレンス/ワークスペースの書式.md#設定)、操作は [プレビューを見る](../../使い方/プレビューを見る.md#表示の設定を変える)にある。

## 版を記録し、版ごとの手順で移し替える

`.mindstella/mindstella-version.ini` が、ワークスペースを最後に整えたときのプラグインの版を持つ。
`init` が作るときに書き、移し替えるたびに書き換える。
版のファイルが無いワークスペースは、版を記録する前の形式として扱う（v0.6.0 より前の置き場所の、直下の `mindstella-version.ini` があればそれを読む）。

プラグインは、ワークスペースの形式を変えた版ごとに、移し替えの手順（`skills/mindmap/migrations/{版}/steps.yaml`）を持つ。
`migrate` は、記録した版より後でプラグインの版以下の手順を、版の順に当てる。
v0.6.0 の手順は、直下の記録のファイルとフォルダを `.mindstella/` へ移す。
写しを取ってから当てるので、途中で失敗しても、ワークスペースは移し替える前の中身に戻る。
手順の後に値が要るキー（設定の `summary` など）は、利用者に聞いて入れる。

`setup`・`session` は、ワークスペースの版がプラグインより古いと、話し合いを始めずに移し替えのスキル `upgrade` を案内する。
新しいと、プラグインの更新を案内して止まる。
どちらも、手順を勝手には当てない。
移し替える手順は [ワークスペースを今の版へ移し替える](../../使い方/セットアップ手順/ワークスペースを今の版へ移し替える.md)。

## 送ったコメントはスレッドになり、AI が返信する

プレビューで書いたコメントは、送るまでレビュー中のコメントとして `comments.yaml` に溜まり、入力欄の書きかけは `drafts.yaml` に残る。
どちらもサーバーを止めても消えない。
コメントの一覧でチェックしてまとめて送ると、サーバーが `comments.yaml` から外し、`threads.yaml` に足す。
新しいスレッドの最初の書き込みは、1 件ごとに 1 つのスレッドになり、既存のスレッドへの返信は、そのスレッドの末尾に足される。
スレッドには利用者と AI の書き込みが書いた順に積まれ、状態（オープン・クローズ）・タグ・要約と、クローズとオープンへの戻しの記録を持つ。
`threads.yaml` は初めてスレッドができたときに作られ、無ければスレッド 0 件として扱う。
送ったときは、起動スクリプトで立てた Claude Code へも、届いた件数を知らせる 1 行を入力する。

AI は、`session` の最初に、取り込んでいない利用者の書き込みを持つスレッドを拾う。
スレッドがオープンでもクローズでも拾うので、返信を送ってからクローズにしても、その返信は AI に届く。
書き込みを読んで記録し、返信するか返信せずにクローズにすると、その書き込みは取り込み済みになる。
返信のたびに、AI がスレッドの要約を書き直す。
資料や検討事項を足したり直したりしたときは、返信にその項目の ID を書き、画面では項目を開くリンクになる。
AI からもスレッドを立てて、利用者に返事を求められる。

書き込みごとに、AI が読んだか（AI の既読・未読）を持つ。
AI がスレッドを読むと、読んだ書き込みが AI の既読になる。
Claude Code のセッションを開くたびに、全ての書き込みが AI の未読に戻り、AI はオープンのスレッドを読み直す。
取り込み済みは別に持つので、AI の未読に戻っても、取り込み済みの書き込みは取り込み直されない。

書き込みは、AI の既読とは別に、利用者が読んだか（利用者の既読・未読）も持つ。
AI の書き込みは利用者の未読で足され、プレビューでスレッドを開くと、そのスレッドの書き込みが利用者の既読になる。
利用者の未読の書き込みを持つスレッドは、プレビューのコメントの一覧とコメントのボタンの印で見分けられる。
セッションを開くたびに未読に戻るのは AI の既読だけで、利用者の既読は戻らない。

スレッドは消さず、クローズにして残す。
取り込んでいない利用者の書き込みを持つスレッドが向けた項目は消せず、それ以外のスレッドが向けた項目は消せる。
同じワークスペースを書き換えるプロセスどうしは、空のファイル `.mindstella.lock` で排他する。
キーは [ワークスペースの書式](../../リファレンス/ワークスペースの書式.md#スレッド)、操作は [プレビューを見る](../../使い方/プレビューを見る.md#コメントの一覧からスレッドを読む)にある。

## コメントは書き戻しで残らない

MCP のツールは YAML を読み込んで書き戻すので、YAML に手で書いたコメントは残らない。
残したい内容は、`attrs`・`reason` などのキーに書く。
書き戻しのたびに、配列の字下げも揃い直る。

ツールの一覧は [コマンド](../../リファレンス/コマンド.md)、立ち上げ方は [起動スクリプトで立ち上げる](../../使い方/セットアップ手順/起動スクリプトで立ち上げる.md)。

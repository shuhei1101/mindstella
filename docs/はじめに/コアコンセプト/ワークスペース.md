# ワークスペース

1 つの話し合いの記録を、YAML と Markdown で置いたフォルダ。
ファイル構成と各 YAML のキーは [ワークスペースの書式](../../リファレンス/ワークスペースの書式.md)にある。

## YAML が正本

検討事項・タスク・調査・資料・用語集・メモ・会話ログは、種類ごとの YAML に 1 項目ずつ記録する。
`docs/` の Markdown は本文だけを持ち、メタデータ（タイトル・状態・参照）は持たない。
項目の `body` が `docs/{ID}.md` を指して、項目と本文が結び付く。

YAML の形は JSON Schema（`skills/mindmap/schemas/`）で決まり、書き込む MCP のツールは書き込む前に全ての YAML をスキーマと突き合わせる。
合わないときは何も書き換えない。

## ID の頭の文字で種類が決まる

項目の ID は、種類の頭の文字に連番を続けた形になる。
`D-12` なら検討事項、`T-3` ならタスクで、頭の文字から書き込む YAML が決まる。
消した番号は使い回さない。

## 依存と採用する案

検討事項は、先に決まっている必要がある検討事項を `depends_on` で、派生元を `parent` で指す。
タスクは、進める検討事項を `for` で指す。
検討事項は複数の案を持ち、採用する案を 1 つに切り替えられる。

`adopt` は採用する案だけを切り替え、状態と答えは変えない。
影響を受ける項目は `impact` が、`depends_on`・`parent`・`for` を逆向きにたどって洗い出す。
`related`（関連）は向きを持たないので、たどらない。

## 版を記録し、版ごとの手順で移し替える

ワークスペースの直下の `mindstella-version.ini` が、ワークスペースを最後に整えたときのプラグインの版を持つ。
`init` が作るときに書き、移し替えるたびに書き換える。
版のファイルが無いワークスペースは、版を記録する前の形式として扱う。

プラグインは、ワークスペースの形式を変えた版ごとに、移し替えの手順（`skills/mindmap/migrations/{版}/steps.yaml`）を持つ。
`migrate` は、記録した版より後でプラグインの版以下の手順を、版の順に当てる。
写しを取ってから当てるので、途中で失敗しても、ワークスペースは移し替える前の中身に戻る。
手順の後に値が要るキー（設定の `summary` など）は、利用者に聞いて入れる。

`setup`・`session` は、ワークスペースの版がプラグインより古いと、話し合いを始めずに移し替えのスキル `upgrade` を案内する。
新しいと、プラグインの更新を案内して止まる。
どちらも、手順を勝手には当てない。
移し替える手順は [ワークスペースを今の版へ移し替える](../../使い方/セットアップ手順/ワークスペースを今の版へ移し替える.md)。

## コメントの送信は submissions.yaml に残る

プレビューで書いたコメントは、送るまでレビュー中のコメントとして `comments.yaml` に溜まり、入力欄の書きかけは `drafts.yaml` に残る。
どちらもサーバーを止めても消えない。
コメントの一覧でチェックしてまとめて送ると、サーバーが向けた項目の ID・選んだ箇所・本文・送った日時とともに `submissions.yaml` に足し、`comments.yaml` から外す。
項目に紐づかないコメントは、向けた項目の ID を持たない。
`submissions.yaml` は初めて送ったときに作られ、無ければ送信 0 件として扱う。
サーバーを止めても消えず、`session` の最初に取り込むと、取り込んだ日時が `taken` に入る。
同じワークスペースを書き換えるプロセスどうしは、空のファイル `.mindstella.lock` で排他する。

## コメントは書き戻しで残らない

MCP のツールは YAML を読み込んで書き戻すので、YAML に手で書いたコメントは残らない。
残したい内容は、`attrs`・`reason` などのキーに書く。
書き戻しのたびに、配列の字下げも揃い直る。

ツールの一覧は [コマンド](../../リファレンス/コマンド.md)、立ち上げ方は [起動スクリプトで立ち上げる](../../使い方/セットアップ手順/起動スクリプトで立ち上げる.md)。

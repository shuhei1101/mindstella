# セットアップから始める

新しい話し合いを始めるとき、起動のコマンドでワークスペースと MindStella のセッションを作る。

## 前提

- [プラグインをインストールする](./セットアップ手順-プラグインをインストールする.md)
- tmux が入っている
- 話し合いの記録を置く、まだ `.mindstella/config.yaml` が無いフォルダ

## 手順

### 起動スクリプトで立ち上げる

ワークスペースにするフォルダを渡して、起動スクリプトを叩く。
フォルダが無ければ作られ、MindStella の API でワークスペース（既定の設定）と MindStella のセッションが作られて、そのペインへつながる。
フォルダは、グローバルの設定のファイルの `mindstella.allowed_dirs` のどれかの下に置く。

```bash
{プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ} [--flow {配信元の ID}#{文書の ID}]
```

進め方の文書があれば `--flow` で渡す。
渡した場所は新しいワークスペースの設定に残り、MindStella のセッションが起動のたびに参照する。

起動スクリプトが最初に、サーバーの依存を確かめる。
足りないと、足りないものとそろえるコマンドが示されて止まる。
示されたコマンドを実行してから、もう一度叩く（[スクリプトの依存を入れる](./セットアップ手順-スクリプトの依存を入れる.md)）。
`{プラグインのフォルダ}` の引き方と、つなぎ方は [起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md)。

### 題名と説明を決める

MindStella のセッションに、話し合いの題名と説明を伝える。
MindStella のセッションが `update_settings` で設定に書く。
プレビューの設定の画面から書き換えてもよい。

### 話し合いへ進む

MindStella のセッションは、起動の直後に起動と再開のエージェントフロー `mindstella/startup` を進め、進め方の文書の工程へ進む（[エージェントフロー](./エージェントフロー.md)）。
利用者は MindStella のセッションに話しかけるか、プレビューからコメントを送信する。

## 結果

フォルダにサブフォルダ `.mindstella/` ができ、その中に `config.yaml`・種類ごとの空の YAML・`docs/` が入る。
フォルダの直下には `.mindstella/` と `README.md` が並ぶ。
`README.md` には、このフォルダの起動・接続のコマンドとエージェントフローの案内が書かれる。
ファイル構成は [ワークスペースの書式](./ワークスペースの書式.mark.md#ファイル構成) にある。

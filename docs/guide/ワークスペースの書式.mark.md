# ワークスペースの書式

ワークスペース（1 つの話し合いのフォルダ）のファイル構成と、各 YAML のキーの一覧。
正本は `skills/mindmap/schemas/` の JSON Schema で、書き込む MCP のツールは書き込む前にこれと突き合わせる。

## ファイル構成

項目の本文のフォルダ `docs/` と資料に埋め込むファイルのフォルダ `files/` はワークスペースの直下に、ほかの記録のファイルとフォルダは直下のサブフォルダ `.mindstella/` に置き、直下には `.mindstella/`・`docs/`・`files/`・`README.md` が並ぶ。
記録の無いフォルダの直下に `docs/` か `files/` が既にあると、ワークスペースを作らない（[ワークスペースを作る](./コマンド.mark.md#ワークスペースを作る)）。
`.mindstella/config.yaml` があるフォルダがワークスペースになる。
`README.md` は記録ではなく、サーバーが書き直す。
1 行目の `<!-- mindstella:readme -->` が無い、利用者が書いた `README.md` は書き換えない。
このマーカーの確認のほかにどのツールも読まず、[ワークスペースを点検する](./コマンド.mark.md#ワークスペースを点検する)の対象にしない。
次の表の名前は、`docs/`・`files/` はワークスペースの直下から、ほかは `.mindstella/` からのパス。

種類ごとの YAML（`config.yaml` 以外）はどれも `items:` の配列を持ち、1 要素が 1 項目になる。

## ID

ID は種類の頭の文字 + `-` + 連番（`D-12`）で、頭の文字で種類が決まる。
連番はその種類の最大 + 1 で振り、削除した番号を使い回さない。
最大は、今ある項目と、`changes.yaml` に残した削除した項目のその種類の ID から取る。

<!-- table: {"kind": "data"} -->

| 頭の文字 | 種類 | YAML |
| --- | --- | --- |
| `D` | 検討事項（`decision`） | `decisions.yaml` |
| `T` | タスク（`task`） | `tasks.yaml` |
| `R` | 調査（`research`） | `research.yaml` |
| `A` | 資料（`doc`） | `docs.yaml` |
| `G` | 用語集（`term`） | `terms.yaml` |
| `N` | メモ（`note`） | `notes.yaml` |
| `L` | 会話ログ（`log`） | `logs.yaml` |

## 設定

`config.yaml`。題名・話し合いの概要・進め方の文書・関連する場所・変更履歴を保持する回数・表示の既定・音声入力の設定・プレビューの待ち受けのポートを持つ。
書き換える MCP のツールは [設定を書き換える](./コマンド.mark.md#設定を書き換える)。プレビューの設定の画面で溜めた編集の保存も書き換える（[保存待ちの編集](#保存待ちの編集)）。
手で修正したときは、[設定を再読み込みする](./コマンド.mark.md#設定を再読み込みする)で開いている画面に効かせる。
前のバージョンの設定ファイル `mindmap.yaml` は、[ワークスペースを今のバージョンへ移し替える](./セットアップ手順-ワークスペースを今のバージョンへ移し替える.mark.md)で `.mindstella/config.yaml` に移る。

<!-- table: {"kind": "data"} -->

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `flow` | object | - | 進め方の文書。要素は `source`（project-index の配信元の ID）・`doc`（文書の ID）。起動のコマンドの `--flow` で、記録の無いフォルダにだけ書く。MindStella のセッションが起動のたびに参照する |
| `links` | array | - | 関連する場所。要素は `title`・`url` |
| `summary` | string | ✅ | 話し合いのタイトル（何についての話し合いかを 1 文で）。プレビューのトップバーに出す |
| `description` | string | - | 話し合いの概要（何についての話し合いかを 1 文の短い文で。60 字以内）。AI が利用者に伝えられて書き、`config.yaml` を修正して書き換えてもよい。プレビューの概要の画面の題名の上に出す。`summary` とは別のもの |
| `history_limit` | number | - | 項目ごとに変更履歴を何回分持つか。0 以上の整数で、上限は設けない。無ければ 5。0 は変更履歴を持たず、差分を出さない。[設定を書き換える](./コマンド.mark.md#設定を書き換える)で変える。AI がまだ読んでいない回（前回参照した時点より後の回）は、この回数を超えても削除しない |
| `display` | object | - | プレビューのワークスペースの既定。ブラウザの個人の上書きが無い項目に使う。要素は `visible_kinds`。[設定を書き換える](./コマンド.mark.md#設定を書き換える)と、プレビューの「ワークスペースの既定にする」が書く |
| `display.visible_kinds` | array | - | プレビューのタブに出す種類。`decisions`・`tasks`・`research`・`docs`・`terms`・`notes`・`logs` の重複しない並びで、空でもよい。無ければ全ての種類。概要は常に出す |
| `transcription` | object | - | コメント・返信の入力の音声入力の設定。要素は `action`・`preset`。[設定を書き換える](./コマンド.mark.md#設定を書き換える)と、プレビューの設定の画面の「音声入力」が書く。どの文字起こしのサービスを使うかは持たない（常駐サーバーの環境変数 `MINDSTELLA_TRANSCRIBER`） |
| `transcription.action` | string | - | 文字起こし後の挙動。`review` は入力欄へ挿入した全文をレビュー中に溜め、送信しない。`send` は入力欄へ挿入した全文を、その 1 件だけで Claude Code へ送信する。`insert` は入力欄のカーソルの位置に挿入し、送信しない。無ければ `review` |
| `transcription.preset` | string \| null | - | 文字起こしのサービスへ渡す用語集のプリセットの名前（1 文字以上）。無いか `null` ならサービスの既定 |

| `mdmark` | object | - | 画面・配る書き出しが読み込む mdmark。要素は `version`・`map` |

## 共通のキー

種類ごとの YAML の項目は、どれも次のキーを持つ。
作成日時・更新日時・編集した人・連番・変更履歴は項目に持たず、[項目の履歴](#項目の履歴)に持つ。

<!-- table: {"kind": "data"} -->

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | ID。書き込む前に `next_id`（[ID を取る](./コマンド.mark.md#id-を取る)）で取る |
| `title` | string | ✅ | タイトル |
| `tags` | array | - | 話題を分けるマーカーとして使い、AI が取り込みで話題ごとに付ける。どの文字列でも持て、比べるときは NFKC と小文字にそろえる。タグの語彙は持たない。使われているタグは project-index の `search_docs` を `group_by: tags` で呼んで引く。要素は `name`（タグの名前）と、その項目の主題のタグなら `main: true` を持つ（主題でないタグは `main` を持たない）。そろえて同じ名前のタグを 2 件持たない。例: `[{name: 通知, main: true}, {name: 画面}]`。文字列の要素は v0.12.0 より前の形式で、常駐サーバーがワークスペースを開くときに移す（[ワークスペースを今のバージョンへ移し替える](./セットアップ手順-ワークスペースを今のバージョンへ移し替える.mark.md)） |
| `related` | array | - | 項目の参照。要素は `to`（指す項目の ID）と `type`（`depends_on` 前提 / `parent` 派生元 / `for` タスクが進める検討事項 / `see_also` 向きを持たない関連）。`depends_on`・`parent` は同じ種類の項目を、`for` はタスクから検討事項を指す。project-index の `trace_related` が種類つきでたどり、`delete_docs` はほかの項目が指している項目の削除を断る。例: `[{to: D-1, type: depends_on}]` |
| `links` | array | - | リンク。要素は `title`・`url` |

## 項目の履歴

`history.yaml`。最上位の `items` に、項目の ID → その項目の行を持つ。
書くのは常駐サーバーだけで、project-index の配信の対象にしない（種類ごとの YAML を project-index と一緒に書き換えないため）。
プレビューの記録の取得は、各項目に行のキーを追加して返す。

| キー | 型 | 説明 |
| --- | --- | --- |
| `created` | string | 作成日時（UTC のタイムゾーン付き ISO 8601。例: `2026-10-02T08:00:00+00:00`） |
| `updated` | string | 更新日時（同じ形式） |
| `updated_by` | string | 編集した人。`ai`（MindStella のセッションの応答の途中の書き込みと MindStella の MCP のツールの書き込み）・`user`（プレビューの画面からの保存）・`external`（それ以外のセッションやエディタの書き込み） |
| `seq` | number | 最後に振った連番。項目を追加した・値を変えたときに振った `changes.yaml` の連番のうち、最も新しいもの。[前回読んだ時点からの変更を読む](./コマンド.mark.md#前回参照した時点からの変更を読み込む)が `read_seq` と比べる |
| `added_seq` | number | 追加したときの連番。読んだ時点より後に追加した項目と変えた項目を分けるのに使う |
| `history` | array | [変更履歴](#変更履歴)。新しい順に並べる。無ければ変更履歴 0 回分として扱う |
| `history_dropped_seq` | number | 保持する回数を超えて `history` から削除した回のうち、最も大きい `seq`。一度も削除していなければ持たない |
| `confirmed` | boolean | 確認済み。`true` のときだけ持ち、無ければ未確認。プレビューの「確認済み」と、コメントの送信（設定の `confirm_on_comment` がオンのとき）が付ける。プレビューの画面からの保存以外（`updated_by` が `ai`・`external`）で項目が変わると外れる。付け外しは `updated`・`seq`・`history` を変えない。行が無い項目を確認済みにすると、`confirmed` だけの行を作る |

## 変更履歴

項目の履歴の行の `history`。常駐サーバーの変更の検知（どのセッションの書き込みも見つける）・[採用する案を切り替える](./コマンド.mark.md#採用する案を切り替える)・[案を書き換える](./コマンド.mark.md#案を書き換える)・プレビューの保存が値を変えるたびに、先頭へ 1 回分を追加する。
前のバージョンを丸ごとは持たず、変わったところだけを持つ。
変わったキーが無い書き換えは積まない。
数は設定の `history_limit` までで、超えた古い分は次に積むときに消える。
ただし、`seq` が前回参照した時点より大きい回（AI がまだ読んでいない回）は、超えても消えない。前回参照した時点が無いワークスペースでは、超えた古い分を今までどおり削除する。
削除した回の最大の `seq` は、行の `history_dropped_seq` に残る。プレビューは、選んだ時点の範囲の中の回が消えているかをこれで見分ける。

| キー | 型 | 説明 |
| --- | --- | --- |
| `seq` | number | `changes.yaml` の連番 |
| `at` | string | 書き換えた日時（UTC のタイムゾーン付き ISO 8601） |
| `by` | string | その回を書き換えたのが AI か利用者かほかのセッションかで、`ai`・`user`・`external` のどれか。このキーを入れる前に積んだ回は持たない |
| `before` | object | 変わったキー → 書き換える前の値。前に無かったキーは `null`。`updated`・`updated_by`・`history`・`history_dropped_seq`・`seq`・`added_seq`・`body` は入れない。ただし `body` は、前に本文が無かった回（`null`）と資料の本文の形式を替えた回（前のファイル名）だけ入れる |
| `body_diff` | array | 本文が変わったときだけ持つ。要素は `line`（書き換えた後の本文の 1 始まりの行）・`now`（そこからの今の行の並び）・`before`（置き換える前の行の並び）。本文の全文は持たない |

## 書き換えのまとまり

`changes.yaml`。`commit` でまとめた書き換えのまとまりと、まだまとめていない変更。
MindStella のセッションの応答の途中でない間のほかのセッションの書き込み（外部の変更）は、書き換えが止んで 1 分後に、常駐サーバーが「ほかのセッションの書き込み」のまとまりに自動でまとめる。
書くのは常駐サーバーだけで、project-index の配信の対象にしない。
削除しない。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `last_seq` | number | ✅ | 最後に振った連番。変更履歴を積むとき・項目を追加するとき・項目を削除するとき・`history_limit` が 0 で変更履歴を積まずに値を変えるときに 1 追加する |
| `sets` | array | ✅ | まとまり。新しい順。要素は `id`（`V-` + 連番）・`at`（まとめた日時）・`summary`（一言の説明）・`until_seq`（まとめたときの `last_seq`）・`added`（追加した項目の ID）・`changed`（変えた項目の ID。追加した項目は入れない）・`removed`（削除した項目。要素は `pending.removed` と同じ形式。削除した項目が無いまとまりはキーを持たない）・`by`（まとめた変更の書いた元。`commit` は `ai`、プレビューの保存は `user`、自動でまとめた外部の変更は `external`。このキーを入れる前のまとまりは持たない） |
| `pending` | object | ✅ | まだまとめていない変更。`added`・`changed`（書き換えた順の項目の ID）と `removed`（削除した順の項目）。`removed` の要素は `id`・`kind`（種類）・`title`（削除したときのタイトル）・`seq`（削除したときに振った連番）・`added_seq`（削除した項目が持っていた `added_seq`。持たなければ 0）。`removed` は任意で、無ければ削除した項目なしとして扱う。最後のまとまりより後に追加して削除した項目は `added` から除き、`removed` に残す。`by`（任意。`ai` か `external`。無ければ `ai`）は入っている変更の書いた元 |
| `read_seq` | number | - | 前のバージョンで AI が最後に読んだ時点。今は常駐サーバーの状態のフォルダ（`~/.local/state/mindstella/workspaces/{ワークスペースの ID}/read_point.json`）に持ち、そのファイルが無いときだけこの値を読む |

## 前回開いた日時

`.mindstella-opened`。プレビューを最後に開いた時点を、1 行目に日時（UTC のタイムゾーン付き ISO 8601）、2 行目に連番で持つ。
連番は、開いた時点の `changes.yaml` の先頭のまとまりの `until_seq` で、まとまりが無ければ 0 になる。
プレビューのタブが開くたびにサーバーが書き換える。
変更履歴の「前回開いてから」の範囲は連番で決め、日時は範囲の始まりの表示にだけ使う。
日時だけを持つ前のバージョンの形式のときと、2 行目が数でない・負のときは、前回開いた時点なしとして読む。
開くたびに書き換わるため、ワークスペースを git などで管理するときは `.gitignore` に入れる。

## 保存待ちの編集

`edits.yaml`。プレビューで利用者が溜め、まだ保存していない項目と設定の編集。
最上位に `seq`（最後に振った編集の連番）・`new_seq`（最後に振った、追加する項目の仮の ID の連番）と `items:` の配列を持ち、1 要素が 1 件の編集になる。共通のキーは持たない。
どちらの連番も、振った番号を使い回さない。並びは連番の小さい順（溜めた順）。
書くのはサーバーの保存待ちの編集の受け付けだけで、project-index の配信の対象にしない。
1 件ずつの取り消しで物理的に消え、まとめて保存したときは全て消えて、項目・設定・[書き換えのまとまり](#書き換えのまとまり)へ移る。保存で空にしても、`seq`・`new_seq` は戻さない。
保存で書き込めなかった理由はここに書かず、保存の応答だけが返す。

<!-- table: {"kind": "data"} -->

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | `E-` + 連番。連番は `seq` + 1 |
| `target` | string | ✅ | 編集する項目の ID（どの種類でもよい）、追加する項目の仮の ID（`new-` + 連番。連番は `new_seq` + 1）、または設定（`settings`） |
| `op` | string | ✅ | 編集の種類。`set`（項目のキー 1 つか本文を書き換える）・`option-add`（案を 1 つ追加する）・`option-edit`（案 1 つの中身を書き換える）・`option-remove`（案を 1 つ削除する）・`adopt`（採用する案を切り替える）・`item-add`（項目を 1 つ追加する）・`item-remove`（項目を 1 つ削除する）・`setting`（設定のキー 1 つを書き換える）のどれか |
| `key` | string | - | `set` は項目のキー（本文は `body`）、`option-*`・`adopt` は案の記号、`item-add` は種類（`decisions` などの YAML のファイル名の頭）、`setting` は設定のキー。`item-remove` は持たない |
| `value` | any | - | 編集した後の値で、そのキーの型の値。`adopt` は採用する案の記号（採用を外すときは `null`）、`item-add` は追加する項目のキーと値のオブジェクト。`option-remove`・`item-remove` は `null` |
| `before` | any | - | 最初に溜めたときの元の値。保存待ちのパネルの「前 → 後」と、設定の編集で保存の前に書き換わったかの確かめに使う。`option-add`・`item-add` は `null` |
| `base` | string | - | 項目への編集（`item-add`・`setting` を除く）のとき、最初に溜めた時点のその項目の `updated`。保存のときに項目の `updated` と違えば、溜めた後に書き換わった編集として書き込まない |
| `created` | string | ✅ | 最初に溜めた日時（UTC のタイムゾーン付き ISO 8601）。同じ編集を書き換えても変えない |

<!-- /table -->

`target`・`op`・`key` が同じ編集は 1 件にまとまり、新しい値で `value` だけを書き換える。`id`・`before`・`base`・`created` は最初のままになる。
`item-add` は `target` が同じ編集を 1 件にまとめ、追加する項目のキーを変えるときは `value` を書き換える。
`set`・`option-edit`・`adopt`・`setting` で、`value` が今のワークスペースの値と同じに戻った編集は、外れる。

## 本文

ワークスペースの直下の `docs/{ID}.mark.md`。項目の本文の Markdown で、項目の `body`（`.mindstella/` からの `../docs/{ID}.mark.md`）から指される。
メタデータ（front matter）は持たず、項目の情報は YAML だけが持つ。
書き込みは project-index の `write_docs`（項目の `body` が指すファイル）が行い、ファイル名は項目の ID に揃える。

資料だけは、本文を HTML で持てる。
`docs/{ID}.html` に HTML の本文を書き、資料の `body` が `../docs/{ID}.html` を指す。
Markdown の `{ID}.mark.md` とは並べて持たず、形式を替えたときは前の形式のファイルを削除する。
サーバーは HTML の中身を解釈も実行もしない。画面はスクリプトを動かさない枠に描く。

## 埋め込むファイル

ワークスペースの直下の `files/` に動画・音声・画像などのファイルを置き、Markdown の本文から mdmark の `![キャプション](../files/{名前})` で埋め込む。
パスは本文（`docs/`）からの相対パスで書き、`files/` の下にフォルダを作ってもよい（`../files/video/clip.mp4`）。
拡張子が動画・音声のファイルは再生バーつきで、画像は画像として描かれ、キャプションが下に出る。

`files/` のファイルは記録ではなく、置く・差し替える・削除するときに項目の変更履歴と書き換えのまとまりに入らない。
mindstella はワークスペースの Git を操作しないため、ファイルを Git に残すかは利用者が決める。
本文が埋め込んだファイルが `files/` に無いときは、[ワークスペースを点検する](./コマンド.mark.md#ワークスペースを点検する)が参照切れとして返す。
HTML の本文（`docs/{ID}.html`）の `src` は、書いたまま描く。

# エージェントフロー

記録のエージェントフローの ID・契機・工程の一覧。
MindStella のセッションの AI は、場面ごとにエージェントフローを project-index の `search_docs` で ID を指して参照し、工程のとおりに記録を進める。
利用者がスラッシュコマンドで呼ぶものは無い。

## 一覧

| ID | 名前 | 進める契機 | 説明 |
| --- | --- | --- | --- |
| `mindstella/startup` | [起動と再開](#起動と再開) | MindStella のセッションを起動したとき、`/clear` の後、圧縮の後（SessionStart のフックが注入で案内する） | 注入された状況を確認し、まとめ忘れを commit し、進め方の文書を参照し、取り込み待ちのコメントを取り込んでから、進め方の工程へ進む |
| `mindstella/on-comment` | [コメントの取り込み](#コメントの取り込み) | 「[mindstella] ユーザーからのコメントが N 件」の入力を受けたとき | 保留のタスクを見直し、取り込み待ちのスレッドを 1 件ずつ参照し、記録に反映して commit し、返信するかクローズにして、最後にその回の報告を 1 件の報告のスレッドにまとめ、手番を返す直前に手番を返す commit をする |
| `mindstella/record` | [記録の使い分け](#記録の使い分け) | 利用者の発言・コメントを記録するとき | 発言を内容ごとに振り分け、話題のタグを付けて記録に書き込み、手番を返す直前に手番を返す commit をする |

エージェントフローは、project-index の配信元 `mindstella-agent-flows` として配る。
配信元の行は、常駐サーバーがワークスペースを作るときに project-index の端末の設定へ追加する。
MindStella のセッションの外の Claude Code からは、`search_docs` に `outside_scope: true` を付けて参照する。

```
search_docs(source: "mindstella-agent-flows", filter: {field: "id", op: "eq", values: ["mindstella/startup"]}, view: "full")
```

エージェントフローは工程ごとの進み具合を持たない。
圧縮・クリアの後は、記録と commit から続きを戻す。

## 起動と再開

| 工程 | すること |
| --- | --- |
| 状況を確認する | SessionStart のフックが注入した、取り込み待ちのスレッドの件数・前回参照した後に変わった項目・要見直しの検討事項・進行中のタスクを確認する。注入に収まらなかった変更があるときだけ、`changes_since_read` で残りを取得する |
| まだまとめていない変更を取得する | `pending` でまとめていない変更を読む |
| まとめ忘れを commit する | まとめていない変更があれば、前の話し合いでまとめ忘れた分として説明を付けて `commit` する（作業の途中の `commit` で、`hand_back` は渡さない） |
| 進め方の文書を参照する | 起動のコマンドの `--flow` で渡した進め方の文書があれば、project-index で参照する |
| 保留のタスクを見直す | 取り込み待ちのスレッドが 0 件のときだけ、[コメントの取り込み](#コメントの取り込み)の「保留のタスクを見直す」のとおりに見直す |
| 取り込み待ちのコメントを取り込む | 取り込み待ちのスレッドがあれば、[コメントの取り込み](#コメントの取り込み)を進める |
| 進め方の工程へ進む | 進め方の文書の工程へ進む |

ワークスペースのバージョンが古ければ、常駐サーバーがワークスペースを開くときに移し替える（[ワークスペースを今のバージョンへ移し替える](./セットアップ手順-ワークスペースを今のバージョンへ移し替える.mark.md)）。

## コメントの取り込み

利用者の回答が要ることは、[記録の使い分け](#記録の使い分け)の「利用者に聞くことを方針と細部に分ける」で分ける。
回の最後に、会話ログのほかに記録を追加・変更したときは、その回の報告を新規の報告のスレッド 1 件に表で書き、前の回の報告のスレッドをクローズにする。
スレッドの書き込みでは、利用者に回答を求めない。

| 工程 | すること |
| --- | --- |
| 保留のタスクを見直す | `search_docs` で状態が保留のタスクを全て検索し、着手できる条件を満たしたものを進行中にしてすぐに着手する |
| 取り込み待ちのスレッドを取得する | `threads` を `awaiting: true` で呼ぶ |
| コメントを参照する | スレッドごとに `thread` で書き込みと箇所を読む |
| 記録に反映する | [記録の使い分け](#記録の使い分け)のとおり記録に書き込む |
| 進め方の続きを進める | コメントで進め方の工程が進んだら、続きを進める |
| 書き換えをまとめる | 書き換えを一言の説明にして `commit` する（返信へ差分のリンクを入れるための作業の途中の `commit` で、`hand_back` は渡さない） |
| クローズのスレッドを再度開く | 返信が要るクローズのスレッドは、`set_thread_status` で理由つきでオープンに戻す |
| 返信する | `reply` で返信し、要約の書き直しと取り込み済みを 1 回で行う |
| 取り込み済みにする | 返信しないスレッドは、`update_thread` で取り込み済みにする |
| 往復が 5 回を超えたスレッドを分ける | 往復が 5 回を超えたスレッドは、新規スレッドに分ける |
| クローズにする | 話が済んだスレッドを、`set_thread_status` で回答の場所を書いた理由つきでクローズにする。クローズにする前に、AI の書き込みの約束がタスクにあることを確かめる |
| 報告のスレッドで報告する | 追加した検討事項と、AI が決めた細部と、反映した回答と、追加・着手したタスクを、`new_thread` で新規の報告のスレッド 1 件に表で書き、前の回の報告のスレッドをクローズにする |
| オープンのスレッドを取得する | 残っているオープンのスレッドの取得 |
| 話が済んだスレッドをクローズにする | 話が済んでいるスレッドをクローズにする |
| 手番を返す | [記録の使い分け](#記録の使い分け)の「手番を返す」のとおり、`hand_back: true` で `commit` する |

## 記録の使い分け

記録の検索と書き込みは project-index の MCP（`search_docs`・`write_docs`・`delete_docs`・`trace_related`）で行い、`source` はワークスペースの ID にする。

| 工程 | すること |
| --- | --- |
| 発言を振り分ける | 発言を、検討事項・タスク・調査・資料・用語集・メモ・会話ログのどれに書くかを振り分ける。後でやる作業はその回のうちにタスクにし、着手できるものは進行中、着手できない条件があるものは保留にする |
| 利用者に聞くことを方針と細部に分ける | 利用者の回答が要ることは全て検討事項に挙げ、スレッドで聞かない。方針（構成・責務・利用者の体験・費用・元に戻せないもの）は AI の理解と案と推奨を持つ未決定の検討事項にする。細部（後から変えられるもの）は AI が決めて決定済みで記録し、報告のスレッドで報告する |
| 覚えておく決まりの配置場所を判定する | 利用者が覚えておいてほしいと言った決まりを、どこに書くかを判定する |
| 話題のタグを付ける | 使われているタグを `search_docs` の `group_by: tags` で引き、話題のタグを付ける。絞り込みはタグで行う |
| 既存の記録にもタグを付ける | 新しく付けたタグの語が当たる既存の記録にも、同じタグを付ける |
| 絞り込みのプリセットを作る・見直す | 新しいタグを付けた・タグを付けた項目が増えたとき、利用者に頼まれなくても、開いて話し合いそうなタグの組み合わせを `create_preset` でプリセットにし、ずれた・0 件になったプリセットを `update_preset`・`delete_preset` で直す |
| 呼び名と概要を記載する | 資料・調査に、別名を `aliases`、何について書いてあるかを `description` に書く |
| 作業から検討事項を指す | タスクから、元の検討事項を `related` で指す |
| 検討事項に案を記載する | 1 件の検討事項では 1 つの質問だけを聞き、決める内容が複数あるときは内容ごとに検討事項を分ける。検討事項に案を書き、未決定なら AI が推す案に推奨のマーカーを付ける |
| 資料の確認を依頼する | 資料 1 件ごとに確認中にし、「この資料で完成でよいか」の未決定の検討事項に新規決定事項の表を書いて資料を指す |
| 保留・取り下げにする | 利用者が後回しにする・やめると言った項目は、削除せずに保留か取り下げにする。回答待ちの検討事項は保留にしない |
| 誤って追加した項目を削除する | 誤って追加した・重複した項目だけを `delete_docs` で削除する |
| ID を採番する | 追加する項目の ID を `next_id` で取る |
| 記録を書き込む | 1 つの発言から出た記録を `write_docs` で 1 回に書く。図や mdmark の記法を持つ資料は、書き込む前に描いたときの警告が無いことを確かめる |
| 手番を返す | 応答を終えて利用者に手番を返す直前に、その間の修正と返信をまとめて `commit` を `hand_back: true` で 1 回だけ呼ぶ。返信だけの応答でも呼ぶ。サブエージェント・バックグラウンドの処理を待つ前と作業の途中の `commit` では `hand_back` を渡さない |

文章と HTML の書き方は、エージェントフローに持たず、knowledge の規約を参照する。

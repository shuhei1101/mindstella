# プレビューを外から見る

プレビューを、トンネル・リバースプロキシを通して端末の外から開くときに実行する。

## 前提

- [起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md)
- [プレビューを見る](./プレビューを見る.mark.md)で、端末のブラウザでプレビューを開ける
- 外のホスト名への要求を、端末の `127.0.0.1` の常駐サーバーのポート（`MINDSTELLA_PORT`。無ければ 8784）へ渡す外の入口（トンネル・リバースプロキシ）を用意している

常駐サーバーは全てのワークスペースの画面を、`127.0.0.1` の 1 つのポートの `/w/{ワークスペースの ID}/` の下で配る。
待ち受けは `127.0.0.1` だけのまま変わらず、配信は認証を持たない。
外から開く画面の認証は、外の入口で付ける。

## 手順

使い方を次の 3 つから 1 つ選ぶ。

### ローカルだけで参照する

何も設定しない。
[プレビューを見る](./プレビューを見る.mark.md)のとおり、示された `127.0.0.1` の URL を端末のブラウザで開く。

### 固定の URL で参照する

外の入口に常駐サーバーのポートを 1 回だけ登録し、全てのワークスペースを同じホスト名で開くときの手順。

#### 許可するホスト名を指定する

外の入口のホスト名を、環境変数 `MINDSTELLA_ALLOWED_HOSTS` に設定する。
外から見る設定の環境変数は、常駐サーバーを起動する環境から読む。
[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)で、`MINDSTELLA_ALLOWED_HOSTS` に `preview.example.com` のようなホスト名を回答して登録する。

ホスト名だけをカンマで区切って並べ、大文字と小文字は区別しない。
スキーム・ポート・`/` を含む要素と空の要素は使われず、常駐サーバーが立つときに標準エラーへ記録される。
画面の経路（`/w/` の下）は、`Host` がこのホスト名の要求と、`Origin` がこのホスト名の `https://` か `http://` の要求も受ける。
ポートを外したホスト名で比べるので、外の入口のポートは問わない。
指定していないホスト名は、`Host` を 403 で返し、`Origin` を断る。
許可するホスト名から受けるのは画面の閲覧とコメントの送信と、画面の MindStella のセッションの状態の取得と再起動だけで、MindStella の API（ワークスペースと MindStella のセッションの作成・停止・クローズ）と `/mcp` は `127.0.0.1`・`localhost` の `Host` からだけ受ける。

#### 公開 URL の基底を指定する

外の入口の URL を、ホームの設定 `${XDG_CONFIG_HOME:-~/.config}/mindstella/settings.yaml` の `preview.public_url` に記載する。

```yaml
preview:
  public_url: https://preview.example.com
```

`http://` か `https://` で始まり、パスを持たない URL にする（末尾の `/` は無視する）。違う値だと、常駐サーバーが起動するときに誤りを出して止まる。
記載すると、MindStella のセッションが示すプレビューの URL、作業の完了の通知・止まったことの通知の末尾の URL、ワークスペースの作成と状態の取得の `url` が、`{preview.public_url}/w/{ワークスペースの ID}/` になる。
`preview.public_url` のホスト名は、`MINDSTELLA_ALLOWED_HOSTS` に重ねて記載しなくても受ける。
記載しなければ、URL は `127.0.0.1` のままになる。

#### 外部のエンドポイントにポートを登録する

外のホスト名の要求を `http://127.0.0.1:8784`（常駐サーバーのポート）へ渡すよう、外の入口に 1 回だけ登録する。
Cloudflare Tunnel の登録は[外部のエンドポイントの例](#外部のエンドポイントの例)。

#### 再起動する

登録した後に開いた新しいシェルで、[起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md)を実行する。
常駐サーバーが既に待ち受けていると、新しい値は効かない。
新しいシェルで `mindstella server restart`（[常駐サーバーを起動する](./セットアップ手順-常駐サーバーを起動する.md)）を叩くと、その環境の値でユニットを書き直して再起動する。

### 配り始めるたびに登録し、やめるたびに削除する

外の入口へワークスペースの画面ごとに登録し、配るのをやめるたびに削除したいときの手順。

#### 許可するホスト名を指定する

[固定の URL で参照する](#許可するホスト名を指定する)と同じ。
外の入口が割り当てうるホスト名を全て並べる。

#### 登録と削除のコマンドを指定する

登録のコマンドを `MINDSTELLA_PREVIEW_START_HOOK`、削除のコマンドを `MINDSTELLA_PREVIEW_STOP_HOOK` に設定する。
[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)で、登録のコマンド（例 `my-gateway add`）と削除のコマンド（例 `my-gateway rm`）を回答して登録する。

どちらも、コマンドの末尾に常駐サーバーのポート・ワークスペースのフォルダの名前・画面のパスを追加して呼ぶ（`my-gateway add 8784 家計簿 /w/{ワークスペースの ID}/`）。
コマンドはシェルを通さずに、シェルの書き方で分けて呼ぶ。

- 起動時のフックは、ワークスペースを配り始めた直後に呼ぶ（常駐サーバーの起動時・ワークスペースの作成時・登録していないフォルダでプレビューを頼んだとき）。既に配っているワークスペースでプレビューを頼んだときは呼ばない
- 終了時のフックは、常駐サーバーを止めるときに配っているワークスペースごとに 1 回、ワークスペースを削除したときにそのワークスペースについて 1 回、配っているワークスペースのフォルダを移して開き直したときに移す前のフォルダについて 1 回呼ぶ。Claude Code を閉じても配信は止まらず、呼ばない
- どちらも終わりを待たない。コマンドが見つからないなど呼べないときは、標準エラーに記録し、配信の起動と終了は止まらない

#### 再起動する

[固定の URL で参照する](#再起動する)と同じ。

### 外部のエンドポイントの例

Cloudflare Tunnel で固定の URL を作る例。
認証は Cloudflare Access などで付ける。

`~/.cloudflared/config.yml` に、ホスト名と渡し先を書く。

```yaml
tunnel: {トンネルの ID}
credentials-file: ~/.cloudflared/{トンネルの ID}.json
ingress:
  - hostname: preview.example.com
    service: http://127.0.0.1:8784
  - service: http_status:404
```

ホスト名をトンネルへ向け、トンネルを動かす。

```bash
cloudflared tunnel route dns {トンネルの名前} preview.example.com
cloudflared tunnel run {トンネルの名前}
```

## 反映

`再起動`（新しいシェルで `mindstella server restart`。[常駐サーバーを起動する](./セットアップ手順-常駐サーバーを起動する.md)）。

## 確認

#### 配信が許可したホスト名を受ける

MindStella のセッションにプレビューを頼み、示された URL へ、許可したホスト名を `Host` に付けてつなぐ。

```bash
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: preview.example.com' http://127.0.0.1:8784/w/{ワークスペースの ID}/
```

`200` と出る。
許可していないホスト名を `Host` に付けると `403` と出る。

#### 外部のホスト名で開ける

端末の外のブラウザで `https://preview.example.com/w/{ワークスペースの ID}/` を開く。
概要が出て、コメントを送信できる。

#### 示される URL が公開 URL になる

`preview.public_url` を記載したときだけ。
MindStella のセッションにプレビューを頼むと、`https://preview.example.com/w/{ワークスペースの ID}/` が示される。

#### フックが呼ばれる

配り始めるたびに登録するときだけ。
登録のコマンドが外の入口へ登録するものなら、ワークスペースを配り始めるとその登録にそのワークスペースの画面のパスの行があり、常駐サーバーを止めるとその行が無くなる。

## 元に戻す

[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)で環境変数を外し、常駐サーバーを止めて起動スクリプトで再起動する。

戻した後に残るものは、次のとおり。

| 残るもの | 扱い |
| --- | --- |
| 外の入口の登録 | 外の入口の側で削除する。削除のフックを設定していた場合は、常駐サーバーを止めたときに消えている |

# 続きを再開する

途中まで進んだ話し合いを再開するとき、起動のコマンドで MindStella のセッションを立ち上げ、起動と再開のエージェントフローで続きから進める。

## 前提

- [プラグインをインストールする](./セットアップ手順-プラグインをインストールする.md)
- [セットアップから始める](./話し合い-セットアップから始める.md)で作った、`.mindstella/config.yaml` があるワークスペース
- tmux が入っている

## 手順

### 起動スクリプトで立ち上げる

ワークスペースのフォルダを渡して、起動スクリプトを叩く。

```bash
{プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ}
```

[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)と、新しいシェルで alias から立ち上げられる。

```bash
mindstella {ワークスペースのフォルダ}
```

残っている記録を開き、同じワークスペースの MindStella のセッションが既にあれば、新しく作らずにそのペインへつながる。止めた後・落ちた後なら、MindStella のセッションを作り、前の会話の記録が残っていればその会話を引き継いで起動する。記録が参照できなければ、新規の会話で起動する。
このコマンドと、立ち上げ済みのセッションへつなぎ直す接続のコマンドは、フォルダの直下の `README.md` に、そのまま叩ける形で書かれている。
手順は [起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md)。

MindStella のセッションが利用上限に達したとき・使用中のアカウントの利用枠がしきい値以上になったとき・会話を圧縮しようとしたとき・落ちた後にプレビューからコメントを送ったときは、常駐サーバーが自動で起動し直す（[MindStella のセッションを起動し直す](./コマンド.mark.md#mindstella-のセッションを起動し直す)）。
利用上限では、利用上限に達していないアカウントで前の会話を引き継ぐ。しきい値では、応答の終わりを待ってから、しきい値以上でないアカウントで前の会話を引き継ぐ。アカウントを指定して起動したときは、利用上限・しきい値のときだけ指定を解除して別のアカウントに切り替わる。圧縮では、新規の会話で起動し、記録と commit から作業に戻る。

ワークスペースの版が古ければ、常駐サーバーがワークスペースを開くときに今の版へ移し替える（[ワークスペースを今の版へ移し替える](./セットアップ手順-ワークスペースを今の版へ移し替える.mark.md)）。

### 状況を受け取る

MindStella のセッションが起動すると、SessionStart のフックが次の状況を注入する。
`/clear` の後と圧縮の後も、同じ状況が注入される。

| 状況 | 中身 |
| --- | --- |
| 取り込み待ち | 取り込んでいない利用者の書き込みを持つスレッドの件数 |
| 前回参照した後の変更 | 前回参照した後に足された・変わった・消された項目の ID と要約 |
| 要見直し | 方針転換で見直しが要る検討事項 |
| 進行中 | 進めているタスク |
| 移し替えの報告 | 移し替えで仮に入れた値と、移せなかった値（移し替えた後の最初の注入だけ） |
| 進め方の文書 | 設定の `flow` の場所 |

注入に収まらない変更があるときは、MindStella のセッションが `changes_since_read` で残りと前の値を取得する。
状況を受け取った後の工程は [起動と再開](./エージェントフロー.md#起動と再開)。

### 話し合いへ進む

MindStella のセッションは、起動と再開のエージェントフロー `mindstella/startup` を進める（[エージェントフロー](./エージェントフロー.md#起動と再開)）。
前の話し合いでまとめ忘れた変更を commit し、取り込み待ちのコメントを取り込んでから、進め方の文書の工程へ進む。

新しい会話では、スレッドの書き込みが全て AI の未読に戻っている。
MindStella のセッションは、取り込み待ちのほかに、オープンのスレッドの AI の未読を読み直して、話の続きを掴む。
過去の経緯が要るときだけ、クローズのスレッドも読む。

既存の項目の ID は変わらず、続きの番号で項目が足される。

### 途中で題名・説明を変える

題名・話し合いの説明を変えたいときは、MindStella のセッションに伝えるか、プレビューの設定の画面で書き換える。
書き換えの内容は変更履歴に残り、項目の ID は変わらない。

# 話し合いの進め方

進め方は導入する側の文書が持ち、MindStella のセッションはエージェントフローで記録を進める仕組み。
記録を置くフォルダは [ワークスペース](./コアコンセプト-ワークスペース.md)。

## 進め方の文書とエージェントフロー

| 持つもの | 持つ場所 | 中身 |
| --- | --- | --- |
| 進め方の文書 | 導入する側の project-index の配信元。起動のコマンドの `--flow {配信元の ID}#{文書の ID}` で渡し、ワークスペースの設定の `flow` に残る | 何をどの順に話し合うか・何を作るか |
| エージェントフロー | プラグインが同梱する配信元 `mindstella-agent-flows` | 起動と再開・コメントの取り込み・記録の使い分けの工程（[エージェントフロー](./エージェントフロー.md)） |

進め方の文書が無いワークスペースでは、利用者の発言に沿って記録を進める。

## 記録の分け方

記録は種類（検討事項・タスク・調査・資料・用語集・メモ・会話ログ）ごとに分け、話題はタグ（`tags`）で表す。
画面と検索の絞り込みはタグで行う。
細かいものは派生（`parent`）・依存（`depends_on`）・関連（`related`）で表す。

## 聞き方と調べ方

- 事実は自分で調べ、決めることだけを聞く
- 利用者の回答が要ること（質問・確認・未決定の点・AI の解釈の確認・ワークスペースの外へ書き込む前の合意）は、スレッドで尋ねずに検討事項に挙げ、案と推奨を書く。利用者は画面で検討事項に回答する
- コメントを取り込んだ回の最後に、追加した検討事項と反映した回答を、新しいスレッド 1 件に表で通知する
- 利用者は Claude Code のターミナルを見ない前提で、知らせはターミナルに書かず、プレビューのスレッドで出す
- 脱線した質問は、言葉の意味なら用語集、それ以外ならメモに残し、タスクにはしない
- 外部ライブラリ・外部 API を決めるときは、ベストプラクティスと候補の調査を必ず積む

## 記録の育て方

- 記録（検討事項・タスク・調査・資料・用語集・メモ・会話ログ）は、状況が変わるたびに利用者に確かめずに追加し、書き換える。確かめるのは、ワークスペースの外へ書き込むときだけ
- 検討事項は、`未整理` を除いて追加する段階で案を書き、AI が推す案に推奨のマーカーを付けて追加する。画面で案と推奨を見比べてから回答できる
- 質問の形式にならない未整理は、案を書けるようになった段階で書く
- 案を採用すると、検討事項は決定済みになる
- AI がやる作業も利用者に頼む作業も、話し合いの中で出た時点でタスクとして積む
- 一般的でない言葉（システムの名前・業務や製品の固有の言葉・話し合いで決めた呼び名）は、指定しなくても用語集に追加する。一般的な技術の言葉は、指定したときだけ追加する
- 作業・検証のタスクで作った成果は、1 件ずつ資料にしてタスクから指す。調査は一次情報をまとめた記録で、資料は調査を踏まえて今の話し合いで使える形式にしたもの
- 調査の観点と確かさは、調査の本文に書く

## 方針を変えたとき

採用する案を切り替えると、その検討事項は決定済みになり、その検討事項に依存する決定済みの項目が、採用した案を持ったまま要見直しになる。
切り替えた検討事項の本文は今の正だけを書き、古い方針を残さない。

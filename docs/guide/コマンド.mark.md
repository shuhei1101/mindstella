# コマンド

MCP のツールと起動スクリプトの引数・出力・結果。
ツールは mindstella の常駐サーバーのもので、Claude Code からは `mcp__plugin_mindstella_mindstella__{ツール}` として呼ぶ。
常駐サーバーは `127.0.0.1` の `MINDSTELLA_PORT`（無ければ 8784）で Streamable HTTP の `/mcp` を待ち受け、並行する複数の Claude Code のセッションが共有する。
Claude Code はプラグインの接続の設定からつなぐので、起動スクリプトを通さずに立ち上げた Claude Code にも、常駐サーバーが待ち受けていれば載る。
サーバーの仕様は [インターフェース定義](https://github.com/shuhei1101/mindstella/blob/develop/docs/interface/README.md) にある。
記録（種類ごとの YAML の項目と `docs/` の本文）の検索・書き込み・削除・関連のたどりは、mindstella のツールではなく project-index の MCP のツール（`search_docs`・`write_docs`・`delete_docs`・`trace_related`）で、`source` にワークスペースの ID を渡して行う。ワークスペースの記録は、作成と移し替えで置く `.mindstella/dev-docs.yaml` で project-index の配信元として配られる。
どのセッションが記録を書き込んでも、常駐サーバーが書き換えを見つけて変更履歴に残す（[ワークスペースの書式](./ワークスペースの書式.mark.md#書き換えのまとまり)）。

- 引数は JSON のオブジェクトで渡す。`create_workspace`・`create_session`・`sessions`・`stop_session`・`restart_session`・`close_workspace`・`reopen_workspace`・`delete_workspace`・`update_workspace`・`server_status`・`server_stop` 以外のどのツールも `workspace`（`.mindstella/config.yaml` があるフォルダのパス）を渡す。記録のファイルは全て `.mindstella/` の下で引き、フォルダの直下には `README.md` のほかは書かない。`.mindstella/config.yaml` が無く、直下に `config.yaml` か `mindmap.yaml`（前のバージョンの設定ファイル）があるフォルダは、どのツールも、起動スクリプトで再度開いて移し替えるよう案内するエラーを返す。相対パスは、ツールを呼んだ Claude Code のセッションの作業フォルダから読む。セッションの作業フォルダは、プラグインの PreToolUse のフックが引数 `session` に入れる。`session` が無いときの相対パスは引数の誤りになる
- 結果は JSON のオブジェクトを 1 個（UTF-8、日本語はエスケープしない）。構造化の結果と、同じ JSON の文字列の本文で返る
- エラーは `isError` が真の結果で、本文に `エラー: {内容}` の行で出す。スキーマに合わないときは、続けて合わない箇所ごとに `{ファイル名}: {キーのパス}: {理由}` の行を出す（キーのパスは `items[0].status` の形式）。要る引数が無い・型が違うときは、ツールを呼ぶ前に MCP の SDK が弾き、本文は SDK の文言になる
- `adopt`・`edit_option` は、合わない箇所に前のバージョンの形式（資料の `done`・設定の `summary` が無い・設定の `field`・削除したキー・対象の項目以外の案と状態の合わない検討事項・対象の項目以外の文字列のタグ）があるとき、最後に、起動スクリプトでワークスペースを再度開くと今の形式に移ることを案内する `ヒント:` の行を続ける（[ワークスペースを今のバージョンへ移し替える](./セットアップ手順-ワークスペースを今のバージョンへ移し替える.mark.md)）
- 書き込むツール（`update_settings`・`adopt`・`edit_option`）は、書き込む前にワークスペースの全ての YAML をスキーマと、検討事項の案と状態の決まり（[ワークスペースの書式](./ワークスペースの書式.mark.md#検討事項)）と突き合わせ、合わなければ何も書き換えない
- `commit` とスレッドの書き込み（`new_thread`・`reply`・`set_thread_status`・`update_thread`）は、そのワークスペースの MindStella のセッションからの呼び出しだけを受け付ける。ほかのセッションから呼ぶと `エラー: MindStella のセッションだけが呼べます: {ツール}` を返し、何も書かない
- ワークスペースを書き換えるツールと、スレッドの書き換え・コメントのまとめて送信する受け付け・レビュー中のコメント・下書きの受け付けは、ワークスペースの `.mindstella/.mindstella.lock` に排他ロックを取ってから読み・書く。同じワークスペースを開く別のプロセスとも排他し、ロックは取れるまで待つ。読むだけのツールと配信はロックを取らない

## 起動スクリプトで立ち上げる

依存を確かめ、mindstella の常駐サーバーが落ちていれば起動してから（[常駐サーバーを確認する](#常駐サーバーを確認する)）、常駐サーバーの [ワークスペースを作る](#ワークスペースを作る)と [MindStella のセッションを作る](#mindstella-のセッションを作る)を呼び、そのペインへつなぐ。
ワークスペースの記録と状態は常駐サーバーが書き、起動スクリプトは書かない。
MindStella のセッションの Claude Code には、インストールした今のバージョンの `skills/mindmap/references/起動時の指示.md` の中身を `--append-system-prompt` で渡す。利用者がターミナルを見ない前提で、質問と知らせを検討事項・資料・スレッドで出す決まりが、クリア・コンパクトの後も効く。

### 使い方

```bash
{プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ} [--flow {配信元の ID}#{文書の ID}] [--mcp-config {ファイル}] [--plugin-dir {フォルダ}]...
{プラグインのフォルダ}/bin/mindstella server {status|stop|restart}
```

`{プラグインのフォルダ}` は、`claude plugin list --json` の `mindstella@mindstella` の `installPath`。
叩いたスクリプトのバージョンではなく、`installPath` が指すインストールした今のバージョンの常駐サーバーを起動する。既に古いコードの常駐サーバーが待ち受けていれば、再起動せずに違いと手順を標準エラーに出し、ワークスペースと MindStella のセッションは作る。
[起動スクリプトを登録する](#起動スクリプトを登録する)と、新しいシェルで登録した alias から叩ける。

```bash
mindstella {ワークスペースのフォルダ}
mindstella-{アカウントの名前} {ワークスペースのフォルダ}
```

`mindstella` は叩くたびに今の `installPath` を引き、引数をそのまま起動スクリプトに渡す。
`mindstella-{アカウントの名前}` は、`installPath` を引く `claude plugin list --json` と起動スクリプトの両方に、登録したそのアカウントの設定のフォルダを `CLAUDE_CONFIG_DIR` で渡す（シェルの `CLAUDE_CONFIG_DIR` は変えない）。

| `MINDSTELLA_PREVIEW_STOP_HOOK` | 任意 | 環境変数。ワークスペースを配るのをやめるときに呼ぶコマンド。常駐サーバーを止めるときは配っているワークスペースごとに 1 回、ワークスペースを削除したときはそのワークスペースについて 1 回呼ぶ。呼び方は `MINDSTELLA_PREVIEW_START_HOOK` と同じ | `my-gateway rm` |
| `MINDSTELLA_TRANSCRIBER` | 任意 | 環境変数。コメント・返信の入力の音声入力が使う文字起こしのサービス。今は `voice-paste` だけ。省略すると `voice-paste`。ほかの値だと常駐サーバーは待ち受けずに終わる | `voice-paste` |
| `MINDSTELLA_TRANSCRIBER_URL` | 任意 | 環境変数。文字起こしのサービスの待ち受けの URL。`http://127.0.0.1:{ポート}` か `http://localhost:{ポート}` だけ受け、ほかの値だと常駐サーバーは待ち受けずに終わる。省略すると `http://127.0.0.1:47823` | `http://127.0.0.1:47900` |
| `MINDSTELLA_DISCORD_WEBHOOK_FILE` | 任意 | 環境変数。作業の完了と停止を通知する Discord の Webhook の URL を 1 行目に記載したファイルの絶対パス。省略すると通知しない。ファイルは送信のたびに参照する（[Discord に通知する](./セットアップ手順-Discordに通知する.md)） | `/home/me/.config/web-hook/mindstella.ini` |
| `PROJECT_INDEX_PORT` | 任意 | 環境変数。常駐サーバーが呼ぶ project-index のポート。省略すると `8786` | - |

<!-- /table -->

`MINDSTELLA_` で始まる環境変数と `PATH`・`TMUX_TMPDIR`・`PROJECT_INDEX_PORT`・`XDG_STATE_HOME` は、常駐サーバーを起動するときにユニットの `Environment=` に書いて渡し、Claude Code の環境には追加しない。
常駐サーバーが既に待ち受けていると、新しい値は効かない。`mindstella server restart` で再起動すると効く。
環境変数は、[起動スクリプトを登録する](#起動スクリプトを登録する)で登録すると、新しいシェルに入る。
使い方は[プレビューを外から見る](./セットアップ手順-プレビューを外から見る.md)。

#### ホームの設定

常駐サーバーは起動時に `${XDG_CONFIG_HOME:-~/.config}/mindstella/settings.yaml` を 1 回だけ読む。ファイルは利用者が作り、無ければ全てのキーを既定値で扱う。

```yaml
claude_balancer:
  url: http://127.0.0.1:8770   # claude-balancer の常駐の待ち受け先
account:
  release_on_limit: true       # 指定したアカウントを利用上限・しきい値で解除するか
```

| キー | 既定値 | 説明 |
| --- | --- | --- |
| `claude_balancer.url` | `http://127.0.0.1:8770` | 利用枠を確かめる claude-balancer の常駐の待ち受け先。書いたときは、MindStella のセッションの `claude-balancer exec` にも `CLAUDE_BALANCER_URL` で渡す。`http://` か `https://` で始める |
| `account.release_on_limit` | `true` | 指定したアカウントが利用上限・しきい値以上・借りられないときに、指定を解除して別のアカウントで再起動するか |

YAML として読めないとき・値が誤っているときは、常駐サーバーは待ち受けずに終わる。知らないキーは標準エラーへ記録して読み飛ばす。
書き換えたら `mindstella server restart` で再起動すると効く。

### 出力

| 出力 | 説明 |
| --- | --- |
| MindStella のセッション | tmux のセッションの名前はワークスペースの ID（`mindstella-{フォルダ名}-{ハッシュ}`）。同じワークスペースの MindStella のセッションが既に動いていれば、新しく立てずにそのペインへつなぎ、標準エラーに既にあった旨を出す |
| 標準出力 | 画面の URL を出す。標準出力が端末なら、続けてそのペインへつなぐ（tmux の外からは `tmux attach-session`、tmux の中からは `tmux switch-client`）。端末でなければ、つながずに、つなぐコマンドを出して終わる。`server status` は常駐サーバーのポート・バージョン・プラグインのフォルダ・配信 |
| 標準エラー | `[mindstella]` で始まる行で、使うプラグインのフォルダ・ワークスペースの ID・MindStella のセッションの ID と、MindStella のセッションを作ったときは `[mindstella] 起動したアカウント: {設定のフォルダの絶対パス}` を出す。エラーは `[mindstella] エラー: {内容}` の行で、そろえるコマンドがあれば次の行に出す |

### 終了コード

確かめる順は、引数 → 依存 → `tmux` → `claude` → プラグインのフォルダ → 常駐サーバー → ワークスペースの作成 → MindStella のセッションの作成。どれかで止まったら、それより後は何もしない。

| コード | 意味 |
| --- | --- |
| `0` | MindStella のセッションを作った（または既にあるものにつないだ） |
| `1` | 依存が足りない（足りないものと、そろえるコマンドを標準エラーに出す。そろえるコマンドが無ければ 3.12 以上の Python を入れるよう出す）・`tmux` が `PATH` に無い・`claude` が `PATH` に無い・`claude plugin list --json` に `mindstella@mindstella` が無い（プラグインのインストールの手順を案内する）・常駐サーバーを起動できない（[常駐サーバーを確認する](#常駐サーバーを確認する)の標準エラーをそのまま出す）・ワークスペースを作れない（応答の `detail` を出す）・MindStella のセッションを作れない（応答の `detail` と画面の URL を出す） |
| `2` | 引数の誤り（ワークスペースのフォルダを渡さない・知らない引数・`server` のサブコマンドが違う）。使い方を標準エラーに出す |

## 常駐サーバーを確認する

`127.0.0.1` の `MINDSTELLA_PORT` で mindstella の常駐サーバーが同じコードで待ち受けているかを確かめ、落ちていれば systemd --user のユニット `mindstella.service` を書いて起動する。
プラグインの SessionStart のフックが会話を始めるたびに `--hook` を付けて呼び、起動スクリプトがワークスペースを作る前に `--hook` を付けずに呼ぶ。
mindstella のツールが Claude Code に無いときは、利用者が端末で叩く。
システムの `python3` の標準ライブラリだけで動く。ワークスペースは書かない。

起動した常駐サーバーは、待ち受けを始める前に、状態のフォルダにワークスペースの ID の一覧（`workspaces.yaml`）が無ければ project-index の配信元の行から再作成し、起動中の MindStella のセッションのうちペインか Claude Code のプロセスが無いものを落ちたと記録して通知する。
待ち受けを始めた後に、エージェントフローの配信元 `mindstella-agent-flows` の行が前のプラグインのフォルダを指していれば、今のプラグインのフォルダへ書き換える。
どれに失敗しても待ち受けを始め、失敗を `~/.mindmap/server.log` に記録する。

### 使い方

```bash
python3 {プラグインのフォルダ}/skills/mindmap/scripts/ensure_server.py [--hook | --restart]
```

起動したときは、Claude Code の `/mcp` で mindstella に再接続する。

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--hook` | 任意 | SessionStart のフックからの呼び出し。標準入力のフックの入力を読み捨て、案内を標準出力に出し、どの結末も終了コード 0 で終わる。省略すると、案内を標準エラーに出し、失敗は終了コード 1 | - |
| `--restart` | 任意 | 待ち受けていても、このスクリプトのプラグインのフォルダでユニットを書き直して再起動する（`mindstella server restart` が呼ぶ） | - |
| `MINDSTELLA_PORT` | 任意 | 環境変数。確かめるポートと、起動する常駐サーバーへ渡すポート。省略すると `8784` | `8790` |
| `MINDSTELLA_VENV` | 任意 | 環境変数。常駐サーバーを動かす仮想環境のフォルダ。省略すると `~/.mindmap/venv` | - |

`MINDSTELLA_` で始まる環境変数と `PATH`・`TMUX_TMPDIR`・`PROJECT_INDEX_PORT`・`XDG_STATE_HOME` は、ユニットの `Environment=` に書いて常駐サーバーへ渡す。

### 出力

| 出力 | 説明 |
| --- | --- |
| 常駐サーバー | `GET http://127.0.0.1:{MINDSTELLA_PORT}/_admin/status` につながらなければ、`{XDG_CONFIG_HOME か ~/.config}/systemd/user/mindstella.service` を書いて `systemctl --user daemon-reload` と `start` を呼び、待ち受けるまで最大 10 秒待つ。ユニットは仮想環境の Python でこのプラグインのフォルダの `server.py` を動かし、標準出力と標準エラーを `~/.mindmap/server.log` に追記し、落ちたら 5 秒後に再起動する（60 秒に 3 回まで） |
| 案内 | 起動した・古いコードの常駐サーバーが待ち受けている・起動できないときだけ出す。起動したときは `/mcp` で再接続する案内。古いコードのとき（バージョンか、プラグインのフォルダの末尾の名前が違う）は違う値と、`mindstella server restart` で再起動する手順。再起動はしない。同じコードが待ち受けていれば何も出さない |
| エラー | `[mindstella] エラー: {内容}` の行で、そろえるコマンド・案内があれば次の行に出す |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 常駐サーバーが待ち受けていた・起動して待ち受けた（古いコードのときを含む）。`--hook` を付けたときは、どの結末も `0` |
| `1` | `--hook` を付けないときだけ。待ち受けのポートが mindstella でないプロセスに使われている（ポートと `MINDSTELLA_PORT` で別のポートを渡す案内。起動しない）・依存が足りない（そろえるコマンド）・systemd --user が使えない・起動した常駐サーバーが待ち受ける前に落ちた（`~/.mindmap/server.log` の追記された末尾）・10 秒以内に応答しない（`~/.mindmap/server.log` を見る案内） |

## 起動スクリプトを登録する

起動スクリプトを呼ぶ alias `mindstella`・`mindstella-{アカウントの名前}`（シェルの関数）と、起動スクリプトが読む環境変数を、ログインシェルの設定に登録・読み返し・外す。
起動スクリプトの `register` のサブコマンドから呼ぶ。MCP のツールも mindstella の仮想環境も使わず、システムの `python3`（3.8 以上）の標準ライブラリだけで動く。
ワークスペースは書かない。

### 使い方

```bash
{プラグインのフォルダ}/bin/mindstella register {show|set|add-account|remove-account|remove} [--env KEY=VALUE]... [--unset-env KEY]... [--name {アカウントの名前}] [--config-dir {フォルダ}]
```

| サブコマンド | することと書き込むもの |
| --- | --- |
| `show` | 登録を読む。何も書かない |
| `set` | alias `mindstella` を登録し、`--env` の環境変数を登録・書き換え、`--unset-env` の環境変数を外す |
| `add-account` | アカウントごとの alias `mindstella-{名前}` を追加する・書き直す |
| `remove-account` | アカウントの alias を外す |
| `remove` | 登録を全て外す |

書き込むサブコマンドは、`{XDG_CONFIG_HOME か ~/.config}/mindstella/` の `registration.json`（登録の中身）と `shell.sh`（alias と `export`）を書く。
ログインシェルの設定ファイルには、`# >>> mindstella >>>` と `# <<< mindstella <<<` で囲んで `shell.sh` を読み込む 1 行だけを、無ければ末尾に追加する。
マーカーの範囲の外の行は変えない。`remove` は 2 つのファイルとマーカーの範囲を削除する。
alias は叩くたびに `claude plugin list --json` の `mindstella@mindstella` の `installPath` を引き、`{installPath}/bin/mindstella` に引数をそのまま渡す。引けなければ `[mindstella] エラー:` で始まる行を標準エラーに出して 1 を返す。
環境変数は `shell.sh` に `export` で書き、値は単引用符で囲む。

### 引数

<!-- table: {"kind": "data"} -->

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--env` | 任意 | `set` で登録する環境変数 `KEY=VALUE`。繰り返し渡せる。渡したキーだけを書き換え、登録済みのほかのキーは残す。キーは `MINDSTELLA_VENV`・`MINDSTELLA_PORT`・`MINDSTELLA_ALLOWED_HOSTS`・`MINDSTELLA_PREVIEW_START_HOOK`・`MINDSTELLA_PREVIEW_STOP_HOOK`・`MINDSTELLA_TRANSCRIBER`・`MINDSTELLA_TRANSCRIBER_URL`・`MINDSTELLA_DISCORD_WEBHOOK_FILE` のどれかで、値は改行を含まない | `MINDSTELLA_ALLOWED_HOSTS=preview.example.com` |
| `--unset-env` | 任意 | `set` で登録から外す環境変数のキー。繰り返し渡せる。キーは `--env` と同じ | `MINDSTELLA_VENV` |
| `--name` | `add-account`・`remove-account` で必須 | アカウントの名前。alias の名前 `mindstella-{名前}` になる。英小文字・数字・`-` の 1〜32 文字で、英小文字か数字で始まる | `sub1` |
| `--config-dir` | `add-account` で必須 | そのアカウントの Claude Code の設定のフォルダ。絶対パスに変更して登録する | `~/.claude-sub1` |
| `HOME` | 必須 | 環境変数。ログインシェルの設定ファイルと、`XDG_CONFIG_HOME` が無いときの登録の置き場所を決める | - |
| `XDG_CONFIG_HOME` | 任意 | 環境変数。登録の置き場所 `{XDG_CONFIG_HOME}/mindstella/` を決める。省略すると `~/.config` | - |
| `SHELL` | 必須 | 環境変数。末尾の名前が `bash` なら `~/.bashrc`（macOS では `~/.bash_profile`・`~/.bash_login`・`~/.profile` のうち最初にあるもの、どれも無ければ `~/.bash_profile`）、`zsh` なら `~/.zshrc` をログインシェルの設定ファイルにする | - |

<!-- /table -->

### 出力

標準出力に、その後の登録を JSON（UTF-8、日本語はエスケープしない）で出す。

<!-- table: {"kind": "data"} -->

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `registered` | bool | alias `mindstella` が登録されているか |
| `rc_file` | str | `shell.sh` を読み込むログインシェルの設定ファイルの絶対パス |
| `shell_file` | str | alias と環境変数を書く `shell.sh` の絶対パス |
| `env` | dict[str, str] | 登録した環境変数 |
| `accounts[].name` | str | アカウントの名前 |
| `accounts[].config_dir` | str | そのアカウントの Claude Code の設定のフォルダの絶対パス |
| `aliases` | list[str] | 登録した alias の名前（`mindstella` と `mindstella-{名前}`） |
| `in_tmux` | bool | `show` を呼んだ環境に空でない `TMUX` があるか（Claude Code が tmux の中で動いているか）。`show` のときだけ持つ |
| `error` | str \| null | 失敗したときの理由。成功したときは持たない |
| `manual_lines` | list[str] \| null | 書き込めなかったとき、手でログインシェルの設定ファイルに書けば同じ登録になる行（マーカーの範囲と alias `mindstella` の定義）。成功したときと、`remove` のときは持たない |

<!-- /table -->

書く前に、書く先の全てに書き込めるかを確かめる。
各ファイルは同じフォルダの一時ファイルに書いてから置き換え、途中で失敗しても下書きのファイルを残さない。
書く先がシンボリックリンクなら、リンクを残してリンク先を書き換える。

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 登録を読んだ・書いた・外した |
| `1` | ログインシェルの設定ファイルか登録の置き場所に書き込めない・`SHELL` が `bash`・`zsh` でない（どちらも何も書かず、`error` と `manual_lines` を出す）・`remove-account` の名前が登録に無い・`registration.json` を JSON として読めない（どちらも何も書かず、`error` を出す） |
| `2` | 引数の誤り（サブコマンドが無い・知らない、`--env` のキーが許すキーでない、`--name` の形式が合わない、`add-account` に `--name` か `--config-dir` が無い）。何も書かず、使い方を標準エラーに出す |

## 依存を確認する

### 引数

<!-- table: {"kind": "data"} -->

## ID を取る

項目を project-index の `write_docs` で書き込む前に、種類ごとの次の ID を返す。
返した ID は常駐サーバーが予約として持ち、並行して取った ID と重ならない。書き込まなかった ID は欠番になる。
ファイルは書き換えない。

### 使い方

`next_id` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "kind": "decision", "count": 2}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `kind` | 必須 | 項目の種類（`decision`・`task`・`research`・`doc`・`term`・`note`・`log`） | `decision` |
| `count` | 任意 | 続けて取る ID の数（1〜50）。省略すると 1 | `2` |

### 出力

<!-- table: {"kind": "data"} -->

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `ids` | list[str] | 振った ID（小さい順） |

<!-- /table -->

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | ID を振った |
| エラー | ワークスペースが無い・その種類の YAML か `changes.yaml` が読めない |
| エラー（引数の誤り） | `kind` が決めた種類でない・`count` が 1〜50 でない |

## 設定を書き換える

`settings` で渡した設定のキーを置き換える。
書き換えられるのは `summary`・`description`・`links`・変更履歴を保持する回数（`history_limit`）と表示の既定（`display`）と音声入力の設定（`transcription`）と画面が読み込む mdmark のバージョンと map の図の種類（`mdmark`）。

### 使い方

`update_settings` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "settings": {置き換えるキーの JSON}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `settings` | 必須 | 置き換えるキーと値の JSON のオブジェクト。渡したキーだけを値ごと置き換え（配列・オブジェクトも丸ごと）、値が `null` のキーは削除する。渡さないキーはそのまま。`null` で削除できるのは `description`・`links`・`history_limit`・`display`・`transcription` だけ。`display` は `visible_kinds` を持つオブジェクトで、渡すと丸ごと置き換える。`transcription` は `action`・`preset` を持つオブジェクトで、渡すと丸ごと置き換える。`mdmark` は `version`・`map` を持つオブジェクトで、渡した方だけを置き換え、渡さなかった方は残す。`map` はノードの種類の `kinds`・線の種類の `lines` を持ち、渡すと丸ごと置き換え、mdmark の設定の `map` と同じ構造でないときは書き換えない | `{"description": null}` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `changed` | list[str] | 値が変わった・消えた設定のキーの名前 |
| `files` | list[str] | 書き換えた YAML（ワークスペースからの相対パス） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き換えられた |
| エラー | ワークスペースが無い・書き換えた後の YAML がスキーマに合わない（書き換えられないキーや必須のキーの `null` を渡したときも含む）・書き込めなかった（どのファイルも書き換えない） |
| エラー（引数の誤り） | 削除したキー（`goal`・`phases`・`playbooks`・`targets`・`target_label`・`categories`）を渡した。エラーの本文に渡したキー。どのファイルも書き換えない |

`presets` は書き換えられない。[プリセットを作成する](#プリセットを作成する)・[プリセットを更新する](#プリセットを更新する)・[プリセットを削除する](#プリセットを削除する)を使う。

## プリセットを作成する

タグの式に名前を付けた絞り込みのプリセットを、設定の `presets` の末尾に追加し、該当する項目の件数を返す。
該当する件数が 0 でも保存し、警告を添える。
式の書き方は [ワークスペースの書式](./ワークスペースの書式.mark.md#設定) の `presets[].filter`。

### 使い方

```json
{"workspace": "{フォルダ}", "name": "画面の設計", "description": "画面の設計の項目を開く", "filter": {"and": [{"field": "tags", "op": "eq", "values": ["画面"]}, {"field": "tags", "op": "ne", "values": ["廃止"]}]}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `name` | 必須 | プリセットの名前。1〜40 字。既にある名前と、全角半角・大文字小文字をそろえて重ならない | `画面の設計` |
| `description` | 任意 | 何を開くプリセットかの 1 文 | - |
| `filter` | 必須 | タグの式 | 上の使い方 |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `preset` | dict | 保存したプリセット |
| `count` | int | 該当する、全ての種類の項目の数 |
| `warnings` | list[str] | `count` が 0 のとき、どの項目にも該当しない旨の 1 行 |
| `files` | list[str] | 書き換えた YAML |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 追加した。件数が 0 のときも含む |
| エラー | ワークスペースが無い・式が合わない（空の束・4 レイヤー以上の入れ子・受け付けないキーや比べ方。本文に合わない箇所のキーのパスと理由）・名前が重なる・書き込めなかった。どれも何も書き換えない |

## 採用する案を切り替える

検討事項の案のうち、指定した記号の案だけを採用にし、ほかの案の採用を外して、状態を `決定済み` にする。
切り替える前の状態は問わない（未決定・要見直し・保留から決定済みにする）。
回答（`answer`）と推奨のマーカーは変えない。
回答は、続けて project-index の `write_docs` で書く。
検討事項の更新日時と編集した人（`updated_by`。`ai`）を `history.yaml` に書き換える。
影響を洗い出さない（project-index の `trace_related` で、種類つきの関連を逆向きにたどる）。
採用か状態が変わったときは、変更の検知と同じように、値が変わったキー（切り替える前の案の並び全体を `options`、切り替える前の状態を `status`）を変更履歴に積む。
既にその案が採用で決定済みのときは積まない。
連番の振り方と、AI がまだ読んでいない回を `history_limit` を超えても残すことは、変更の検知と同じ（[ワークスペースの書式](./ワークスペースの書式.mark.md#項目の履歴)）。

### 使い方

`adopt` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}", "key": "{記号}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 検討事項の ID。`D-` で始まる | `D-1` |
| `key` | 必須 | 採用する案の記号（`options[].key`） | `B` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 検討事項の ID |
| `adopted` | str | 採用した案の記号 |
| `previous` | str \| null | それまで採用していた案の記号。無ければ `null` |
| `status` | str | 切り替えた後の状態。常に `決定済み` |
| `previous_status` | str | 切り替える前の状態 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 切り替えた（既にその案が採用で決定済みのときも含む） |
| エラー | ワークスペースが無い・検討事項が無い・渡した記号の案が無い（エラーの本文に、その検討事項が持つ案の記号の一覧）・切り替えた後の YAML がスキーマか案と状態の決まりに合わない・書き込めなかった（どのファイルも書き換えない） |

## 案を書き換える

検討事項の案を記号（`key`）で指して、1 つ追加する・中身と推奨のマーカーを修正する・削除する。
指さない案と、検討事項のほかのキーはそのまま残る（推奨のマーカーを立てたときは、ほかの案のマーカーを外す）。
検討事項の更新日時と編集した人（`updated_by`。`ai`）を書き換える。
案の `adopted` と検討事項の `status`・`answer` は書き換えない（採用と状態は[採用する案を切り替える](#採用する案を切り替える)が書き換える）。
`未整理`・`対象外`・`取り下げ` のほかの状態の検討事項は、最後の案を削除できない。
案の並びが変わったときは、変更の検知と同じように、書き換える前の案の並び全体を `options` として変更履歴に積む。
連番の振り方と、AI がまだ読んでいない回を `history_limit` を超えても残すことも、変更の検知と同じ。

### 使い方

`edit_option` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}", "action": "{add | update | remove}", "key": "{記号}", "option": {案の JSON}}
```

`remove` のときは `option` を渡さない。

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 案を書き換える検討事項の ID。`D-` で始まる | `D-1` |
| `action` | 必須 | `add` は案を並びの末尾に追加する。`update` は指した案の中身を、その位置のまま修正する。`remove` は指した案だけを抜く | `add` |
| `key` | 必須 | 案の記号。`add` では追加する案の記号、`update`・`remove` では指す案の記号 | `B` |
| `option` | `add`・`update` では必須 | `add` では追加する案の中身。`update` では置き換えるキーと値で、渡したキーだけを置き換え、値が `null` のキーは削除する。キーは `content`・`pros`・`cons`・`note`・`reason`・`recommended` だけ（`key`・`adopted` は渡さない）。`recommended` は `true` でマーカーを立て、`false` か `null` でマーカーを外す。`remove` では渡さない | `{"content": "種類ごとに分ける", "pros": "探しやすい", "recommended": true}` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 書き換えた検討事項の ID |
| `file` | str | 書き換えた YAML（ワークスペースからの相対パス） |
| `options` | list[dict] | 書き換えた後の案の並び |
| `changed` | bool | 案の並びが変わったか。同じ値で修正したときは `false` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き換えられた |
| エラー | ワークスペースが無い・検討事項が無い・`add` で同じ記号の案が既にある・`update`・`remove` で指した記号の案が無い・`remove` で採用している案を指した（エラーの本文に、先に[採用する案を切り替える](#採用する案を切り替える)で採用を移す案内）・`remove` で、案を持たなくてよい状態（`未整理`・`対象外`・`取り下げ`）以外の検討事項の最後の案を指した（エラーの本文に、案を 1 つ以上残す案内）・書き換えた後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない）。案の記号のエラーは `エラー: {ID} の案 {記号}: {理由}` の行 |
| エラー（引数の誤り） | `id` が `D-` で始まらない・`add`・`update` で `option` を渡さない・`remove` で `option` を渡した・`option` が `key` か `adopted` を持つ。何も書き込まない |

## 書き換えをまとめる

まだまとめていない書き換え（最後のまとまりより後に、MindStella のセッションの応答の途中に書き込んだ変更と、`adopt`・`edit_option` の書き換え）を、日時と一言の説明を付けた 1 つのまとまりにする。
プレビューの変更履歴は、このまとまりを並べる。
`changes.yaml` だけを書き換え、項目の YAML と本文は書き換えない。
まとめる書き換えが無いときは、まとまりを追加しない。
ほかのセッションの書き込み（外部の変更）が残っていれば、先に「ほかのセッションの書き込み」のまとまりにする。
MindStella のセッションからだけ呼べる。

### 使い方

`commit` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "summary": "{一言の説明}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `summary` | 必須 | このまとまりで何をしたかの一言の説明。プレビューの変更履歴にそのまま出る。前後の空白を除いて 1〜200 文字 | `D-1 を決め、T-1 を積む` |

### 出力

<!-- table: {"kind": "data"} -->

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str \| null | 追加したまとまりの ID（`V-` + 連番）。まとめる書き換えが無く、追加しなかったときは `null` |
| `at` | str \| null | まとめた日時（UTC のタイムゾーン付き ISO 8601）。追加しなかったときは `null` |
| `summary` | str \| null | 前後の空白を除いた説明。追加しなかったときは `null` |
| `added` | list[str] | このまとまりで追加した項目の ID |
| `changed` | list[str] | このまとまりで変えた項目の ID（追加した項目は含めない） |
| `removed` | list[dict] | このまとまりで削除した項目。要素は `id`・`kind`・`title`（削除したときのタイトル） |

<!-- /table -->

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | まとめた（まとめる書き換えが無く、何も追加しなかったときも含む） |
| エラー | ワークスペースが無い・`changes.yaml` がスキーマに合わないか YAML として読めない・書き込めなかった（`changes.yaml` を書き換えない） |
| エラー（引数の誤り） | `summary` が空白だけか、200 文字を超える。何も書き込まない |
| エラー（MindStella のセッションでない） | MindStella のセッションでない呼び出し。何も書き込まない |

## 前回参照した時点からの変更を読み込む

AI が最後に読んだ時点（`read_seq`）より後に追加した・変えた・削除した項目を、変わったキーと読んだ時点の値（本文は行の差分）つきで返し、`read_seq` を今の `last_seq` に書き換える。
SessionStart の注入に収まらない変更があったときに、MindStella のセッションが呼ぶ（[起動と再開](./エージェントフロー.md#起動と再開)）。
`read_seq` は常駐サーバーの状態のフォルダの `workspaces/{ワークスペースの ID}/read_point.json` に持ち、無ければ `changes.yaml` の前のバージョンの `read_seq` を読む。
`read_point.json` だけを書き換え、項目の YAML と本文は書き換えない。`changes.yaml` が無ければ、まとまり 0 件・まだまとめていない変更なし・`last_seq: 0` で作る。
`read_seq` はこのツールを呼んだときと、SessionStart の注入を書き終えたときだけ進み、AI が MCP のツールで書いた分も、次に呼ぶまでは読んでいない変更に数える。
読んだ時点の記録（`read_seq`）が無いワークスペースでは、差分を返さず、今の `last_seq` を記録する。
返すのは種類ごとの YAML の項目と、`changes.yaml` に残した削除した項目だけで、設定（`config.yaml`）は返さない。
読んだ時点より後に追加して削除した項目は、読んだ時点にも今にも無いため返さない。


## ワークスペースを点検する

スキーマに合わない箇所・参照切れ・YAML と直下の `docs/` の本文（Markdown と HTML）のずれ・変更履歴のずれ・案と状態の合わない検討事項を全て洗い出す。
見つけた問題は修正しない。

- 参照切れは、`depends_on`・`parent`・`for`・`related`・`sources` が、存在しない ID や、キーが決めた種類でない ID（`parent` が `D-` 以外 など）を指しているもの
- 本文のずれは、`body` が指す直下の `docs/` のファイルが無いもの（`missing_body`）と、どの項目の `body` からも指されない直下の `docs/` の `*.md`・`*.html`（`orphan_body`）。全ての種類の項目の本文を確かめる
- 埋め込んだファイルは、Markdown の本文の画像の記法 `![…](パス)` の相対パスが指すファイルが無いもの（`missing_file`）。`file` は本文のファイル、`detail` は記法に書かれたパス。絶対 URL・`data:`・`/` で始まるパス・コードの中・HTML の本文は確かめない
- 変更履歴は、本文を持つ項目の変更履歴を新しい順に今の本文へ当て、`body_diff` の `now` の行が当てる先の行と合わない回があるもの（`stale_history`）。ツールを通さずに本文を書き換えたときに起きる
- 案と状態は、検討事項が[案と状態の決まり](./ワークスペースの書式.mark.md#検討事項)に合わないもの（`decision_state`）。合わない決まり 1 つにつき 1 件で、`未整理`・`対象外`・`取り下げ` の検討事項が案を持たないことは問題にしない

### 使い方

`check` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

問題があるときも点検そのものは正常に終えているので、同じ構造の結果を返し、エラーにしない。
`problems` はファイル名の順、同じファイルの中は項目の並びの順に並ぶ。

<!-- table: {"kind": "data"} -->

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `ok` | bool | 問題が 1 つも無いか |
| `problems[].kind` | `schema` \| `duplicate_id` \| `broken_ref` \| `missing_body` \| `orphan_body` \| `stale_history` \| `decision_state` \| `missing_file` | 問題の種類（スキーマに合わない・ID の重複・参照切れ・指す本文が無い・どの項目からも指されない本文・変更履歴から前の本文を組み立てられない・検討事項の案と状態が合わない・埋め込んだファイルが無い） |

## プレビューの配信先を返却する

ワークスペースのプレビューを配る URL を返す。
常駐サーバーは全てのワークスペースの画面を、待ち受けのポート（`MINDSTELLA_PORT`）の `/w/{ワークスペースの ID}/` の下で配る。
登録済みのワークスペース（クローズしたものを含む）は常駐サーバーの起動時から、作成したワークスペースは作成の時点から配り、削除したら配るのをやめる。
まだ配っていなければ、`config.yaml` をスキーマと突き合わせ、通れば配り始める。
合わなければ、違う箇所（キーと理由）をエラーで返し、配らない。既に配っているワークスペースでは、突き合わせずに同じ URL を返す。
ワークスペースの ID が、配っている別のフォルダと同じときは、エラーを返して配らない。
配信は、プレビューの画面を `/w/{ワークスペースの ID}/` で（`/w/{ワークスペースの ID}` と前の画面の `/w/{ワークスペースの ID}/mindstella.html`・`/w/{ワークスペースの ID}/spa/` は search を残してそこへ再送信して）返し、記録を返し、記録が書き換わったら開いている画面へ知らせ、溜めるコメントと下書きを受けて `comments.yaml`・`drafts.yaml` に置き、まとめて送信されたコメントを `threads.yaml` のスレッド（新規スレッドの最初の書き込みと、スレッドへの返信）として受け、画面からのスレッドのクローズとオープンへの戻しを受ける。
[設定を再読み込みする](#設定を再読み込みする)・[設定の既定を書き換える](#設定の既定を書き換える)・[画面からプリセットを保存する](#画面からプリセットを保存する)も、同じ配信が受ける。
同じワークスペースで再呼び出しすると同じ URL を返す。
コメントをまとめて送信した後に貼る先は、そのワークスペースを指して最後にツールを呼んだセッション（同じワークスペースを 2 つのセッションが指すと、後から呼んだ方に貼る）。そのセッションが終わった後は貼らない。
配り始めたときは、[README を書き直す](#readme-を書き直す)と同じ判定で、直下の `README.md` のプレビューのセクションを返す URL にして書き直す。書けなくても配信は止めず、URL を返す。
配り始めたときは、`MINDSTELLA_PREVIEW_START_HOOK` があれば、配り始めた直後に常駐サーバーのポート・ワークスペースのフォルダの名前・画面のパスを追加して呼ぶ。既に配っているワークスペースで再呼び出ししたときは呼ばない。
配信は `Host` と `Origin` を確かめる。受けるのは、`127.0.0.1:{常駐サーバーのポート}`・`localhost:{常駐サーバーのポート}` と、`MINDSTELLA_ALLOWED_HOSTS` のホスト名。許可するホスト名は、ポートを外したホスト名の部分で大文字と小文字を区別せずに比べ、外の入口のポートは問わない。`Origin` は、許可するホスト名の `https://` と `http://` も受ける。
配信は常駐サーバーのプロセスが持ち、ツールを呼んだ Claude Code を閉じても止まらない。常駐サーバーが止まるとき（[常駐サーバーを止める](#常駐サーバーを止める)を含む）に、`MINDSTELLA_PREVIEW_STOP_HOOK` があれば配っているワークスペースごとに 1 回呼んでから、配信が止まる。ワークスペースを削除したときも、そのワークスペースについて 1 回呼ぶ。
フックのコマンドは、新しいセッションで起動して終わりを待たない。呼べない（コマンドが見つからない など）ときは標準エラーに記録し、配信の起動と終了は止めない。
画面ごとの操作は [プレビューを見る](./プレビューを見る.mark.md)。

### 使い方

`preview_url` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `diff` | 任意 | `url` で差分を開くまとまりの ID（`commit` が返した `id`）。`changes.yaml` の `sets` にある ID で、`since`・`pending` は受けない。省略すると `url` に search を付けない | `V-2` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `url` | str | 配信の画面の URL（`http://127.0.0.1:{常駐サーバーのポート}/w/{ワークスペースの ID}/`）。`diff` を渡したときは、末尾に search の `?diff={ID}` を付ける |
| `workspace` | str | 配っているワークスペースの絶対パス |
| `started` | bool | この呼び出しで配り始めたか。既に配っていたら `false` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 配信の URL を返せた |
| エラー | ワークスペースが無い・`config.yaml` がスキーマに合わない（エラーの本文に合わない箇所ごとの `config.yaml: {キーのパス}: {理由}` の行）・ワークスペースの ID が配っている別のフォルダと同じ（エラーの本文に ID と両方のフォルダ）・`diff` を渡したときの `changes.yaml` がスキーマに合わない、または YAML として読めない（既に配っていても。エラーの本文に `changes.yaml: {キーのパス}: {理由}` の行）・`diff` が記録に無いまとまり（既に配っていても。エラーの本文に渡した ID）。まだ配っていなければ、どれも配らず、起動時のフックも呼ばない |

## README を書き直す

ワークスペースの直下の `README.md` を、起動・接続のコマンドとエージェントフローの案内・プレビューの URL を書いた一覧に書き直す。
コマンドは、そのフォルダの絶対パス・今のプラグインのフォルダ・tmux のセッションの名前を埋めた、そのまま叩ける形式で書く。
プレビューのセクションは、このプロセスがワークスペースを配っていればその URL、配っていなければ MindStella のセッションにプレビューを頼む案内になる。
直下に `README.md` が無いか、1 行目が自動で書いたマーカー `<!-- mindstella:readme -->` のときだけ書く。利用者が書いた `README.md` は書き換えない。
`.mindstella/` には書かず、ワークスペースの排他ロックは取らない。

### 使い方

`readme` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `path` | str | 直下の `README.md` の絶対パス |
| `written` | bool | この呼び出しで書いたか。利用者が書いた `README.md` があれば `false` |
| `preview_url` | str \| null | `README.md` に書いたプレビューの URL。このプロセスがワークスペースを配っていなければ `null` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書いた、または利用者が書いた `README.md` があって書かなかった |
| エラー | ワークスペースが無い・`README.md` を書けない（同じ名前のフォルダがある・権限が無い など。エラーの本文に書けなかったパスと理由。前からあったファイルは残す） |

## 設定を再読み込みする

手で修正した `config.yaml` をスキーマと突き合わせ、通れば新しい設定を使い、開いている画面に知らせる。
通らなければ、最後に検査に通った設定のまま、違う箇所を返す。
ワークスペースには書かない。

### 使い方

`preview_url` が返した URL の末尾に `api/config/reload` を付けた URL へ、本文なしの `POST` を送信する。

```bash
curl -X POST http://127.0.0.1:8784/w/{ワークスペースの ID}/api/config/reload
```

### 引数

なし。
`Host` は `127.0.0.1:{常駐サーバーのポート}`・`localhost:{常駐サーバーのポート}` か、ポートを外したホスト名が `MINDSTELLA_ALLOWED_HOSTS` のどれかと同じもの、`Origin` は無いか、配信の URL と同じものか、スキームが `https` か `http` でポートを外したホスト名が `MINDSTELLA_ALLOWED_HOSTS` のどれかと同じものだけ通る。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `settings` | dict | 検査に通った `config.yaml` の中身 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功（200） | 検査に通った。新しい設定を使い、開いている画面に知らせた |
| エラー（403） | `Host` か `Origin` が合わない |
| エラー（422） | `config.yaml` がスキーマに合わないか、YAML として読めない。本文は `application/problem+json` で、`detail` に合わない箇所ごとの `config.yaml: {キーのパス}: {理由}` の行を出す。配信は最後に検査に通った設定のまま動く |

## 設定の既定を書き換える

プレビューの「ワークスペースの既定にする」が呼び、表示する種類の既定を `config.yaml` の `display` に書く。
書いたら、開いている画面に知らせる。
`display` 以外のキーと種類ごとの YAML は書き換えず、変更履歴にも書き換えのまとまりにも入れない。
画面の操作から呼ぶエンドポイントで、開けた人は誰でも書き換えられる。配る書き出しの画面は呼ばない。

### 使い方

`preview_url` が返した URL の末尾に `api/config/display` を付けた URL へ、`PUT` を送信する。

```bash
curl -X PUT http://127.0.0.1:8784/w/{ワークスペースの ID}/api/config/display -H 'Content-Type: application/json' -d '{"visible_kinds": ["decisions", "tasks", "research", "docs", "notes", "logs"]}'
```

### 引数

本文の JSON のオブジェクトで渡す。

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `visible_kinds` | 必須 | 表示する種類の既定。`decisions`・`tasks`・`research`・`docs`・`terms`・`notes`・`logs` の重複しない配列。空の配列でもよい（概要だけを出す） | `["decisions", "tasks"]` |

`Content-Type` は `application/json`。
`Host` と `Origin` は[設定を再読み込みする](#設定を再読み込みする)と同じ。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `display` | dict | 書いた後の `config.yaml` の `display`（`visible_kinds`） |

### 結果

<!-- table: {"kind": "data"} -->

| 結果 | 意味 |
| --- | --- |
| 成功（200） | 書けた。`display` だけを置き換え、ほかのキーは書く前のまま |
| エラー（400） | 本文が JSON のオブジェクトでない・`visible_kinds` が無いか値が合わない・ほかのキー（削除した `network_look` を含む）がある。`detail` に合わないキーと選べる値。何も書かない |
| エラー（403） | `Host` か `Origin` が合わない。何も書かない |
| エラー（415） | `Content-Type` が `application/json` でない |
| エラー（422） | 今の `config.yaml` がスキーマに合わない（`display` 以外のキーが崩れている）。`detail` に合わない箇所。何も書かない |
| エラー（500） | `config.yaml` を書けない（ワークスペースのフォルダが読み取り専用 など）。`detail` に書けなかったパスと理由。`config.yaml` は書く前のまま |

<!-- /table -->

エラーの本文は `application/problem+json`（`type`・`title`・`status`・`detail`）で、`detail` は日本語。

## 画面からプリセットを保存する

プレビューの絞り込みのドロワーの「プリセットとして保存」が呼び、今のタグの条件に名前を付けたプリセットを `config.yaml` の `presets` の末尾に加える。
検証・追加・件数の数え方は [プリセットを作成する](#プリセットを作成する)（`create_preset`） と同じで、説明（`description`）は受け付けない。
書いたら、開いている画面に知らせる。変更履歴にも書き換えのまとまりにも入れない。
画面の操作から呼ぶエンドポイントで、開けた人は誰でも書き換えられる。配る書き出しの画面は呼ばない。

### 使い方

`preview_url` が返した URL の末尾に `api/presets` を付けた URL へ、`POST` を送信する。

```bash
curl -X POST http://127.0.0.1:8784/w/{ワークスペースの ID}/api/presets -H 'Content-Type: application/json' -d '{"name": "廃止する画面", "filter": {"and": [{"field": "tags", "op": "eq", "values": ["画面"]}, {"field": "tags", "op": "eq", "values": ["廃止"]}]}}'
```

### 引数

本文の JSON のオブジェクトで渡す。

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `name` | 必須 | プリセットの名前。1 字以上 40 字以内で、既にあるプリセットの名前と重ならない（全角半角・大文字小文字の違いだけのものも重なりとみなす） | `廃止する画面` |
| `filter` | 必須 | タグの式。`create_preset` の `filter` と同じ構造 | 上の使い方の例 |

`Content-Type` は `application/json`。
`Host` と `Origin` は[設定を再読み込みする](#設定を再読み込みする)と同じ。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `preset` | dict | 保存したプリセット（`name`・`filter`） |
| `count` | int | そのプリセットに該当する、全ての種類の項目の数 |

### 結果

<!-- table: {"kind": "data"} -->

| 結果 | 意味 |
| --- | --- |
| 成功（201） | 加えた。該当する件数が 0 のときも含む |
| エラー（400） | 本文が JSON のオブジェクトでない・`name` が空か 40 字を超える・`filter` が合わない・ほかのキーがある。`detail` に合わないキーと理由。何も書かない |
| エラー（403） | `Host` か `Origin` が合わない。何も書かない |
| エラー（409） | `name` が既にあるプリセットの名前と重なる。`detail` に重なった名前。何も書かない |
| エラー（415） | `Content-Type` が `application/json` でない。何も書かない |
| エラー（422） | 今の `config.yaml` がスキーマに合わない。`detail` に合わない箇所。何も書かない |
| エラー（500） | `config.yaml` を書けない。`detail` に書けなかったパスと理由。`config.yaml` は書く前のまま |

<!-- /table -->

エラーの本文は `application/problem+json`（`type`・`title`・`status`・`detail`）で、`detail` は日本語。

## 埋め込むファイルを配る

画面が、資料の本文に埋め込んだ動画・音声・画像を読むために呼ぶ。
直下の `files/` の中のファイルだけを返し、フォルダの外を指すパスとフォルダの中の一覧は返さない。
ワークスペースは書き換えない。

### 使い方

`preview_url` が返した URL の末尾に `files/{名前}` を付けた URL へ、`GET` を送信する。

```bash
curl -H 'Range: bytes=0-1023' http://127.0.0.1:8784/w/{ワークスペースの ID}/files/clip.mp4 -o part.mp4
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `{path}` | 必須 | 直下の `files/` からのパス。URL エンコードしてよい | `video/clip.mp4` |
| `Range` | 任意 | 返す範囲。`bytes={始め}-{終わり}`・`bytes={始め}-`・`bytes=-{末尾からの長さ}` の 1 つだけ。複数の範囲と書式に合わない値は無視して全体を返す | `bytes=0-1023` |

`Host` は[設定を再読み込みする](#設定を再読み込みする)と同じ。

### 出力

ファイルの中身。`Content-Type` は拡張子から決まる（`.mp4`・`.webm`・`.mov`・`.mp3`・`.wav`・`.ogg`・`.m4a`・`.png`・`.jpg`・`.jpeg`・`.gif`・`.webp`・`.svg`。ほかは `application/octet-stream`）。
どの応答も `Accept-Ranges: bytes`・`Cache-Control: no-cache`・`X-Content-Type-Options: nosniff`・`Content-Security-Policy: sandbox` を持つ。

### 結果

<!-- table: {"kind": "data"} -->

| 結果 | 意味 |
| --- | --- |
| 成功（200） | ファイルの全体を返した |
| 成功（206） | `Range` の範囲を返した。`Content-Range` が `bytes {始め}-{終わり}/{大きさ}` |
| エラー（403） | `Host` が合わない |
| エラー（404） | ファイルが無い・フォルダを指す・直下の `files/` の外を指す |
| エラー（416） | `Range` の始めがファイルの大きさ以上。`Content-Range` が `bytes */{大きさ}` |

<!-- /table -->

エラーの本文は `application/problem+json`（`type`・`title`・`status`・`detail`）で、`detail` は日本語。

## 配る書き出しを作る

ワークスペースの全ての YAML と本文を、React の画面と描画のライブラリ（mdmark・marked・mermaid・jsdiff）まで中に持つ、見るだけの 1 枚の HTML にして、指定したパスへ書き出す。
画面は、プラグインが持つ React の画面の書き出し用のビルド（`preview/export/index.html`）を元にする。
ワークスペースもサーバーもネットも持たない人へ配るために使う。
描画のライブラリの配布ファイルとライセンスの本文は、書き出すときに jsDelivr から取る。
mdmark は、ワークスペースの設定の `mdmark.version`（無ければ develop の最新）の配布ファイル・部品と、束ねた依存のライセンスを取る。
mdmark の MIT の本文だけは、プラグインの `preview/licenses/mdmark-LICENSE.txt` から読む。
mdmark 以外の取った配布ファイルは `preview/libraries.json` の `integrity` と突き合わせ、合わなければ書き出さない。
1 回の要求で、接続と 1 回の読み取りをそれぞれ 30 秒まで待ち、再取得しない。
書き出した HTML は外のファイルも URL も指さず、開いても通信しない。
ワークスペースへ書き込む操作は画面に出ない。
ブラウザは開かない。
YAML がスキーマに合わないときと、jsDelivr から取れないときは書き出さず、前の `out` のファイルを残す。

### 使い方

`export` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "out": "{パス}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `out` | 必須 | 書き出す HTML のファイルのパス。末尾は `.html`。親のフォルダは作らないので、先に用意する。相対パスは `workspace` と同じく、ツールを呼んだ Claude Code の作業フォルダから読む。既にあるファイルは置き換える | `~/渡す/新規事業の検討.html` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `path` | str | 書き出した HTML の絶対パス |

書き出した HTML には、`<script type="application/json" id="mindmap-data"></script>` の中身として、次の埋め込みのデータが入る（サーバーが配るプレビューが読む記録と同じ構造）。
画面はこの要素の中身を `JSON.parse` して読む。
スレッド（`threads.yaml`）は埋め込まない。

<!-- table: {"kind": "data"} -->

| キー | 型 | 説明 |
| --- | --- | --- |
| `settings` | dict | `config.yaml` の中身（`display` を含む）。トップバーのタイトルは `settings.summary` |
| `decisions` / `tasks` / `research` / `docs` / `terms` / `notes` / `logs` | list[dict] | 種類ごとの YAML の `items` の中身（キー名はファイル名から `.yaml` を落としたもの） |
| `bodies` | dict[str, str] | 項目の `body` の値 → 本文の原文（項目の `body` が指すものだけ。Markdown は `../docs/{ID}.mark.md`、HTML は `../docs/{ID}.html`） |
| `marked_bodies` | dict[str, str] | `bodies` の HTML の本文ごとの、ファイル名 → 開きタグに原文の行のマーカー（`data-line`）を追加した HTML。HTML の本文が無ければ `{}` |
| `changes` | dict | `changes.yaml` の中身（`last_seq`・`sets`・`pending`）。無ければ `{last_seq: 0, sets: [], pending: {added: [], changed: []}}`。変更履歴の一覧と、新規・変更のマーカーに使う。種類ごとの項目は `history` を持ったまま入る |
| `built_at` | str | 書き出した日時（UTC のタイムゾーン付き ISO 8601） |
| `derived.ready[]` | list[str] | 着手可能な検討事項（前提が全て決着した未決定）の ID。表の「着手可否」の列に使う |

<!-- /table -->

これに加えて、ライセンスの表示が入る。
ライセンスの表示は `<script type="text/plain" id="mindmap-licenses">` の中身で、画面には出ない。

| 内容 | 説明 |
| --- | --- |
| 中に持つライブラリ | mdmark・marked・mermaid・jsdiff のそれぞれの名前・バージョン・著作権の表示・ライセンスの名前と本文 |
| mdmark | MIT の本文の後に、配布物が中に束ねた依存ごとのライセンスの本文（`dist/THIRD_PARTY_LICENSES.txt`） |
| mermaid | 配布ファイルが中に束ねた依存（d3・cytoscape・katex など）ごとの名前・バージョンとライセンスの本文 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き出せた |
| エラー | ワークスペースが無い・YAML がスキーマに合わないか YAML として読めない・jsDelivr から取れない（届かない・待ちの上限を超えた・取った配布ファイルが `integrity` と合わない）・書き込めなかった（`out` の親のフォルダが無い）。前の `out` のファイルを残す |
| エラー（引数の誤り） | `out` の末尾が `.html` でない。何も書き込まない |

## スレッドを一覧する

スレッドを状態・タグ・AI の未読・取り込み待ちで絞り、書き込みの本文を含めないキーだけを返す。
読むだけで、既読にも取り込み済みにもしない。

### 使い方

`threads` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "awaiting": true}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `status` | 任意 | 返すスレッドの状態。`open`（オープンだけ）・`closed`（クローズだけ）・`all`（両方）。省略すると `open`。`awaiting` が真のときは `all` | `closed` |
| `tag` | 任意 | このタグを持つスレッドだけを返す | `起票` |
| `unread` | 任意 | 真なら、AI の未読の書き込みを持つスレッドだけを返す。省略すると偽 | `true` |
| `awaiting` | 任意 | 真なら、取り込み待ち（AI が取り込んでいない利用者の書き込みを持つ）のスレッドだけを返す。`status` を渡さなければオープンとクローズの両方を返す。省略すると偽 | `true` |

渡した条件を全て満たすスレッドだけを返す。

### 出力

| `items[].status` | `open` \| `closed` | 状態 |
| `items[].tags` | list[str] | タグ |
| `items[].summary` | str \| null | 要約。まだ書いていなければ `null` |
| `items[].head` | str | 最初の書き込みの本文の先頭（改行を空白にして 80 文字まで） |
| `items[].target` | str \| null | 向けた項目の ID。項目に紐づかないスレッドは `null` |
| `items[].target_title` | str \| null | その項目のタイトル。項目に紐づかないか、項目が消えていれば `null` |
| `items[].last_author` | `user` \| `ai` | 最後の書き込みの書き手 |
| `items[].last_at` | str | 最後の書き込みの日時（UTC のタイムゾーン付き ISO 8601） |
| `items[].posts` | int | 書き込みの件数 |
| `items[].unread` | int | AI の未読の書き込みの件数 |
| `items[].awaiting` | int | AI が取り込んでいない利用者の書き込みの件数 |

| 結果 | 意味 |
| --- | --- |
| 成功 | 一覧を作れた（0 件のときも含む。`threads.yaml` が無ければ 0 件） |
| エラー | ワークスペースが無い・`threads.yaml` がスキーマに合わないか YAML として読めない |

## スレッドの作成

AI から利用者へ返事を求めるスレッドの作成。
最初の書き込みは AI の本文で、要約とタグを一緒に書く。
AI の書き込みだけのスレッドは、取り込み待ちにならない。

### 使い方

`new_thread` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "body": "{質問の本文}", "summary": "{要約}", "tags": ["起票"], "target": "D-1"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `body` | 必須 | 最初の書き込み（AI の質問・知らせ）の本文。前後の空白を除いて 1〜10000 文字 | `D-1 の比べた結果を Issue に起票してよいですか` |
| `summary` | 必須 | スレッドの要約。前後の空白を除いて 1〜400 文字 | `D-1 の結果を起票してよいかの確認` |
| `tags` | 任意 | 付けるタグ。どの文字列でも渡した表記のまま付く。重なりも空の文字列も持たない。省略すると付けない | `["起票"]` |
| `target` | 任意 | 向ける項目の ID。ワークスペースにある項目。省略すると項目に紐づかないスレッドになる | `D-1` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 立てたスレッドの ID |
| `post` | str | 最初の書き込みの ID |
| `created` | str | 書いた日時（UTC のタイムゾーン付き ISO 8601） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | オープンのスレッドを 1 件追加した（`threads.yaml` が無ければ作る） |
| エラー | ワークスペースが無い・`body`・`summary` が空か上限を超える・`tags` に重なりか空の文字列がある・`target` の項目が無い・`threads.yaml` がスキーマに合わないか YAML として読めない・書き込めなかった（前の `threads.yaml` を残す） |
| エラー（MindStella のセッションでない） | MindStella のセッションでない呼び出し。何も書き込まない |

## スレッドに返信する

オープンのスレッドの末尾に AI の返信を追加し、同じ呼び出しで要約を書き直して、AI が読んだ利用者の書き込みを取り込み済みにする。

### 使い方

`reply` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "TH-1", "body": "{返信の本文}", "summary": "{書き直した要約}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 返信するスレッドの ID | `TH-1` |
| `body` | 必須 | 返信の本文。追加した・修正した項目があれば、その ID を書く。前後の空白を除いて 1〜10000 文字 | `D-1 の案 B を採用しました` |
| `summary` | 必須 | 書き直したスレッドの要約。前後の空白を除いて 1〜400 文字 | `D-1 の相談。案 B で決まった` |
| `take` | 任意 | 真なら、そのスレッドの AI が既読にした、取り込んでいない利用者の書き込みを取り込み済みにする。省略すると真 | `true` |

読んだ後に送信された AI の未読の書き込みは、取り込み済みにせず取り込み待ちに残す。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | スレッドの ID |
| `post` | str | 追加した書き込みの ID |
| `created` | str | 書いた日時（UTC のタイムゾーン付き ISO 8601） |
| `taken` | list[str] | 取り込み済みにした利用者の書き込みの ID。無ければ空 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 返信を追加し、要約を書き直した |
| エラー（クローズ） | スレッドがクローズ。本文に、[スレッドの状態を書き換える](#スレッドの状態を書き換える)でオープンに戻してから返信する案内を出す。何も書き込まない |
| エラー | ワークスペースが無い・`id` のスレッドが無い・`body`・`summary` が空か上限を超える・`threads.yaml` がスキーマに合わないか YAML として読めない・書き込めなかった（前の `threads.yaml` を残す） |
| エラー（MindStella のセッションでない） | MindStella のセッションでない呼び出し。何も書き込まない |

## スレッドの状態を書き換える

AI がスレッドをクローズにするかオープンに戻し、書き手（AI）・任意の理由・日時をスレッドに残す。
利用者が画面で行うクローズとオープンへの戻しも、同じ構造で残る。

### 使い方

`set_thread_status` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "TH-1", "status": "closed", "reason": "案 A で決着"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | スレッドの ID | `TH-1` |
| `status` | 必須 | 変えた後の状態。`open` か `closed` | `closed` |
| `reason` | 任意 | 状態を変える理由。前後の空白を除いて 400 文字まで。空白だけは理由なしとして扱う。省略すると理由を持たない | `案 A で決着` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | スレッドの ID |
| `status` | `open` \| `closed` | 呼んだ後の状態 |
| `changed` | bool | 状態を変えたか。既にその状態なら `false` で、何も書かない |

状態を変えても、利用者の書き込みの取り込み済みは書かない。
取り込んでいない利用者の書き込みを持つスレッドは、クローズにしても取り込み待ちに残る。

AI がクローズにできるのは、利用者の書き込みが全て取り込み済みで、AI の書き込みが全て利用者の既読のスレッドだけ。最後の書き込みが AI のものかは問わない。オープンに戻すときと、利用者が画面でクローズにするときは確かめない。

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 状態を変えたか、既にその状態だった |
| エラー | ワークスペースが無い・`id` のスレッドが無い・`reason` が上限を超える・`threads.yaml` がスキーマに合わないか YAML として読めない・書き込めなかった（前の `threads.yaml` を残す） |
| エラー（クローズにできない） | AI がクローズにしようとしたスレッドに、取り込んでいない利用者の書き込みか、利用者が読んでいない AI の書き込みがある。本文に、当たった条件ごとに書き込みの ID と、[スレッドの要約とタグを書き換える](#スレッドの要約とタグを書き換える)で取り込み済みにする案内か、利用者が読むまで開いたまま待つ案内を出す。何も書き込まない |
| エラー（MindStella のセッションでない） | MindStella のセッションでない呼び出し。何も書き込まない |

## スレッドの要約とタグを書き換える

スレッドの要約とタグを書き換え、AI が読んだ利用者の書き込みを取り込み済みにする。
返信せずに取り込むとき（クローズにする前・クローズのまま取り込むとき）に使う。

### 使い方

`update_thread` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "TH-1", "summary": "{書き直した要約}", "take": true}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | スレッドの ID | `TH-1` |
| `summary` | 任意 | 書き直した要約。前後の空白を除いて 1〜400 文字。省略すると変えない | `取り下げになった` |
| `tags` | 任意 | 置き換えるタグの一覧。どの文字列でも渡した表記のまま付く。重なりも空の文字列も持たない。空の一覧でタグを外す。省略すると変えない | `["起票"]` |
| `take` | 任意 | 真なら、そのスレッドの AI が既読にした、取り込んでいない利用者の書き込みを取り込み済みにする。省略すると偽 | `true` |

`summary`・`tags`・`take` のどれも渡さない（`take` が偽）呼び方はできない。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | スレッドの ID |
| `taken` | list[str] | 取り込み済みにした利用者の書き込みの ID。無ければ空 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き換えた（クローズのスレッドも書き換える） |
| エラー | ワークスペースが無い・`id` のスレッドが無い・`summary`・`tags`・`take` のどれも渡していない・`summary` が空か上限を超える・`tags` に重なりか空の文字列がある・`threads.yaml` がスキーマに合わないか YAML として読めない・書き込めなかった（前の `threads.yaml` を残す） |
| エラー（MindStella のセッションでない） | MindStella のセッションでない呼び出し。何も書き込まない |

## ワークスペースを作る

許可するフォルダの下に、ワークスペースの記録を作るか残っている記録を開き、project-index の配信元に登録して、ワークスペースの ID と画面の URL を返す。
同じ処理を、常駐サーバーの `POST http://127.0.0.1:{MINDSTELLA_PORT}/workspaces` も受ける（`Host` は `127.0.0.1:{ポート}`・`localhost:{ポート}` だけ）。
記録が無いフォルダには、`.mindstella/` に既定の設定（ワークスペースの ID・進め方の文書・タイトルにフォルダ名）と空の記録を作り、直下に本文のフォルダ `docs/` を作って `README.md` を書く。題名は、作った後に [設定を書き換える](#設定を書き換える)で書く。
記録が既にあるフォルダは、ワークスペースのバージョンがプラグインより古ければ、開く前に今のバージョンへ移し替える（[ワークスペースを今のバージョンへ移し替える](./セットアップ手順-ワークスペースを今のバージョンへ移し替える.mark.md)）。それ以外は記録を書き換えない。
フォルダを移したときは、同じワークスペースの ID のまま、配信元の行を移した先のフォルダへ変える。
開くときに、エージェントフローの配信元 `mindstella-agent-flows` の行が project-index の端末の設定に無ければ追加する。プラグインを上げた後の行は、常駐サーバーが起動したときに今のプラグインのフォルダへ書き換える（[常駐サーバーを確認する](#常駐サーバーを確認する)）。

```json
{"folder": "{フォルダの絶対パス}", "flow": {"source": "aituber", "doc": "flow-script"}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `folder` | 必須 | ワークスペースのフォルダの絶対パス。許可するフォルダ（project-index と共有する端末の設定のファイルの最上位の `mindstella.allowed_dirs`）のどれかの下。無ければ作る |
| `flow` | 任意 | 進め方の文書 `{source: 配信元の ID, doc: 文書の ID}`。記録が無いフォルダの設定にだけ記録する。配信元の `scope.read` にフォルダが含まれ、文書を取得できなければエラー |
| `mcp_config` | 任意 | Claude Code の `--mcp-config` に渡す JSON（`{"mcpServers": {...}}`）。`mindstella`・`project-index` の名前は使えない |
| `plugin_dirs` | 任意 | Claude Code の `--plugin-dir` に渡すフォルダの絶対パスの並び。どのフォルダも `.claude-plugin/plugin.json` を持つ |

`mcp_config`・`plugin_dirs` は、常駐サーバーの状態のフォルダ（`${XDG_STATE_HOME:-~/.local/state}/mindstella/`）にそのワークスペースの記録が無いときだけ記録する。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | ワークスペースの ID（`mindstella-{フォルダ名}-{ハッシュ}`）。project-index の配信元の ID と、MindStella のセッションの tmux のセッションの名前になる |
| `url` | str | 画面の URL（[プレビューの配信先を返却する](#プレビューの配信先を返却する)と同じ） |
| `result` | str | `created` 記録を作った・`opened` 残っている記録を開いた・`reopened` クローズしたワークスペースを再度開いた・`already_open` 既に開いている |
| `launch_options_recorded` | bool | 今回の `mcp_config`・`plugin_dirs` を記録したか |
| `migration` | {from_version, to_version, steps, not_carried} \| null | 記録を移し替えたときの報告。`not_carried` は移せずに記録から消えた値（項目・キー・値）。移し替えなかったときは `null` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 作った・開いた（API は `created` で 201、ほかは 200） |
| エラー | 本文が読めない（400）・許可するフォルダの外（403）・ワークスペースのバージョンがプラグインより新しい（409、`stage: version`。何も書き換えない）・同じ ID の記録が別のフォルダに残っている（409、`stage: duplicate`。そのフォルダのパスを示す）・記録が無いフォルダの直下に `docs/` か `files/` が既にある（409、`stage: root_folder`。改名してから再作成する。何も作らない）・`mcp_config`・`plugin_dirs`・`flow` が読めない（422）・移し替えが失敗した（422、`stage: migration`。コピーから元に戻す）・project-index へつながらないか配信元の行を追加・変更できない（502。この依頼で作った記録を削除する）。API はどれも `application/problem+json` で、失敗した段階を `stage` に持つ |

## ワークスペースを一覧する

常駐サーバーが知っているワークスペースのうち、クローズしていないものの ID・題名・画面の URL を返す。何も書き換えない。
常駐サーバーが知っているワークスペースは、状態のフォルダの ID の一覧にあるもの。一覧が無いときは、常駐サーバーが起動したときに配信元の行から再作成する。
同じ処理を `GET /workspaces[?include_closed=true]` も受ける。
クローズしたかは、project-index と共有する端末の設定のファイルを直接読んで判定する（project-index が止まっていても返す）。

```json
{"include_closed": true}
```

### 引数

| 引数 | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `include_closed` | 任意 | 真ならクローズしたワークスペースも含める。既定は偽 |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `workspaces[].id` | str | ワークスペースの ID |
| `workspaces[].title` | str \| null | 題名。記録が無いか題名が無ければ `null` |
| `workspaces[].url` | str \| null | 画面の URL。プレビューを配信していなければ `null` |
| `workspaces[].closed` | bool | クローズ済みか |
| `warnings` | list[{stage, detail}] | 端末の設定のファイルを読めないとき `stage: settings` の警告。無ければ空の並び |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 返した（端末の設定のファイルを読めないときは、`workspaces` を空の並びにして警告を付ける） |
| エラー | `include_closed` が `true`・`false` でない（API は 400、`stage: request`） |

## ワークスペースの状態を読み込む

ワークスペースの状態と MindStella のセッションの状態を、まとめて返す。何も書き換えない。
同じ処理を `GET /workspaces/{id}` も受ける。
停止の完了・活動の期限・再度開くかの判断と、追加の MCP・プラグインの記録が無いことに気づくのに使う。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c"}
```

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | ワークスペースの ID |
| `status` | str \| null | `active` 進行中（MindStella のセッションが無い・落ちたときを含む）・`stopped` 停止（停止を受けてクローズ待ち）・`closed` 完了（クローズ済み）。端末の設定のファイルを読めなければ `null` |
| `title` | str \| null | 題名 |
| `url` | str \| null | 画面の URL。プレビューを配信していなければ `null`（この操作は配信を始めない） |
| `closed` | bool \| null | クローズ済みか |
| `unseen_ai_posts` | int \| null | 利用者が読んでいない AI の書き込みの数 |
| `awaiting_user_posts` | int \| null | MindStella のセッションが取り込んでいない利用者のコメントの数 |
| `updated` | str \| null | 記録の最後の更新の日時（項目の変更とスレッドの書き込みのうち最も新しいもの） |
| `sessions` | list | [MindStella のセッションを一覧する](#mindstella-のセッションを一覧する)の `sessions` と同じ |
| `close_pending` | bool | クローズ待ちか |
| `launch_options_recorded` | bool | 追加の MCP・プラグインの記録があるか（中身は返さない。指定が空の記録も真）。偽なら [設定を書き換える](#設定を書き換える)で再指定し、[MindStella のセッションを再起動する](#mindstella-のセッションを再起動する) |
| `warnings` | list[{stage, detail}] | `records` 記録のフォルダが無いか読めない（`detail` にパスか理由）・`settings` 端末の設定のファイルを読めない。分からない項目は `null` にし、MindStella のセッションの部分は返す |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 返した（警告があるときも 200） |
| エラー | ワークスペースが無い（404、`stage: workspace`。削除したワークスペースを含む） |

## MindStella のセッションを作る

ワークスペースの MindStella のセッションを tmux のペインの中で起動し、SessionStart のフックが登録するのを待ってから、MindStella のセッションの ID・ペイン・画面の URL を返す。
同じ処理を `POST /workspaces/{id}/sessions` も受ける。
claude-balancer がある端末は `claude-balancer exec --client mindstella` で借りたアカウントの Claude Code を、無い端末は `claude` を起動する。`claude_config_dir` を渡すと、そのアカウントを借りて起動する。
準備ができたら、ペインに `[mindstella] MindStella のセッションを起動しました` を入力する。
止めた後・落ちた後の MindStella のセッションの会話の記録が残っていれば、`--resume` でその会話を引き継いで起動する。記録が参照できなければ、新規の会話で起動する。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `workspace_id` | 必須 | ワークスペースの ID |
| `claude_config_dir` | 任意 | 起動するアカウントの Claude Code の設定のフォルダ。claude-balancer がある端末ではこのアカウントを借り（`exec --account`）、無い端末では `CLAUDE_CONFIG_DIR` にする |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `session` | str | MindStella のセッションの ID（`S-` に続く 12 桁の 16 進） |
| `pane` | str | MindStella のセッションが動く tmux のペイン（`{ワークスペースの ID}:0.0`） |
| `url` | str | 画面の URL |
| `account` | str | 起動したアカウントの Claude Code の設定のフォルダの絶対パス（`CLAUDE_CONFIG_DIR` が無いまま起動したときは `~/.claude` の絶対パス） |
| `warnings` | list[str] | 状態のフォルダに追加の MCP・プラグインの記録が無く、指定なしで起動したとき `launch_record_missing` を含む。無ければ空の並び |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 起動した（API は 201） |
| エラー | ワークスペースが無い（404）・MindStella のセッションが既にある（409、`stage: exists`。動いている `session`・`pane` を持つ）・クローズ済み（409、`stage: closed`）・claude-balancer がアカウントを貸せない（503、`stage: account`。`claude_config_dir` を渡したときは、そのアカウントを貸せなくてもほかのアカウントでは起動しない）・Claude Code が起動直後に終わった（502、`stage: launch`）・30 秒以内に準備ができない（504、`stage: ready`）。起動できなかったときはペインを閉じ、状態を残さない |

## MindStella のセッションを一覧する

ワークスペースの最後の MindStella のセッション 1 つの状態を返す。停止の完了はこれで確かめる。
同じ処理を `GET /workspaces/{id}/sessions` も受ける。
状態が `running` でもペインか Claude Code のプロセスが無ければ、`crashed` を返す。状態は書き換えない（落ちたことの記録と Discord への通知は、常駐サーバーが起動したときと一定の間隔の見回りで行う）。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c"}
```

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `sessions[].id` | str | MindStella のセッションの ID |
| `sessions[].status` | str | `running` 起動中・`restarting` 再起動の途中・`stopping` 停止の途中・`stopped` 停止済み・`crashed` 落ちている |
| `sessions[].responding` | bool | 応答の途中か |
| `sessions[].pending_write` | bool | 停止を待つ上限を過ぎ、最後の書き込みを待っているか |
| `sessions[].pane` | str \| null | tmux のペイン。`stopped`・`crashed` では `null` |
| `sessions[].last_error` | str \| null | 最後の停止か再起動に失敗した段階と理由（`{段階}: {理由}`） |
| `close_pending` | bool | クローズ待ちか（停止かクローズを受けた後） |

一度も作っていないワークスペースは、`sessions` が空の並び。

## MindStella のセッションを止める

停止の依頼をすぐに受け付けて返し、クローズ待ちにしてから、応答の途中でなくなるのを待って MindStella のセッションを止める。
同じ処理を `DELETE /workspaces/{id}/sessions/{session}[?force=true]` も受ける。
止める前に、まだまとめていない変更を [書き換えをまとめる](#書き換えをまとめる)と同じ処理でまとめ、`/exit` を入力し、10 秒以内に終わらなければ SIGTERM を送信してペインを閉じる。
クローズ待ちの間とその後に届いたコメントは、スレッドに残し、ペインへ入力しない。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c", "session_id": "S-0123456789ab"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `workspace_id` | 必須 | ワークスペースの ID |
| `session_id` | 必須 | MindStella のセッションの ID |
| `force` | 任意 | 真なら応答の終わりを待たずに止める。まだまとめていない変更は、強制で止めた旨を説明に入れてまとめる |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `session` | str | 止める MindStella のセッションの ID |
| `status` | str | `stopping` 受け付けて止め始めた（API は 202）・`stopped` 既に止まっていた（落ちていたものを含む。API は 200） |

応答の終わりを 90 分待っても終わらなければ、止めずに `pending_write` を真にして `running` に戻す。止める間に失敗したら、`status` を戻して `last_error` に段階と理由を入れる。

## MindStella のセッションを再起動する

再起動の依頼をすぐに受け付けて返し、MindStella のセッションを同じ ID のまま止めて再起動する。
同じ処理を `POST /workspaces/{id}/sessions/{session}/restart[?force=true]` も受ける。
止め方は [MindStella のセッションを止める](#mindstella-のセッションを止める)と同じで、Claude Code が終わった後に claude-balancer の `exec` が終わるのを 75 秒まで待ってから起動する。
会話の記録が残っていれば `--resume` で前の会話を引き継ぎ、claude-balancer は前回のアカウントを優先して貸す。
クローズ待ちのワークスペースは、クローズ待ちを解いて再起動する。

常駐サーバーは、次のときにも同じ処理で自動で再起動する。

| 契機 | 再起動の方法 |
| --- | --- |
| 利用上限に達した | 応答の終わりを待たずに止め、利用上限に達していないアカウントで前の会話を引き継ぐ |
| 会話を圧縮しようとした | 圧縮を止め、応答の終わりを待たずに止めて、新規の会話で起動する。起動と再開のエージェントフローで記録と commit から作業に戻る |
| 落ちた後にコメントが届いた | 再起動してから、届いたコメントを入力する。クローズ待ち・クローズの後は再起動しない |
| 使用中のアカウントの利用枠がしきい値以上になった | 応答の終わりを待って止め、しきい値以上でないアカウントで前の会話を引き継ぐ。ほかに貸せるアカウントが無いときと、claude-balancer の利用枠を確かめられないときは止めずに続ける |

常駐サーバーは 60 秒ごとに `running` の MindStella のセッションを見回り、落ちていれば `crashed` として記録する。
同じく 60 秒ごとに claude-balancer の `GET /accounts` で使用中のアカウントの利用枠を確かめる。しきい値は claude-balancer の設定の貸与のしきい値で、MindStella は持たない。

アカウントを指定して起動した MindStella のセッションは、再起動しても指定したアカウントを借りる。
指定したアカウントが利用上限に達したとき・しきい値以上になったとき・借りられないときは、指定を解除して claude-balancer が選ぶアカウントで再起動し、以降はアカウントを指定しない MindStella のセッションとして扱う。
解除しないようにするには、[ホームの設定](#ホームの設定)の `account.release_on_limit` を `false` にする。このときは、しきい値では再起動せず、利用上限では止めたまま再起動しない。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c", "session_id": "S-0123456789ab"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 |
| --- | --- | --- |
| `workspace_id` | 必須 | ワークスペースの ID |
| `session_id` | 必須 | MindStella のセッションの ID |
| `force` | 任意 | 真なら応答の終わりを待たずに止める |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `session` | str | MindStella のセッションの ID（再起動で変わらない） |
| `status` | str | 常に `restarting`（API は 202） |
| `warnings` | list[str] | 状態のフォルダに追加の MCP・プラグインの記録が無いとき `launch_record_missing` を含む。無ければ空の並び |

再起動の完了と失敗は [MindStella のセッションを一覧する](#mindstella-のセッションを一覧する)で確かめる。
応答の終わりを 90 分待っても終わらなければ、再起動せずに `pending_write` を真にして `running` に戻す。
再起動に失敗したら（claude-balancer に空いたアカウントが無い・記録した追加の MCP やプラグインを読み込めない・準備ができない）、`crashed` にして `last_error` に段階（`account`・`launch_options`・`launch`・`ready`）と理由を入れる。

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 再起動を受け付けた（API は 202） |
| エラー | ワークスペースが無いか、最後の MindStella のセッションでない（404）・クローズ済みか、停止の途中・再起動の途中（409、`stage` は `closed`・`stopping`・`restarting`） |

## ワークスペースをクローズにする

[ワークスペースを再度開く](#ワークスペースを再度開く)でも戻せる。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c"}
```

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | クローズにしたワークスペースの ID |
| `closed` | bool | 常に `true` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | クローズにした（既にクローズ済みのときも成功） |
| エラー | ワークスペースが無い（404）・MindStella のセッションがある（409、`stage: session`）・project-index へつながらない（502） |

## ワークスペースを再度開く

クローズしたワークスペースの、project-index の配信元の行を `outside_read: true` に戻し、クローズ待ちを解く。
クローズしていないワークスペースは、クローズ待ちだけを解く。
同じ処理を `POST /workspaces/{id}/reopen` も受ける。
MindStella のセッションは起動しない。クローズ待ちの間に届いたコメントは、取り込み待ちのままスレッドに残る。
再度開いた後は、[MindStella のセッションを作る](#mindstella-のセッションを作る)で、クローズの前と同じ進め方の文書・追加の MCP・プラグインで起動できる。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c"}
```

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 再度開いたワークスペースの ID |
| `reopened` | bool | 配信元の行を戻したとき `true`。クローズしていなかったとき `false` |
| `closed` | bool | 常に `false` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 再度開いた（クローズしていないワークスペースも成功） |
| エラー | ワークスペースが無い（404、`stage: workspace`）・project-index へつながらない（502、`stage: source`） |

## ワークスペースを削除する

クローズしたワークスペースの、project-index の配信元の行と、状態のフォルダのそのワークスペースの記録（`workspaces/{ID}/`）と ID の一覧の行を削除する。
同じ処理を `DELETE /workspaces/{id}` も受ける。
そのワークスペースのプレビューの配信と変更の検知も止める。
記録のフォルダ（`.mindstella/`）は削除しない。同じフォルダで[ワークスペースを作る](#ワークスペースを作る)を呼ぶと、残った記録を開く。
途中で失敗したときは ID の一覧の行が残るので、同じ削除をもう一度呼べば残りを削除できる。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c"}
```

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 削除したワークスペースの ID |
| `deleted` | bool | 常に `true` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 削除した（配信元の行が既に無かったときも成功） |
| エラー | ワークスペースが無い（404、`stage: workspace`。削除済みを含む）・クローズしていない（409、`stage: not_closed`）・状態のフォルダを削除できない（500、`stage: state`）・project-index へつながらない（502、`stage: source`） |

## ワークスペースの設定を書き換える

ワークスペースの設定のキー（[設定を書き換える](#設定を書き換える)と同じキー）と進め方の文書を `.mindstella/config.yaml` に、追加の MCP・プラグインを状態のフォルダの `workspaces/{ID}/launch.json` に書き換える。
同じ処理を `PATCH /workspaces/{id}` も受ける。
指定した引数だけを書き換え、指定しなかった引数の値は残す。どれか 1 つでも読めない指定があるときは、何も書き換えない。
起動中の MindStella のセッションには反映しない。反映するときは[MindStella のセッションを再起動する](#mindstella-のセッションを再起動する)を呼ぶ。次に[MindStella のセッションを作る](#mindstella-のセッションを作る)ときも、書き換えた指定で起動する。
クローズしたワークスペースも書き換えられる。再度開いた後に作る MindStella のセッションから、書き換えた指定で起動する。

```json
{"workspace_id": "mindstella-家計簿アプリ-3f2a9c", "flow": {"source": "aituber", "doc": "FLOW-3"}, "plugin_dirs": ["/home/user/plugins/aituber"]}
```

### 引数

| 引数 | 型 | 説明 |
| --- | --- | --- |
| `workspace_id` | str | ワークスペースの ID |
| `settings` | object | 書き換える設定のキー（`summary`・`description`・`links`・`history_limit`・`display`・`transcription`・`mdmark`）。省略できる |
| `flow` | object | 進め方の文書（`source`: project-index の配信元の ID、`doc`: 文書の ID）。省略できる |
| `mcp_config` | object | Claude Code の `--mcp-config` に渡す JSON（`{"mcpServers": {...}}`）。空にするときは `{"mcpServers": {}}`。省略できる |
| `plugin_dirs` | list[str] | Claude Code の `--plugin-dir` に渡すフォルダの絶対パス。空にするときは `[]`。省略できる |
| `remove_flow` | bool | `true` のとき進め方の文書を外す。`flow` と同時には指定できない。省略すると `false` |

`workspace_id` のほかに、1 つ以上の引数を指定する。`PATCH /workspaces/{id}` では、`remove_flow` の代わりに本文の `flow` を `null` にすると進め方の文書を外す。`settings` を指定するときは、1 つ以上のキーを持たせる（空のオブジェクトは 400、`stage: body`）。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 書き換えたワークスペースの ID |
| `changed` | list[str] | 値が変わったキー（設定のキーの名前と `flow`・`mcp_config`・`plugin_dirs`）。同じ値を指定したときは空 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き換えた（値が変わらなかったときも成功） |
| エラー | 指定が無い・構造が違う（400、`stage: body`）・ワークスペースが無い（404、`stage: workspace`）・記録のフォルダが無い（409、`stage: records`）・読めない指定（422、`stage` は `mcp_config`・`plugin_dirs`・`settings`・`flow` のどれか）・書き込めない（500、`stage: write`）・project-index へつながらない（502、`stage: source`） |

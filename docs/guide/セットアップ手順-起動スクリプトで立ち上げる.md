# 起動スクリプトで立ち上げる

mindstella のスキルを使い始めるとき、話し合いを再開するとき、止まったサーバーを立ち上げ直すときに実行する。

## 前提

- [プラグインをインストールする](./セットアップ手順-プラグインをインストールする.md)
- Python 3.12 以上（`venv` を含む）、`tmux`、`claude` が `PATH` にある
- systemd --user が使える（[常駐サーバーを起動する](./セットアップ手順-常駐サーバーを起動する.md)）
- ワークスペースのフォルダが、グローバルの設定のファイル（project-index と共有する端末の設定）の `mindstella.allowed_dirs` のどれかの下にある
- claude-balancer を使うときは、claude-balancer の設定の `clients` に `mindstella` がある

## 手順

### プラグインのフォルダを引く

```bash
claude plugin list --json
```

出力の `mindstella@mindstella` の `installPath` が `{プラグインのフォルダ}`。
出なければ、プラグインがインストールされていない。

### 起動スクリプトを叩く

```bash
{プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ} [--flow {配信元の ID}#{文書の ID}] [--mcp-config {ファイル}] [--plugin-dir {フォルダ}]...
```

依存を確かめ、mindstella の常駐サーバーが落ちていれば起動してから、MindStella の API でワークスペースと MindStella のセッションを作り、画面の URL を出して、そのセッションのペインへつなぐ。
MindStella のセッションは、tmux のセッション `mindstella-{フォルダ名}-{ハッシュ}` の中で、claude-balancer がある端末では一番空いているアカウントで、無い端末では既定のアカウントで起動する。
ワークスペースのフォルダが無ければ作り、記録が残っていればその記録を開く。
同じワークスペースの MindStella のセッションが既にあれば、新しく作らずにそのペインへつなぐ。
標準出力が端末でないときは、つながずに、画面の URL とつなぐコマンドを標準出力に出して終わる。

| 引数 | 中身 |
| --- | --- |
| `--flow` | 進め方の文書（project-index の配信元の ID と文書の ID）。新しく作るワークスペースの設定にだけ記録し、SessionStart で MindStella のセッションに場所を伝える |
| `--mcp-config` | 追加の MCP の定義の JSON のファイル（Claude Code の `--mcp-config` と同じ形）。`mindstella`・`project-index` の名前は使えない |
| `--plugin-dir` | 追加のプラグインのフォルダ（何度でも）。`.claude-plugin/plugin.json` を持つフォルダ |

追加の MCP とプラグインは、端末の状態のフォルダ（`~/.local/state/mindstella/`）にワークスペースごとに記録し、記録が無いときだけ今回の指定を記録する。

依存が足りないと、標準エラーに足りないものとそろえるコマンドを出して、終了コード 1 で止まる。
ワークスペースも MindStella のセッションも作られないので、[スクリプトの依存を入れる](./セットアップ手順-スクリプトの依存を入れる.md)を実行してから叩き直す。

常駐サーバーを起動できない（待ち受けのポートがほかのプロセスに使われている・systemd --user が使えない）と、標準エラーに理由と案内を出して、終了コード 1 で止まる。
古いコードの常駐サーバーが待ち受けているときは、再起動せずに違いと `mindstella server restart` の手順を標準エラーに出し、ワークスペースと MindStella のセッションは作る。

ワークスペースを作れない（許可するフォルダの外・読めない指定・参照できない進め方の文書）と、MindStella の API が返した理由を出して、終了コード 1 で止まる。
MindStella のセッションを作れない（claude-balancer に空いたアカウントが無い・準備ができない）と、理由と画面の URL を出して、終了コード 1 で止まる。ワークスペースは開いたまま残る。

### MindStella のセッションを止め、ワークスペースをクローズにする

MindStella のセッションで `/exit` を打つか、Claude Code に MindStella の MCP のツール `stop_session` を頼むと止まる。
止めた後に `close_workspace` を頼むと、ワークスペースをクローズにし、作業範囲の外から参照できなくなる。
クローズの後に画面から送ったコメントはスレッドに残り、MindStella のセッションは起動しない。
クローズしたワークスペースは、同じフォルダで起動スクリプトを叩くと開き直す。

### 登録した alias から叩く

[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)と、`{プラグインのフォルダ}` を引かずに、新しいシェルで alias にワークスペースのフォルダを渡して立ち上げられる。

```bash
mindstella {ワークスペースのフォルダ}
```

alias は、叩くたびに今の `installPath` を引く。
Claude Code のアカウントごとの alias `mindstella-{アカウントの名前}` は、そのアカウントの設定のフォルダを `CLAUDE_CONFIG_DIR` で渡す。
`CLAUDE_CONFIG_DIR` は、claude-balancer が無い端末でだけ MindStella のセッションのアカウントになる。

### 外から見る設定を渡す

[プレビューを外から見る](./セットアップ手順-プレビューを外から見る.md)の設定は、起動スクリプトを叩くシェルの環境変数で渡す。
[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)で登録すると、新しいシェルに入っているので、叩くたびに打たなくてよい。
登録しないときは、叩くときに環境変数を前に置く。

```bash
MINDSTELLA_ALLOWED_HOSTS=preview.example.com {プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ}
```

渡せる環境変数は、`MINDSTELLA_PORT`（常駐サーバーの待ち受けのポート）・`MINDSTELLA_ALLOWED_HOSTS`（許可するホスト名）・`MINDSTELLA_PREVIEW_START_HOOK`（配信を立てたときのフック）・`MINDSTELLA_PREVIEW_STOP_HOOK`（配信を止めるときのフック）・`MINDSTELLA_TRANSCRIBER`（文字起こしのサービス）・`MINDSTELLA_TRANSCRIBER_URL`（文字起こしのサービスの待ち受けの URL）・`PROJECT_INDEX_PORT`（project-index のポート）。
常駐サーバーを起動するときに、叩いたシェルの環境のままユニットの `Environment=` に書き、MindStella のセッションの環境には追加しない。
常駐サーバーが既に待ち受けていると、新しい値は効かない。
`mindstella server restart` で起動し直すと効く。

### スキルを呼ぶ

つないだ MindStella のセッションで、スキルを呼ぶ。

```
/mindstella:setup {ワークスペースのフォルダ}
```

起動スクリプト以外で立ち上げた Claude Code でも、常駐サーバーが待ち受けていれば MCP のツールが載る。
MindStella のセッションがあるワークスペースでは、プレビューから送ったコメントは MindStella のセッションのペインへ入力される。
tmux の外で立ち上げた Claude Code では、プレビューから送ったコメントが Claude Code へ入力されない。
その会話でスキル `setup` を呼ぶと、未登録なら[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)が持ちかけられる。

## 反映

即時。

## 確認

#### セッションが立っている

```bash
tmux list-sessions
```

`mindstella-{フォルダ名}-{ハッシュ}` が出る。
名前はワークスペースの ID と同じで、ハッシュはワークスペースのフォルダの絶対パスの SHA-256 の先頭 6 桁。別の場所にある同じ名前のフォルダは別のセッションになる。
先にあった MindStella のセッションは起動し直されない。

## 元に戻す

MindStella のセッションを止める（`/exit` か `stop_session`）。
止めた後に残るものは、次のとおり。

| 残るもの | 扱い |
| --- | --- |
| ワークスペースのフォルダ | 消えずに残る。要らなければ手で消す |
| 端末の状態のフォルダ（`~/.local/state/mindstella/`） | ワークスペースの ID の一覧と、ワークスペースごとの MindStella のセッションの状態・追加の MCP とプラグインの記録が残る |
| project-index の配信元の行 | ワークスペースの行が残る（クローズでは参照の範囲から外れる） |
| 常駐サーバーとプレビューの配信 | ほかのセッションと共有しているため、止まらずに残る。止めるときは[常駐サーバーを起動する](./セットアップ手順-常駐サーバーを起動する.md)の手順で止める |

# 常駐サーバーを起動する

mindstella のツールが Claude Code に無いとき、常駐サーバーの状態を確かめたいとき、常駐サーバーを止めたいとき、待ち受けのポートを変えたいとき、プラグインを上げた後に古いコードのままと出たときに実行する。

## 前提

- [プラグインをインストールする](./セットアップ手順-プラグインをインストールする.md)
- [スクリプトの依存を入れる](./セットアップ手順-スクリプトの依存を入れる.md)で、スキル専用の仮想環境に依存がそろっている
- systemd --user が使える（`systemctl --user show-environment` が終了コード 0 で終わる）

mindstella のツールは、端末に 1 つの常駐サーバーが持つ。
常駐サーバーは systemd --user のユニット `mindstella.service` として動き、並行する複数の Claude Code のセッションが共有する。
Claude Code を立ち上げると、プラグインのフックが常駐サーバーを確かめ、落ちていればユニットを書いて起動する。
[起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md)ときも、起動スクリプトが同じように起動する。

## 手順

### 常駐サーバーを起動する

```bash
python3 {プラグインのフォルダ}/skills/mindmap/scripts/ensure_server.py
```

`{プラグインのフォルダ}` の引き方は [起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md#プラグインのフォルダを引く)。
常駐サーバーが落ちていれば、`~/.config/systemd/user/mindstella.service` を書いて起動し、標準エラーに `[mindstella]` で始まる、起動したポートの行を出す。
既に待ち受けていれば、何も出さずに終わる。
systemd --user が使えない端末では起動せず、systemd --user が要ることを出して、終了コード 1 で止まる。
起動した後は、開いている Claude Code で `/mcp` を実行し、mindstella につなぎ直す。

依存が足りないと、足りないものとそろえるコマンドを出して、終了コード 1 で止まる。
[スクリプトの依存を入れる](./セットアップ手順-スクリプトの依存を入れる.md)を実行してから叩き直す。

### ポートを変える

常駐サーバーは `127.0.0.1` の 8784 で待ち受ける。
ほかのプロセスが 8784 を使っていると、常駐サーバーを起動せずに、使われているポートと `MINDSTELLA_PORT` の案内を出して、終了コード 1 で止まる。
別のポートを、環境変数 `MINDSTELLA_PORT` で渡す。

```bash
MINDSTELLA_PORT=8790 python3 {プラグインのフォルダ}/skills/mindmap/scripts/ensure_server.py
```

渡した値はユニットの `Environment=` に書かれる。
Claude Code も同じ `MINDSTELLA_PORT` でつなぐので、Claude Code を立ち上げるシェルにも同じ値を設定する。
[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)で `MINDSTELLA_PORT` を登録すると、新しいシェルの全てに入る。

### 状態を確かめる

```bash
{プラグインのフォルダ}/bin/mindstella server status
```

待ち受けのポート・バージョン・読み込んだプラグインのフォルダと、配信しているワークスペースごとのポートを出す。
Claude Code からは、ツール `server_status` が同じ値を返す（[常駐サーバーの状態を読む](./コマンド.md#常駐サーバーの状態を読む)）。

### 止める

```bash
{プラグインのフォルダ}/bin/mindstella server stop
```

`systemctl --user stop mindstella.service` で止める。
配信ごとに終了時のフック（`MINDSTELLA_PREVIEW_STOP_HOOK`）を呼び、全てのプレビューの配信を止めて、常駐サーバーを終える。
並行する全てのセッションから mindstella のツールが使えなくなる。
次に Claude Code を立ち上げたとき、そのときにインストールされているバージョンで起動する。

### プラグインを上げた後

古いコードの常駐サーバーが待ち受けていると、Claude Code を立ち上げたとき・起動スクリプトを叩いたときに、常駐サーバーが読み込んだプラグインのフォルダとインストールしたフォルダの違いと、再起動の手順が出る。
`version.ini` のバージョンが同じでも、フォルダ（コミットの名前）が違えば出る。
常駐サーバーは並行するほかのセッションが使っているため、自動では再起動しない。

```bash
{プラグインのフォルダ}/bin/mindstella server restart
```

インストールしたプラグインのフォルダでユニットを書き直してから、常駐サーバーを起動し直す。

## 反映

即時。

## 確認

#### 常駐サーバーが待ち受けている

```bash
curl -s http://127.0.0.1:${MINDSTELLA_PORT:-8784}/_admin/status
```

`"name": "mindstella"` を持つ JSON が出る。

#### Claude Code がつながっている

```bash
claude mcp list
```

`plugin:mindstella:mindstella` がつながった状態で出る。

## 元に戻す

常駐サーバーを止める。
Claude Code を立ち上げると、また起動する。

止めた後に残るものは、次のとおり。

| 残るもの | 扱い |
| --- | --- |
| `~/.mindmap/server.log` | 常駐サーバーの標準出力と標準エラーの記録。要らなければ手で削除する |
| `~/.config/systemd/user/mindstella.service` | 常駐サーバーのユニット。次に起動するときに書き直される |
| ワークスペースのフォルダ | 削除されずに残る |

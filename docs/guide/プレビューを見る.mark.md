# プレビューを見る

話し合いの記録を、サーバーが配るプレビューをブラウザで開いて読み返し、コメントを溜めて送信する。
項目と設定は、画面から修正して保存待ちに溜め、まとめて保存できる。
項目や選んだ箇所へのコメントもレビュー中に溜め、まとめて送信できる。送信したコメントはスレッドになり、AI の返信をスレッドで読める。

## 前提

- [セットアップから始める](./話し合い-セットアップから始める.md)で作った、`.mindstella/config.yaml` があるワークスペース
- mindstella の常駐サーバーにつながった Claude Code（[常駐サーバーを起動する](./セットアップ手順-常駐サーバーを起動する.md)）。コメントを Claude Code へ入力するときは、[起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md)で立ち上げた Claude Code
- [動作環境](./動作環境.mark.md#プレビュー)を満たすブラウザ

## 手順

### プレビューの URL を示してもらう

MindStella のセッションにプレビューを頼む。
MindStella のセッションが、サーバーが配るプレビューの URL（`http://127.0.0.1:{ポート}/w/{ワークスペースの ID}/`）を示す。ブラウザは自動では開かない。
ポートは常駐サーバーのポート（`MINDSTELLA_PORT`。無ければ 8784）で、全てのワークスペースの画面を同じポートの、ワークスペースごとのパスで配る。
示された URL は、ワークスペースの直下の `README.md` のプレビューのセクションにも書かれる。
スマートフォンなど端末の外から開くときは、[プレビューを外から見る](./セットアップ手順-プレビューを外から見る.md)。

### ブラウザで開く

示された URL をブラウザで開く。
開くと概要が出る。

ワークスペースの YAML が書き換わると、再読み込みの操作なしで画面に反映される。
入力欄にカーソルがある間と、音声入力で録音を始めてから文字起こしの結果が入るまでの間は、書き換わっても画面に反映せず、入力欄から離れると反映する。
入力欄の外を押すなどしてカーソルが離れ、音声入力もしていないときに、まとめて反映される。
入力中の文字・変換中の文字・録音は、書き換えで途切れない。
配信は常駐サーバーが持つので、Claude Code を閉じても止まらず、同じ URL で開ける。再起動した Claude Code で再依頼しても、同じ URL が示される。
常駐サーバーを止めると配信も止まり、開いたままの画面のトップバーにつながらないマーカーが出て、前に読んだ記録のまま残る。
マーカーにマウスを乗せると「サーバーにつながりません（{日時} に読んだ記録）」が出る。
読み返したいときは、起動スクリプトで再起動して、示された新しい URL で開く。

トップバーの接続の状態の右の更新のボタン（回る矢印）を押すと、ページを再読み込みせずにサーバーへ接続し直し、最新の記録を読み込み直す。つながっている間も押せる。
開いている項目・絞り込み・入力中のコメントはそのまま残る。
入力中で画面への反映を待っている間は、更新のボタンの右上に点が出て、マウスを乗せると「更新があります。最新の記録を読み込む」が出る。
画面を閉じずに別のタブやアプリから戻ったときに接続が切れていれば、ボタンを押さなくても接続し直す。

描画のライブラリと文字を、開いたときにネットから読む。
読み込めなかったライブラリがあると、それを使う箇所に名前が出る。
本文とスレッドの書き込みを描く mdmark が読み込めなかったときは、名前の知らせと一緒に、Markdown の原文が出る。

### 画面を移る

上のトップバーに、話し合いのタイトル・検索・変更履歴・表示の設定・絞り込み・保存待ち（溜めた編集があるときだけ）・コメント・ライトとダークの切り替えのボタンと、画面を移るタブの帯がある。
トップバーのボタンはアイコン（と件数）だけで、マウスを乗せるか Tab キーで選ぶと、ボタンの下に名前が出る。
タブの帯で、概要・検討事項・タスク・調査・資料・用語集・メモ・会話ログを移る。タブには、アイコンと項目の件数が付く。
[表示の設定](#表示の設定を変える)で外した種類のタブは出ない。
タブを移っても、開いていた詳細パネルは閉じない。
トップバーとタブの帯は、どの画面でもどこまでスクロールしても見えたまま残る。
表・ボードは帯の下の領域の中で縦・横にスクロールでき、ページ全体は送信しない。ボードは、カードの無い所をマウスでドラッグしても横にスクロールできる。幅 720px 以下では、帯の下の領域ごと送信する。

URL の search params（配る書き出しでは `#/?` に続く部分）に、画面と開いている項目が入る。
同じ URL を再度開くと、同じ画面と項目が開く。
ブラウザの戻る・進むで、開いてきた項目と、絞り込み・並べ替えの変更を 1 つずつたどれる。タブを移っても履歴は増えない。

| 画面 | 見方 |
| --- | --- |
| 概要 | タイルで状況を見る |
| 検討事項 | ボード（既定）・表を切り替える |
| タスク | ボード（既定）・表を切り替える |
| 調査・用語集・メモ・会話ログ | 表で見る |
| 資料 | カード（既定）・ボード・表を切り替える |

### 概要で状況を参照する

題名の上に、設定の話し合いの概要（何についての話し合いかを 1 文で書いたもの）が出る。
概要を持たない設定では、行が出ない。

概要は、次のタイルを並べる。

<!-- table: {"kind": "data"} -->

| タイル | 中身 |
| --- | --- |
| 未読の AI の書き込み | まだ読んでいない AI の書き込みを持つオープンのスレッド。最後の未読の書き込みの新しい順に、タイルに収まるだけ並ぶ |
| 未決定 | 未決定の検討事項。ID の順に、タイルに収まるだけ並ぶ |
| 要見直し | 要見直しの検討事項 |
| 確認中の資料 | 状態が確認中の資料 |

<!-- /table -->

項目を押すと、詳細パネルが開く。未読の AI の書き込みの行を押すと、コメントの一覧でそのスレッドが開く。
「すべて表示」を押すと、その条件で絞った画面を開く。ドロワーにその条件が選ばれ、絞り込みのボタンにバッジが付く。未読の AI の書き込みの「すべて表示」は、コメントの一覧を開く。

### 絞り込みのドロワーで絞り込む

概要を除く、項目を並べる画面（検討事項・タスク・調査・用語集・メモ・会話ログ・資料）で、同じ操作で絞り込める。
トップバーのコメントのボタンの隣にある絞り込みのボタンを押すと、見ている画面に重ねて左からドロワーが開く。
条件ごとに、値を件数つきのチェックボックスで選ぶ。
値の条件の上の「文字を含む」には、ID・タイトル・用語・意味など値を選ばない列の欄が並び、入れた文字を含む項目に絞る。大文字・小文字は区別しない。

<!-- table: {"kind": "data"} -->

| 画面 | 条件 |
| --- | --- |
| 検討事項 | 状態・タグ・着手可否 |
| タスク | 種類・状態・タグ |
| 資料 | 種類・状態・タグ |
| 調査・用語集・メモ・会話ログ | タグ |

<!-- /table -->

同じ条件の中で複数の値を選ぶと、どれかに合う項目を出す。条件どうしは、全てに合う項目を出す。
タグだけは、条件の見出しの下の「すべて含む / どれかを含む」で組み合わせ方を選ぶ。既定の「すべて含む」は選んだタグを全て持つ項目を、「どれかを含む」はどれかを持つ項目を出す。「どれかを含む」でタグを 2 つ以上選ぶと、チップは「タグ（どれかを含む）: {名前}」で出る。
タグの条件の見出しの下の「簡易 / 詳細」で指定方法を切り替えられる。
「詳細」では、「含む / 含まない」の条件を「すべて一致 / いずれか一致 / 一致しない」のグループで組み合わせ、グループを 3 段まで入れ子にできる（「画面」を含み「廃止」を含まない、など）。
条件のタグは、選択したタグだけがチップで並び、残りは入力欄に入れて候補から追加する。
「詳細」で簡易で表せない条件にしている間は「簡易」を選べず、チップは「タグ: 「画面」を含む かつ 「廃止」を含まない」のように条件を文で出し、× でタグの条件ごと外せる。
値を 1 つも選んでいない条件では、絞らない。
値の右の件数は、その条件以外の条件で絞った項目のうち、その値を持つ項目の数で、0 件になる値は薄く出るが選べる。
見出しの右には、何も選んでいなければ「{件数} 件」、選んでいれば「{件数} 件中 {合う件数} 件」が出る。
値を選んだ条件には「{件数} 件を選択」と「解除」が付き、下端の「すべて解除」で全ての条件を外せる。
選んだ条件は、ツールバーの下にチップでも出て、× で 1 つずつ、「すべて解除」で全てを外せる。
ドロワーで値を選ぶ・外す・すべて解除する・組み合わせ方やプリセットを選ぶたびに、ブラウザの戻る操作で 1 つ前の条件へ戻れる。文字の条件は、打ち終えた（入力を止めた・Enter を押した・欄を離れた）単位で 1 つ戻る。文字の条件のチップは「用語に「移し」を含む」の構造で出る。

絞り込みのボタンには、値を 1 つ以上選んでいる条件の数がバッジで出る。選んだ値の数ではない。
状態で 4 つ、タグで 1 つ選んでいれば、バッジは 2 になる。何も選んでいなければ、バッジは出ない。

ドロワーの先頭には、AI が作った絞り込みのプリセットが「{名前} {件数} 件」のボタンで並ぶ（プリセットが無いときは出ない）。
件数はその画面の項目のうちプリセットに合う数で、0 件のプリセットは破線の枠線と薄い文字で出るが選べる。
プリセットを押すと、タグの条件がプリセットの条件に置き換わり、状態・種類などほかの条件は残る。簡易で表せる条件は簡易に、表せない条件は詳細に入る。
今のタグの条件がプリセットと同じときは、そのプリセットが選択済みの見た目になる。プリセットだけを解除する操作は無く、タグの条件を外すと解除される。

プリセットのまとまりの下の「プリセットとして保存」を押すと、今のタグの条件に名前を付けてプリセットとして保存できる。名前を入れて「保存」を押すと、プリセットが並びの末尾に加わる。
保存するのはタグの条件だけで、状態・種類・文字の条件は保存しない（ほかの条件を選んでいるときは、名前の入力の下にその旨が出る）。
タグの条件を選んでいないときは押せず、下に理由が出る。同じ名前（全角半角・大文字小文字の違いだけのものを含む）のプリセットが既にあるときは保存されず、名前の入力の下に理由が出る。

開いたときの条件は、画面で決まる。

- 検討事項は、ボード・表とも、状態で要見直し・未決定・未整理・保留を選んだ状態で開く
- ほかの画面は、何も選んでいない状態で開く
- 概要のタイルの「すべて表示」や進捗のセルから開いたときは、URL の search params の `f.{列}` の条件だけが選ばれた状態で開く

サーバーの配信で開いたときは、選んだ条件とタグの組み合わせ方・詳細のタグの条件が画面ごとにそのブラウザのタブに残り、ほかの画面へ移って戻っても、同じタブで再読み込みしても同じ条件で開く。ブラウザのタブを閉じると残らない。
残した条件は上の画面ごとの条件より先に当たるが、`f.{列}` で開いたときはその条件で開き、残した条件をその条件に書き換える。配る書き出しでは残らない。

表・ボード・カード・詳細パネルのタグを押すと、詳細を開かずに、そのタグが開いている画面の絞り込みに加わる。既に絞り込みにあるタグを押しても条件は変わらない。詳細のタグの条件で絞っている間は、今の条件と押したタグの「含む」が「すべて一致」でまとまる。ブラウザの戻る操作で、加える前の条件に 1 つずつ戻る。
概要から開いた詳細パネルでタグを押すと、その項目の種類の画面へ移り、そのタグで絞った状態で開く。

ほかの画面（タブ）へ移って戻ったとき・ブラウザの戻る・進むで戻ったときは、表・ボード・カードのスクロール位置が離れる前の位置に戻る。

ボード・カード・表を切り替えても、選んだ条件は保たれる。
ボードでは、状態の条件から外した状態の列も残り、列の中に「状態の条件で外しています。」と出る。
条件に合う項目が無いときは、画面に、条件のせいで空になっている旨が出る。

開いている間、トップバーとタブの帯とドロワー以外はグレーアウトし、透けて見えるが操作できない。
閉じるには、ドロワーの見出しの ×・下端の「{件数} 件を表示」・Esc・グレーアウトした所の押下のどれかを使う。トップバーの絞り込みのボタンをもう一度押しても閉じる。
コメントの一覧とは同時に開かず、どちらかを開くと他方が閉じる。
幅 900px 以下では、ドロワーは画面の幅いっぱいに出る。
詳細パネルを開いていても、ドロワーは詳細パネルの前に出る。閉じると、開く前の詳細パネルが見える。

### 表で絞り込む

どの表でも、同じ操作ができる。

| 操作 | やり方 |
| --- | --- |
| 並べ替える | 列の見出しを押す。昇順 → 降順 → 解除の順に変わり、ブラウザの戻る操作で 1 つ前の並びへ戻れる |
| 絞り込む | 絞り込みのボタンを押し、ドロワーで値を選ぶか、列の文字を入れる（[絞り込みのドロワーで絞り込む](#絞り込みのドロワーで絞り込む)）。かかっている条件は表の上にチップで出て、1 つずつ・全部を解除できる |
| 列を固定する | 列の見出しのピンのボタンを押す。左端から押した列までが、横にスクロールしても固定される。固定中の列をもう一度押すと外れる |
| 表示する列を選ぶ | 表の右上の「列の表示」のボタンを押し、列を付け外しする。タイトルの列は外せない |
| 初期設定に戻す | 「列の表示」のボタンから、列・並べ替え・固定を初期設定に戻す |

操作しても、スクロールの位置は変わらない。
表で絞り込んだ条件は、ドロワーで選んだ条件と同じくそのブラウザのタブに残る。概要から絞って開いたときは、ドロワーでその条件が選ばれ、チップが付いた状態で開く。
列の表示で選んだ列は、この端末に残る。表示の設定の「既定に戻す」で外れる。
表には「作成日時」「更新日時」の列がある。今年の日時は `MM/DD HH:mm`、今年でない日時は `YYYY/MM/DD HH:mm` で出る。

### カード・ボードを並べ替える

検討事項・タスク・資料のカードとボードのカードに、作成日時と更新日時が「作成 11/02 10:15　更新 11/20 18:40」の構造で出る。今年でない日時は年も出る。
カード・ボードの上の「並べ替え」の「連番」「作成日時」「更新日時」で並びを選ぶ。日時を押すと新しい順になり、もう一度押すと古い順に変わる。向きはボタンの矢印で分かる。
ボードは列の中を並べ替える。
開いた直後は連番の順で、資料だけは更新日時の新しい順。
並べ替えると URL に入り、ブラウザの戻る操作で 1 つ前の並びへ戻れる。

### 資料を読み込む

資料のカードは、開いた直後は更新日時の新しい順に並ぶ（[カード・ボードを並べ替える](#カードボードを並べ替える)）。
カードと表に、資料の状態（下書き・確認中・完成）が出る。
カード・ボードのカードの種類の右と、表の「形式」の列に、本文の形式の札が付く。HTML の資料は `HTML`、Markdown の資料は `MD`。表の「形式」の列では、形式で絞れる。
カード・ボード・表のどれでも、絞り込みのドロワーで、状態・種類・タグで絞れる。
ボードは、資料を状態（下書き・確認中・完成）の列に並べる。
資料が 0 件の列も出る。
ボードの列の中も、カードと同じ並びになる。
カード・ボードのカードの下端に資料のタグが記録の順に並び、主題のタグは名前の前に二重丸のマーカーが付き、枠と文字が 1 段階濃くなる。
表のタグの列と絞り込みのドロワーのタグは、主題かどうかによらず名前で出る。

### 詳細を読み込む

項目を押すと、詳細パネルが右から出る。
幅 1100px 以上では、本文を寄せて並べる。それより狭いと、本文に重なる。
どの種類の項目も、同じ既定の幅（640px）で開く。
幅 901px 以上では、詳細パネルの左端をドラッグして幅を変えられる。iPad など指で操作する端末では、左端の線を中心に指でつかめる幅が広がる。
変えた幅は、そのタブで詳細パネルを再度開いても、別の項目を開いても、再読み込みしても保たれる。
幅 900px 以下では画面の幅いっぱいに出て、ドラッグの操作は出ない。

詳細パネルは、上部の「本文」「関連」「コメント」のタブで中身を切り替える。開いたときと別の項目へ移ったときは「本文」を選ぶ。「関連」には前提・後続などの項目とリンク、「コメント」にはその項目へのレビュー中のコメントが出る（配る書き出しには「コメント」のタブが無い）。タブは左右の矢印でも選べる。

詳細パネルは、次を出す。

- 項目の ID・タイトル・状態。資料には、種類と ID の右に本文の形式の札（`HTML` / `MD`）も付く
  本文を送信して先頭のタイトルが見えなくなると、見出しの ID の右にもタイトルが出る。先頭へ戻すと隠れる
  長いタイトルは見出しで 1 行に省略され、乗せると全文が出る
- 検討事項の背景（`lead`。何を決めるか）。タイトルの下に出す
- タグ。タイトルの下のキーの一覧の末尾の「タグ」の行に、記録の順に並ぶ。その項目の主題のタグは、名前の前に二重丸のマーカーが付き、枠と文字が 1 段階濃くなる。ポインターを重ねると「主題」と出る
- 検討事項の案。カードの縦並びで、見出しに記号と内容、その下にメリット・デメリット・備考・理由を出す。採用した案に「採用」、不採用の案に「不採用」が付き、どちらでもない案には何も付かない。
  AI が推す案のカードには、見出しの右に星と「推奨」のバッジが付く。採用した案があるときは、推奨のバッジを出さない
- 検討事項の採用した案と理由。案の後に、決定内容（`answer`）と理由（`reason`）を、値のあるものだけ出す
- 本文。Markdown と mermaid の図を描く。本文の中の用語・項目の ID・見出しから移れる（[本文のリンクで移る](#本文のリンクで移る)）。表とセクションは、[本文の表とセクションを読み込む](#本文の表とセクションを読み込む)の操作で読みやすくできる
- HTML の資料の本文。本文の代わりに、HTML を描いた結果を枠の中に出す。本文のスクリプトは動かず、本文の CSS は画面へ漏れない。用語のマーカー・項目の ID・見出しのリンクは付かない。本文の中の `http`・`https` のリンクを押すと、本文を残したまま、リンク先が新しいタブで開く。`mailto` のリンクはメールのアプリで開く。`#` で始まるリンクは、本文の中のその `id` の場所までスクロールする。ほかのリンク（相対の URL など）は、押しても移らない。Markdown の本文の中の言語指定 `html` のコードブロックも、コードではなく描いた結果で出る
- 本文に埋め込んだ動画・音声・画像（ワークスペースの直下の `files/` のファイル）。動画・音声は再生バーで再生し、再生位置を移せる。ファイルが無いときは再生できない枠が出て、本文のほかの部分は描かれる（無いファイルは [ワークスペースを点検する](./コマンド.mark.md#ワークスペースを点検する) で分かる）
- Markdown の資料の本文に埋め込んだ HTML・チャート・操作できる部品。本文の一部として描かれ、動かせる（[埋め込んだ HTML と操作できる部品を使用する](#埋め込んだ-html-と操作できる部品を使用する)）
- Markdown の資料の見出しの「エクスポート」。資料 1 件を書き出す（[資料を書き出す](#資料を書き出す)）
- 見出しのコメントのボタン（吹き出しのアイコン）。押すと、その項目へのコメントだけに絞ったコメントの一覧が開く（[コメントの一覧からスレッドの取得](#コメントの一覧からスレッドの取得)）。全画面には出ない
- 見出しの「本文の目次」（Markdown の本文が見出しを持つときだけ）。押すと本文の見出しが階層の字下げつきで並び、押すと「本文」のタブでその見出しまでスクロールする。HTML の本文には出ない
- 「関連」のタブに、前提・後続の項目・関連タスク・経緯・関連する項目・参照元。押すとその項目へ移る
- 「コメント」のタブに、その項目へのレビュー中のコメント。各行の右上のマーカーのボタンで、その場で修正する・削除する・元に戻す（[コメントをレビュー中に溜める](#コメントをレビュー中に溜める)）。チェックとまとめて送信はコメントの一覧のレビュー中の書き込みの画面で行う
- コメントの入力欄と、その右の「レビューに追加」のボタン（吹き出しのアイコン）。下端に留まり、本文だけがスクロールする。右上のボタンで閉じる・開く（[コメントの入力を閉じる](#コメントの入力を閉じる)）

背景・決定内容・理由・案の各値のほか、タスクの理由、調査の質問と結論、用語の意味、メモの内容も、本文と同じく Markdown として描く。
本文と違い、値の段落の中の 1 つの改行も改行として出す。
値の中の用語・項目の ID・スレッドの ID からも、本文と同じく移れる（配る書き出しではスレッドの ID は文字のまま）。
資料・調査は、説明とエイリアスを持っていれば「説明」「エイリアス」のセクションに出す。

項目を移ると履歴に追加され、見出しの「← →」で、見てきた項目を行き来できる。間にした絞り込み・並べ替えは飛ばし、今の絞り込み・並べ替えと後ろの画面はそのまま残る。
ブラウザの戻る・進むは、絞り込み・並べ替えの変更も含めて 1 つずつたどる。
表・ボード・カードから開いたときは、見出しの「← →」の左に、上向きと下向きの山形のボタンと「{何件目} / {件数}」が出る。後ろの画面の今の並び（絞り込み・並べ替えをした順。ボードは開いた項目の列の中の順）で、前後の項目へ移る。
`k` で前の項目、`j` で次の項目へ移る。入力欄で文字を入れている間・修飾キーを押している間・表示の設定で「1 文字のショートカットを使用する」を外している間は、キーでは移らない。
本文を送信した位置は項目ごとに覚えられ、同じ項目へ戻る・全画面と行き来する・同じタブで再読み込みすると、その位置から読める。見出しやコメントの箇所を示して開いたときは、そちらが出る。
閉じるには、閉じるボタンか Esc を使う。

幅 768px 以上では、「全画面表示」を押すと画面の中央に大きく出る（それより狭い幅では、詳細パネルが画面いっぱいに出るため、ボタンは出ない）。本文は全画面の幅いっぱいに広がり、全画面の中を送信しても後ろの画面は動かない。
全画面でも、本文を送信すると見出しに ID とタイトルが出る。
全画面の間は、後ろの画面がほかのモーダルと同じ濃さでグレーアウトし、ボタンが縮小のマーカーの「元の大きさに戻す」に替わる。これを押すか、グレーアウトした所を押すと元の大きさに戻る。

#### 本文の表とセクションを読み込む

Markdown の本文には、詳細パネル・詳細の全画面・本文の差分（描いた結果・原文の差分）のどれでも、同じスタイルが当たる。配る書き出しも同じ。
本文はブラウザの印刷で印刷でき、畳んだセクションは開いた状態で印刷される。
本文に特別な書き方は要らず、普通の Markdown のまま見せ方が変わる。HTML の資料の本文には当たらない。

表は mdmark の表として描かれ、列の幅と折り返し・並べ替え・列のピン止め・列の幅の変更は mdmark の表のとおりに動く。
表が本文の幅に収まらないときは、先頭の列が左端に留まり、表の中だけが横にスクロールする。本文の区画は横にスクロールしない。

| 操作 | やり方 |
| --- | --- |
| セクションを畳む・開く | 見出しの頭の矢印を押すと、その見出しの下（次の同じか上の階層の見出しまで）が畳まれる。もう一度押すと開く |

セクションの矢印は、本文で使っている上位 2 つの階層の見出しだけに付き、開いた状態で描かれる。
見出しの文言は、これまでどおり選んでコメントできる。矢印を押しても URL は変わらない。
畳んだ中身は、ページ内の検索・本文のリンク・URL の search params で飛んだときに開く。
本文の差分には矢印が付かず、畳めない。

幅 720px 以下では、列の固定と固定のボタンは出ない。見出しの行を残す動きは変わらない。
4 つの切り替えは、[表示の設定](#表示の設定を変える)で付け外しできる。

コードブロックには、言語の札とコピーのボタンが付く。
コードブロックの長い行は折り返さず、コードブロックの中だけで横にスクロールできる。コードブロックにフォーカスを置くと、矢印キーでも送信できる。
GitHub の Alert の記法（`> [!NOTE]` など）は、囲みで出る。囲みの見出しは、補足・ヒント・重要・警告・注意。

#### 本文のリンクで移る

| 本文の中 | 見え方と操作 |
| --- | --- |
| 用語集の用語（タイトルと別名） | 文字の色は変わらず、点線の下線が付く。乗せるかフォーカスすると、用語の意味が出る。押すとその用語の詳細へ移る。同じ語に用語が 2 つ以上一致したときは、資料・調査のエイリアスと同じく「用語」の見出しの下に並び、タイトルを押してその詳細へ移る。マーカーを押すとツールチップが残り、外を押すか Esc で閉じる |
| 資料・調査のエイリアス | 用語と同じ点線の下線が付く。乗せるかフォーカスすると、マーカーの上のツールチップに、その語に一致した用語・資料・調査が「用語」「資料」「調査」の見出しごとに並ぶ。資料・調査はタイトル・ID・説明が出て、タイトルを押すとその詳細へ移る。押すとツールチップが残り、外を押すか Esc で閉じる。項目が多いときはツールチップの中を送信して読む |
| 記録にある項目の ID（`D-95` など） | 等幅の色の文字と下線のリンクになる。乗せるかフォーカスすると、マーカーと同じツールチップに、その項目のタイトルと ID、種類と状態が出る。押すとその項目の詳細へ移る。記録に無い ID はリンクにならない |
| 見出し | 乗せるかフォーカスすると、右に # が出る。押すとその見出しまでスクロールし、URL がその見出しを指す。この URL を開くと、その見出しまでスクロールした詳細が開く |

コードブロックと図の中には、用語のマーカーも ID のリンクも付かない。見出しの中の用語にもマーカーは付かない。
本文の `[文言](#見出し)` のリンクを押すと、その見出しまでスクロールする。
本文の `[文言](#diff=V-2)` のリンクを押すと、開いている項目のまま、そのまとまりの差分の表示に切り替わる（変更履歴でそのまとまりを選んだときと同じ）。
記録に無いまとまりと、`since`・`pending` を指すリンクは、押しても何も変わらない。

#### 埋め込んだ HTML と操作できる部品を使用する

Markdown の資料の本文に埋め込まれた HTML・チャート・操作できる部品は、詳細パネル・詳細の全画面・本文の差分のどれでも、枠に入れずに本文の一部として描かれる。
埋め込む書き方は AI が資料に従って書くため、利用者が書き方を覚える必要は無い。

| 埋め込まれたもの | 見え方と操作 |
| --- | --- |
| HTML | 段落・図などが本文の中にそのまま描かれる。資料に書いたスクリプトは動かず、ボタンを押しても何も起きない |
| チャート | 右上のボタンか、フォーカスして `+`・`-`・`0` のキーで拡大・縮小し、ドラッグで表示の位置を動かす。図の拡大の画面は開かない。ホイールは本文のスクロールに使う。チャート以外の要素には、拡大・縮小のボタンが付かない |
| 操作できる部品 | スライダーを動かす（フォーカスして矢印キーでも動く）と、今の値が出て、グラフが再描画される。「今の値をコピー」を押すと、今の値の JSON がクリップボードに入る |
| 用語・項目の ID | 埋め込まれた HTML の中の文にも、本文と同じ用語のマーカーとツールチップ、項目の ID のリンクが付く（[本文のリンクで移る](#本文のリンクで移る)） |

コピーした JSON は、部品のキーごとに名前と今の値を持つ。

```json
{ "rps": { "name": "ピーク時のリクエスト数", "value": 800 } }
```

AI へ値を返すときは、コピーした JSON をその資料へのコメントの入力欄に貼り、[レビューに追加してまとめて送信する](#スレッドに返信してまとめて送信する)。
MindStella のセッションがコメントを取り込むときに、その値を読んで受け取る。

埋め込みの書き方に誤りがあると、その場所に「書き方の警告」の枠が出て、修正方法が書かれる。同じ本文のほかの部分は描かれる。

### 資料を書き出す

資料 1 件を、Markdown か 1 枚の HTML でダウンロードする。
本文が Markdown の資料の詳細パネルと詳細の全画面の見出しにある「エクスポート」を押すと、形式を選ぶメニューが開く。
本文が HTML の資料と、資料以外の項目には「エクスポート」が出ない。

| 形式 | 書き出されるもの | ファイル名 |
| --- | --- | --- |
| HTML でエクスポート | 共通のスタイル（CSS）と用語のツールチップを中に持つ 1 枚の HTML。mindstella が無くても、ネットにつながらなくても開け、本文・図・チャート・操作できる部品が動く。ほかの項目へのリンクは移らない | `{資料の ID}.html` |
| Markdown でエクスポート | 本文の Markdown から、埋め込んだ HTML・チャート・操作できる部品の範囲を除いたもの | `{資料の ID}.mark.md` |

「Markdown でエクスポート」を押すと、ダウンロードの前に、埋め込んだ HTML が含まれないことと共通のスタイルが外れることの警告がメニューの中に出る。
「エクスポート」を押すとダウンロードされ、「戻る」を押すと形式を選ぶメニューに戻る。

書き出しても、画面は移らず、記録・URL・ブラウザの履歴は変わらない。
Esc かメニューの外を押すと、メニューだけが閉じる。
「HTML でエクスポート」は、組み立てる間、メニューに「エクスポートしています…」が出る。
mdmark のスタイルとスクリプトを読み込めなかったときは、ダウンロードされず、メニューに理由と「戻る」「再試行」が出る。
サーバーが配るプレビューから書き出すときは、[動作環境](./動作環境.mark.md#プレビュー)の jsDelivr へ届いている必要がある。

### コメントをレビュー中に溜める

詳細パネルと全画面の下端の入力欄「{ID} へのコメント」に書いて、入力欄の右の「レビューに追加」（吹き出しのアイコンのボタン）を押す。入力欄で Ctrl+Enter（macOS は Cmd+Enter）を押しても追加できる。
追加したコメントは、送信せずにレビュー中に溜まり、トップバーのコメントのボタンの件数が増える。
溜めた項目には、吹き出しとその項目へのレビュー中のコメントの件数のマーカーが出る。
項目へのコメントは、送信すると、その項目へ向けた新規スレッドの最初の書き込みになる（[コメントの一覧からスレッドの取得](#コメントの一覧からスレッドの取得)）。

| 画面 | マーカーの配置場所 |
| --- | --- |
| ボード・カード | カードの一番下の行の右端 |
| 表 | タイトルの右（差分のマーカーの後ろ） |

件数が 100 以上のときは「99+」と出る。
コメントを削除する・戻す・送信すると、画面を再度開かずに件数が変わる。送信したコメントの分だけ件数が減り、レビュー中のコメントが無くなった項目からはマーカーが消える。
本文は、前後の空白を除いて 1 文字以上 10000 文字以下。

| 結果 | 画面の出方 |
| --- | --- |
| 溜まった | 入力欄が空になり、「レビューに追加しました（レビュー中 {件数} 件）。」が出る |
| 本文が空 | 入力欄の枠が赤くなり、「コメントを入れてから追加してください。」が出る。入力欄の中身は残る |
| サーバーが理由を返した | 入力欄の中身が残り、「レビューに追加できませんでした。{理由}」が出る |
| サーバーにつながらない | 入力欄の中身が残り、起動スクリプトで再起動して新しい URL で開くよう出る。その下のコピーのアイコンのボタン（本文をコピー）を押すと、入力欄の中身をクリップボードにコピーできる |

溜まった後のフォーカスは、[表示の設定](#表示の設定を変える)の「レビューに追加した後のフォーカス」に従う。
既定の「自動」では、マウスで操作する端末は入力欄に戻り、タッチで操作する端末は「レビューに追加」のボタンに移ってソフトウェアキーボードが閉じる。
本文が空・溜められなかったときは、設定によらず入力欄に戻る。
新規スレッドの入力・返信の入力と、音声入力でレビュー中に追加した・送信した後も同じで、音声入力で入力欄へ挿入した後は入力欄に戻る。

詳細パネルと全画面の「レビュー中のコメント」は、既定で新しい順に並ぶ。2 件以上あるときは、見出しの右のボタン（「新しい順」「古い順」）を押すたびに並びが入れ替わる。
選んだ並びはこの端末の個人の上書きとして残り、[表示の設定](#表示の設定を変える)の「この端末で変えている項目」に「コメントの並び」として並び、「既定に戻す」で新しい順に戻る。

溜めたコメントは、詳細パネルと全画面の「レビュー中のコメント」の各行の右上にある鉛筆とごみ箱のアイコンのボタンで、コメントの一覧を開かずに変更できる。

| 操作 | やり方 |
| --- | --- |
| 長いコメントを読む | 本文は Markdown として描かれ、5 行を超えるコメントは 5 行までで畳まれている。「続きを表示」で全文を開き、「折りたたむ」で再度畳む。開いた行は、修正しても開いたまま |
| 修正 | 行の鉛筆のアイコンを押し、本文をその場で修正して「修正」を押す。Ctrl+Enter（macOS は Cmd+Enter）でも修正できる。「キャンセル」か Esc で捨てる。書き換えられるのは、コメントの一覧のスレッドの画面・レビュー中の書き込みの画面と合わせて 1 行だけで、別の行の鉛筆のアイコンを押すと前の書き換えを捨てる |
| 削除する | 行のごみ箱のアイコンを押す。確認は出ず、行が「コメントを削除しました。」と「元に戻す」に変わる |
| 元に戻す | 削除した行の「元に戻す」を押す。別の項目へ移るか、パネルを閉じるまで押せる |

| 修正の結果 | 画面の出方 |
| --- | --- |
| 修正できた | 行が修正した本文に戻る |
| 本文が空 | 入力欄の枠が赤くなり、「コメントを入れてから修正してください。」が出る。入力欄の中身は残る |
| サーバーが理由を返した | 入力欄の中身が残り、その理由が出る |
| サーバーにつながらない | 入力欄の中身が残り、「サーバーが止まっています。再起動してから修正してください。」が出る |

下書きとレビュー中のコメントは、ワークスペースの `drafts.yaml`・`comments.yaml` に残る。
パネルを閉じても、再読み込みしても、起動スクリプトで再起動しても消えない。
配る書き出しには、入力欄もマーカーも出ない。

#### コメントの入力を閉じる

下端の入力の「{ID} へのコメント」の行の右端のボタンを押すと、入力が閉じて「{ID} へのコメント」の 1 行だけになる。
もう一度押すと開く。
閉じたか開いたかはこの端末に残り、ほかの項目へ移っても・再度開いても同じ構造で出る。「既定に戻す」では変わらない。
閉じても下書きは消えず、下書きがあるときは「{ID} へのコメント」の右に「下書き」が出る。
閉じている間に[選んだ箇所へコメントする](#選んだ箇所へコメントする)のボタンを押すと、入力が開いて入力欄へ移る。

### 音声でコメントする

コメントの入力と返信の入力の「レビューに追加」の左にあるマイクのボタンを押すと、録音が始まる。
初めて使うときは、ブラウザがマイクの許可を求める。
録音中は、2 つのボタンが × と ✓ に替わり、入力欄の下に赤い丸と録音の経過の時間が出る。
録音中は、端末の画面が自動で暗くならない（ブラウザが画面の消灯の抑止に対応していないときは、そのまま録音を続ける）。
入力欄の場所には入力している音声の波形が出て、キーボードでは入力できない。打ちかけの文字とカーソルの位置は残り、録音を終えると入力欄に戻る。

| 操作 | やり方 |
| --- | --- |
| 録音をやめる | × を押す。録音を捨て、入力欄の中身は変わらない |
| 文字起こしする | ✓ を押す。録音を止めて文字起こしのサービスへ渡し、終わるまで回るマーカーが出る。起こした文字は、入力欄のカーソルの位置に挿入される |

挿入した後の扱いは、設定の画面の「音声入力」の「文字起こし後の挙動」で決まる（既定は「レビュー中に追加する」）。

| 文字起こし後の挙動 | 画面の出方 |
| --- | --- |
| レビュー中に追加する（既定） | 挿入した全文を、「レビューに追加」を押したときと同じくレビュー中に溜める。入力欄が空になり、「文字起こしの結果をレビュー中に追加しました。」が出る。Claude Code へは送信しない |
| 入力欄へ挿入する | 送信せずに入力欄に残し、「文字起こしの結果を挿入しました。」が出る。誤認識を修正してから、「レビューに追加」でレビュー中に溜める |
| 送信する | 挿入した全文を、レビュー中に溜めずにその 1 件だけでスレッドへ送信し、Claude Code へ入力する。入力欄が空になり、「送信し、Claude Code へ入力しました。」が出る。Claude Code へ入力できなかったときは「送信しました。Claude Code へは入力していません。」 |

打ちかけの文字があるときは、カーソルの位置に挿入され、レビュー中に追加するときと送信するときは打ちかけと合わせた全文を扱う。
溜めたレビュー中のコメントは、送信しても残る。
音声入力は同時に 1 つだけで、録音中か文字起こし中は、ほかの入力欄のマイクのボタンを押せない（キーボードでは入力できる）。
録音中か文字起こし中も、パネルを閉じる・別の項目やスレッド・タブへ移るなど、ほかの資料を開ける。その間も録音と文字起こしは続く。
録音中か文字起こし中は、トップバーのコメントのボタンの左に、赤い枠のマイクのアイコンと経過の時間（文字起こし中は回るマーカー）が出る。押すと録音を始めた入力欄の画面が開き、録音中は ✓ に移る。
詳細の全画面などのモーダルを開いている間はトップバーを押せないので、閉じてから押す。

| 入力欄が画面に無い間の結果 | 画面の出方 |
| --- | --- |
| 文字起こし・レビュー中への追加・送信を終えた | 結果はその入力欄の下書きに入り、何も出ない |
| 文字起こし・レビュー中への追加・送信に失敗した | 文字はその入力欄に残り、トップバーの下の帯に理由と「入力欄を開く」が出る。「入力欄を開く」でその入力欄の画面が開く。× で閉じられる |
| 録音中に行き先の項目・スレッドが削除された | 録音を捨て、トップバーの下の帯に「{ID} が削除されたため、録音を破棄しました。」が出る |

レビュー中の書き込みを修正する入力（コメントの一覧のスレッドの画面・レビュー中の書き込みの画面と、詳細パネルのレビュー中のコメント）にも、「キャンセル」の左にマイクのボタンがある。
録音の操作はコメントの入力と同じで、録音中は「キャンセル」「修正」が × と ✓ に替わる。
起こした文字は「文字起こし後の挙動」によらず入力欄のカーソルの位置に挿入され、「文字起こしの結果を挿入しました。」が出る。レビュー中への追加と送信はせず、「修正」を押すまでコメントは変わらない。
× は録音だけを捨て、修正の入力は開いたまま残る。

| 修正の入力で録音したとき | 画面の出方 |
| --- | --- |
| 録音中にほかの画面へ移った | トップバーのマイクのアイコンを押すと、録音を始めた画面が開き、その書き込みが修正の入力のまま出る |
| 入力欄が画面に無い間に文字起こしを終えた | 下書きには入らない。その書き込みの修正の入力を再度開くと、挿入した全文が入力欄に入っている |
| 録音中・文字起こし中にその書き込みを削除・送信した | 録音と結果を捨て、トップバーの下の帯に録音を破棄したことが出る。「元に戻す」で書き込みを戻しても、結果は入らない |

マイクのボタンを押せないときは、ボタンが沈んだ見た目になり、ホバーかフォーカスで理由が出る。押しても録音は始まらず、入力欄の下に同じ理由が出る。

| 理由 | 修正方法 |
| --- | --- |
| 文字起こしのサービスが起動していないため、音声で入力できません。 | 文字起こしのサービスを起動してから、マイクのボタンを再度押す（[動作環境](./動作環境.mark.md#プレビュー)） |
| 文字起こしのサービスが音声の受け付けに対応していないため、音声で入力できません。 | 文字起こしのサービスを、音声を受け付ける環境（[動作環境](./動作環境.mark.md#プレビュー)の音声入力の条件）で起動する |
| このページではマイクを使用できません。HTTPS か localhost の URL で開いてください。 | HTTPS か localhost の URL でプレビューを再度開く |
| ほかの入力欄で音声入力中のため、音声で入力できません。 | トップバーのマイクのアイコンから録音中の入力欄へ移り、録音を終える |

| そのほかの結果 | 画面の出方 |
| --- | --- |
| マイクの許可を拒否した | 「マイクを使用できませんでした。ブラウザの設定でこのページのマイクを許可してください。」が出る |
| 文字起こしに失敗した・何も聞き取れなかった | 入力欄の中身が残り、「文字起こしできませんでした。もう一度お試しください。」が出る |
| レビュー中に追加できなかった | 挿入した全文が入力欄に残り、「レビュー中に追加できませんでした。文字起こしの結果は入力欄に残しています。」が出る |
| 送信できなかった | 挿入した全文が入力欄に残り、「送信できませんでした。文字起こしの結果は入力欄に残しています。」が出る |

録音した音声は文字起こしのサービスへ渡すだけで、ワークスペースにもログにも残らない。
配る書き出しには、マイクのボタンは出ない。

### 選んだ箇所へコメントする

詳細パネルと全画面で、本文の文章か項目の値（タイトル・案の中身・長所・短所・理由など）を選ぶ。
選び終えると、選んだ範囲の始まりの上に、コメントのアイコンだけの丸いボタンが出る（上に収まらないときは、選んだ範囲の終わりの下に出る）。
ボタンに乗せるかフォーカスすると、「選んだ箇所にコメント」の名前が出る。
ボタンを押すと、下端の入力欄に、選んだ箇所（「本文 {行} 行目」かキーの名前）と選んだ文の引用が添えられる。
コメントを書いて「レビューに追加」を押すと、その箇所を指すコメントとして溜まる。
添えた箇所は、× を押すと外れ、項目へのコメントに戻る。
HTML の資料も、描いた結果の文を選ぶと同じボタンが出る。箇所は「本文 {行} 行目」で、HTML の原文の行になる。

本文と値の外（セクションの見出し・関係する項目・図・レビュー中のコメント・入力欄）を選んだときは、ボタンは出ない。
ボタンは Esc で閉じる。

### コメントの一覧からスレッドの取得

トップバーのコメントのボタンを押すと、見ている画面に重ねて左からコメントの一覧が開く。
一覧はスレッドの一覧で、1 行が 1 つのスレッドになる。
ボタンには、レビュー中の書き込みの件数が出る。スマホの幅では、マーカーと件数だけが出る。
オープンのスレッドに、まだ開いていない AI の書き込みがあるときは、ボタンの吹き出しのアイコンの右上に点が重なる。件数はそのまま出る。
幅 900px 以下では、一覧は画面の幅いっぱいに出る。
詳細パネルを開いたままトップバーから開くと、一覧は詳細パネルの前に出る。一覧の行から詳細パネルを開くと、詳細パネルが一覧の前に出る。
開いている間、トップバーとタブの帯と一覧以外はグレーアウトし、透けて見えるが操作できない。一覧の中から開いた詳細パネルは、グレーアウトの上に出て操作できる。
閉じて再度開くと、閉じる前の画面・開いていたスレッド・スクロールの位置に戻る。開いていたスレッドが無くなっていれば、スレッドの一覧から始まる。再読み込みすると、スレッドの一覧から始まる。

| 操作 | やり方 |
| --- | --- |
| 状態で絞る | 「オープン」「クローズ」「すべて」を押す。件数が添えられる。開いたときはオープンで、パネルを開いている間は保たれる |
| タグで絞る | スレッドの行のタグを押す。もう一度押すか、絞り込みの × を押すと外れる。タグは AI が付け、画面では付け外しできない |
| 項目で絞る | 詳細パネルの見出しのコメントのボタンを押す。その項目へ向けたスレッドと、その項目へのまだ送信していない新規スレッドだけが並び、状態の絞り込みの下にその項目の ID とタイトルのチップが出る。状態の件数は項目で絞った後の数になる。チップの × を押すと外れる。一覧を開いたまま別の項目のボタンを押すと、状態とタグの絞り込みはそのままで、絞る項目だけが替わる。詳細パネルで別の項目へ移るだけでは替わらない。トップバーのコメントのボタンで開くと、項目では絞らない |
| スレッドの取得 | 行を押す。行には要約と最後の書き手が出る |
| 新規スレッドの作成 | 下端の「新規スレッド」を押して書く。項目を指さないスレッドの最初の書き込みとして、レビュー中に溜まる |
| 閉じる | 閉じるボタン・Esc・コメントのボタン・グレーアウトした所のどれかを押す。幅 901px 以上で詳細パネルを開いているときの Esc は、詳細パネルを先に閉じる。幅 900px 以下の Esc は、前に出ている側から閉じる |
| ピン止めする | 閉じるボタンの左の錠のボタンを押す（ピン止めの間は閉じた錠、外している間は開いた錠）。ピン止めの間はグレーアウトせず、一覧の外側を見たまま操作でき、外側を押しても閉じない。もう一度押すと外れる。この端末に保存され、次に開いたときも保たれる |

まだ送信していない新規スレッドは、一覧の先頭に「レビュー中」の札で並ぶ。
返信をレビュー中に溜めたスレッドの行には、それと分かるマーカーが出る。
AI の返信と AI が立てたスレッドは、画面を開いたまま一覧に現れる。
MindStella のセッションは利用者がターミナルを見ない前提で、知らせを全てスレッドで出す。利用者の回答が要ることはスレッドで尋ねずに検討事項に挙げ、コメントを取り込んだ回の最後に、追加した検討事項と反映した回答を 1 件のスレッドに表で知らせる。挙がった検討事項を開いて案と推奨を見比べ、画面で回答するか、その検討事項にコメントを送信する。
まだ開いていない AI の書き込みを持つスレッドの行には、2 行目の先頭に塗りつぶしの「● 未読」の札が出る。クローズのスレッドの行にも出る。
スレッドを開くと、そのスレッドは既読になり、札と点が消える。開いているスレッドに AI の返信が届いたときも、返信が描かれた後に既読になる。

スレッドの画面では、書き込みと、クローズ・オープンへの戻しの記録が、書いた順に並ぶ。
スレッドを開くと、最新の書き込みの先頭までスクロールした位置で開く。
最新以外の書き込みで 5 行を超えるものは 5 行までに畳まれ、「続きを表示」で全文を、「折りたたむ」で畳み直せる。最新の書き込みは全文が出る。
見出しのスレッドのタイトルは、スクロールすると 1 行に省略される。
書き込みとレビュー中の返信の本文は、資料の本文と同じく Markdown として描かれる。見出し・表・コード・mermaid の図・`> [!NOTE]` の囲みを読める。
書き込みの中の項目の ID（`D-12` など）は、押すとその項目の詳細パネルが開き、乗せるかフォーカスすると本文の項目の ID と同じツールチップが出る。段落の中の改行は、そのまま改行として出る。
向けた項目を押すと、一覧を開いたまま右にその項目の詳細パネルが開き、箇所があれば本文か値のその箇所を色の地で示す。
書き込みの中の `[文言](#diff=V-2)` は文言だけのリンクになり、押すとスレッドを開いたまま、そのまとまりの差分の表示に切り替わる。レビュー中の書き込みの画面の行でも同じ。
記録に無いまとまりと、`since`・`pending` を指すもの、`diff` を持たない `#` のリンク（`[文言](#tab=docs)` など）は、リンクにならず文言だけが出る。
「一覧へ戻る」か、入力欄にフォーカスが無いときの Esc で一覧へ戻る。

### スレッドに返信してまとめて送信する

スレッドの画面の下端の入力欄に書いて、入力欄の右の「レビューに追加」（吹き出しのアイコンのボタン）を押す。Ctrl+Enter（macOS は Cmd+Enter）でも追加できる。
返信は送信せずにレビュー中に溜まり、スレッドの末尾にレビュー中のマーカーつきで並ぶ。
5 行を超える返信は 5 行までで畳まれ、「続きを表示」で全文を開き、「折りたたむ」で再度畳む。送信した書き込みは畳まれない。
下書きは、スレッドごとに保たれ、一覧へ戻る・別のスレッドを開く・パネルを閉じる・再読み込みするのどれでも消えない。

新規スレッドと返信は、見出しの帯の「レビュー中（{件数}）」で開くレビュー中の書き込みの画面でまとめて確かめる。

<!-- table: {"kind": "data"} -->

| 操作 | やり方 |
| --- | --- |
| 送信するものを選ぶ | 行のチェックを付け外しする。「すべて選ぶ」の箱で、まとめて付け外しする。開いたときと、新しく溜めた書き込みは、チェックした状態で入る |
| 元のスレッドや項目へ移る | 返信の行は返信先のスレッドを、新規スレッドの行は向けた項目を押す |
| 長い書き込みを読む | 5 行を超える書き込みは 5 行までで畳まれている。「続きを表示」で全文を開き、「折りたたむ」で再度畳む。開いた行は、修正しても開いたまま |
| 修正 | 行の鉛筆のアイコンを押し、本文をその場で修正して「修正」を押す。Ctrl+Enter（macOS は Cmd+Enter）でも修正できる。「キャンセル」か Esc で捨てる |
| 削除する | 行のごみ箱のアイコンを押す。確認は出ず、行が「コメントを削除しました。」と「元に戻す」に変わる。「元に戻す」は、パネルを閉じるかまとめて送信するまで押せる |
| 戻る | 「戻る」か、入力欄にフォーカスが無いときの Esc を押す |

<!-- /table -->

「まとめて送信（{件数} 件）」を押すと、チェックした書き込みだけが送信される。
チェックしなかった書き込みは、レビュー中に残る。
新規スレッドの書き込みは 1 件ごとに新規スレッドの最初の書き込みになり、返信は向けたスレッドの末尾に追加される。

<!-- table: {"kind": "data"} -->

| 結果 | 画面の出方 |
| --- | --- |
| 送れて、Claude Code に入力できた | 送信した行が外れ、コメントのボタンの件数が減る。「{件数} 件を送信し、Claude Code に入力しました（{HH:mm}）。」が出る |
| 送信できたが、Claude Code に入力できなかった | 送信した行の外れ方と件数の減り方は同じで、注意のマーカーと「{件数} 件を送信しましたが、Claude Code には入力できませんでした（{HH:mm}）。送信した内容は保存されていて、次に話し合いを始めたときに取り込まれます。」が出る |
| チェックが 0 件 | 「送信する書き込みにチェックを付けてください。」が出る |
| 箇所が合わない | どれも送信しない。本文が書き換わるなどして箇所が合わない書き込みの行に理由が出て、枠が赤くなる。「箇所を解除」で項目へのコメントにするか、削除してから再送信する。項目が無くなった書き込みは、削除するだけができる |
| クローズのスレッドへの返信がある | どれも送信しない。その行はチェックできず、「クローズのスレッドへの返信は送信できません。オープンに戻すと送信できます。」が出る。「スレッドを開く」から「オープンに戻す」で戻してから送信する |
| サーバーが理由を返した | 「送信できませんでした。{理由}」が出る |
| サーバーにつながらない | 「送信できませんでした。サーバーが止まっています。再起動してから送信してください。」が出る |

<!-- /table -->

起動スクリプトで作った MindStella のセッションには、送信した直後に「[mindstella] ユーザーからのコメントが {件数} 件届きました。再読み込みしてください。」の 1 行が入力される。
MindStella のセッションを止めた後（停止の依頼の後とクローズの後）に送信したコメントは、スレッドに残るだけで入力されない。
MindStella のセッションが、コメントの取り込みのエージェントフローで、取り込んでいない書き込みを持つスレッドを読んで記録し、返信するか、返信せずにクローズにする。
tmux の外で立てた Claude Code や、入力が会話に入らなかったときは、入力できなかったと出る。
入力欄に打ちかけがあるときや選択の表示（ツールの許可の確認など）が出ているときも、入力は止まらずに貼られる。
打ちかけとつながったり、選択の表示で入力が失われたりしたら、tmux のセッションを見て修正する。

送信したコメントは、ワークスペースの `threads.yaml` に残り、サーバーを止めても消えない。
Claude Code に入力できなかった書き込みは、次に MindStella のセッションを起動・再開したときの最初に取り込まれる（[続きを再開する](./話し合い-続きを再開する.md#話し合いへ進む)）。
配る書き出しには、コメントのボタン・一覧・選んだ箇所のコメントのボタンは出ない。

### スレッドをクローズにする

スレッドの画面の見出しの「クローズにする」を押すと、すぐにクローズになり、スレッドの一覧へ戻る。理由の入力と確認のモーダルは出ない。
戻った一覧では、開いていたスレッドの行にフォーカスが移る。状態の絞り込みがオープンでその行が外れたときは、次の行（無ければ前の行）にフォーカスが移る。
クローズのスレッドには返信の入力が出ず、「オープンに戻す」で戻してから返信する。「オープンに戻す」も押すとすぐに戻り、スレッドの画面に留まる。

クローズにしても、返信を送信してからクローズにしたときのその返信は、AI に届く。
AI も、返信が要らず話が済んだスレッドをクローズにし、クローズのスレッドに返信が要るときは理由つきでオープンに戻す。
AI は、まだ読んでいない AI の返信や、回答を待つ質問のあるスレッドをクローズにしない。読むか回答すると、AI がクローズにできるようになる。
クローズとオープンへの戻しは、誰が・いつ・なぜ行ったかが、スレッドの書き込みの間に並ぶ。


図の文字は、拡大表示を開かなくても選んでコピーできる（図を押しても拡大しない）。
図には、次のボタンがある。

| ボタン | 動き |
| --- | --- |
| 拡大表示 | 図を大きく開く。ホイールで拡大・縮小し、背景のドラッグで動かす。図の文字は選んでコピーできる |
| Raw | 図と mermaid の原文を切り替える |
| コピー | mermaid の原文をクリップボードに写す |

### 前回からの差分を読み込む

トップバーの変更履歴のボタンを押すと、差分の表示で比べる時点を選ぶモーダルが開く。
時点は、次の行が上から並ぶ。

| 行 | 中身 |
| --- | --- |
| 差分を出さない（今の内容） | 差分の表示をやめる。既定はこの行で、今の内容だけを読む |
| まだまとめていない変更 | AI がまだ区切っていない書き換え。あるときだけ出る |
| 前回開いてから | 前回開いた後に `commit` した書き換えのまとまりと、まだまとめていない変更 |
| 書き換えのまとまり | MindStella のセッションが記録を書き換え終えるたびに付ける一言の説明と日時、変わった項目の件数。新しい順 |

行を押すとモーダルが閉じ、どの画面も、選んだ時点の差分の表示になる。
選んだ時点は、URL の search params（`diff`）とこの端末に残り、画面を移っても再読み込みしても保たれる。
アドレス欄の URL を人に渡すと、端末の保存領域を持たないブラウザでも、同じ時点の差分の表示で開く。
記録に無いまとまりを指す URL と、まだまとめていない変更が空のときの `pending` を指す URL は、差分を出さずに開く。
「前回開いてから」と「まだまとめていない変更」は、開く端末や時刻で中身が変わる。
開いたまま記録が書き換わっても、同じ時点の差分の表示のまま再描画される。

差分の表示の間は、トップバーの変更履歴のボタンの右に、選んだ時点の札が出る。
抜けるには、札の × を押すか、モーダルの「差分を出さない（今の内容）」を押す。

選んだ時点で追加された項目には新規（+）、変わった項目には変更（●）の記号が付く。
表・ボード・カード・概要のタイルではマーカーだけで、詳細パネルではタイトルの横に「新規」の札が付く。
差分のある項目を持つタブには、件数を残したまま、右上に点が付く。

選んだ時点で削除した項目は、その種類の画面の一覧（ボード・カード・表）の上の「削除した項目」の帯に、削除したマーカー・ID・削除したときのタイトルで並ぶ。
削除した項目は中身が残らないので、帯の項目は押せず、詳細パネルも開かない。
選んだ時点で削除した項目だけを持つ種類のタブにも点が付く。タブの件数は、今ある項目の数のまま変わらない。
モーダルの時点の件数には、その時点で削除した項目も入る。
「前回開いてから」のように複数のまとまりを合わせた範囲で、追加した後に削除した項目は、新規のマーカーが付かず、削除した項目の帯にだけ出る。

取り下げた調査・資料・用語集・メモ・会話ログは、差分の表示によらず、表・カード・ボード・詳細パネルで、タイトルの右に枠付きの「取り下げ」の札が付き、行・カードの文字が薄くなる。
詳細パネルには、見出し「取り下げた理由」のセクションに理由が出る。
選んだ時点で取り下げた項目は、変更（●）の記号と取り下げの札で読め、「取り下げた理由」は前の値（なし）と今の値が並ぶ。

詳細パネルと資料では、選んだ時点の前後の差分を読める。

Markdown の本文の差分は、「描いた結果」と「原文の差分」で切り替えて読める。
切り替えは、詳細パネルと詳細の全画面の本文の差分の頭に出る。選んだ時点から本文が変わっていない項目には出ない。
既定は「描いた結果」で、項目を開き直すと「描いた結果」に戻る。
「原文の差分」では、選んだ時点と今の本文の行の差分がそのまま出る。比べる時点は変更履歴で選んだ時点で、本文の中に「変更表示」のボタンとリビジョンの欄は出ない。

詳細パネルと詳細の全画面では、変わった箇所を[差分のミニマップ](#差分のミニマップで変わった箇所へ飛ぶ)でも見渡せる。

「前回開いてから」の範囲の始まりは、ワークスペースに残る前回開いた時点（[前回開いた日時](./ワークスペースの書式.mark.md#前回開いた日時)）で、同じワークスペースを開いた全てのブラウザで共有する。
範囲は開いた時点の連番で決まり、日時は範囲の始まりの表示（`{日時} より後`）にだけ使う。
タブを開いたときの値をそのタブで使い、同じタブで再読み込みしても変えない。
前回開いた時点が無いときと、ワークスペースを戻して前回の連番が今より先にあるときは、そのタブを開いた時点からになる。

項目が持つ変更履歴は、設定の `history_limit` の回数分（既定は 5）までで、それより古い書き換えとは比べられない（[設定](./ワークスペースの書式.mark.md#設定)）。
差分を出せないときは、次のようになる。

| 状況 | 画面の出方 |
| --- | --- |
| 選んだ時点の範囲の中の変更履歴が、保持する回数を超えて消えている（範囲の中で同じ項目を回数より多く書き換えたときを含む） | 項目にマーカーだけが付き、詳細パネルの本文の頭に「このまとまりの前後を組み立てられません。保持する回数を超えた古い変更履歴は消えています。今の内容を出しています。」が出る |
| 書き換えの後に、本文のファイルが直接書き換えられている | 本文の頭に「本文の差分を出せません。書き換えの後に、本文のファイルが直接書き換えられています。今の本文を出しています。」が出る。キーの差分は出る |
| 書き換えが大きく、本文の差分を計算しきれない | 本文の頭に「本文の差分を出せません。書き換えが大きく、差分を計算しきれませんでした。今の本文を出しています。」が出る。キーの差分は出る |
| 差分の計算に使うライブラリ jsdiff を読み込めない | 本文の頭に「本文と図の差分を表示できません。読み込めなかったライブラリ: jsdiff」と「通信を確認して、ページを再読み込みしてください。」が出て、本文・図・図の Raw は差分なしで出る。キーの差分は出る |
| `history_limit` が 0 | 変更履歴を持たないので、差分が出ない |
| 変更履歴を持たない既存のワークスペース | そのまま読めて、差分が出ないだけ |

配る書き出しでも、同じ差分の表示を使える。
「前回開いてから」の範囲の始まりは、前回開いた時点（日時と連番）をその端末に持ち、同じ決め方で範囲を決める。

#### 差分のミニマップで変わった箇所へ飛ぶ

詳細パネルと詳細の全画面で、差分の表示の間、本文のスクロールバーの外側に、変わった箇所のマーカーを並べた縦の帯が出る。
帯は本文の全体を縮めた形状で、マーカーは本文の中のその箇所と同じ高さに並ぶ。
見えている範囲は、帯の中の面で示す。
本文に変わった箇所のマーカーが 1 つも無いとき、[表示の設定](#表示の設定を変える)で外したとき、Markdown の本文を「原文の差分」で読んでいるとき（行の差分が自分の帯を出す）は、帯が出ない。

マーカーは、色だけでなく形状でも見分けられる。

| マーカー | 形状 |
| --- | --- |
| 追加した | 塗りつぶし |
| 削除した | 中抜き |
| 変わった | 斜めの縞 |

前に無かったキーは追加した、値が変わったキーは変わったのマーカーになる。
続く同じ種類の箇所は 1 つにまとまり、削除した塊のすぐ後ろの追加した塊は、変わった 1 つになる。

| 操作 | 動き |
| --- | --- |
| マーカーを押す | その箇所が本文の上から 4 分の 1 の位置に来るまで本文を送信し、その箇所を 1.6 秒だけ枠で示す。URL の search params は変わらない |
| マーカーの無い所を押す | 押した位置に見えている範囲の中央が来るまで、本文をすぐに送信する。スマートフォンなどのタッチの端末でも同じ |
| PC で押したまま上下に動かす | スクロールバーと同じように本文が送信される。面の中を押したときはつかんだ位置を保ち、面の外を押したときは面の中央が押した所に合う。押した位置から 5px 動くまでは押しただけとして扱い、動かした後に離してもマーカーへは飛ばない |

### 項目を検索する

トップバーの検索を押すか、Ctrl+K（macOS は Cmd+K）を押す。入力欄で文字を入れている間も開ける。
ID・タイトル・本文を、空白で区切ったキーワードを全て含むもので検索する。大文字・小文字は区別しない。
HTML の資料の本文と、Markdown の本文の中の `html` のコードブロックは、描いた文で当たる。タグや属性の名前・値では当たらない。
結果は「完全に一致」（ID かタイトルがキーワードとちょうど同じ）→「タイトルに一致」（タイトルがキーワードを全て含む）→「ほかの所に一致」の見出しの順に並び、それぞれの結果に種類が付く。
結果を押すか、矢印で選んで Enter を押すと、その項目のタブと詳細パネルが開く。

絞り込みを持つ画面（概要以外）で開いたときは、キーワードで始まる絞り込みの値（タグ・状態など）が、結果の先頭の「絞り込みをオンにする」に「{条件} = {値}」と件数つきで並ぶ（全角半角・大文字小文字は区別しない）。押すか矢印で選んで Enter を押すと、検索が閉じ、今の画面の絞り込みにその値が加わる。ブラウザの戻る操作で、加える前の条件へ戻れる。
閉じるには、Esc か外側の押下を使う。

### ライトとダークを切り替える

トップバーの右端のボタンで、ライトとダークを切り替える。
選んだほうは、この端末に残る。
選ぶまでは、端末のライト / ダークに従う。

### 表示の設定を変える

トップバーの表示の設定のボタンを押すと、見ている画面に重ねて左から表示の設定が開く。
コメントの一覧とは片方だけが開き、開くともう片方が閉じる。右の詳細パネルは開いたままになる。
幅 900px 以下では、画面の幅いっぱいに出る。
詳細パネルを開いていても、表示の設定は詳細パネルの前に出る。閉じると、開く前の詳細パネルが見える。
開いている間、トップバーとタブの帯とパネル以外はグレーアウトし、透けて見えるが操作できない。
閉じるには、見出しの ×・Esc・グレーアウトした所の押下、またはもう一度表示の設定のボタンを押す。

選んだ値は、その場で画面に当たり、この端末の個人の上書きとして残る。
サーバーへは送信せず、同じワークスペースを見るほかの人の表示は変わらない。
値は項目ごとに、個人の上書きがあればそれを、無ければワークスペースの既定（`config.yaml` の `display`）を使う。

| 操作 | やり方 |
| --- | --- |
| 表示する種類を選ぶ | 検討事項・タスク・調査・資料・用語集・メモ・会話ログのチェックを付け外しする。「すべて」で全てを付け外しし、一部だけのときは途中のマーカーと `5/7` の形式の件数が出る。外した種類のタブは、トップバーから外れる。概要は常に出る |
| 差分のミニマップを選ぶ | 「表示する種類」の下の区画「詳細に表示するもの」の「差分のミニマップ」のチェックを付け外しする。既定は表示する。外すと、開いている詳細パネル・詳細の全画面からその場でミニマップが消える |
| 本文のセクションの見せ方を選ぶ | 同じ区画「詳細に表示するもの」の「セクションの折りたたみ」のチェックを付け外しする。既定は付いている。付け外すと、開いている詳細パネル・詳細の全画面の本文がその場で再描画され、畳んだセクションは初めの状態に戻る（[本文の表とセクションを読み込む](#本文の表とセクションを読み込む)） |
| レビューに追加した後のフォーカスを選ぶ | 区画「詳細に表示するもの」の下の区画「コメントの入力」で、「自動」「入力欄へ戻す」「戻さない」から選ぶ。既定は「自動」で、マウスで操作する端末では入力欄へ戻し、タッチで操作する端末では戻さない。「自動」の下に、使用している端末でどちらになるかが出る（[コメントをレビュー中に溜める](#コメントをレビュー中に溜める)） |
| 1 文字のショートカットを選ぶ | 区画「コメントの入力」の下の区画「キーボード」の「1 文字のショートカットを使用する」のチェックを付け外しする。既定は付いている。外すと、詳細の `j`・`k` で一覧の前後の項目へ移らない |
| ワークスペースの設定を編集する | 下端の「設定を編集する」を押す。サーバーが配るプレビューで、差分の表示をしていないときだけ出る（[設定を編集する](#設定を編集する)） |
| 既定に戻す | 「この端末で変えている項目」に並んだ項目（表示する種類・ライト / ダーク・表の列・差分のミニマップ・本文のセクションの見せ方・レビュー中のコメントの並び・レビューに追加した後のフォーカス・1 文字のショートカット）の上書きを全て外し、ワークスペースの既定の表示に戻す。上書きが無いときは「ワークスペースの既定のまま表示しています。」が出て、ボタンは出ない |

開いている画面の種類を外したときは、概要へ移る。
外した種類のタブを指す URL は、概要で開く。検索の結果から開いた詳細と、外した種類の項目を指す URL は、そのまま開く。
概要のタイルは、外した種類のものも残り、その種類の画面へ移る「すべて表示」と進捗のセルのリンクだけが外れる。

ライト / ダークはトップバー、表の列は表の上で変える。どちらも個人の上書きで、「既定に戻す」で外れる。

端末に保存できないときは、パネルの先頭に「この端末に保存できません。選んだ表示は、このページを開いている間だけ当たります。」が出る。

#### ワークスペースの既定にする

選んだ表示する種類を、同じワークスペースを見る全員の既定として保存できる。
サーバーが配るプレビューだけで、選びが今の既定と違うときに、「この端末で変えている項目」の下に線で区切って「ワークスペースの既定にする」が出る。
同じときは、ボタンの代わりに「表示する種類は、ワークスペースの既定と同じです。」が出る。
差分のミニマップと本文のセクションの見せ方はワークスペースの既定にならず、`config.yaml` は変わらない。これらだけを変えているときも、同じ文言が出る。

押すと、確かめのモーダル「ワークスペースの既定を書き換えますか」が開き、今の既定と保存する値が並ぶ。

| 操作 | 結果 |
| --- | --- |
| 保存する | `config.yaml` の `display` が書き換わり、モーダルが閉じる。パネルに「ワークスペースの既定にしました（{MM/DD HH:mm}）。」が残る。個人の上書きはそのまま残る |
| 取り消す・Esc | 何も書かずにモーダルが閉じる |
| 保存できなかった | モーダルの中に理由が出る。`config.yaml` も画面の表示も保存の前のまま。サーバーが止まっているときは、起動スクリプトで再起動し、示された新しい URL で開いてから保存する |

保存は誰でもできる。
他の人が保存したときと、`config.yaml` を手で修正して[設定を再読み込みする](./コマンド.mark.md#設定を再読み込みする)で効かせたときは、上書きを持たない項目にだけ新しい既定が当たる。
画面の下に「ワークスペースの既定が変わりました。」が 6 秒出て、同じ知らせが時刻つきでパネルに残る。
`config.yaml` が検査に通らないときは、最後に検査に通った設定のまま表示する。

### 項目と設定を編集して保存する

項目の追加・修正・削除・取り下げと、ワークスペースの設定の書き換えは、その場では書かず、保存待ちに溜める。
溜めた編集は、保存待ちのパネルでまとめて 1 回で保存すると、ワークスペースに書かれる。
保存待ちの編集はワークスペースの `edits.yaml` に残り、パネルを閉じても、再読み込みしても、起動スクリプトで再起動しても、保存するか取り消すまで消えない。
編集できるのは、サーバーが配るプレビューだけで、配る書き出しには編集の操作が出ない。
差分の表示の間は、編集の操作・保存待ちのマーカー・トップバーの保存待ちのボタンが出ず、保存待ちのパネルが開いていれば閉じる。差分の表示をやめると、マーカーとボタンが再表示される。

保存待ちの編集の件数は、項目のキー 1 つ・本文・案 1 つの追加と書き換えと削除・採用する案の切り替え・設定のキー 1 つをそれぞれ 1 件と数え、項目の追加と削除は項目ごとに 1 件と数える。

#### 項目を編集する

詳細パネルと詳細の全画面の見出しの「編集する」を押すと、読む表示が編集の表示に替わる。もう一度押す（「編集を終える」）か、別の項目を開くと、読む表示に戻る。溜めた編集は保存待ちに残る。
編集の表示は、編集できないキー（ID・作成・更新）を頭に並べ、その種類のキーを入力にする。ID・作成日時・更新日時・編集した人・変更履歴は編集できない。

<!-- table: {"kind": "data"} -->

| キー | 入力 |
| --- | --- |
| 状態 | 選ぶ |
| タグ | 記録で使われているタグを候補に出し、候補に無いタグも入れられるチップ。チップの左端のトグルで主題を付け外しする |
| 参照のキー | ID を入れるチップ |
| 取り下げ | チェック |
| 回答・理由・結果など | 何行も書く欄 |
| 本文 | 等幅の何行も書く欄 |

<!-- /table -->

入力欄を離れたとき（選ぶ・チェックは選んだとき）に、そのキーの編集を 1 件溜める。溜めたキーの入力欄は、枠が破線になる。
元の値に戻すと、保存待ちから外れる。
タイトルは空にできない。空のまま入力欄を離れると、溜めずに「タイトルを書いてください。」が出る。
届かない・エラーのときは入力が残り、キーの下に理由が出る。

タグのチップの左端のトグルは、主題のタグでは二重丸、主題でないタグでは輪で出る。
押すと主題を付け外しし、タグの編集を 1 件溜める。
主題のタグは 1 項目に複数にできる。
入力欄から追加したタグは、主題でないまま並ぶ。
削除を溜めた項目では、トグルを押せない。

検討事項は、案も編集する。
案ごとに、記号・「採用」のラジオ・中身の入力欄・「案 {記号} を削除」があり、末尾の「案追加」で次の記号の空の案が増える。
中身を離れたときに案の追加か書き換えを、採用を選んだときに採用する案の切り替えを、削除を押したときに案の削除を溜める。削除を溜めた案は、中身に取り消し線が引かれる。

やめた項目は、削除せずに取り下げる。

| 種類 | 取り下げ方 |
| --- | --- |
| 検討事項 | 状態を `対象外` か `取り下げ` にする |
| タスク | 状態を `中止` にする |
| 調査・資料・用語集・メモ・会話ログ | 取り下げのチェックを付ける |

#### 項目を追加する

検討事項・タスク・調査・資料・用語集・メモ・会話ログの画面の「項目追加」を押すと、開いていた詳細パネルが閉じ、その種類の追加の入力が詳細パネルと同じ置き方で開く。
タイトルを書いて入力欄を離れると、項目を追加する編集が 1 件溜まる。残りのキーは、その 1 件の中に溜まる。
検討事項の案と採用も、その 1 件の中に溜まる。
追加の入力では、採用している案に「案 {記号} を削除」が出ない（採用をほかの案へ移すと出る）。
ID は保存したときにサーバーが振るので、溜めている間は付かない。

溜めた項目は、一覧の先頭（ボードは状態の列の先頭）に破線の枠で出る。
ID の場所には「ID は保存時に決定」（表は「—」）が出て、タイトルが空なら「（タイトル未入力）」が出る。
押すと、追加の入力が開き直る。

#### 項目を削除する

詳細パネルの編集の表示の末尾の「項目を削除」を押すと、項目の削除が溜まる。確認は出ない。
溜めた後は、同じ場所が「削除を取り消す」に替わり、押すと削除が取り消される。削除を溜めた項目は、入力が読むだけになる。

ほかの項目が指している項目でも削除は溜まるが、保存のときに書き込めない編集になる。
ボタンの下に「{指している項目の ID} が指しているため、保存のときに削除できません。指している項目から外すと削除できます。」が出る。指している項目も同じ保存で削除するときは、書き込める。

#### 設定を編集する

表示の設定のパネルの下端の「設定を編集する」を押すと、パネルが閉じ、設定の画面が開く。
閉じるボタンで、開く前の画面に戻る。溜めた編集は保存待ちに残る。

設定の画面は、設定のキーを次のまとまりに分けて並べる。

| まとまり | キー |
| --- | --- |
| 話し合い | 題名・説明 |
| 関連 | 関連する場所 |
| 変更履歴 | 保持する回数 |
| 音声入力 | 文字起こし後の挙動・用語集のプリセット |

入力欄を離れたとき（選ぶ・チップ・行の追加と削除は操作したとき）に、そのキーの編集が 1 件溜まる。
用語集のプリセットの候補は、設定の画面を開いたときに文字起こしのサービスから読む。サービスが使えないときは、今の値のまま選べず、下に理由が出る。サービスを起動してから設定の画面を再度開くと選べる。

#### 保存待ちのマーカーで変えた箇所を参照する

保存待ちの編集がある項目・キー・案に、破線の枠とマーカーが付く。マーカーは 3 種類ある。

| マーカー | 文言 | 意味 |
| --- | --- | --- |
| 重ねた紙 | 保存待ち | 書き換え・追加の編集がある |
| ゴミ箱 | 保存で削除 | 削除の編集がある |
| 警告 | 書き込めない | 直前の保存で書き込めなかった編集がある |

マーカーは、一覧（ボード・カード・表）の項目のタイトルの後ろと、詳細パネルの見出しと、変えたキー・案の名前の後ろに付く。
詳細パネルの見出し・キー・案は、マーカーだけになる。幅 480px 以下では、見出しのマーカーは出ず、キー・案のマーカーだけが出る。
読む表示は、保存待ちの編集を当てた値で描かれる。

トップバーの保存待ちのボタンは、絞り込みとコメントのボタンの間に出て、保存待ちの編集の件数を持つ。100 件以上は「99+」と出る。
直前の保存で書き込めなかった編集が残っているときは、件数の色が失敗の赤になる。

#### 保存待ちの編集を取り消す

保存待ちのボタンを押すと、保存待ちのパネルが左から開く。パネルは、編集を項目（設定は「設定」、追加する項目は「{種類}追加」）ごとにまとめ、溜めた順に並べる。
行は、編集した内容（キーの名前・「案 {記号}」・「採用する案」・「項目追加」・「項目を削除」）と、前の値 → 後の値を出す。本文と削除は値を出さない。

編集は、1 件ずつ取り消せる。
行の「取り消す」を押すと、その 1 件が保存待ちから外れる。詳細パネルで元の値に戻しても外れる。削除は、詳細パネルの「削除を取り消す」でも取り消せる。
まとまりの見出しを押すと、その項目が詳細パネルの編集の表示で開く（設定は設定の画面、追加する項目は追加の入力）。

#### 保存待ちの編集をまとめて保存する

保存待ちのパネルのフッターに、「{件数} 件（うち削除 {件数} 件）をワークスペースに書き込みます」と「まとめて保存する」が出る。削除を含むときは、ボタンが「まとめて保存する（{件数} 件を削除）」になる。
押すと、保存待ちの編集が 1 回でワークスペースに書かれる。1 件でも書き込めない編集があるときは、何も書かない。

保存待ちのパネルは、コメントの一覧・表示の設定のパネルと片方だけが開く。幅 900px 以下では、画面の幅いっぱいに出る。
開いている間、トップバーとタブの帯とパネル以外はグレーアウトし、透けて見えるが操作できない。まとまりの見出しから開いた詳細パネルは、グレーアウトの上に出て操作できる。
閉じるには、見出しの ×・Esc・グレーアウトした所の押下・もう一度保存待ちのボタンを使う。保存待ちの編集は残る。

| 結果 | 画面の出方 |
| --- | --- |
| 全て書けた | パネルが閉じ、詳細パネルは読む表示に戻り、画面の下に「{件数} 件を保存しました。」が 5 秒出る。画面を再度開かずに、マーカーと保存待ちのボタンが消える |
| 書き込めない編集がある | 何も書かず、パネルを開いたまま、「{件数} 件の編集を書き込めないため、何も保存していません。」と書き込めない編集の一覧が出る。その項目・キーに「書き込めない」の記号と理由が付く |
| サーバーにつながらない | 「サーバーにつながらないため、保存できませんでした。」が出る。保存待ちの編集は残るので、起動スクリプトで再起動し、示された新しい URL で開いてから、もう一度保存する |

書き込めない編集は、取り消してから、もう一度保存する。理由ごとの修正方法は次のとおり。

| 理由 | 修正方法 |
| --- | --- |
| 溜めた後に AI がその項目を書き換えた（設定は、溜めた後に値が変わった） | その編集を取り消し、今の値を見て再入力する |
| 編集する項目が無くなった | その編集を取り消す |
| 削除する項目をほかの項目が指している | 理由に出た項目を押して開き、指している側から外すか、その項目も同じ保存で削除する |
| 書いた値が、案と状態の決まり・参照の指す先などに合わない | 理由に出た内容を見て、その編集を取り消し、値を修正して再入力する |

保存した項目は、最後に編集した人と変更履歴の書き換えた人が `user` になり、変更履歴に説明「画面からの編集」のまとまりで残る（[編集した人を項目ごとに残す](./コアコンセプト-ワークスペース.md#編集した人を項目ごとに残す)）。
保存した変更は、MindStella のセッションが次の起動・再開の注入か `changes_since_read` で、利用者が画面で変えた分として受け取る（[起動と再開](./エージェントフロー.md#起動と再開)）。

### 配る書き出しを依頼して配布する

ワークスペースもサーバーも持たない人へ記録を見せるときは、MindStella のセッションに書き出す先のパスを伝えて、配る書き出しを頼む。
MindStella のセッションが、画面と描画のライブラリを全て中に持つ 1 枚の HTML を、そのパスへ書き出して絶対パスをスレッドで示す。
書き出す先に、ワークスペースの `.mindstella/` の中は使わない。
書き出すときは、jsDelivr へ届いている必要がある。

渡された人は、その HTML をブラウザで開くだけで読める。
ネットにつながらなくても、本文の Markdown・mermaid の図が描かれる。
文字は端末の文字で描く。

配る書き出しは見るだけの画面で、項目の追加・編集・削除、回答・コメントの送信、設定の保存の操作は出ない。
見るための操作は、サーバーが配るプレビューと同じ。
本文が Markdown の資料の[書き出し](#資料を書き出す)も使える。「HTML でエクスポート」は、中に持つ mdmark のスタイルとスクリプトを使うので、通信が要らない。
書き出した HTML は、書き出したときのワークスペースの既定を中に持ち、開いた人の個人の上書きと合わせて表示する。
表示の設定で表示する種類は変えられるが、「ワークスペースの既定にする」は出ない。
中に持つライブラリのライセンスの表示は、HTML の中に入るが画面には出ない。mdmark が同梱するライブラリのライセンスの本文も入る。

# Discord に通知する

MindStella のセッションに依頼した作業が完了したことを、Discord のチャンネルで受け取りたいときに実行する。

## 前提

- [起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)
- 通知を受け取る Discord のチャンネルで、Webhook を作成できる

## 手順

1. Discord のチャンネルの設定の「連携サービス」で Webhook を作成し、「ウェブフック URL をコピー」で URL をコピーする
2. URL を 1 行だけ記載したファイルを、リポジトリとワークスペースの外に作成する（例 `~/.config/web-hook/mindstella.ini`）
3. [起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)で、`MINDSTELLA_DISCORD_WEBHOOK_FILE` にそのファイルの絶対パスを回答して登録する
4. 登録した後に開いたシェルで、[常駐サーバーを起動する](./セットアップ手順-常駐サーバーを起動する.md)の手順で常駐サーバーを停止してから、[起動スクリプトで立ち上げる](./セットアップ手順-起動スクリプトで立ち上げる.md)を実行する

Webhook の URL を知っていれば誰でもチャンネルへ投稿できるので、ファイルは他の人と共有しない。
環境変数にはファイルの場所だけを登録し、URL そのものは登録しない。

## 届く通知

MindStella のセッションが 1 回の応答の間にスレッドへ書き込んだか commit したとき、応答の終わりに次の 2 行が 1 件届く。

```text
{ワークスペースの題名}: 作業が完了しました
{プレビューの URL}
```

- 題名が空なら、ワークスペースのフォルダの名前になる
- プレビューを配信していないときは、1 行目だけが届く
- 何も書き込まなかった応答、エラーで終わった応答、MindStella のセッションが止まったときは届かない

## 確認方法

MindStella のセッションに、スレッドへ返信する作業を 1 つ依頼する。
応答が終わった後にチャンネルへ通知が届けば完了。

届かないときは、常駐サーバーのログ（`journalctl --user -u mindstella`）に送信の行があるかを確認する。

| ログ | 原因 |
| --- | --- |
| 送信の行が無い | ファイルの場所が登録されていないか、ファイルの 1 行目が `http://` か `https://` で始まっていない |
| 送信が失敗した行に `404` がある | Webhook が削除されたか、URL が誤っている |

ログに Webhook の URL は出ない。

## 通知をやめる

[起動スクリプトを登録する](./セットアップ手順-起動スクリプトを登録する.md)で `MINDSTELLA_DISCORD_WEBHOOK_FILE` の登録を解除し、常駐サーバーを立ち上げ直す。
立ち上げ直さずにやめるときは、ファイルを削除するか 1 行目を空にする（ファイルは送信のたびに参照される）。

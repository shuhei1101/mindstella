# スキル

プラグイン mindstella が持つスキルの一覧と、進め方ガイドの一覧。
どれも Claude Code のセッションでスラッシュコマンドとして呼び、ワークスペースへの記録は [コマンド](./コマンド.md) の MCP のツールを呼んで行う。
MCP のツールは起動スクリプトで立ち上げた Claude Code にだけ載り、載っていない会話では、どのスキルも何も書き込まずに、起動スクリプトでの立ち上げを案内して止まる（`setup` は起動スクリプトの登録へも進める）。

## 一覧

| 名前 | コマンド | 説明 |
| --- | --- | --- |
| [話し合いをセットアップする](#話し合いをセットアップする) | `/mindstella:setup` | 新しいワークスペースを作るか、既存のワークスペースの状況を示す |
| [話し合いを進める](#話し合いを進める) | `/mindstella:session` | 取り込み・ヒアリング・リサーチ・方針転換・範囲の見直し・プレビュー・ゴール判定を回して、ゴールまで進める |
| [ワークスペースを移し替える](#ワークスペースを移し替える) | `/mindstella:upgrade` | ワークスペースの版とプラグインの版を比べ、版ごとの手順で今の版へ移し替える |

## 話し合いをセットアップする

新しいワークスペースを作るか、既存のワークスペースの状況を示して、`/mindstella:session` へ渡す。
スキルが自分でファイルを書くことはない。

### 使い方

```
/mindstella:setup [ワークスペースのフォルダ]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| ワークスペースのフォルダ | 任意 | `.mindstella/config.yaml` があれば既存のワークスペース（`.mindstella/config.yaml` が無く、直下の `config.yaml` か `mindmap.yaml` だけがあれば版が古いワークスペースとして移し替えを案内する）、どれも無ければ新しいワークスペースとして扱う。省略すると指定を求める | `~/discussions/家計簿アプリ` |

### ステップ

| ステップ | 手順 | 使うツール | することと残る記録 |
| --- | --- | --- | --- |
| 新しいワークスペース | [新しいワークスペース](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/setup/steps/%E6%96%B0%E3%81%97%E3%81%84%E3%83%AF%E3%83%BC%E3%82%AF%E3%82%B9%E3%83%9A%E3%83%BC%E3%82%B9.md) | `init` | 話題に合う進め方ガイドを 1 つ以上選び、タイトル・話し合いの概要・最上位の軸の呼び名・フェーズ・カテゴリー・ゴールのたたき台を示して確定をもらい、ワークスペースを作る。ゴールは決めずに始められる |
| 既存のワークスペース | [既存のワークスペース](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/setup/steps/%E6%97%A2%E5%AD%98%E3%81%AE%E3%83%AF%E3%83%BC%E3%82%AF%E3%82%B9%E3%83%9A%E3%83%BC%E3%82%B9.md) | `migrate`（`plan: true`）・`status`・`find` | `migrate` を `plan: true` で呼んで版を比べ、ワークスペースの版が古ければ `/mindstella:upgrade` を、新しければプラグインの更新を案内して止まる。同じなら、要見直し・進行中・再開可能・次の候補を示し、続きを推奨する。ファイルは書き換えない |
| 起動スクリプトの登録 | [起動スクリプトの登録](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/setup/steps/%E8%B5%B7%E5%8B%95%E3%82%B9%E3%82%AF%E3%83%AA%E3%83%97%E3%83%88%E3%81%AE%E7%99%BB%E9%8C%B2.md) | なし（Bash で `register.py`） | 登録を読んで未登録なら持ちかけ、設定したい環境変数（`MINDSTELLA_VENV`・`MINDSTELLA_ALLOWED_HOSTS`・`MINDSTELLA_PREVIEW_START_HOOK`・`MINDSTELLA_PREVIEW_STOP_HOOK`）を尋ねて、起動スクリプトを呼ぶ alias `mindstella` と環境変数をログインシェルの設定に登録する。アカウントを足すと、アカウントごとの alias `mindstella-{アカウントの名前}` も登録する。登録を変える・外す・アカウントを外すこともできる。書くのはシェルの設定と `~/.config/mindstella/` だけで、ワークスペースは書かない。書き込めないときは、何も書き換えずに理由と手で書く行を示して止まる |

MCP のツールが無いときは、ワークスペースに何も書き込まず、登録を読む。
未登録なら起動スクリプトの登録を持ちかけ、登録済みなら新しいシェルで alias にフォルダを渡して立ち上げ直すよう案内して止まる。
登録を変えたい・外したい・アカウントを足したいと伝えたときは、MCP のツールの有無に関わらず起動スクリプトの登録へ進む。
新しいワークスペースと既存のワークスペースのステップは、最後に `/mindstella:session {ワークスペースのフォルダ}` で続けるよう案内する。

## 話し合いを進める

作成済みのワークスペースで、ステップを場面に応じて回す。

### 使い方

```
/mindstella:session [ワークスペースのフォルダ]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| ワークスペースのフォルダ | 任意 | `.mindstella/config.yaml` か、直下の `config.yaml`・`mindmap.yaml` があるフォルダ。省略すると、同じ会話で `setup` が渡したフォルダを使う。どれも無いときは、書き込まずに `/mindstella:setup` を案内する | `~/discussions/家計簿アプリ` |

### ステップ

準備で `.mindstella/config.yaml`（無ければ直下の `config.yaml` か `mindmap.yaml`）を読んだ後に、`migrate` を `plan: true` で呼んで版を比べる。
ワークスペースの版が古ければ、何も書き込まずに `/mindstella:upgrade` を案内して止まる。新しければ、プラグインの更新を案内して止まる。
同じなら、`readme` でワークスペースの直下の `README.md` を書き直す。利用者が書いた `README.md` は書き換えず、エラーを返したときはエラーの本文を短く示して準備を続ける。
続けて `changes_since_read` で前回読んだ時点からの変更を読み、足された・変わった項目があれば、前回の後に変わったものとして短く示して話し合いの前提にする。読んだ時点の記録が無いワークスペースでは何も示さず、今の時点を記録する。
続けて `submissions` で取り込んでいない送信を読み、1 件以上あれば、届いていた送信を示す。
箇所を持つ送信には、本文の行の範囲か値のキーと、選んだ文を添える。項目に紐づかない送信には、項目を指さない旨を添える。
続けて `pending` でまだまとめていない変更を読み、空でなければ、前の話し合いでまとめ忘れた分として説明を付けて `commit` する。
取り込み・ヒアリング・リサーチ・方針転換は、記録を書き換え終えたら、そのステップで何をしたかを一言の説明にして `commit` を呼ぶ。
書き換えが無いステップと範囲の見直しでは呼ばない。

| ステップ | 手順 | 使うツール | することと残る記録 |
| --- | --- | --- | --- |
| 取り込み | [取り込み](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/session/steps/%E5%8F%96%E3%82%8A%E8%BE%BC%E3%81%BF.md) | `tags`・`batch`・`add`・`update`・`edit_option`・`adopt`・`update_settings`・`take_submission`・`commit` | 発言を対象・カテゴリー・フェーズに振り分けて記録し、派生の検討事項・未整理・タスクを積む。記録を書く前に `tags` でタグの一覧を引き、既にある話題のタグを使い回して、新しい話題のときだけタグを作って付ける。1 項目に複数の話題が当たるときは全て付ける。1 つの発言から出た記録（項目の追加・更新と会話ログ）は `batch` で 1 回に書き、同じ発言で足す項目を指すときは `$番号` を使う。検討事項は、`未整理` を除いて必ず案を書いて足し、未決定なら AI が推す案に推奨の印（`recommended`）を付ける。決まったこととして足すときは、選ばれた案を採用して `決定済み` にする。問いの形にならない未整理は案を持たずに足し、未決定へ変えるときに案を書く。既にある検討事項の案と推奨の印を足す・直す・消すときは `edit_option` を使い、採用している案を消すときは先に `adopt` で採用を移す。一般的でない言葉は用語集に足す。保留・解除・中止もここで行う。図や文書と、作業・検証のタスクの成果は資料に残し、ゴールの納品物で資料の無いものは資料を作る。ゴールの納品物に当たる資料なら `update_settings` で納品物へ足す・つなぐ。会話ログを書き足す。準備で届いていた送信は、送った順に 1 件ずつここで記録してから、`take_submission` で取り込み済みにする |
| ヒアリング | [ヒアリング](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/session/steps/%E3%83%92%E3%82%A2%E3%83%AA%E3%83%B3%E3%82%B0.md) | `next`・`find`・`edit_option`・`adopt`・`update`・`add`・`commit` | 前提が揃った未決定を、聞く前に `edit_option` で推奨の印を案の表の推奨と揃え、検討事項が持つ案の表と推奨を付けて 1 ラウンドにまとめて聞く。答えを受けたら `adopt` で選ばれた案を採用して決定済みにし、`update` で答えを `answer`・`reason` に入れる |
| リサーチ | [リサーチ](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/session/steps/%E3%83%AA%E3%82%B5%E3%83%BC%E3%83%81.md) | `add`・`update`・`find`・`commit` | 「何を・どの観点で・何体で」を示して確認を取り、サブエージェントで調べ、調査を元の検討事項に `related` で繋ぐ。調べた結果にある固有の言葉を用語集に足す。利用者が自分から頼んだときは確認を省く |
| 方針転換 | [方針転換](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/session/steps/%E6%96%B9%E9%87%9D%E8%BB%A2%E6%8F%9B.md) | `adopt`・`impact`・`update`・`update_settings`・`add`・`check`・`commit` | 採用する案を切り替えて（`adopt` が状態を `決定済み` にする）、影響を受ける決定済みの項目を採用した案を持ったまま要見直しにし、見直しのタスクを積む。納品物が要らなくなったときは、資料へ格下げし、`update_settings` でゴールの納品物から外す |
| 範囲の見直し | [範囲の見直し](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/session/steps/%E7%AF%84%E5%9B%B2%E3%81%AE%E8%A6%8B%E7%9B%B4%E3%81%97.md) | `update_settings`・`add` | 範囲が広がったとき、題名・話し合いの概要・ゴール・進め方ガイド・最上位の軸の呼び名・対象・カテゴリーを変えたいと言われたとき、話の中身と呼び名が合わなくなったとき、ゴールが無くて利用者が決めると言ったときに回す。書き換えのたたき台を示し、フェーズ・対象・カテゴリーが変わるときは新しい設定に無い古い名前から新しい名前への対応の表も示して、確定をもらってから設定を書き換え、項目のフェーズ・対象・カテゴリーを付け替える。ゴールの納品物を足したときは、その資料を作って納品物から指す。会話ログを書き足す |
| プレビュー | [プレビュー](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/session/steps/%E3%83%97%E3%83%AC%E3%83%93%E3%83%A5%E3%83%BC.md) | `preview_url`・`export` | `preview_url` が返した URL を示す。ブラウザは開かないので、利用者が開く。利用者が記録を人に渡したいと言ったときだけ、書き出す先のパスを聞き、`export` で配る書き出し（ネットにつながらなくても開け、書き込む操作を持たない 1 枚の HTML）を書き出して絶対パスを示す |
| ゴール判定 | [ゴール判定](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/session/steps/%E3%82%B4%E3%83%BC%E3%83%AB%E5%88%A4%E5%AE%9A.md) | `goal`・`show`・`find`・`update`・`clear_release`・`add` | ゴールに届いていれば、完了したタスクの成果と資料が揃っているかを確かめて欠けた資料を足し、検討事項と納品物を示して確定をもらい、`.mindstella/release/` に書き出す。届いていなければ、残りを示す。ゴールが無ければ、リリースせず、ゴールを決めるかを尋ね、決めると言われたら範囲の見直しでゴールを書く |

### 確認が出る操作

スキルが許す操作は、ファイルを読むことと、サブエージェントによる調査と、MCP のツールの呼び出しだけ。
リリースの資料（`.mindstella/release/`）の書き出しは、Claude Code が書き込みの確認を出す。項目の本文（`.mindstella/docs/`）は `add`・`update` の `body_markdown` で、設定（`.mindstella/config.yaml`）は `update_settings` で書くので、確認は出ない。

## ワークスペースを移し替える

ワークスペースの版とプラグインの版を比べ、版ごとの手順を当てて今の版へ移し替える。
プラグインを上げた後に、`setup`・`session` がワークスペースの版が古いと案内したときに呼ぶ。
スキルが自分でファイルを書くことはなく、写しを取る・手順を当てる・値を入れる・版を書き換えるは [記録の形式を移す](./コマンド.md#記録の形式を移す)が行う。

### 使い方

```
/mindstella:upgrade [ワークスペースのフォルダ]
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| ワークスペースのフォルダ | 任意 | `.mindstella/config.yaml` か、直下の `config.yaml`・`mindmap.yaml` があるフォルダ。省略すると指定を求めて終える。どれも無いときは、書き込まずに `/mindstella:setup` を案内する | `~/discussions/家計簿アプリ` |

### ステップ

上から順に進む。

| ステップ | 使うツール | することと残る記録 |
| --- | --- | --- |
| 版の比較 | `migrate`（`plan: true`） | ワークスペースの版とプラグインの版を比べる。同じなら移し替えるものが無いと示して終える。ワークスペースの版が新しければ、プラグインの更新を案内して止まる |
| 手順の一覧 | - | 当てる手順を版の順に示す。破壊的な操作（`rename_file`・`move_dir`・`delete`）を含むときだけ、当ててよいかを確かめる |
| 手順を当てる | `migrate` | 写しを取って手順を当てる。写しは git の管理下ならコミット、そうでなければフォルダの複製。失敗したら写しから元に戻し、失敗した版・手順・理由を示して止まる |
| 点検 | `check`・`migrate`（`values`） | 今のスキーマで点検し、値が要るキーだけを利用者に聞いて入れる |
| 案と状態の補正 | `check`・`batch` | `check` が `decision_state` で返した検討事項を直す。案を持たない検討事項は AI が問いと本文から案のたたき台（未決定なら推奨の印も）を書いて示し、採用した案と状態が合わない検討事項はどう直すかを示して、まとめて利用者に確かめる。確かめた内容を `batch` 1 回で書き、もう一度 `check` を呼んで、問題が残れば示して止まる |
| 版の書き換え | `migrate`（`record: true`） | `.mindstella/mindstella-version.ini` をプラグインの版に書き換える |
| 仕上げ | - | 移し替えた版と写しの場所を示して、`/mindstella:session {ワークスペースのフォルダ}` で続けるよう案内する |

スキルが許す操作は、ファイルを読むことと、MCP のツールの呼び出しだけ。

## 進め方ガイド

分野ごとの進め方の手引きで、`skills/mindmap/playbooks/` に置く。
どの進め方ガイドも、フェーズの並び・フェーズごとの観点・必ず調べるもの・ゴールの候補・リリースの形を、同じ項目立てで持つ。
手引きの意味は [話し合いの進め方](../はじめに/コアコンセプト/話し合いの進め方.md#進め方ガイド) にある。
ワークスペースは設定の `playbooks` に進め方ガイドを複数並べられ、AI は並べたガイドをすべて読む。

| 分野 | 最上位の軸の呼び名 | フェーズ |
| --- | --- | --- |
| システム開発 | 機能 | 目的 → 要件 → 構成 → インターフェース → コンテンツ |
| 調査 | 調査対象 | 問い → 観点 → 事実 → 評価 → 結論 |
| 資料作り | 資料 | 目的 → 読み手 → 構成 → コンテンツ → 仕上げ |
| 壁打ち | テーマ | 問い → 発散 → 整理 → 絞り込み → 結論 |

システム開発のゴールの候補は、要件まで・インターフェースまで（既定）・モジュール構成まで。
進め方ガイドの置き場所は [playbooks](https://github.com/shuhei1101/mindstella/blob/develop/plugins/mindstella/skills/mindmap/playbooks/)。

# ワークスペースの書式

ワークスペース（1 つの話し合いのフォルダ）のファイル構成と、各 YAML のキーの一覧。
正本は `skills/mindmap/schemas/` の JSON Schema で、書き込む MCP のツールは書き込む前にこれと突き合わせる。

## ファイル構成

記録のファイルとフォルダは全て、ワークスペースの直下のサブフォルダ `.mindstella/` に置き、直下には `.mindstella/` だけが並ぶ。
`.mindstella/config.yaml` があるフォルダがワークスペースになる。
次の表の名前は `.mindstella/` からのパス。

| ファイル・フォルダ | 中身 |
| --- | --- |
| `config.yaml` | [設定](#設定) |
| `mindstella-version.ini` | ワークスペースを最後に整えたときのプラグインの版。1 行目に `v{メジャー}.{マイナー}.{パッチ}`（例: `v0.3.0`）を書き、2 行目より後は読まない。[ワークスペースを作る](./コマンド.md#ワークスペースを作る)が作るときに書き、[記録の形式を移す](./コマンド.md#記録の形式を移す)が移し替えた後に書き換える。無ければ、直下の `mindstella-version.ini`（v0.6.0 より前の置き場所）を読み、それも無ければ版を記録する前の形式として扱う |
| `decisions.yaml` | [検討事項](#検討事項) |
| `tasks.yaml` | [タスク](#タスク) |
| `research.yaml` | [調査](#調査) |
| `docs.yaml` | [資料](#資料) |
| `terms.yaml` | [用語集](#用語集) |
| `notes.yaml` | [メモ](#メモ) |
| `logs.yaml` | [会話ログ](#会話ログ) |
| `docs/` | 項目の本文の Markdown（`{ID}.md`）。[本文](#本文) |
| `release/` | 書き出す資料を置く |
| `comments.yaml` | [レビュー中のコメント](#レビュー中のコメント)。初めて溜めたときにサーバーが作る。無ければ 0 件として扱う |
| `drafts.yaml` | [書きかけ](#書きかけ)。初めて書きかけを保つときにサーバーが作る。無ければ 0 件として扱う |
| `submissions.yaml` | [送信](#送信)。初めて送ったときにサーバーが作る。無ければ送信 0 件として扱う |
| `.mindstella.lock` | 同じワークスペースを書き換えるプロセスどうしの排他に使う空のファイル。書き換えるツールと、送信・レビュー中のコメント・書きかけの受け付けが初めてロックを取るときに作る |
| `changes.yaml` | [書き換えのまとまり](#書き換えのまとまり)。`add`・`update`・`adopt`・`edit_option`・`batch`・`changes_since_read` が初めて書き換えたときにツールが作る。無ければまとまり 0 件・まだまとめていない変更なしとして扱う |
| `.mindstella-opened` | [前回開いた日時](#前回開いた日時)。プレビューのタブが開くたびにサーバーが書き換える。無ければ前回開いた日時なしとして扱う |

種類ごとの YAML（`config.yaml` 以外）はどれも `items:` の配列を持ち、1 要素が 1 項目になる。

## ID

ID は種類の頭の文字 + `-` + 連番（`D-12`）で、頭の文字で種類が決まる。
連番はその種類の最大 + 1 で振り、消した番号を使い回さない。

| 頭の文字 | 種類 | YAML |
| --- | --- | --- |
| `D` | 検討事項（`decision`） | `decisions.yaml` |
| `T` | タスク（`task`） | `tasks.yaml` |
| `R` | 調査（`research`） | `research.yaml` |
| `A` | 資料（`doc`） | `docs.yaml` |
| `G` | 用語集（`term`） | `terms.yaml` |
| `N` | メモ（`note`） | `notes.yaml` |
| `L` | 会話ログ（`log`） | `logs.yaml` |

## 設定

`config.yaml`。題名・話し合いの概要・プレイブック・最上位の軸の呼び名・フェーズ・対象とカテゴリー・ゴール・関連する場所・変更履歴を保持する回数・表示の既定を持つ。
書き換える MCP のツールは [設定を書き換える](./コマンド.md#設定を書き換える)。
手で直したときは、[設定を再読み込みする](./コマンド.md#設定を再読み込みする)で開いている画面に効かせる。
前の版の設定ファイル `mindmap.yaml` は、[ワークスペースを今の版へ移し替える](../使い方/セットアップ手順/ワークスペースを今の版へ移し替える.md)で `.mindstella/config.yaml` に移る。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `playbooks` | array | ✅ | 並べて使う進め方ガイドの名前（例: `[壁打ち, システム開発]`）。1 件以上で、重複しない。AI は並べたガイドをすべて読む |
| `target_label` | string | ✅ | 対象を画面で何と呼ぶか（例: `システム`） |
| `phases` | array | ✅ | フェーズの名前を浅い順に並べる（例: `[目的, 要件, 構成]`）。プレイブックを複数並べても 1 本の並びで持つ。`next` の並べ替えはこの順を使う。項目の `phase` と `goal.phase` はこのどれか（[ワークスペースを点検する](./コマンド.md#ワークスペースを点検する)が確かめる） |
| `targets` | array | ✅ | 対象の一覧。要素は `name`・`summary` |
| `categories` | array | ✅ | カテゴリーの一覧。要素は `name`・`target`（`targets[].name` のどれか）・`summary` |
| `goal` | object | - | `phase`（どのフェーズまでやるか）・`summary`・`deliverables[]`（`title` と、できた資料の `doc`（`A-` の ID。任意））。無いときは、ゴールを決めていない話し合い |
| `links` | array | - | 関連する場所。要素は `title`・`url` |
| `summary` | string | ✅ | 話し合いのタイトル（何についての話し合いかを 1 文で）。プレビューのトップバーに出す |
| `description` | string | - | 話し合いの概要（何についての話し合いかを 1 文の短い文で。60 字以内）。AI がセットアップと範囲の見直しで書き、`config.yaml` を直して書き換えてもよい。プレビューの概要の画面の題名の上に出す。`summary`・`goal.summary` とは別のもの |
| `history_limit` | number | - | 項目ごとに変更履歴を何回分持つか。0 以上の整数で、上限は設けない。無ければ 5。0 は変更履歴を持たず、差分を出さない。[設定を書き換える](./コマンド.md#設定を書き換える)で変える。AI がまだ読んでいない回（`changes.yaml` の `read_seq` より後の回）は、この回数を超えても消さない |
| `display` | object | - | プレビューのワークスペースの既定。ブラウザの個人の上書きが無い項目に使う。要素は `network_look`・`visible_kinds`。[設定を書き換える](./コマンド.md#設定を書き換える)と、プレビューの「ワークスペースの既定にする」が書く |
| `display.network_look` | string | - | つながりの見た目。`glow`・`starlight`・`constellation`・`deep`・`dust` のどれか。無ければ `deep` |
| `display.visible_kinds` | array | - | プレビューのタブに出す種類。`decisions`・`tasks`・`research`・`docs`・`terms`・`notes`・`logs` の重複しない並びで、空でもよい。無ければ全ての種類。概要とつながりは常に出す |

## 共通のキー

種類ごとの YAML の項目は、どれも次のキーを持つ。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | ID。ツールが付ける |
| `title` | string | ✅ | タイトル |
| `target` | string | - | 設定の `targets[].name` のどれか |
| `category` | string | - | 設定の `categories[].name` のどれか |
| `phase` | string | - | 設定の `phases` のどれか |
| `tags` | array | - | 自由な文字列。話題を分ける印として使い、AI が取り込みで話題ごとに付ける。使っているタグは [タグを一覧する](./コマンド.md#タグを一覧する)で引く |
| `attrs` | object | - | 自由なキーと値（値は文字列・数値・真偽値）。使っているキーの名前は [属性名を一覧する](./コマンド.md#属性名を一覧する)で引く |
| `related` | array | - | 関連する項目の ID。向きを持たず、[影響を洗い出す](./コマンド.md#影響を洗い出す)はたどらない |
| `links` | array | - | リンク。要素は `title`・`url` |
| `created` | string | ✅ | 作成日時（UTC のタイムゾーン付き ISO 8601。例: `2026-10-02T08:00:00+00:00`）。ツールが付ける |
| `updated` | string | ✅ | 更新日時（同じ形）。ツールが付ける |
| `updated_by` | string | - | 編集した人。最後に項目を足した・値を変えたのが AI か利用者かで、`ai`（MCP のツールの書き込み）か `user` のどちらか。`updated` を書き換える書き込みが一緒に書く（フェーズ・対象・カテゴリーの付け替えを含む）。このキーを入れる前に書いた項目は、次に書き換えるまで持たず、編集した人が分からないものとして扱う。ツールが付け、`add`・`update` の `item` では渡せない |
| `history` | array | - | [変更履歴](#変更履歴)。新しい順に並べる。ツールが付け、`add`・`update` の `item` では渡せない。無ければ変更履歴 0 回分として扱う |
| `history_dropped_seq` | number | - | 保持する回数を超えて `history` から消した回のうち、最も大きい `seq`。一度も消していなければ持たない。ツールが付け、`add`・`update` の `item` では渡せない |
| `seq` | number | - | 最後に振った通し番号。項目を足した・値を変えたときに振った `changes.yaml` の通し番号のうち、最も新しいもの。[前回読んだ時点からの変更を読む](./コマンド.md#前回読んだ時点からの変更を読む)が `read_seq` と比べる。フェーズ・対象・カテゴリーの付け替えでは進めない。このキーを入れる前に足した項目は、次に値を変えるまで持たない。ツールが付け、`add`・`update` の `item` では渡せない |
| `added_seq` | number | - | 足したときの通し番号。項目を足したときに振った `changes.yaml` の通し番号。読んだ時点より後に足した項目と変えた項目を分けるのに使う。このキーを入れる前に足した項目は持たない。ツールが付け、`add`・`update` の `item` では渡せない |

## 変更履歴

項目の `history`。[項目を直す](./コマンド.md#項目を直す)・[採用する案を切り替える](./コマンド.md#採用する案を切り替える)・[案を書き換える](./コマンド.md#案を書き換える)が値を変えるたびに、先頭へ 1 回分を足す。
前の版を丸ごとは持たず、変わったところだけを持つ。
変わったキーが無い書き換えは積まない。
[設定を書き換える](./コマンド.md#設定を書き換える)が `phase_map`・`target_map`・`category_map` で項目の `phase`・`target`・`category` を付け替える書き換えも積まない。
数は設定の `history_limit` までで、超えた古い分は次に積むときに消える。
ただし、`seq` が `changes.yaml` の `read_seq` より大きい回（AI がまだ読んでいない回）は、超えても消えない。`read_seq` が無いワークスペースでは、超えた古い分を今までどおり消す。
消した回の最大の `seq` は、項目の `history_dropped_seq` に残る。プレビューは、選んだ時点の範囲の中の回が消えているかをこれで見分ける。

| キー | 型 | 説明 |
| --- | --- | --- |
| `seq` | number | `changes.yaml` の通し番号 |
| `at` | string | 書き換えた日時（UTC のタイムゾーン付き ISO 8601） |
| `by` | string | その回を書き換えたのが AI か利用者かで、`ai` か `user`。このキーを入れる前に積んだ回は持たない |
| `before` | object | 変わったキー → 書き換える前の値。前に無かったキーは `null`。`updated`・`updated_by`・`history`・`history_dropped_seq`・`seq`・`added_seq`・`body` は入れない |
| `body_diff` | array | 本文が変わったときだけ持つ。要素は `line`（書き換えた後の本文の 1 始まりの行）・`now`（そこからの今の行の並び）・`before`（置き換える前の行の並び）。本文の全文は持たない |

## 書き換えのまとまり

`changes.yaml`。`commit` でまとめた書き換えのまとまりと、まだまとめていない変更。
書くのはツールだけで、`add`・`update` の対象にしない。
消さない。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `last_seq` | number | ✅ | 最後に振った通し番号。変更履歴を積むとき・項目を足すとき・`history_limit` が 0 で変更履歴を積まずに値を変えるときに 1 足す |
| `sets` | array | ✅ | まとまり。新しい順。要素は `id`（`V-` + 連番）・`at`（まとめた日時）・`summary`（一言の説明）・`until_seq`（まとめたときの `last_seq`）・`added`（足した項目の ID）・`changed`（変えた項目の ID。足した項目は入れない） |
| `pending` | object | ✅ | まだまとめていない変更。`added`・`changed`（書き換えた順の項目の ID） |
| `read_seq` | number | - | AI が最後に読んだ時点。[前回読んだ時点からの変更を読む](./コマンド.md#前回読んだ時点からの変更を読む)を最後に呼んだときの `last_seq`で、そのツールだけが書き換える。[前回開いた日時](#前回開いた日時)とは別に持つ。一度も呼んでいなければ持たない |

## 前回開いた日時

`.mindstella-opened`。プレビューを最後に開いた日時を、1 行目に UTC のタイムゾーン付き ISO 8601 で持つ。
プレビューのタブが開くたびにサーバーが書き換え、変更履歴の「前回開いてから」の範囲の始まりに使う。
開くたびに書き換わるため、ワークスペースを git などで管理するときは `.gitignore` に入れる。

## 検討事項

`decisions.yaml`。問いと答えの単位で、未決定のものも入る。
消さず、状態を `取り下げ` か `対象外` にする。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `status` | string | ✅ | 状態。`未決定`・`決定済み`・`要見直し`・`保留`・`未整理`・`対象外`・`取り下げ` のどれか |
| `lead` | string | - | 何を決める問いか |
| `answer` | string | - | 決まった答え |
| `options` | array | - | 案。要素は `key`（記号）・`content`・`pros`・`cons`・`note`・`adopted`（真偽値）・`reason`。`adopted` が真の案は 0 か 1 つ |
| `weight` | string | - | 影響度（派生の多さ）。`大`・`中`・`小` のどれか |
| `parent` | string | - | この検討事項が派生した検討事項の ID（`D-`） |
| `depends_on` | array | - | 先に決まっている必要がある検討事項の ID（`D-`）。保留の待ち先もここで持つ |
| `reason` | string | - | 決めた理由・保留や取り下げの理由 |
| `body` | string | - | `docs/` の本文の Markdown のファイル名（`{ID}.md`） |
| `sources` | array | - | 決めた会話ログの ID（`L-`） |

## タスク

`tasks.yaml`。検討事項を決めるための作業と「後でやっといて」。
消さず、状態を `中止` にする。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `kind` | string | ✅ | 種類。`作業`・`調査`・`検証` のどれか |
| `status` | string | ✅ | 状態。`未着手`・`進行中`・`保留`・`完了`・`中止` のどれか |
| `for` | array | - | このタスクが進める検討事項の ID（`D-`） |
| `depends_on` | array | - | 先に終わっている必要があるタスクの ID（`T-`） |
| `reason` | string | - | 積んだ理由・保留や中止の理由 |
| `result` | string | - | 終えたときの結果 |
| `body` | string | - | `docs/` の本文の Markdown のファイル名（`{ID}.md`）。経緯や補足を残す |

| --- | --- | --- | --- |
| `question` | string | ✅ | 何を調べたか |
| `conclusion` | string | - | 調べた結論 |
| `confidence` | string | - | 結論の確からしさ。`高`・`中`・`低` のどれか |

## 資料

`docs.yaml`。会話の中で作った図・文書。納品物もこの中で印を付ける。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `kind` | string | ✅ | 図 / 文書 など（自由な文字列） |
| `deliverable` | boolean | ✅ | ゴールでリリースする納品物か（既定は `false`） |
| `status` | string | ✅ | 資料の状態。`下書き`・`確認中`・`完成` のどれか（既定は `下書き`）。納品物は `完成` でできたとみなす |
| `body` | string | ✅ | `docs/` の本文の Markdown のファイル名（`{ID}.md`） |

`terms.yaml`。話し合いの中で決めた言い方。`title` が用語になる。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `meaning` | string | ✅ | 用語の意味 |
| `aliases` | array | - | 同じものを指す別の言い方 |
| `avoid` | array | - | やめた言い方 |
| `body` | string | - | `docs/` の本文の Markdown のファイル名（`{ID}.md`）。経緯や補足を残す |

## メモ

`notes.yaml`。検討事項にしない覚え書き。脱線で調べたことはタグ `脱線` を付ける。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `content` | string | ✅ | メモの中身 |
| `body` | string | - | `docs/` の本文の Markdown のファイル名（`{ID}.md`）。経緯や補足を残す |

## 会話ログ

`logs.yaml`。会話の要約と残しておきたい言葉。後から書き換えず、消さない。
`related` は、この会話で更新した項目を指す。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `date` | string | ✅ | 会話の日（`YYYY-MM-DD`） |
| `body` | string | - | `docs/` の本文の Markdown のファイル名（`{ID}.md`） |

## レビュー中のコメント

`comments.yaml`。プレビューで書いて溜め、まだ送っていないコメント。
最上位に `seq`（最後に振った連番。振った番号を使い回さないために持つ）と `items:` の配列を持ち、1 要素が 1 件のコメントになる。共通のキーは持たない。
書くのはサーバーのコメントの受け付けだけで、`add`・`update` の対象にしない。
消すと物理的に消え、まとめて送ったときは [送信](#送信)へ移る。チェックの状態は画面だけが持ち、ここには書かない。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | `C-` + 連番。連番は `seq` + 1 で振る。消したコメントを元に戻すときだけ、同じ ID で戻す |
| `target` | string | - | コメントを向けた項目の ID（どの種類でもよい）。項目に紐づかないコメントはキーを持たない |
| `loc` | object | - | [箇所](#箇所)。箇所を持たないコメントはキーを持たない。`target` を持つときだけ持つ |
| `body` | string | ✅ | コメントの本文。前後の空白を除いて 1〜10000 文字 |
| `created` | string | ✅ | 溜めた日時（UTC のタイムゾーン付き ISO 8601）。元に戻したときは元の日時 |

### 箇所

`loc`。画面で選んだ箇所を持つ。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `kind` | string | ✅ | `body`（本文の文を選んだ）か `value`（項目の値を選んだ） |
| `start` | number | - | `body` のとき必須。本文の Markdown の行（1 始まり）の始め |
| `end` | number | - | `body` のとき必須。本文の Markdown の行（1 始まり）の終わり。`start` 以上 |
| `key` | string | - | `value` のとき必須。項目のキーのパス。案の中は `options[{案の key}].{キー}` |
| `text` | string | ✅ | 画面で選んだ文（描いた文のまま）。前後の空白を除いて 1〜10000 文字 |

## 書きかけ

`drafts.yaml`。コメントの入力欄に書いて、まだ溜めていない本文。
`items:` の配列を持ち、1 要素が 1 つの入力欄の書きかけになる。向けた先（`target` と `loc` の組）ごとに 1 件で、共通のキーは持たない。
書くのはサーバーの書きかけの保存とコメントの追加だけで、`add`・`update` の対象にしない。
溜めたときと、入力欄を空にしたときに消える。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `target` | string | - | 入力欄が向ける項目の ID。項目に紐づかないコメントの入力欄はキーを持たない |
| `loc` | object | - | 入力欄に添えた[箇所](#箇所) |
| `body` | string | ✅ | 書きかけの本文。1〜10000 文字（空白だけも保つ） |
| `updated` | string | ✅ | 書いた日時（UTC のタイムゾーン付き ISO 8601） |

## 送信

`submissions.yaml`。プレビューのコメントの一覧からまとめて送られた、項目・箇所へのコメントと、項目に紐づかないコメント。
`items:` の配列を持ち、1 要素が 1 件の送信になる。共通のキーは持たない。
書くのはサーバーのまとめて送る受け付けと `take_submission` だけで、`add`・`update` の対象にしない。
消さず、取り込んだら `taken` に日時を書く。

| キー | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | `S-` + 連番。連番は最大 + 1 で振り、消した番号を使い回さない |
| `target` | string | - | コメントを向けた項目の ID（どの種類でもよい）。送ったときにワークスペースにあった項目。項目に紐づかないコメントはキーを持たない |
| `body` | string | ✅ | コメントの本文。前後の空白を除いて 1〜10000 文字 |
| `sent` | string | ✅ | 送った日時（UTC のタイムゾーン付き ISO 8601） |
| `taken` | string \| null | ✅ | 取り込んだ日時（同じ形）。取り込んでいなければ `null` |
| `loc` | object | - | 選んだ[箇所](#箇所)。箇所を持たないコメントはキーを持たない。`target` を持つときだけ持つ |
| `comment` | string | - | 送ったレビュー中のコメントの ID（`C-`）。まとめて送る途中で止まったとき、同じコメントを二重に足さないために持つ。前の版の送信はキーを持たない |

## 本文

`docs/{ID}.md`。項目の本文の Markdown で、項目の `body` から指される。
メタデータ（front matter）は持たず、項目の情報は YAML だけが持つ。
書き込みは [項目を足す](./コマンド.md#項目を足す)・[項目を直す](./コマンド.md#項目を直す)が行い、ファイル名は項目の ID に揃える。

# コマンド

スキルが呼ぶ MCP のツールと、利用者が叩く起動スクリプトの一覧。
ツールは mindstella の MCP サーバーのもので、Claude Code からは `mcp__mindstella__{ツール}` として呼ぶ。
起動スクリプトで立ち上げた Claude Code にだけ載る。
サーバーの仕様は [インターフェース定義](https://github.com/shuhei1101/mindstella/blob/develop/dev/%E8%A8%AD%E8%A8%88%E6%9B%B8/%E3%82%A4%E3%83%B3%E3%82%BF%E3%83%BC%E3%83%95%E3%82%A7%E3%83%BC%E3%82%B9%E5%AE%9A%E7%BE%A9/%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC/README.md) にある。

- 引数は JSON のオブジェクトで渡す。どのツールも `workspace`（`.mindstella/config.yaml` があるフォルダのパス）を渡す。記録のファイルは全て `.mindstella/` の下で引き、フォルダの直下には `README.md` のほかは書かない。`.mindstella/config.yaml` が無く、直下に `config.yaml` か `mindmap.yaml`（前の版の設定ファイル）があるフォルダは、`migrate` 以外のツールが移し替えを案内するエラーを返す。相対パスは、サーバーの作業フォルダ（起動スクリプトが Claude Code を立ち上げたフォルダ）から読む
- 結果は JSON のオブジェクトを 1 個（UTF-8、日本語はエスケープしない）。構造化の結果と、同じ JSON の文字列の本文で返る
- エラーは `isError` が真の結果で、本文に `エラー: {内容}` の行で出す。スキーマに合わないときは、続けて合わない箇所ごとに `{ファイル名}: {キーのパス}: {理由}` の行を出す（キーのパスは `items[0].status` の形）。要る引数が無い・型が違うときは、ツールを呼ぶ前に MCP の SDK が弾き、本文は SDK の文言になる
- `add`・`update`・`adopt` は、合わない箇所に前の版の形式（資料の `done`・設定の `summary` が無い・設定の `field`・対象の項目以外の案と状態の合わない検討事項）があるとき、最後に `ヒント: 前の版の形式の記録は /mindstella:upgrade で今の形式に移せます` の行を続ける。前の版の形式の記録は [ワークスペースを移し替える](./スキル.md#ワークスペースを移し替える)スキルが [記録の形式を移す](#記録の形式を移す)を呼んで移す
- 書き込むツール（`init`・`add`・`update`・`update_settings`・`adopt`・`edit_option`・`batch`・`migrate`・`clear_release`）は、書き込む前にワークスペースの全ての YAML をスキーマと、検討事項の案と状態の決まり（[ワークスペースの書式](./ワークスペースの書式.md#検討事項)）と突き合わせ（`clear_release` を除く）、合わなければ何も書き換えない。`migrate` は、手順を当てるときと `values` では突き合わせず、`record` で版を書く前に突き合わせる
- ワークスペースを書き換えるツールと、送信・レビュー中のコメント・書きかけの受け付けは、ワークスペースの `.mindstella/.mindstella.lock` に排他ロックを取ってから読み・書く。同じワークスペースを開く別のプロセスとも排他し、ロックは取れるまで待つ。読むだけのツールと配信はロックを取らない

## 起動スクリプトで立ち上げる

依存を確かめ、tmux のセッションの中で mindstella の MCP サーバーを渡した Claude Code を立ち上げ、そのセッションへつなぐ。
ワークスペースの中は書かない。

### 使い方

```bash
{プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ}
```

`{プラグインのフォルダ}` は、`claude plugin list --json` の `mindstella@mindstella` の `installPath`。
叩いたスクリプトの版ではなく、`installPath` が指すインストールした今の版のサーバーを立てる。
[起動スクリプトを登録する](#起動スクリプトを登録する)と、新しいシェルで登録した alias から叩ける。

```bash
mindstella {ワークスペースのフォルダ}
mindstella-{アカウントの名前} {ワークスペースのフォルダ}
```

`mindstella` は叩くたびに今の `installPath` を引き、引数をそのまま起動スクリプトに渡す。
`mindstella-{アカウントの名前}` は、`installPath` を引く `claude plugin list --json` と起動スクリプトの両方に、登録したそのアカウントの設定のフォルダを `CLAUDE_CONFIG_DIR` で渡す（シェルの `CLAUDE_CONFIG_DIR` は変えない）。

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `{ワークスペースのフォルダ}` | 必須 | 話し合いのワークスペースのフォルダ。Claude Code の作業フォルダになり、フォルダ名と絶対パスを tmux のセッションの名前に使う。無ければ作る | `~/discussions/家計簿アプリ` |
| `MINDSTELLA_VENV` | 任意 | 環境変数。MCP サーバーを動かす仮想環境のフォルダ。省略すると `~/.mindmap/venv` | - |
| `CLAUDE_CONFIG_DIR` | 任意 | 環境変数。Claude Code の設定のフォルダ（アカウント）。あれば tmux のセッションへ渡し、セッションの名前のハッシュにも使う。`mindstella-{アカウントの名前}` が渡す | - |
| `MINDSTELLA_ALLOWED_HOSTS` | 任意 | 環境変数。プレビューの配信が `Host` と `Origin` で受ける外のホスト名。ホスト名だけをカンマで区切って並べ、大文字と小文字は区別しない。スキーム・ポート・`/` を含む要素と空の要素は使われず、MCP サーバーが立つときに標準エラーへ記録される。空でなければ MCP の設定の `env` に書いて MCP サーバーへ渡す | `preview.example.com,notes.example.com` |
| `MINDSTELLA_PREVIEW_START_HOOK` | 任意 | 環境変数。配信を立てた直後に呼ぶコマンド。末尾にポートとワークスペースのフォルダの名前を引数で足し、シェルを通さずに呼ぶ。空でなければ MCP の設定の `env` に書いて MCP サーバーへ渡す | `my-gateway add`（`my-gateway add 47800 家計簿` を呼ぶ） |
| `MINDSTELLA_PREVIEW_STOP_HOOK` | 任意 | 環境変数。Claude Code を閉じて配信を止めるとき、立てた配信ごとに 1 回呼ぶコマンド。呼び方は `MINDSTELLA_PREVIEW_START_HOOK` と同じ。空でなければ MCP の設定の `env` に書いて MCP サーバーへ渡す | `my-gateway rm` |

`MINDSTELLA_ALLOWED_HOSTS` とフックの環境変数は、MCP サーバーにだけ届き、Claude Code の全体の環境には入れない。
同じフォルダのセッションが既にあると、新しい値は効かない。Claude Code を閉じて立ち上げ直すと効く。
環境変数は、[起動スクリプトを登録する](#起動スクリプトを登録する)で登録すると、新しいシェルに入る。
使い方は[プレビューを外から見る](../使い方/セットアップ手順/プレビューを外から見る.md)。

### 出力

| 出力 | 説明 |
| --- | --- |
| tmux のセッション | 名前は `mindstella-{フォルダ名}-{ハッシュ}`。フォルダ名の `.`・`:` は `-` に置き換える。ハッシュは、ワークスペースのフォルダのシンボリックリンクを解いた絶対パスの SHA-256 の 16 進の先頭 6 桁。`CLAUDE_CONFIG_DIR` が空でないときは、その絶対パスの後ろに改行と `CLAUDE_CONFIG_DIR` のシンボリックリンクを解いた絶対パスをつないだ文字列の SHA-256 にする（同じフォルダを別のアカウントで開くと別のセッションになり、先にあったセッションは立ち上げ直されない）。同じ名前のセッションが既にあれば、新しく立てずにそのセッションへつなぐ |
| MCP の設定 | この起動だけの `{一時フォルダ}/mindstella-{ランダム}/mcp.json`。mindstella のサーバーだけを足し、利用者のほかの MCP の設定は消さない。使い終えても消さない。プラグインのマニフェストには MCP サーバーを書かない |
| 標準出力 | 標準出力が端末なら、そのセッションへつなぐ（tmux の外からは `tmux attach-session`、tmux の中からは `tmux switch-client`）。端末でなければ、つながずに、つなぐコマンドを出して終わる |
| 標準エラー | `[mindstella]` で始まる行で、使うプラグインのフォルダとセッションの名前を出す。エラーは `[mindstella] エラー: {内容}` の行で、そろえるコマンドがあれば次の行に出す |

### 終了コード

確かめる順は、引数 → 依存 → `tmux` → `claude` → プラグインのフォルダ。どれかで止まったら、それより後は何もしない。

| コード | 意味 |
| --- | --- |
| `0` | セッションを立てた（またはつないだ） |
| `1` | 依存が足りない（足りないものと、そろえるコマンドを標準エラーに出す。そろえるコマンドが無ければ 3.12 以上の Python を入れるよう出す）・`tmux` が `PATH` に無い・`claude` が `PATH` に無い・`claude plugin list --json` に `mindstella@mindstella` が無い（プラグインのインストールの手順を案内する）。tmux も Claude Code も立てない |
| `2` | 引数の誤り（ワークスペースのフォルダを渡さない）。使い方を標準エラーに出す |

## 起動スクリプトを登録する

起動スクリプトを呼ぶ alias `mindstella`・`mindstella-{アカウントの名前}`（シェルの関数）と、起動スクリプトが読む環境変数を、ログインシェルの設定に登録・読み返し・外す。
セットアップのスキルが Bash で呼ぶ。MCP のツールも mindstella の仮想環境も使わず、システムの `python3`（3.8 以上）の標準ライブラリだけで動く。
ワークスペースは書かない。

### 使い方

```bash
python3 {プラグインのフォルダ}/skills/setup/scripts/register.py {show|set|add-account|remove-account|remove} [--env KEY=VALUE]... [--unset-env KEY]... [--name {アカウントの名前}] [--config-dir {フォルダ}]
```

| サブコマンド | することと書くもの |
| --- | --- |
| `show` | 登録を読む。何も書かない |
| `set` | alias `mindstella` を登録し、`--env` の環境変数を登録・書き換え、`--unset-env` の環境変数を外す |
| `add-account` | アカウントごとの alias `mindstella-{名前}` を足す・書き直す |
| `remove-account` | アカウントの alias を外す |
| `remove` | 登録を全て外す |

書き込むサブコマンドは、`{XDG_CONFIG_HOME か ~/.config}/mindstella/` の `registration.json`（登録の中身）と `shell.sh`（alias と `export`）を書く。
ログインシェルの設定ファイルには、`# >>> mindstella >>>` と `# <<< mindstella <<<` で囲んで `shell.sh` を読み込む 1 行だけを、無ければ末尾に足す。
印の範囲の外の行は変えない。`remove` は 2 つのファイルと印の範囲を消す。
alias は叩くたびに `claude plugin list --json` の `mindstella@mindstella` の `installPath` を引き、`{installPath}/bin/mindstella` に引数をそのまま渡す。引けなければ `[mindstella] エラー:` で始まる行を標準エラーに出して 1 を返す。
環境変数は `shell.sh` に `export` で書き、値は単引用符で囲む。

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `--env` | 任意 | `set` で登録する環境変数 `KEY=VALUE`。繰り返し渡せる。渡したキーだけを書き換え、登録済みのほかのキーは残す。キーは `MINDSTELLA_VENV`・`MINDSTELLA_ALLOWED_HOSTS`・`MINDSTELLA_PREVIEW_START_HOOK`・`MINDSTELLA_PREVIEW_STOP_HOOK` のどれかで、値は改行を含まない | `MINDSTELLA_ALLOWED_HOSTS=preview.example.com` |
| `--unset-env` | 任意 | `set` で登録から外す環境変数のキー。繰り返し渡せる。キーは `--env` と同じ | `MINDSTELLA_VENV` |
| `--name` | `add-account`・`remove-account` で必須 | アカウントの名前。alias の名前 `mindstella-{名前}` になる。英小文字・数字・`-` の 1〜32 文字で、英小文字か数字で始まる | `sub1` |
| `--config-dir` | `add-account` で必須 | そのアカウントの Claude Code の設定のフォルダ。絶対パスに直して登録する | `~/.claude-sub1` |
| `HOME` | 必須 | 環境変数。ログインシェルの設定ファイルと、`XDG_CONFIG_HOME` が無いときの登録の置き場所を決める | - |
| `XDG_CONFIG_HOME` | 任意 | 環境変数。登録の置き場所 `{XDG_CONFIG_HOME}/mindstella/` を決める。省略すると `~/.config` | - |
| `SHELL` | 必須 | 環境変数。末尾の名前が `bash` なら `~/.bashrc`（macOS では `~/.bash_profile`）、`zsh` なら `~/.zshrc` をログインシェルの設定ファイルにする | - |

### 出力

標準出力に、その後の登録を JSON（UTF-8、日本語はエスケープしない）で出す。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `registered` | bool | alias `mindstella` が登録されているか |
| `rc_file` | str | `shell.sh` を読み込むログインシェルの設定ファイルの絶対パス |
| `shell_file` | str | alias と環境変数を書く `shell.sh` の絶対パス |
| `env` | dict[str, str] | 登録した環境変数 |
| `accounts[].name` | str | アカウントの名前 |
| `accounts[].config_dir` | str | そのアカウントの Claude Code の設定のフォルダの絶対パス |
| `aliases` | list[str] | 登録した alias の名前（`mindstella` と `mindstella-{名前}`） |
| `error` | str \| null | 失敗したときの理由。成功したときは持たない |
| `manual_lines` | list[str] \| null | 書き込めなかったとき、手でログインシェルの設定ファイルに書けば同じ登録になる行（印の範囲と alias `mindstella` の定義）。成功したときは持たない |

書く前に、書く先の全てに書き込めるかを確かめる。
各ファイルは同じフォルダの一時ファイルに書いてから置き換え、途中で失敗しても書きかけのファイルを残さない。
書く先がシンボリックリンクなら、リンクを残してリンク先を書き換える。

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 登録を読んだ・書いた・外した |
| `1` | ログインシェルの設定ファイルか登録の置き場所に書き込めない・`SHELL` が `bash`・`zsh` でない（どちらも何も書かず、`error` と `manual_lines` を出す）・`remove-account` の名前が登録に無い・`registration.json` を JSON として読めない（どちらも何も書かず、`error` を出す） |
| `2` | 引数の誤り（サブコマンドが無い・知らない、`--env` のキーが許すキーでない、`--name` の形が合わない、`add-account` に `--name` か `--config-dir` が無い）。何も書かず、使い方を標準エラーに出す |

## 項目を足す

`item` で渡した中身に ID・作成日時・更新日時・編集した人（`updated_by`。MCP のツールの書き込みは `ai`）を付けて、種類の YAML に 1 項目足す。
ID は種類の頭の文字 + その種類の連番の最大 + 1 で振る。
参照先の ID があるかは確かめない（[ワークスペースを点検する](#ワークスペースを点検する)が確かめる）。
検討事項は、案と状態の決まりに合わせて足す。
`未整理`・`対象外`・`取り下げ` のほかの状態は案（`options`）を 1 つ以上持って足し、採用した案を持つ検討事項は `未決定` で足さない。
足した項目は変更履歴を持たず、`changes.yaml` の、まだまとめていない変更の足した項目に入る。
`changes.yaml` の `last_seq` を 1 進め、その番号を項目の `seq` と `added_seq` に入れる。

### 使い方

`add` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "kind": "{種類}", "item": {項目の JSON}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `kind` | 必須 | 足す項目の種類。書き込む YAML と ID の頭の文字が決まる（`decision` → `decisions.yaml`・`D` / `task` → `tasks.yaml`・`T` / `research` → `research.yaml`・`R` / `doc` → `docs.yaml`・`A` / `term` → `terms.yaml`・`G` / `note` → `notes.yaml`・`N` / `log` → `logs.yaml`・`L`） | `decision` |
| `item` | 必須 | 項目の中身の JSON のオブジェクト。キーは [ワークスペースの書式](./ワークスペースの書式.md)のその種類のもの。`id`・`created`・`updated`・`updated_by`・`body`・`history`・`seq`・`added_seq` は渡さない | `{"title": "YAML のキーをどう分けるか", "status": "未決定", "options": [{"key": "A", "content": "種類ごとに分ける", "recommended": true}, {"key": "B", "content": "1 つにまとめる"}], "weight": "大"}` |
| `item.body_markdown` | 任意 | 本文の Markdown。YAML には残らず `.mindstella/docs/{ID}.md` に書かれ、項目の `body` が `{ID}.md` になる。どの種類も持てる（資料は必須） | `"## 経緯\n\n..."` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 振った ID |
| `file` | str | 書いた YAML（ワークスペースからの相対パス） |
| `body` | str \| null | 書いた本文の Markdown（ワークスペースからの相対パス）。本文が無ければ `null` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 足せた |
| エラー | ワークスペースが無い・足した後の YAML がスキーマか案と状態の決まりに合わない（エラーの本文に `decisions.yaml: items[{番号}].options:` か `.status:` で始まる行）・書き込めなかった（どのファイルも書き換えない） |

## 項目を直す

ID で指した 1 項目のキーを、`item` で渡した値に置き換えて、更新日時を変え、編集した人（`updated_by`）を `ai` にする。
値が変わった・消えた・足したキーか、中身が変わった本文があるときだけ、書き換える前の値を、その項目の[変更履歴](./ワークスペースの書式.md#変更履歴)に 1 回分積む。
積む回には、書き換えた人 `ai` を持たせる。
変わったものが無いときは積まない。
検討事項は、直した後も案と状態の決まりに合わせる。
採用した案を持たないまま `決定済み` には直せず、先に[採用する案を切り替える](#採用する案を切り替える)で案を採用する。
積んだ項目は、まだまとめていない変更の変えた項目に入る。
設定の `history_limit` を超えた古い変更履歴は、積むときに消す。
ただし、`changes.yaml` に `read_seq`（AI が最後に読んだ時点）があるときは、`seq` が `read_seq` より大きい回（AI がまだ読んでいない回）を `history_limit` を超えても消さない。
`history_limit` が 0 のときは積まず、持っていた変更履歴も消す。
値が変わったときは、項目の `seq` をその書き換えで振った通し番号にする。`history_limit` が 0 で積まないときも `last_seq` を 1 進めてその番号を入れる。

### 使い方

`update` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}", "item": {変えるキーの JSON}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 直す項目の ID。頭の文字で書き換える YAML が決まる | `D-2` |
| `item` | 必須 | 置き換えるキーと値の JSON のオブジェクト。渡したキーだけを値ごと置き換え（配列・オブジェクトも丸ごと）、値が `null` のキーは消す。渡さないキーはそのまま。`id`・`created`・`updated`・`updated_by`・`body`・`history`・`seq`・`added_seq` は渡さない | `{"answer": "種類ごとに分ける", "reason": "探しやすい", "weight": null}` |
| `item.body_markdown` | 任意 | 本文の Markdown。`.mindstella/docs/{ID}.md` をこの内容で置き換える。どの種類も持てる | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 直した項目の ID |
| `file` | str | 書き換えた YAML（ワークスペースからの相対パス） |
| `changed` | list[str] | 値が変わった・消えたキーの名前（`updated` は含めない） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 直せた |
| エラー | ワークスペースが無い・ID の項目が無い・直した後の YAML がスキーマか案と状態の決まりに合わない・書き込めなかった（どのファイルも書き換えない） |

## 設定を書き換える

`settings` で渡した設定のキーを置き換える。
フェーズを変えるときは、`phase_map` の対応で項目の `phase` と `goal.phase` も同じ書き込みで付け替える。
対象・カテゴリーを変えるときは、`target_map`・`category_map` の対応で項目の `target`・`category` とカテゴリーの `target` も同じ書き込みで付け替える。
書き換えられるのは `summary`・`description`・`playbooks`・`phases`・`target_label`・`goal`・`targets`・`categories`・`links`・変更履歴を保持する回数（`history_limit`）と表示の既定（`display`）で、`config.yaml` のすべてのキーに当たる。
`phase_map`・`target_map`・`category_map` による付け替えは、付け替えた項目の更新日時と編集した人（`updated_by`。`ai`）を書き換える。変更履歴にも書き換えのまとまりにも入れず、項目の `seq` も進めない。

### 使い方

`update_settings` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "settings": {置き換えるキーの JSON}, "phase_map": {"{古いフェーズ}": "{新しいフェーズ}"}, "target_map": {"{古い対象}": "{新しい対象}"}, "category_map": {"{古いカテゴリー}": "{新しいカテゴリー}"}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `settings` | 必須 | 置き換えるキーと値の JSON のオブジェクト。渡したキーだけを値ごと置き換え（配列・オブジェクトも丸ごと）、値が `null` のキーは消す。渡さないキーはそのまま。`null` で消せるのは `description`・`goal`・`links`・`history_limit`・`display` だけ。`display` は `network_look`・`visible_kinds` を持つオブジェクトで、渡すと丸ごと置き換える | `{"goal": null, "description": null}` |
| `phase_map` | 任意 | 古いフェーズ → 新しいフェーズの対応。`settings.phases` を渡したとき、新しい `phases` に無いフェーズを持つ項目と `goal.phase` をこの対応で付け替える。新しい `phases` にも同じ名前があるフェーズは、渡さなくてもそのまま残る。キーは今の `phases` にあって新しい `phases` に無いフェーズだけで、値は新しい `phases` のどれか。`settings.phases` を渡さないときは渡さない | `{"問い": "目的", "結論": "要件"}` |
| `target_map` | 任意 | 古い対象 → 新しい対象の対応。`settings.targets` を渡したとき、新しい `targets` に無い対象を持つ項目の `target` とカテゴリーの `target` をこの対応で付け替える。新しい `targets` にも同じ名前がある対象は、渡さなくてもそのまま残る。キーは今の `targets` にあって新しい `targets` に無い対象だけで、値は新しい `targets` のどれか。`settings.targets` を渡さないときは渡さない | `{"本体": "アプリ"}` |
| `category_map` | 任意 | 古いカテゴリー → 新しいカテゴリーの対応。`settings.categories` を渡したとき、新しい `categories` に無いカテゴリーを持つ項目の `category` をこの対応で付け替える。新しい `categories` にも同じ名前があるカテゴリーは、渡さなくてもそのまま残る。キーは今の `categories` にあって新しい `categories` に無いカテゴリーだけで、値は新しい `categories` のどれか。`settings.categories` を渡さないときは渡さない | `{"設定": "運用"}` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `changed` | list[str] | 値が変わった・消えた設定のキーの名前。対応で `goal.phase` だけが変わったときも `goal` を含める |
| `remapped[]` | list[{id, key, from, to}] | 付け替えた項目の ID・付け替えたキー（`phase`・`target`・`category`）・前の値・後の値。種類の順、同じ種類の中は項目の並びの順、同じ項目の中は `phase`・`target`・`category` の順 |
| `files` | list[str] | 書き換えた YAML（ワークスペースからの相対パス） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き換えられた |
| エラー | ワークスペースが無い・書き換えた後に新しい `phases` に無いフェーズを持つ項目か `goal.phase` が残る（エラーの本文に残るものごとの `{ID か goal}: {フェーズ}` の行）・書き換えた後の YAML がスキーマに合わない（書き換えられないキーや必須のキーの `null` を渡したときも含む）・書き込めなかった（どのファイルも書き換えない） |
| エラー（対象・カテゴリーの対応が足りない） | 書き換えた後に新しい `targets` に無い対象を持つ項目かカテゴリー、新しい `categories` に無いカテゴリーを持つ項目が残る。`target_map`・`category_map` の値が新しい設定に無いときも含む（エラーの本文に残るものごとの `{ID か categories[{名前}]}: {target か category}: {名前}` の行）。どのファイルも書き換えない |
| エラー（引数の誤り） | `settings.phases` を渡さずに `phase_map` を渡した・`phase_map` のキーが今の `phases` に無い、または新しい `phases` にもある。`target_map`・`category_map` も同じ（`settings.targets`・`settings.categories` を渡さずに渡した、キーが今の設定に無いか新しい設定にもある）。エラーの本文に引数の名前とキー |

## 採用する案を切り替える

検討事項の案のうち、指定した記号の案だけを採用にし、ほかの案の採用を外して、状態を `決定済み` にする。
切り替える前の状態は問わない（未決定・要見直し・保留から決定済みにする）。
答え（`answer`）と推奨の印は変えない。
答えは、続けて[項目を直す](#項目を直す)で書く。
検討事項の更新日時と編集した人（`updated_by`。`ai`）を書き換える。
影響を洗い出さない（[影響を洗い出す](#影響を洗い出す)が持つ）。
採用か状態が変わったときは、[項目を直す](#項目を直す)と同じように、値が変わったキー（切り替える前の案の並び全体を `options`、切り替える前の状態を `status`）を変更履歴に積む。
既にその案が採用で決定済みのときは積まない。
通し番号の振り方と、AI がまだ読んでいない回を `history_limit` を超えても残すことは、[項目を直す](#項目を直す)と同じ。

### 使い方

`adopt` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}", "key": "{記号}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 検討事項の ID。`D-` で始まる | `D-1` |
| `key` | 必須 | 採用する案の記号（`options[].key`） | `B` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 検討事項の ID |
| `adopted` | str | 採用した案の記号 |
| `previous` | str \| null | それまで採用していた案の記号。無ければ `null` |
| `status` | str | 切り替えた後の状態。常に `決定済み` |
| `previous_status` | str | 切り替える前の状態 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 切り替えた（既にその案が採用で決定済みのときも含む） |
| エラー | ワークスペースが無い・検討事項が無い・渡した記号の案が無い（エラーの本文に、その検討事項が持つ案の記号の一覧）・切り替えた後の YAML がスキーマか案と状態の決まりに合わない・書き込めなかった（どのファイルも書き換えない） |

## 案を書き換える

検討事項の案を記号（`key`）で指して、1 つ足す・中身と推奨の印を直す・消す。
指さない案と、検討事項のほかのキーはそのまま残る（推奨の印を立てたときは、ほかの案の印を外す）。
検討事項の更新日時と編集した人（`updated_by`。`ai`）を書き換える。
案の `adopted` と検討事項の `status`・`answer` は書き換えない（採用と状態は[採用する案を切り替える](#採用する案を切り替える)が書き換える）。
`未整理`・`対象外`・`取り下げ` のほかの状態の検討事項は、最後の案を消せない。
案の並びが変わったときは、[項目を直す](#項目を直す)と同じように、書き換える前の案の並び全体を `options` として変更履歴に積む。
通し番号の振り方と、AI がまだ読んでいない回を `history_limit` を超えても残すことも、項目を直すと同じ。

### 使い方

`edit_option` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}", "action": "{add | update | remove}", "key": "{記号}", "option": {案の JSON}}
```

`remove` のときは `option` を渡さない。

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 案を書き換える検討事項の ID。`D-` で始まる | `D-1` |
| `action` | 必須 | `add` は案を並びの末尾に足す。`update` は指した案の中身を、その位置のまま直す。`remove` は指した案だけを抜く | `add` |
| `key` | 必須 | 案の記号。`add` では足す案の記号、`update`・`remove` では指す案の記号 | `B` |
| `option` | `add`・`update` では必須 | `add` では足す案の中身。`update` では置き換えるキーと値で、渡したキーだけを置き換え、値が `null` のキーは消す。キーは `content`・`pros`・`cons`・`note`・`reason`・`recommended` だけ（`key`・`adopted` は渡さない）。`recommended` は `true` で印を立て、`false` か `null` で印を外す。`remove` では渡さない | `{"content": "種類ごとに分ける", "pros": "探しやすい", "recommended": true}` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 書き換えた検討事項の ID |
| `file` | str | 書き換えた YAML（ワークスペースからの相対パス） |
| `options` | list[dict] | 書き換えた後の案の並び |
| `changed` | bool | 案の並びが変わったか。同じ値で直したときは `false` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き換えられた |
| エラー | ワークスペースが無い・検討事項が無い・`add` で同じ記号の案が既にある・`update`・`remove` で指した記号の案が無い・`remove` で採用している案を指した（エラーの本文に、先に[採用する案を切り替える](#採用する案を切り替える)で採用を移す案内）・`remove` で、案を持たなくてよい状態（`未整理`・`対象外`・`取り下げ`）以外の検討事項の最後の案を指した（エラーの本文に、案を 1 つ以上残す案内）・書き換えた後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない）。案の記号のエラーは `エラー: {ID} の案 {記号}: {理由}` の行 |
| エラー（引数の誤り） | `id` が `D-` で始まらない・`add`・`update` で `option` を渡さない・`remove` で `option` を渡した・`option` が `key` か `adopted` を持つ。何も書き込まない |

## まとめて読み書きする

項目の追加・更新・取得の操作を並べて受け、並べた順に 1 回の呼び出しで当てる。
全てを当ててから 1 回だけスキーマと案と状態の決まりと突き合わせて書き、1 つでも失敗したらどのファイルも書き換えない。
途中の操作の後の形は問わないため、案を書いてから状態を変える順に並べなくてよい。
操作は `add`・`update`・`show` の 3 つで、中身は[項目を足す](#項目を足す)・[項目を直す](#項目を直す)・[項目を表示する](#項目を表示する)と同じ。
ID・日時・通し番号・変更履歴の付け方も、操作ごとにそれらと同じに振る。

### 使い方

`batch` を、次の引数で呼ぶ。

```json
{
  "workspace": "{フォルダ}",
  "operations": [
    {"op": "add", "kind": "decision", "item": {"title": "記録の単位", "status": "未決定", "options": [{"key": "A", "content": "月ごとに分ける", "recommended": true}, {"key": "B", "content": "1 つにまとめる"}]}},
    {"op": "add", "kind": "task", "item": {"title": "記録の単位を調べる", "kind": "調査", "status": "未着手", "for": ["$1"]}},
    {"op": "update", "id": "D-1", "item": {"reason": "記録の単位が決まるまで待つ", "status": "保留"}},
    {"op": "show", "id": "D-1"}
  ]
}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `operations` | 必須 | 当てる操作の並び。1 件以上で、並べた順に当てる | - |
| `operations[].op` | 必須 | `add`・`update`・`show` のどれか | `update` |
| `operations[].kind` | `add` では必須 | 足す項目の種類。[項目を足す](#項目を足す)の `kind` と同じ。`add` だけが持つ | `decision` |
| `operations[].id` | `update`・`show` では必須 | 指す項目の ID。同じ呼び出しで先に足した項目は `$番号` で指せる。`update`・`show` だけが持つ | `D-1` |
| `operations[].item` | `add`・`update` では必須 | 項目の中身。[項目を足す](#項目を足す)・[項目を直す](#項目を直す)の `item` と同じ。`add`・`update` だけが持つ | - |

`$番号` は、`id` と、`item` の参照のキー（`parent`・`depends_on`・`for`・`related`・`sources`）の値に書ける。
値全体が `$` と数字だけの文字列を、その番号（1 始まり）の `add` で振った ID に置き換える。
指せるのは、その操作より前の `add` だけ。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `results[]` | list[dict] | 操作ごとの結果。渡した操作と同じ順で同じ数 |
| `results[].op` | str | その結果の操作 |
| `results[].result` | dict | `add` は[項目を足す](#項目を足す)、`update` は[項目を直す](#項目を直す)、`show` は[項目を表示する](#項目を表示する)の出力と同じ形。`show` は、それより前の操作を当てた後の中身を返す |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 全ての操作を当てられた（`show` だけの呼び出しは何も書かない） |
| エラー | ワークスペースが無い・`update`・`show` の ID の項目が無い・全てを当てた後の YAML がスキーマか案と状態の決まりに合わない・書き込めなかった（どのファイルも書き換えない）。本文は `エラー: {番号} 番目の操作（{op}）: {内容}` の行で、スキーマに合わないときは合わない箇所ごとの行を続ける |
| エラー（引数の誤り） | `operations` が空・操作に要るキーが無いか要らないキーがある・`$番号` がその操作より前の `add` を指していない。何も書き込まない |

## 書き換えをまとめる

まだまとめていない書き換え（最後のまとまりより後の `add`・`update`・`adopt`・`edit_option`・`batch`）を、日時と一言の説明を付けた 1 つのまとまりにする。
プレビューの変更履歴は、このまとまりを並べる。
`changes.yaml` だけを書き換え、項目の YAML と本文は書き換えない。
まとめる書き換えが無いときは、まとまりを足さない。

### 使い方

`commit` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "summary": "{一言の説明}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `summary` | 必須 | このまとまりで何をしたかの一言の説明。プレビューの変更履歴にそのまま出る。前後の空白を除いて 1〜200 文字 | `D-1 を決め、T-1 を積む` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str \| null | 足したまとまりの ID（`V-` + 連番）。まとめる書き換えが無く、足さなかったときは `null` |
| `at` | str \| null | まとめた日時（UTC のタイムゾーン付き ISO 8601）。足さなかったときは `null` |
| `summary` | str \| null | 前後の空白を除いた説明。足さなかったときは `null` |
| `added` | list[str] | このまとまりで足した項目の ID |
| `changed` | list[str] | このまとまりで変えた項目の ID（足した項目は含めない） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | まとめた（まとめる書き換えが無く、何も足さなかったときも含む） |
| エラー | ワークスペースが無い・`changes.yaml` がスキーマに合わないか YAML として読めない・書き込めなかった（`changes.yaml` を書き換えない） |
| エラー（引数の誤り） | `summary` が空白だけか、200 文字を超える。何も書き込まない |

## まだまとめていない変更を読む

最後のまとまりより後に足した項目と、変えた項目・変えたキーを返す。
読むだけで、まとめない。

### 使い方

`pending` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

並びは、書き換えた順。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `added[].id` | str | 足した項目の ID |
| `added[].title` | str | その項目のタイトル |
| `changed[].id` | str | 変えた項目の ID（足した項目は `added` にだけ入る） |

### 結果

## 前回読んだ時点からの変更を読む

AI が最後に読んだ時点（`changes.yaml` の `read_seq`）より後に足した・変えた項目を、変わったキーと読んだ時点の値（本文は行の差分）つきで返し、`read_seq` を今の `last_seq` に書き換える。
`session` の準備で必ず呼ぶ。
`changes.yaml` の `read_seq` だけを書き換え、項目の YAML と本文は書き換えない。`changes.yaml` が無ければ、まとまり 0 件・まだまとめていない変更なし・`last_seq: 0` で作る。
`read_seq` はこのツールを呼んだときだけ進み、AI が MCP のツールで書いた分も、次に呼ぶまでは読んでいない変更に数える。
読んだ時点の記録（`read_seq`）が無いワークスペースでは、差分を返さず、今の `last_seq` を記録する。
返すのは種類ごとの YAML の項目だけで、設定（`config.yaml`）と、フェーズ・対象・カテゴリーの付け替えは返さない。

### 使い方

`changes_since_read` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

並びは、種類の順、同じ種類の中は項目の並びの順。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `had_read_point` | bool | 呼ぶ前に `read_seq` があったか。`false` のときは `added`・`changed` を空で返す |
| `read_seq` | int \| null | 呼ぶ前の `read_seq`。無ければ `null` |
| `until_seq` | int | 今回記録した `read_seq`（呼んだときの `last_seq`） |
| `added[].id` | str | `added_seq` が `read_seq` より大きい項目の ID |
| `added[].kind` | str | 種類（`decision` など） |
| `added[].title` | str | その項目のタイトル |
| `added[].updated_by` | `ai` \| `user` \| null | 今の編集した人。持たない項目は `null` |
| `changed[].id` | str | `seq` が `read_seq` より大きく、`added` に入らない項目の ID |
| `changed[].kind` | str | 種類 |
| `changed[].title` | str | 今のタイトル |
| `changed[].updated_by` | `ai` \| `user` \| null | 今の編集した人（最後に書き換えたのが誰か）。持たない項目は `null` |
| `changed[].by` | list[`ai` \| `user`] | 読んだ時点より後の変更履歴の回を書き換えた人（重なりなし。`user`・`ai` の順）。利用者が直した後に AI が直しても、利用者の編集を見分けられる。人を持たない回と、`history_limit` が 0 で変更履歴が無いときは空 |
| `changed[].before` | dict \| null | 変わったキー → 読んだ時点の値（無かったキーは `null`）。今の値と同じキーは入れない。`history_limit` が 0 で変更履歴が無いときは `null` |
| `changed[].body_diff` | list[{line, now, before}] \| null | 本文が変わったとき、今の本文の行を読んだ時点の本文の行へ戻す差分（形は[変更履歴](./ワークスペースの書式.md#変更履歴)の `body_diff` と同じ）。本文が変わっていないときと、`history_limit` が 0 のときは `null` |

`history_limit` が 0 のワークスペースでは、変えた項目の ID とタイトルだけを返す。
変わったキーも本文の差分も残らない項目は、`changed` に入れない。

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 読めて、`read_seq` を書けた（`added`・`changed` が空のときも含む） |
| エラー | ワークスペースが無い・`changes.yaml` を書き込めなかった（`read_seq` を書き換えず、次に呼んだときに同じ変更を返す） |

## 再開時の状況を読む

`status` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

決着は、検討事項が `決定済み`・`対象外`・`取り下げ`、タスクが `完了`・`中止`。

| 結果 | 意味 |
| --- | --- |

| エラー | ワークスペースが無い |

## 次の候補を読む

## 影響を洗い出す

指定した項目から、`depends_on`・`parent`・`for` を逆向きにたどって影響を受ける項目を返す。
項目 X に対し、`depends_on` か `parent` に X を持つ項目と、`for` に X を持つタスクを影響を受ける項目にし、得た項目から同じようにたどる。
`related`・`sources` はたどらない。
状態では絞らず、決定済み・完了も含めて出す。
読むだけで、ファイルを書き換えない。

### 使い方

`impact` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 起点の項目の ID | `D-1` |

### 出力

一度出た項目は、起点も含めて 2 度出ない。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 起点の項目の ID |

## ワークスペースを点検する

スキーマに合わない箇所・参照切れ・YAML と `.mindstella/docs/` の Markdown のずれ・変更履歴のずれ・案と状態の合わない検討事項を全て洗い出す。
見つけた問題は直さない。

- 参照切れは、`depends_on`・`parent`・`for`・`related`・`sources` と設定の `goal.deliverables[].doc` が、存在しない ID や、キーが決めた種類でない ID（`parent` が `D-` 以外 など）を指しているもの
- 本文のずれは、`body` が指す `.mindstella/docs/` のファイルが無いもの（`missing_body`）と、どの項目の `body` からも指されない `.mindstella/docs/` の Markdown（`orphan_body`）。全ての種類の項目の本文を確かめる
- フェーズは、項目の `phase` と設定の `goal.phase` が、設定の `phases` のどれでもないもの（`unknown_phase`）
- 変更履歴は、本文を持つ項目の変更履歴を新しい順に今の本文へ当て、`body_diff` の `now` の行が当てる先の行と合わない回があるもの（`stale_history`）。ツールを通さずに本文を書き換えたときに起きる
- 案と状態は、検討事項が[案と状態の決まり](./ワークスペースの書式.md#検討事項)に合わないもの（`decision_state`）。合わない決まり 1 つにつき 1 件で、`未整理`・`対象外`・`取り下げ` の検討事項が案を持たないことは問題にしない

### 使い方

`check` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

問題があるときも点検そのものは正常に終えているので、同じ形の結果を返し、エラーにしない。
`problems` はファイル名の順、同じファイルの中は項目の並びの順に並ぶ。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `ok` | bool | 問題が 1 つも無いか |
| `problems[].kind` | `schema` \| `duplicate_id` \| `broken_ref` \| `missing_body` \| `orphan_body` \| `unknown_phase` \| `stale_history` \| `decision_state` | 問題の種類（スキーマに合わない・ID の重複・参照切れ・指す本文が無い・どの項目からも指されない本文・設定の `phases` に無いフェーズ・変更履歴から前の本文を組み立てられない・検討事項の案と状態が合わない） |
| `problems[].file` | str | 問題のあるファイル（ワークスペースからの相対パス。例 `.mindstella/decisions.yaml`） |
| `problems[].id` | str \| null | 問題のある項目の ID（`orphan_body` と、項目を特定できない `schema`、`goal.phase` の `unknown_phase` は `null`） |
| `problems[].key` | str \| null | 問題のあるキーのパス（`items[0].status`・`items[0].options`・`history[0].body_diff`・`depends_on`・`goal.phase` など） |
| `problems[].detail` | str | 中身（参照先の ID・スキーマの理由・設定に無いフェーズの名前・案と状態の決まりに合わない理由・その回より前の本文の差分を出せないことなど）。前の版の形式で合わない `schema` と `decision_state` は、理由に続けて `/mindstella:upgrade` で今の形式に移せることを書く |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 点検できた（問題があるときも含む） |
| エラー | ワークスペースが無い |

## プレビューの配信先を返す

ワークスペースのプレビューを配る URL を返す。
このプロセスでまだ配っていなければ、`config.yaml` をスキーマと突き合わせ、通れば `127.0.0.1` で配信を立てる。
ポートは、`config.yaml` の `preview.port` があればそのポート、無ければ OS が選んだ空きポート。
合わなければ、違う箇所（キーと理由）をエラーで返し、配信を立てない。既に配っているワークスペースでは、突き合わせずに同じ URL を返す。
配信は、プレビューの画面を `/mindstella.html` で（`/` はそこへ送り直して）返し、記録を返し、記録が書き換わったら開いている画面へ知らせ、溜めるコメントと書きかけを受けて `comments.yaml`・`drafts.yaml` に置き、コメントの一覧からまとめて送られたコメントを送信として受ける。
[設定を再読み込みする](#設定を再読み込みする)と[設定の既定を書き換える](#設定の既定を書き換える)も、同じ配信が受ける。
同じワークスペースで呼び直すと同じ URL を返す。別のプロセスが同じワークスペースを配っていても、このプロセスは別のポートで配る。
配信を立てたときは、[README を書き直す](#readme-を書き直す)と同じ判定で、直下の `README.md` のプレビューの節を返す URL にして書き直す。書けなくても配信は止めず、URL を返す。
配信を立てたときは、`MINDSTELLA_PREVIEW_START_HOOK` があれば、立てた直後にポートとワークスペースのフォルダの名前を足して呼ぶ。同じワークスペースで呼び直して配信を立てなかったときは呼ばない。
配信は `Host` と `Origin` を確かめる。受けるのは、`127.0.0.1:{ポート}`・`localhost:{ポート}` と、`MINDSTELLA_ALLOWED_HOSTS` のホスト名。許可するホスト名は、ポートを外したホスト名の部分で大文字と小文字を区別せずに比べ、外の入口のポートは問わない。`Origin` は、許可するホスト名の `https://` と `http://` も受ける。
Claude Code を閉じると、`MINDSTELLA_PREVIEW_STOP_HOOK` があれば立てた配信ごとに 1 回呼んでから、配信が止まる。
フックのコマンドは、新しいセッションで立てて終わりを待たない。呼べない（コマンドが見つからない など）ときは標準エラーに記録し、配信の起動と終了は止めない。
画面ごとの操作は [プレビューを見る](../使い方/プレビューを見る.md)。

### 使い方

`preview_url` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `url` | str | 配信の画面の URL（`http://127.0.0.1:{ポート}/mindstella.html`）。ポートは `preview.port` があればそのポート |
| `workspace` | str | 配っているワークスペースの絶対パス |
| `started` | bool | この呼び出しで配信を立てたか。既に配っていたら `false` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 配信の URL を返せた |
| エラー | ワークスペースが無い・`config.yaml` がスキーマに合わない（エラーの本文に合わない箇所ごとの `config.yaml: {キーのパス}: {理由}` の行）・待ち受けを立てられない（空きポートが取れない・`preview.port` のポートを別のプロセスが使っている など。エラーの本文に理由とポート）。どれも配信を立てず、起動時のフックも呼ばない |

## README を書き直す

コマンドは、そのフォルダの絶対パス・今のプラグインのフォルダ・tmux のセッションの名前を埋めた、そのまま叩ける形で書く。
プレビューの節は、このプロセスがワークスペースを配っていればその URL、配っていなければ `/mindstella:session` でプレビューを頼む案内になる。

## 設定を再読み込みする

手で直した `config.yaml` をスキーマと突き合わせ、通れば新しい設定を使い、開いている画面に知らせる。
通らなければ、最後に検査に通った設定のまま、違う箇所を返す。
ワークスペースには書かない。

### 使い方

`preview_url` が返した URL のポートへ、本文なしの `POST` を送る。

```bash
curl -X POST http://127.0.0.1:{ポート}/api/config/reload
```

### 引数

なし。
`Host` は `127.0.0.1:{ポート}`・`localhost:{ポート}` か、ポートを外したホスト名が `MINDSTELLA_ALLOWED_HOSTS` のどれかと同じもの、`Origin` は無いか、配信の URL と同じものか、スキームが `https` か `http` でポートを外したホスト名が `MINDSTELLA_ALLOWED_HOSTS` のどれかと同じものだけ通る。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `settings` | dict | 検査に通った `config.yaml` の中身 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功（200） | 検査に通った。新しい設定を使い、開いている画面に知らせた |
| エラー（403） | `Host` か `Origin` が合わない |
| エラー（422） | `config.yaml` がスキーマに合わないか、YAML として読めない。本文は `application/problem+json` で、`detail` に合わない箇所ごとの `config.yaml: {キーのパス}: {理由}` の行を出す。配信は最後に検査に通った設定のまま動く |

## 設定の既定を書き換える

プレビューの「ワークスペースの既定にする」が呼び、見た目の既定と表示する種類の既定を `config.yaml` の `display` に書く。
書いたら、開いている画面に知らせる。
`display` 以外のキーと種類ごとの YAML は書き換えず、変更履歴にも書き換えのまとまりにも入れない。
画面の操作から呼ぶ口で、開けた人は誰でも書き換えられる。配る書き出しの画面は呼ばない。

### 使い方

`preview_url` が返した URL のポートへ、`PUT` を送る。

```bash
curl -X PUT http://127.0.0.1:{ポート}/api/config/display -H 'Content-Type: application/json' -d '{"network_look": "glow", "visible_kinds": ["decisions", "tasks", "research", "docs", "notes", "logs"]}'
```

### 引数

本文の JSON のオブジェクトで渡す。

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `network_look` | 必須 | 見た目の既定。`glow`・`starlight`・`constellation`・`deep`・`dust` のどれか | `glow` |
| `visible_kinds` | 必須 | 表示する種類の既定。`decisions`・`tasks`・`research`・`docs`・`terms`・`notes`・`logs` の重複しない配列。空の配列でもよい（概要とネットワークだけを出す） | `["decisions", "tasks"]` |

`Content-Type` は `application/json`。
`Host` と `Origin` は[設定を再読み込みする](#設定を再読み込みする)と同じ。

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `display` | dict | 書いた後の `config.yaml` の `display`（`network_look`・`visible_kinds`） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功（200） | 書けた。`display` だけを置き換え、ほかのキーは書く前のまま |
| エラー（400） | 本文が JSON のオブジェクトでない・`network_look` か `visible_kinds` が無い、または値が合わない。`detail` に合わないキーと選べる値。何も書かない |
| エラー（403） | `Host` か `Origin` が合わない。何も書かない |
| エラー（415） | `Content-Type` が `application/json` でない |
| エラー（422） | 今の `config.yaml` がスキーマに合わない（`display` 以外のキーが崩れている）。`detail` に合わない箇所。何も書かない |
| エラー（500） | `config.yaml` を書けない（ワークスペースのフォルダが読み取り専用 など）。`detail` に書けなかったパスと理由。`config.yaml` は書く前のまま |

エラーの本文は `application/problem+json`（`type`・`title`・`status`・`detail`）で、`detail` は日本語。

## 配る書き出しを作る

ワークスペースの全ての YAML と本文を、画面と描画のライブラリ（marked・DOMPurify・elkjs・mermaid・jsdiff）まで中に持つ、見るだけの 1 枚の HTML にして、指定したパスへ書き出す。
ワークスペースもサーバーもネットも持たない人へ配るために使う。
描画のライブラリの配布ファイルとライセンスの本文は、書き出すときに jsDelivr から取る。
取った配布ファイルは雛形の `integrity` と突き合わせ、合わなければ書き出さない。
1 回の要求で、接続と 1 回の読み取りをそれぞれ 30 秒まで待ち、取り直さない。
書き出した HTML は外のファイルも URL も指さず、開いても通信しない。
ワークスペースへ書き込む操作は画面に出ない。
ブラウザは開かない。
YAML がスキーマに合わないときと、jsDelivr から取れないときは書き出さず、前の `out` のファイルを残す。

### 使い方

`export` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "out": "{パス}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `out` | 必須 | 書き出す HTML のファイルのパス。末尾は `.html`。親のフォルダは作らないので、先に用意する。相対パスはサーバーの作業フォルダ（起動スクリプトが Claude Code を立ち上げたフォルダ）から読む。既にあるファイルは置き換える | `~/渡す/新規事業の検討.html` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `path` | str | 書き出した HTML の絶対パス |

書き出した HTML には、`<script type="application/json" id="mindmap-data"></script>` の中身として、次の埋め込みのデータが入る（サーバーが配るプレビューが読む記録と同じ形）。
画面はこの要素の中身を `JSON.parse` して読む。
送信（`submissions.yaml`）は埋め込まない。

| キー | 型 | 説明 |
| --- | --- | --- |
| `settings` | dict | `config.yaml` の中身（`display` を含む）。トップバーのタイトルは `settings.summary` |
| `decisions` / `tasks` / `research` / `docs` / `terms` / `notes` / `logs` | list[dict] | 種類ごとの YAML の `items` の中身（キー名はファイル名から `.yaml` を落としたもの） |
| `bodies` | dict[str, str] | `.mindstella/docs/` のファイル名 → 本文の Markdown（項目の `body` が指すものだけ） |
| `changes` | dict | `changes.yaml` の中身（`last_seq`・`sets`・`pending`）。無ければ `{last_seq: 0, sets: [], pending: {added: [], changed: []}}`。変更履歴の一覧と、新規・変更の印に使う。種類ごとの項目は `history` を持ったまま入る |
| `built_at` | str | 書き出した日時（UTC のタイムゾーン付き ISO 8601） |
| `derived.next[]` | list[{id, title, phase, weight, followers}] | 次に検討する項目。[次の候補を読む](#次の候補を読む)と同じ並びと中身 |
| `derived.goal` | dict | [ゴールに届いたかを読む](#ゴールに届いたかを読む)の出力と同じキーに、フェーズごとの決着した数と全体の数 `phase_progress[]`（`{phase, settled, total}`）を足したもの |
| `derived.progress[]` | list[{category, cells, settled, total}] | カテゴリー別の進捗。`cells` は `{phase, settled, total}` の並びで、`settings.phases` の順 |

これに加えて、ライセンスの表示が入る。
ライセンスの表示は `<script type="text/plain" id="mindmap-licenses">` の中身で、画面には出ない。

| 内容 | 説明 |
| --- | --- |
| 中に持つライブラリ | marked・DOMPurify・elkjs・mermaid・jsdiff のそれぞれの名前・版・著作権の表示・ライセンスの名前と本文 |
| DOMPurify | Apache-2.0 を選んだ旨 |
| elkjs | EPL-2.0 を選んだ旨と、ソースコードの入手先（リポジトリと版のタグの URL） |
| mermaid | 配布ファイルが中に束ねた依存（d3・cytoscape・katex など）ごとの名前・版とライセンスの本文 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き出せた |
| エラー | ワークスペースが無い・YAML がスキーマに合わないか YAML として読めない・jsDelivr から取れない（届かない・待ちの上限を超えた・取った配布ファイルが `integrity` と合わない）・書き込めなかった（`out` の親のフォルダが無い）。前の `out` のファイルを残す |
| エラー（引数の誤り） | `out` の末尾が `.html` でない。何も書き込まない |

## ゴールに届いたかを読む

設定の `goal.phase` までのフェーズの検討事項が全て決着し、`goal.deliverables` の資料が全て完成しているかを判定し、届いたかと残りの項目を返す。
読むだけで、ファイルを書き換えない。

- 決着は、検討事項の状態が `決定済み`・`対象外`・`取り下げ` のどれか
- 判定に入れる検討事項は、`phases` の先頭から `goal.phase` までのフェーズのもの。それより後ろのフェーズと、`phases` に無いフェーズの項目は入れない
- 完成は、`goal.deliverables[].doc` が指す資料の状態が `完成` であること。`doc` を持たない納品物は残りに出る
- 設定がゴールを持たないときは、届いたかを判定せず、全フェーズの決着していない検討事項を返す

### 使い方

`goal` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

届いていないときも判定そのものは正常に終えているので、同じ形の結果を返し、エラーにしない。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `has_goal` | bool | 設定がゴールを持つか |
| `reached` | bool \| null | ゴールに届いたか。`remaining_decisions` と `remaining_deliverables` がどちらも空のときだけ `true`。ゴールが無いときは判定せず `null` |
| `goal_phase` | str \| null | 設定の `goal.phase`。ゴールが無いときは `null` |
| `phases` | list[str] | 判定に入れたフェーズ（`phases` の先頭から `goal.phase` まで）。ゴールが無いときは `phases` の全て |
| `remaining_decisions[]` | list[{id, title, phase, status}] | 判定に入れたフェーズの検討事項のうち、決着していないもの（フェーズの順、同じフェーズの中は連番の小さい順） |
| `remaining_deliverables[]` | list[{title, doc}] | `goal.deliverables` のうち、`doc` を持たないか、`doc` の資料の状態が `完成` でないもの（`goal.deliverables` の並び）。`doc` が無いときは `null`。ゴールが無いときは空 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 判定できた（届いていないときも含む） |
| エラー | ワークスペースが無い |

## 記録の形式を移す

ワークスペースの版（`.mindstella/mindstella-version.ini`）とプラグインの版を比べ、間の版の手順（`skills/mindmap/migrations/{版}/steps.yaml`）を版の順に並べる・当てる。
値が要るキーを入れ、点検に合えば版のファイルを書き換える。

- `plan: true`: 当てずに、版を比べた結果と当てる手順を返す。何も書き込まない
- `plan`・`values`・`record` を渡さない: 写しを取ってから、`from_version` より後で `to_version` 以下の版の手順を版の順に当てる。版のファイルは書かない。失敗したら写しから戻す
- `values`: 値が要るキーに値を入れる
- `record: true`: 全ての YAML をスキーマと突き合わせ、合えば版のファイルを書く

v0.6.0 の手順が、設定ファイル `mindmap.yaml` を `config.yaml` に改め（破壊的な操作 `rename_file`）、直下の種類ごとの YAML・`changes.yaml`・`comments.yaml`・`drafts.yaml`・`submissions.yaml`・`mindstella-version.ini`・`.mindstella-opened` と `docs/`・`release/` を `.mindstella/` の下へ移し（`rename_file`・`move_dir`）、前の版の画面 `preview.html` と直下の `.mindstella.lock` を消す（`delete`）。
`config.yaml` は、ほかのツールが移しかけのワークスペースをワークスペースと見ないように、移す手順の最後に移す。
v0.7.0 の手順（`call` の `answer_to_adopted_option`）が、`決定済み` で `answer` を持ち案を持たない検討事項に、`answer` を内容・`reason` を理由にした採用した案（記号 `A`）を 1 つ作る。
ほかの検討事項と、案を持つ検討事項は変えない。
案と状態の合わない残りの検討事項は、手順では直さず、[ワークスペースを点検する](#ワークスペースを点検する)が `decision_state` で返し、[ワークスペースを移し替える](./スキル.md#ワークスペースを移し替える)スキルが直す。
無いファイルは飛ばし、今の形のワークスペースでは何も変えない。
今ある項目には `updated_by` を足さない。
このツールだけは、`.mindstella/config.yaml`・直下の `config.yaml`・直下の `mindmap.yaml` のどれかがあるフォルダをワークスペースとして扱う。
ワークスペースの版は `.mindstella/mindstella-version.ini` の 1 行目で、無ければ直下の `mindstella-version.ini` を読む。
版は `v{メジャー}.{マイナー}.{パッチ}` で、`v` を落とした 3 つの整数を左から比べる。
版のファイルが無いワークスペースは、版を記録する前の形式として、どの版よりも古く扱う。
どの手順も、同じ手順を 2 度当てても結果が変わらない。
写しは、ワークスペースが git の作業ツリーの中にあり、ワークスペースの中に ignore されたファイルが 1 つも無いときだけ、ワークスペースのパスだけをコミットして取る。
そうでなければ、ワークスペースの隣の `{フォルダ名}.before-{to_version}` へ複製する。
写しは成功しても消さない。

### 使い方

`migrate` を、次のいずれかの引数で呼ぶ。`from_version`・`to_version` は、`plan` を渡す形と、渡さない形で足せる。

```json
{"workspace": "{フォルダ}", "plan": true}
{"workspace": "{フォルダ}"}
{"workspace": "{フォルダ}", "values": [{"file": "{ファイル}", "key": "{キーのパス}", "value": "{値}"}]}
{"workspace": "{フォルダ}", "record": true}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `plan` | 任意 | 当てずに、版を比べた結果と当てる手順を返す。`values`・`record` と一緒に使わない | `true` |
| `from_version` | 任意 | この版より後の手順を当てる。省略すると、ワークスペースの版。版のファイルが無ければ、版を記録する前の形式 | `v0.2.0` |
| `to_version` | 任意 | この版以下の手順を当てる。`record` では書く版。省略すると、プラグインの版（`plugins/mindstella/version.ini` の 1 行目）。`from_version` より前の版は渡さない | `v0.3.0` |
| `values` | 任意 | 値が要るキーに入れる値の配列。1 キー = 1 要素で、要素は `file`（ワークスペースからの相対パス。全ての手順を当てた後の名前）・`key`（`.` 区切りのキーのパス）・`value`。手順を当てる・`record` と一緒に使わない | `[{"file": ".mindstella/config.yaml", "key": "summary", "value": "要件出しのスキルを設計する"}]` |
| `record` | 任意 | ワークスペースを点検し、問題が無ければ `.mindstella/mindstella-version.ini` を `to_version` の版に書き換える。`plan`・`values` と一緒に使わない | `true` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `workspace_version` | str \| null | ワークスペースの版。版を記録する前の形式は `null` |
| `plugin_version` | str | プラグインの版 |
| `relation` | `older` \| `same` \| `newer` | プラグインの版と比べたワークスペースの版 |
| `steps[]` | list[{version, index, op, destructive, summary}] | 当てる（当てた）手順を版の順・並びの順に並べたもの。`values`・`record` では空 |
| `steps[].version` | str | 手順の版（`migrations/` のフォルダ名） |
| `steps[].index` | int | `steps.yaml` の中の 1 始まりの番号 |
| `steps[].op` | str | 操作（`rename_file`・`move_dir`・`delete`・`rename_key`・`set_default`・`map_values`・`call`） |
| `steps[].destructive` | bool | 破壊的な操作（`rename_file`・`move_dir`・`delete`）か |
| `steps[].summary` | str | 手順の中身の 1 行 |
| `needs_values[]` | list[{file, key, description}] | 手順を当てた後に値が要るキー。`values` で値を入れるまで、点検に合わない。`plan` でも返す |
| `backup` | {kind, ref} \| null | 取った写し。手順を当てたときだけ持つ |
| `backup.kind` | `git` \| `copy` | git のコミットか、フォルダの複製か |
| `backup.ref` | str | コミットの ID か、複製したフォルダの絶対パス |
| `recorded` | str \| null | `record` で書いた版 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 並べた・当てた・値を入れた・版を書いた、または当てる手順が無かった |
| エラー | `.mindstella/config.yaml` も、直下の `config.yaml`・`mindmap.yaml` も無い・手順を当てる、または `record` で、ワークスペースの版がプラグインの版より新しい（エラーの本文に 2 つの版と、プラグインを更新する旨。`plan` は `relation: newer` を返してエラーにしない）・手順が失敗した（写しから戻してから、エラーの本文に `エラー: {版} の手順 {番号}（{操作}）: {理由}`）・`record` で YAML がスキーマに合わない（合わない箇所をエラーの本文に出し、版のファイルを書かない）・写しを取れない（手順を当てない）・書き込めなかった |
| エラー（引数の誤り） | 版の形が違う・`to_version` が `from_version` より前・一緒に使わない引数を渡した・`values` の形が違う |

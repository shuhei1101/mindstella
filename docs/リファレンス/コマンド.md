# コマンド

スキルが呼ぶ MCP のツールと、利用者が叩く起動スクリプトの一覧。
ツールは mindstella の MCP サーバーのもので、Claude Code からは `mcp__mindstella__{ツール}` として呼ぶ。
起動スクリプトで立ち上げた Claude Code にだけ載る。
サーバーの仕様は [インターフェース定義](https://github.com/shuhei1101/mindstella/blob/develop/dev/%E8%A8%AD%E8%A8%88%E6%9B%B8/%E3%82%A4%E3%83%B3%E3%82%BF%E3%83%BC%E3%83%95%E3%82%A7%E3%83%BC%E3%82%B9%E5%AE%9A%E7%BE%A9/%E3%82%B5%E3%83%BC%E3%83%90%E3%83%BC/README.md) にある。

- 引数は JSON のオブジェクトで渡す。どのツールも `workspace`（`mindmap.yaml` があるフォルダのパス）を渡す。相対パスは、サーバーの作業フォルダ（起動スクリプトが Claude Code を立ち上げたフォルダ）から読む
- 結果は JSON のオブジェクトを 1 個（UTF-8、日本語はエスケープしない）。構造化の結果と、同じ JSON の文字列の本文で返る
- エラーは `isError` が真の結果で、本文に `エラー: {内容}` の行で出す。スキーマに合わないときは、続けて合わない箇所ごとに `{ファイル名}: {キーのパス}: {理由}` の行を出す（キーのパスは `items[0].status` の形）。要る引数が無い・型が違うときは、ツールを呼ぶ前に MCP の SDK が弾き、本文は SDK の文言になる
- `add`・`update`・`adopt` は、合わない箇所に前の版の形式（資料の `done`・設定の `summary` が無い）があるとき、最後に `ヒント: 前の版の形式の記録は /mindstella:upgrade で今の形式に移せます` の行を続ける。前の版の形式の記録は [ワークスペースを移し替える](./スキル.md#ワークスペースを移し替える)スキルが [記録の形式を移す](#記録の形式を移す)を呼んで移す
- 書き込むツール（`init`・`add`・`update`・`adopt`・`migrate`・`clear_release`）は、書き込む前にワークスペースの全ての YAML をスキーマと突き合わせ（`clear_release` を除く）、合わなければ何も書き換えない。`migrate` は、手順を当てるときと `values` では突き合わせず、`record` で版を書く前に突き合わせる
- ワークスペースを書き換えるツールと送信の受け付けは、ワークスペースの `.mindstella.lock` に排他ロックを取ってから読み・書く。同じワークスペースを開く別のプロセスとも排他し、ロックは取れるまで待つ。読むだけのツールと配信はロックを取らない

## 起動スクリプトで立ち上げる

依存を確かめ、tmux のセッションの中で mindstella の MCP サーバーを渡した Claude Code を立ち上げ、そのセッションへつなぐ。
ワークスペースの中は書かない。

### 使い方

```bash
{プラグインのフォルダ}/bin/mindstella {ワークスペースのフォルダ}
```

`{プラグインのフォルダ}` は、`claude plugin list --json` の `mindstella@mindstella` の `installPath`。
叩いたスクリプトの版ではなく、`installPath` が指すインストールした今の版のサーバーを立てる。

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `{ワークスペースのフォルダ}` | 必須 | 話し合いのワークスペースのフォルダ。Claude Code の作業フォルダになり、フォルダ名と絶対パスを tmux のセッションの名前に使う。無ければ作る | `~/discussions/家計簿アプリ` |
| `MINDSTELLA_VENV` | 任意 | 環境変数。MCP サーバーを動かす仮想環境のフォルダ。省略すると `~/.mindmap/venv` | - |
| `CLAUDE_CONFIG_DIR` | 任意 | 環境変数。Claude Code の設定のフォルダ。あれば tmux のセッションへ渡す | - |

### 出力

| 出力 | 説明 |
| --- | --- |
| tmux のセッション | 名前は `mindstella-{フォルダ名}-{ハッシュ}`。フォルダ名の `.`・`:` は `-` に置き換える。ハッシュは、ワークスペースのフォルダのシンボリックリンクを解いた絶対パスの SHA-256 の 16 進の先頭 6 桁。同じ名前のセッションが既にあれば、新しく立てずにそのセッションへつなぐ |
| MCP の設定 | この起動だけの `{一時フォルダ}/mindstella-{ランダム}/mcp.json`。mindstella のサーバーだけを足し、利用者のほかの MCP の設定は消さない。使い終えても消さない。プラグインのマニフェストには MCP サーバーを書かない |
| 標準出力 | 標準出力が端末なら、そのセッションへつなぐ（tmux の外からは `tmux attach-session`、tmux の中からは `tmux switch-client`）。端末でなければ、つながずに、つなぐコマンドを出して終わる |
| 標準エラー | `[mindstella]` で始まる行で、使うプラグインのフォルダとセッションの名前を出す。エラーは `[mindstella] エラー: {内容}` の行で、そろえるコマンドがあれば次の行に出す |

### 終了コード

確かめる順は、引数 → 依存 → `tmux` → `claude` → プラグインのフォルダ。どれかで止まったら、それより後は何もしない。

| コード | 意味 |
| --- | --- |
| `0` | セッションを立てた（またはつないだ） |
| `1` | 依存が足りない（足りないものと、そろえるコマンドを標準エラーに出す。そろえるコマンドが無ければ 3.12 以上の Python を入れるよう出す）・`tmux` が `PATH` に無い・`claude` が `PATH` に無い・`claude plugin list --json` に `mindstella@mindstella` が無い（プラグインのインストールの手順を案内する）。tmux も Claude Code も立てない |
| `2` | 引数の誤り（ワークスペースのフォルダを渡さない）。使い方を標準エラーに出す |

## 依存を確かめる

スキル専用の仮想環境に、下限以上の Python・PyYAML・jsonschema・mcp がそろっているかを確かめ、MCP サーバーを動かす Python と、足りないときにそろえるコマンドを返す。
何も書き込まず、通信もしない。
起動スクリプトが MCP サーバーを立てる前に、システムの `python3` で起動する。

### 使い方

```bash
python3 {プラグインのフォルダ}/skills/mindmap/scripts/check_env.py [--venv {フォルダ}]
```

### 引数

| 引数 | 必須 | 説明 |
| --- | --- | --- |
| `--venv` | - | 確かめる仮想環境のフォルダ。省略すると `~/.mindmap/venv`（Windows は `%USERPROFILE%\.mindmap\venv`）。起動スクリプトは、環境変数 `MINDSTELLA_VENV` があればその値を渡す |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `venv` | str | 確かめた仮想環境のフォルダ |
| `venv_ok` | bool | 仮想環境の Python があるか |
| `python_path` | str | MCP サーバーを動かす Python |
| `python` | str \| null | 仮想環境の Python の版。仮想環境が無ければ `null` |
| `python_ok` | bool | 仮想環境の Python の版が 3.12 以上か |
| `base_python` | str | 仮想環境を作る Python（`check_env.py` を動かしている Python）のパス |
| `base_python_version` | str | 仮想環境を作る Python の版 |
| `base_python_ok` | bool | 仮想環境を作る Python の版が 3.12 以上か |
| `packages[].name` | str | 確かめたライブラリ（`PyYAML`・`jsonschema`・`mcp`） |
| `packages[].required` | str | 版の下限 |
| `packages[].installed` | str \| null | 仮想環境に入っている版。入っていなければ `null` |
| `packages[].ok` | bool | 下限以上が入っているか |
| `install` | str \| null | 仮想環境とライブラリをそろえるコマンド（仮想環境が無ければ作る、Python が古ければ作り直す）。全てそろっていれば `null`。作る・作り直すときに `base_python_ok` が `false` なら `null` |

### 終了コード

| コード | 意味 |
| --- | --- |
| `0` | 仮想環境があり、その Python と両方のライブラリが下限以上 |
| `1` | 仮想環境が無いか、その Python が下限より古いか、ライブラリが足りない（出力は同じ形） |

## ワークスペースを作る

`settings` で渡した設定を持つ `mindmap.yaml` と、空の種類ごとの YAML・`docs/`・`release/`・プラグインの版を書いた `mindstella-version.ini` を作る。
既にワークスペースがあるフォルダには作らない。

### 使い方

`init` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "settings": {設定の JSON}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | 作るワークスペースのフォルダ。`mindmap.yaml` がまだ無いフォルダで、フォルダが無ければ作る | - |
| `settings` | 必須 | 設定の JSON のオブジェクト（`summary`・`field`・`target_label`・`phases`・`targets`・`categories`・`goal`・`links`）。キーは [ワークスペースの書式](./ワークスペースの書式.md#設定) | `{"summary": "家計簿アプリの要件を決める", "field": "システム開発", "target_label": "システム", "phases": ["目的", "要件"], ...}` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `workspace` | str | 作ったワークスペースの絶対パス |
| `files` | list[str] | 作ったファイルとフォルダ（ワークスペースからの相対パス） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 作れた |
| エラー | `mindmap.yaml` が既にある・設定がスキーマに合わない・書き込めなかった（どれも `mindmap.yaml` を残さない） |

## 項目を足す

`item` で渡した中身に ID・作成日時・更新日時を付けて、種類の YAML に 1 項目足す。
ID は種類の頭の文字 + その種類の連番の最大 + 1 で振る。
参照先の ID があるかは確かめない（[ワークスペースを点検する](#ワークスペースを点検する)が確かめる）。

### 使い方

`add` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "kind": "{種類}", "item": {項目の JSON}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `kind` | 必須 | 足す項目の種類。書き込む YAML と ID の頭の文字が決まる（`decision` → `decisions.yaml`・`D` / `task` → `tasks.yaml`・`T` / `research` → `research.yaml`・`R` / `doc` → `docs.yaml`・`A` / `term` → `terms.yaml`・`G` / `note` → `notes.yaml`・`N` / `log` → `logs.yaml`・`L`） | `decision` |
| `item` | 必須 | 項目の中身の JSON のオブジェクト。キーは [ワークスペースの書式](./ワークスペースの書式.md)のその種類のもの。`id`・`created`・`updated`・`body` は渡さない | `{"title": "YAML のキーをどう分けるか", "status": "未決定", "weight": "大"}` |
| `item.body_markdown` | 任意 | 本文の Markdown。YAML には残らず `docs/{ID}.md` に書かれ、項目の `body` が `{ID}.md` になる。調査・資料・検討事項・会話ログだけが持てる（資料は必須） | `"## 経緯\n\n..."` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 振った ID |
| `file` | str | 書いた YAML（ワークスペースからの相対パス） |
| `body` | str \| null | 書いた本文の Markdown（ワークスペースからの相対パス）。本文が無ければ `null` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 足せた |
| エラー | ワークスペースが無い・足した後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 項目を直す

ID で指した 1 項目のキーを、`item` で渡した値に置き換えて、更新日時を変える。

### 使い方

`update` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}", "item": {変えるキーの JSON}}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 直す項目の ID。頭の文字で書き換える YAML が決まる | `D-2` |
| `item` | 必須 | 置き換えるキーと値の JSON のオブジェクト。渡したキーだけを値ごと置き換え（配列・オブジェクトも丸ごと）、値が `null` のキーは消す。渡さないキーはそのまま。`id`・`created`・`updated`・`body` は渡さない | `{"answer": "種類ごとに分ける", "status": "決定済み", "weight": null}` |
| `item.body_markdown` | 任意 | 本文の Markdown。`docs/{ID}.md` をこの内容で置き換える。調査・資料・検討事項・会話ログだけが持てる | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 直した項目の ID |
| `file` | str | 書き換えた YAML（ワークスペースからの相対パス） |
| `changed` | list[str] | 値が変わった・消えたキーの名前（`updated` は含めない） |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 直せた |
| エラー | ワークスペースが無い・ID の項目が無い・直した後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 採用する案を切り替える

検討事項の案のうち、指定した記号の案だけを採用にし、ほかの案の採用を外す。
状態と答えは変えない。
影響を洗い出さない（[影響を洗い出す](#影響を洗い出す)が持つ）。

### 使い方

`adopt` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{ID}", "key": "{記号}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 検討事項の ID。`D-` で始まる | `D-1` |
| `key` | 必須 | 採用する案の記号（`options[].key`） | `B` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 検討事項の ID |
| `adopted` | str | 採用した案の記号 |
| `previous` | str \| null | それまで採用していた案の記号。無ければ `null` |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 切り替えた（既にその案が採用のときも含む） |
| エラー | ワークスペースが無い・検討事項が無い・渡した記号の案が無い（エラーの本文に、その検討事項が持つ案の記号の一覧）・切り替えた後の YAML がスキーマに合わない・書き込めなかった（どのファイルも書き換えない） |

## 再開時の状況を読む

話し合いを再開するときに読む状況をまとめて返す。
読むだけで、ファイルを書き換えない。

### 使い方

`status` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

決着は、検討事項が `決定済み`・`対象外`・`取り下げ`、タスクが `完了`・`中止`。
存在しない ID は未完了として扱う。
各一覧は ID の種類（D → T）、連番の小さい順に並ぶ（`next` を除く）。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `needs_review[]` | list[{id, title}] | 状態が `要見直し` の検討事項 |
| `in_progress[]` | list[{id, title}] | 状態が `進行中` のタスク |

## 配る書き出しを作る

ワークスペースの全ての YAML と本文を、画面と描画のライブラリ（marked・DOMPurify・elkjs・mermaid）まで中に持つ、見るだけの 1 枚の HTML にして、指定したパスへ書き出す。
ワークスペースもサーバーもネットも持たない人へ配るために使う。
描画のライブラリの配布ファイルとライセンスの本文は、書き出すときに jsDelivr から取る。
取った配布ファイルは雛形の `integrity` と突き合わせ、合わなければ書き出さない。
1 回の要求で、接続と 1 回の読み取りをそれぞれ 30 秒まで待ち、取り直さない。
書き出した HTML は外のファイルも URL も指さず、開いても通信しない。
ワークスペースへ書き込む操作は画面に出ない。
ブラウザは開かない。
YAML がスキーマに合わないときと、jsDelivr から取れないときは書き出さず、前の `out` のファイルを残す。

### 使い方

`export` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "out": "{パス}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `out` | 必須 | 書き出す HTML のファイルのパス。末尾は `.html`。親のフォルダは作らないので、先に用意する。相対パスはサーバーの作業フォルダ（起動スクリプトが Claude Code を立ち上げたフォルダ）から読む。既にあるファイルは置き換える | `~/渡す/新規事業の検討.html` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `path` | str | 書き出した HTML の絶対パス |

書き出した HTML には、`<script type="application/json" id="mindmap-data"></script>` の中身として、次の埋め込みのデータが入る（サーバーが配るプレビューが読む記録と同じ形）。
画面はこの要素の中身を `JSON.parse` して読む。
送信（`submissions.yaml`）は埋め込まない。

| キー | 型 | 説明 |
| --- | --- | --- |
| `settings` | dict | `mindmap.yaml` の中身。トップバーのタイトルは `settings.summary` |
| `decisions` / `tasks` / `research` / `docs` / `terms` / `notes` / `logs` | list[dict] | 種類ごとの YAML の `items` の中身（キー名はファイル名から `.yaml` を落としたもの） |
| `bodies` | dict[str, str] | `docs/` のファイル名 → 本文の Markdown（項目の `body` が指すものだけ） |
| `built_at` | str | 書き出した日時（UTC のタイムゾーン付き ISO 8601） |
| `derived.next[]` | list[{id, title, phase, weight, followers}] | 次に検討する項目。[次の候補を読む](#次の候補を読む)と同じ並びと中身 |
| `derived.goal` | dict | [ゴールに届いたかを読む](#ゴールに届いたかを読む)の出力と同じキーに、フェーズごとの決着した数と全体の数 `phase_progress[]`（`{phase, settled, total}`）を足したもの |
| `derived.progress[]` | list[{category, cells, settled, total}] | カテゴリー別の進捗。`cells` は `{phase, settled, total}` の並びで、`settings.phases` の順 |

これに加えて、ライセンスの表示が入る。
ライセンスの表示は `<script type="text/plain" id="mindmap-licenses">` の中身で、画面には出ない。

| 内容 | 説明 |
| --- | --- |
| 中に持つライブラリ | marked・DOMPurify・elkjs・mermaid のそれぞれの名前・版・著作権の表示・ライセンスの名前と本文 |
| DOMPurify | Apache-2.0 を選んだ旨 |
| elkjs | EPL-2.0 を選んだ旨と、ソースコードの入手先（リポジトリと版のタグの URL） |
| mermaid | 配布ファイルが中に束ねた依存（d3・cytoscape・katex など）ごとの名前・版とライセンスの本文 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 書き出せた |
| エラー | ワークスペースが無い・YAML がスキーマに合わないか YAML として読めない・jsDelivr から取れない（届かない・待ちの上限を超えた・取った配布ファイルが `integrity` と合わない）・書き込めなかった（`out` の親のフォルダが無い）。前の `out` のファイルを残す |

## ゴールに届いたかを読む

- 決着は、検討事項の状態が `決定済み`・`対象外`・`取り下げ` のどれか
- 判定に入れる検討事項は、`phases` の先頭から `goal.phase` までのフェーズのもの。それより後ろのフェーズと、`phases` に無いフェーズの項目は入れない
- 完成は、`goal.deliverables[].doc` が指す資料の状態が `完成` であること。`doc` を持たない納品物は残りに出る

| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `reached` | bool | ゴールに届いたか。`remaining_decisions` と `remaining_deliverables` がどちらも空のときだけ `true` |
| `goal_phase` | str | 設定の `goal.phase` |
| `phases` | list[str] | 判定に入れたフェーズ（`phases` の先頭から `goal.phase` まで） |
| `remaining_decisions[]` | list[{id, title, phase, status}] | 判定に入れたフェーズの検討事項のうち、決着していないもの（フェーズの順、同じフェーズの中は連番の小さい順） |
| `remaining_deliverables[]` | list[{title, doc}] | `goal.deliverables` のうち、`doc` を持たないか、`doc` の資料の状態が `完成` でないもの（`goal.deliverables` の並び）。`doc` が無いときは `null` |

| `removed[]` | list[str] | 消したものの `release/` からのパス。フォルダは末尾に `/` を付け、中のファイルは並べない。名前の順。消すものが無かったときは空 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 片付けられた（消すものが無かったときも含む） |
| エラー | ワークスペースが無い（何も消さない）・`release/` の中のものを消せない、または `release/` を作れない（消せなかった時点で止め、それまでに消したものは戻さない。次の `clear_release` で片付く） |

## 記録の形式を移す

ワークスペースの版（`mindstella-version.ini`）とプラグインの版を比べ、間の版の手順（`skills/mindmap/migrations/{版}/steps.yaml`）を版の順に並べる・当てる。
値が要るキーを入れ、点検に合えば版のファイルを書き換える。

- `plan: true`: 当てずに、版を比べた結果と当てる手順を返す。何も書き込まない
- `plan`・`values`・`record` を渡さない: 写しを取ってから、`from_version` より後で `to_version` 以下の版の手順を版の順に当てる。版のファイルは書かない。失敗したら写しから戻す
- `values`: 値が要るキーに値を入れる
- `record: true`: 全ての YAML をスキーマと突き合わせ、合えば版のファイルを書く

版は `v{メジャー}.{マイナー}.{パッチ}` で、`v` を落とした 3 つの整数を左から比べる。
版のファイルが無いワークスペースは、版を記録する前の形式として、どの版よりも古く扱う。
どの手順も、同じ手順を 2 度当てても結果が変わらない。
写しは、ワークスペースが git の作業ツリーの中にあり、ワークスペースの中に ignore されたファイルが 1 つも無いときだけ、ワークスペースのパスだけをコミットして取る。
そうでなければ、ワークスペースの隣の `{フォルダ名}.before-{to_version}` へ複製する。
写しは成功しても消さない。

### 使い方

`migrate` を、次のいずれかの引数で呼ぶ。`from_version`・`to_version` は、`plan` を渡す形と、渡さない形で足せる。

```json
{"workspace": "{フォルダ}", "plan": true}
{"workspace": "{フォルダ}"}
{"workspace": "{フォルダ}", "values": [{"file": "{ファイル}", "key": "{キーのパス}", "value": "{値}"}]}
{"workspace": "{フォルダ}", "record": true}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `plan` | 任意 | 当てずに、版を比べた結果と当てる手順を返す。`values`・`record` と一緒に使わない | `true` |
| `from_version` | 任意 | この版より後の手順を当てる。省略すると、ワークスペースの版。版のファイルが無ければ、版を記録する前の形式 | `v0.2.0` |
| `to_version` | 任意 | この版以下の手順を当てる。`record` では書く版。省略すると、プラグインの版（`plugins/mindstella/version.ini` の 1 行目）。`from_version` より前の版は渡さない | `v0.3.0` |
| `values` | 任意 | 値が要るキーに入れる値の配列。1 キー = 1 要素で、要素は `file`（ワークスペースからの相対パス）・`key`（`.` 区切りのキーのパス）・`value`。手順を当てる・`record` と一緒に使わない | `[{"file": "mindmap.yaml", "key": "summary", "value": "要件出しのスキルを設計する"}]` |
| `record` | 任意 | ワークスペースを点検し、問題が無ければ `mindstella-version.ini` を `to_version` の版に書き換える。`plan`・`values` と一緒に使わない | `true` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `workspace_version` | str \| null | ワークスペースの版。版を記録する前の形式は `null` |
| `plugin_version` | str | プラグインの版 |
| `relation` | `older` \| `same` \| `newer` | プラグインの版と比べたワークスペースの版 |
| `steps[]` | list[{version, index, op, destructive, summary}] | 当てる（当てた）手順を版の順・並びの順に並べたもの。`values`・`record` では空 |
| `steps[].version` | str | 手順の版（`migrations/` のフォルダ名） |
| `steps[].index` | int | `steps.yaml` の中の 1 始まりの番号 |
| `steps[].op` | str | 操作（`rename_file`・`move_dir`・`delete`・`rename_key`・`set_default`・`map_values`・`call`） |
| `steps[].destructive` | bool | 破壊的な操作（`rename_file`・`move_dir`・`delete`）か |
| `steps[].summary` | str | 手順の中身の 1 行 |
| `needs_values[]` | list[{file, key, description}] | 手順を当てた後に値が要るキー。`values` で値を入れるまで、点検に合わない。`plan` でも返す |
| `backup` | {kind, ref} \| null | 取った写し。手順を当てたときだけ持つ |
| `backup.kind` | `git` \| `copy` | git のコミットか、フォルダの複製か |
| `backup.ref` | str | コミットの ID か、複製したフォルダの絶対パス |
| `recorded` | str \| null | `record` で書いた版 |

### 結果

| 結果 | 意味 |
| --- | --- |
| 成功 | 並べた・当てた・値を入れた・版を書いた、または当てる手順が無かった |
| エラー | ワークスペースが無い・手順を当てる、または `record` で、ワークスペースの版がプラグインの版より新しい（エラーの本文に 2 つの版と、プラグインを更新する旨。`plan` は `relation: newer` を返してエラーにしない）・手順が失敗した（写しから戻してから、エラーの本文に `エラー: {版} の手順 {番号}（{操作}）: {理由}`）・`record` で YAML がスキーマに合わない（合わない箇所をエラーの本文に出し、版のファイルを書かない）・写しを取れない（手順を当てない）・書き込めなかった |
| エラー（引数の誤り） | 版の形が違う・`to_version` が `from_version` より前・一緒に使わない引数を渡した・`values` の形が違う |

## 取り込んでいない送信を読む

プレビューから送られ、まだ取り込んでいない送信を、送った順に返す。
読むだけで、取り込み済みにはしない。

### 使い方

`submissions` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `items[].id` | str | 送信の ID（`S-` + 連番） |
| `items[].target` | str | 回答・意見を向けた項目の ID |
| `items[].target_title` | str \| null | その項目のタイトル。項目が消えていれば `null` |
| `items[].body` | str | 本文 |
| `items[].sent` | str | 送った日時（UTC のタイムゾーン付き ISO 8601） |

### 結果

## 送信を取り込み済みにする

記録へ取り込んだ送信 1 件に、取り込んだ日時を付けて取り込み済みにする。
`submissions.yaml` のその送信の `taken` に日時を書き、ほかのファイルは書き換えない。

### 使い方

`take_submission` を、次の引数で呼ぶ。

```json
{"workspace": "{フォルダ}", "id": "{送信の ID}"}
```

### 引数

| 引数 | 必須 / 任意 | 説明 | 例 |
| --- | --- | --- | --- |
| `workspace` | 必須 | ワークスペースのフォルダ | - |
| `id` | 必須 | 取り込み済みにする送信の ID | `S-2` |

### 出力

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `id` | str | 取り込み済みにした送信の ID |
| `taken` | str | 取り込んだ日時（UTC のタイムゾーン付き ISO 8601）。既に取り込み済みなら前の日時 |

### 結果

| 結果 | 意味 |

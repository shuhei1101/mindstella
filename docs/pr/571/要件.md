# 要件

## 要望

- MindStella のセッションが止まったときに、常駐サーバーが利用者の Discord のチャンネルへ Webhook で 1 件通知する
- この PR で通知する停止は、エラー（ペイン・Claude Code のプロセスが無くなった・止める間に失敗した）と、停止の依頼（外部のアプリからの停止）。利用上限・無操作の上限の停止は、それを作る #520・#521 が、この PR の通知を止まった理由を添えて呼ぶ
- 通知の本文は、ワークスペースの名前と止まった理由を記載し、絵文字を使用しない
- 1 回の停止で届く通知は 1 件にする（停止の依頼の後の SessionEnd で重ねて送信しない）。`clear`・`resume` の SessionEnd は止まったとみなさない
- Webhook の設定・URL の秘匿・送信の失敗の扱いは、作業の完了の通知（インターフェース定義『作業の完了の通知』）と同じにする。送信に失敗しても、停止・状態の記録・まとめていない変更の commit は失敗させない

`未確定`: 通知の文面（決める段: 単一ユースケース設計。利用者の目に触れる文面のため、確認事項で利用者へ確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `{ワークスペースの名前}: 止まりました（{止まった理由}）` とプレビューの URL の 2 行 | 作業の完了の通知と同じ構成で、どのワークスペースかをプレビューで確認できる | 止まった後はプレビューを開いても作業は進まない |
| B | `{ワークスペースの名前}: 止まりました（{止まった理由}）` の 1 行 | 短い | 開き直す先を通知から辿れない |

推奨: A

作業の完了の通知と同じ構成にそろえると、利用者が通知の種類を 1 行目の文言だけで見分けられ、記録を確認する先も同じになる。

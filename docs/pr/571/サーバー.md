## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 単一ユースケース | 単一ユースケース『止まったことを通知する』を新規作成する。『作業の完了を通知する』の `notes` の、止まったときは範囲の外という記載を修正する | - |
| 止まったとき | `session.json` の `status` が `stopped` か `crashed` に変わったときに 1 件送信する。止まった理由は、停止の依頼・強制で止めた・落ちた・止める間に失敗した・Claude Code が終了した（SessionEnd）を区別する | 応答がエラーで終わっただけ（`stop_failure`）では MindStella のセッションは止まらないため通知しない |
| 1 回の停止で 1 件 | 既に `stopped`・`crashed` の状態から同じ状態へ書き換えるときは送信しない。停止の依頼で `/exit` を貼った後の SessionEnd は、停止の依頼の通知と重ねない | - |
| 呼び出すインターフェース | 止まった理由を受けて送信する関数を `notify.py` に配置し、#520・#521 が利用上限・無操作の上限の停止から同じ関数を呼べるようにする | - |
| 通知の文面 | `{ワークスペースの名前}: 停止しました（{止まった理由}）` とプレビューの URL の 2 行 | 止まった理由の文言は `未確定`（決める段: 単一ユースケース設計。[要件](./要件.md) の案と推奨） |
| 送信の方法・設定・秘匿 | 作業の完了の通知と同じ（`daemon` のスレッドで送信、`MINDSTELLA_DISCORD_WEBHOOK_FILE`、URL を記録しない、再送信しない） | 送信を待つ上限は非機能要件『Webhook の送信を待つ上限』のまま |
| 公開ドキュメント | 手順『Discord に通知する』に、止まったときに届く通知を追加する | - |

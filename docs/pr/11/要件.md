# 要件

## 要望

スキルが呼ぶスクリプトのコマンドで、ワークスペースの YAML を読み書き・検索・点検し、プレビューの HTML を書き出せるようにする。

- ワークスペースは、設定 `mindmap.yaml` と、種類ごとの YAML（検討事項 `decisions.yaml`・タスク `tasks.yaml`・調査 `research.yaml`・資料 `docs.yaml`・用語集 `terms.yaml`・メモ `notes.yaml`・会話ログ `logs.yaml`）、本文の Markdown を置く `docs/`、書き出す資料を置く `handoff/`、プレビュー `preview.html` で構成する
- 各 YAML の形を `skills/mindmap/schemas/` の JSON Schema で決める。キーは Issue の `### キー` を一案として設計で確定させる。ID の頭の文字（`D-`・`T-`・`R-`・`A-`・`G-`・`N-`・`L-`）で種類が決まる
- 書き込むコマンドは、書き込む前に YAML をスキーマと突き合わせ、合わなければエラーにしてファイルを書き換えない
- 本文の Markdown（`docs/`）はメタデータを持たず、YAML を正本にする
- コマンドは Issue の `### スクリプト` の候補（`check-env`・`init`・`status`・`find`・`show`・`add`・`update`・`adopt`・`impact`・`next`・`attrs`・`check`・`build`）を一案として、名前と引数を設計で確定させる
- `check-env` は、スキル専用の仮想環境（`~/.mindmap/venv`）の Python 3・PyYAML・jsonschema のうち足りないものと、そろえるコマンドを出す。ほかのコマンドはその仮想環境の Python で起動する
- `next` は、前提（依存先）が揃った未決定の検討事項を、フェーズ → 影響度 → 後続の件数の順に並べて出す
- `impact` は、依存をたどって影響を受ける項目を出す。`adopt` は検討事項の採用する案を切り替える
- `check` は、参照切れ（存在しない ID を指す参照）と、YAML と `docs/` の Markdown のずれを出す
- `build` は、YAML を JSON にして HTML に埋め込んだ 1 ファイル `preview.html` を書き出す。描画のライブラリは CDN から読み、サーバーは立てない
- スクリプトのファイルは依存の向き（読み書きと検証 / 検索 / 依存・影響・次の候補 / 点検 / ビルド / 入口）で分け、1 ファイルに詰めない
- スクリプトは Python 3 + PyYAML + jsonschema で書き、ほかのライブラリに依存しない

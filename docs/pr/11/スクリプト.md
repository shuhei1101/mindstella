## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| スキーマ | 設定と 7 種類の YAML ごとに JSON Schema を `skills/mindmap/schemas/` に置く。共通のキーは 1 か所で定義して各種類から参照する | キーの説明は、AI が何を入れるかの手がかりとして書く |
| データストア | ワークスペースの YAML の形を ER 図の設計書（データストア `YAML`）に書く | 項目間の参照（`related`・`depends_on`・`parent`・`for`）を関連として描く |
| 作成機能 | `init` が空のワークスペース（設定と空の YAML、`docs/`・`handoff/`）を作る。既にあるフォルダには作らずエラーにする | |
| 作成・編集機能 | `add` / `update` が 1 項目を足す・直す。ID は種類の頭の文字 + 連番で振り、`created` / `updated` を入れる | |
| バリデーション | 書き込む前にワークスペースの全体をスキーマと突き合わせ、合わなければエラーの箇所を出して書き込まない | 書き込みは一時ファイルからの置き換えで行い、途中で止まっても元のファイルを壊さない |
| 案の切り替え | `adopt` が採用する案を 1 つに切り替え、`impact` が `depends_on`・`parent`・`for` を逆向きにたどって影響を受ける項目を出す。`related`（関連）はたどらない | 要見直しにするかはスキルの手順（#4）が決める |
| 次の候補 | `next` が、依存先が全て決定済みの未決定を、フェーズの並び → 影響度 → 後続の件数の順で出す | 後続の件数は依存をたどった先の未完了の数 |
| 閲覧・検索機能 | `status`・`find`・`show`・`attrs` が読むだけで、ファイルを書き換えない | `show` は参照元も出す |
| 点検 | `check` が参照切れと YAML と `docs/` の Markdown のずれを出し、見つかったら 0 以外の終了コードで終える | |
| ビルド | `build` が全 YAML を 1 つの JSON にまとめ、HTML の 1 ファイルに埋め込んで `preview.html` に書き出す | 埋め込む先の画面の中身は #5。この PR では埋め込むデータの形と埋め込み方を決め、雛形 `skills/mindmap/preview/template.html` はデータの件数を出すだけのものを置く |
| エラー返却 | コマンドの成否は終了コードで返し、エラーは標準エラーに出す。出力の形（人が読む表か JSON か）はインターフェース定義で決める | 呼ぶのは Claude Code のスキル |
| ファイルの分け方 | 読み書きと検証 / 検索 / 依存・影響・次の候補 / 点検 / ビルド / 入口でモジュールを分け、依存は入口 → 各機能 → 読み書きと検証の一方向にする | |
| 動作環境 | 非機能要件の OS・Python の版・通信を、PyYAML・jsonschema の対応する版と合わせて決める | テストは Python 3.12 以上で動いている（`tests/conftest.py`） |
| 外部ライブラリ | PyYAML・jsonschema を外部ライブラリの設計書に書く | ほかのライブラリに依存しない |
| テスト | 単体テストの実行コマンドをテスト実行方法に書く。結合テストはコマンドを実際に起動して一時フォルダのワークスペースで確かめる | |

結論は成立。
動かした環境は Ubuntu 24.04（WSL2）・Python 3.12.3・PyYAML 6.0.3・jsonschema 4.26.0・referencing 0.37.0。

コメントが消えるため、書き込みのコマンドの仕様は「YAML のコメントは残らない」とし、手で残したい内容は `attrs`・`reason` などのキーに書く前提にする。
`safe_dump` は配列の要素を字下げせずに書く（`items:` の直下に `- title: ...`）ため、手で書いた字下げも書き戻しで揃い直る。
版の下限は jsonschema 4.18.0（`Registry`）・PyYAML 5.1（`sort_keys`）を外部ライブラリの設計書に書く。

核心部（[poc/yaml_roundtrip.py](https://github.com/shuhei1101/mindmap/blob/71f0870/poc/yaml_roundtrip.py)）:

```python
registry = Registry().with_resources(
    [("common.json", DRAFT202012.create_resource(COMMON_SCHEMA))]
)
validator = Draft202012Validator(DECISIONS_SCHEMA, registry=registry)

data = yaml.safe_load(path.read_text(encoding="utf-8"))
data["items"][0]["status"] = "要見直し"
dumped = yaml.safe_dump(data, allow_unicode=True, sort_keys=False)

fd, tmp = tempfile.mkstemp(dir=path.parent, suffix=".tmp")
with os.fdopen(fd, "w", encoding="utf-8") as f:
    f.write(dumped)
os.replace(tmp, path)

for error in validator.iter_errors(bad):
    print(path.name, list(error.absolute_path), error.message)
```

closed PR の diff の見どころは `poc/yaml_roundtrip.py` の `build_validator`（共通のスキーマを `DRAFT202012.create_resource` で登録する）と、`poc/result.txt` の実行結果。

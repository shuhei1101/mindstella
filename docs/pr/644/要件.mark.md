# 要件

## 要望

React 移行（[#365](https://github.com/shuhei1101/mindstella/issues/365)）の仕上げとして、利用者が開く画面と配る書き出しを React の画面だけにし、今のバニラ TS の画面を保守の対象から除外する。

<!-- table: {"kind": "data"} -->

| 対象 | 終了の条件 |
| --- | --- |
| サーバーの配信 | 常駐サーバーが配る画面が React の画面だけになる。`preview_url`・ワークスペースの作成・README が示す画面の URL を開くと React の画面が開く。雛形に CSS と JavaScript を差し込んで返す今の画面の配信が無くなる |
| 配る書き出し | `export` が書き出す 1 枚の HTML を React のビルドから作る。ネットにつながらない端末で開いて、今の書き出しと同じく記録を参照するだけの画面として表示できる。記録の埋め込み・ライセンスの表示・書き出しの失敗の扱いは今と同じ |
| 今の画面と雛形 | `plugins/mindstella/skills/mindmap/preview/` の `app.ts`・`components/`・`core/`・`screens/`（`.ts` と生成した `.js`）・`template.html`・`style.css`・`tokens.css` と、今の画面の tsc の設定・ビルドの npm scripts を削除する。React のビルドの出力（`preview/spa/`）とライセンスの本文（`preview/licenses/`）は残す |
| 今の Storybook | `.storybook/`・今の部品のストーリー（`components/*.stories.ts`）・それを確かめる結合テスト（`tests/integration/storybook/`）・`@storybook/html-vite` の依存と npm scripts を削除する |
| テスト | 今の画面を前提にした単体テスト（`tests/unit/preview/`）と結合テスト（`tests/integration/preview/` の今の画面の分）を削除し、React の画面の結合テストを切り替えた後の URL で実行して合格させる。配る書き出しの結合テストを React の画面で合格させる |
| 設計書 | 今の画面の設計書（モジュール構成・部品設計・画面設計・インターフェース定義の今の画面の分）を削除し、残す設計書から今の画面への参照を削除する |
| 公開ドキュメント | `docs/guide/` のプレビューの説明・URL・コマンドを React の画面に合わせる |

<!-- /table -->

`未確定`: React の画面を配る URL のパス（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `/w/{workspace}/` で React の画面を返し、`/w/{workspace}/mindstella.html` と `/w/{workspace}/spa/` は `/w/{workspace}/` へ送り直す | 示す URL が短くなり、今の URL を保存していた利用者もそのまま開ける | 送り直しの経路が 2 つ残る |
| B | 今の `/w/{workspace}/spa/` のまま配り、`/w/{workspace}/` と `/w/{workspace}/mindstella.html` を送り直す | 配信の経路を変えずに済む | 切り替えの途中だった名前が URL に残る |

推奨: A

画面が 1 つになるため、ワークスペースの URL がそのまま画面を指す構造にそろえられる。

配る書き出しは、React の画面を 1 枚の HTML にする書き出し用のビルドを commit し、`export` がそこへ記録と mdmark・描画のライブラリの配布ファイルを差し込んで作る（PoC 検証で成立。[プレビュー](./プレビュー.mark.md) の `## PoC 結果`）。

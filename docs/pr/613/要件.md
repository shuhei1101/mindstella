# 要件

## 要望

レビュー中の書き込みを修正する入力欄に、コメント・返信の入力欄と同じ音声入力を追加する。今の画面と React の画面の両方が対象。

<!-- table: {"kind": "data"} -->

| 対象 | 要件 |
| --- | --- |
| 修正の入力欄の場所 | レビュー中の書き込みの画面の行・スレッドの中のレビュー中の返信・詳細パネル（全画面を含む）のレビュー中のコメントの、修正の入力欄の全て |
| 操作 | コメント・返信の入力欄と同じく、マイクのボタン・録音中の波形と経過の時間・× と ✓・押せないときの理由を出す |
| 文字起こしの結果 | 修正の入力欄のカーソルの位置へ挿入する。設定の「文字起こし後の挙動」によらず、レビュー中への追加・送信はしない。修正は利用者が「修正」を押して確定する |
| 同時に 1 つ | 修正の入力欄も、画面で 1 つだけの音声入力に含める。ほかの入力欄で録音中・文字起こし中は始めず、修正の入力欄で録音中はほかの入力欄で始めない |
| トップバーの音声入力中の表示 | 修正の入力欄で録音中・文字起こし中も、コメント・返信の入力欄と同じく出す |

<!-- /table -->

`未確定`: 修正の入力欄が画面に無い間に録音・文字起こしが終わったとき、と、録音中に「キャンセル」を押したときの扱い（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 画面に無い間に終わった結果は、その行の修正の入力欄を開き直したときに適用する（書きかけには保存しない）。トップバーの表示を押すと、その行の修正の入力欄を開く。「キャンセル」と行の削除では録音を捨てる | コメント・返信の入力欄と同じく、録音中にほかの項目・スレッドへ移れる | 修正の入力欄を開く画面と行を覚えて開き直す処理が要る |
| B | 修正の入力欄が画面から無くなったら、録音・文字起こしを捨てる。「キャンセル」と行の削除でも捨てる | 処理が少ない | 録音中に移ると話した内容が失われ、コメント・返信の入力欄と振る舞いが違う |

推奨: A

コメント・返信の入力欄の振る舞いと統一され、利用者が録音中にほかの資料を開いても話した内容を失わないため。

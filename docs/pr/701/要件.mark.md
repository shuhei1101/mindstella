# 要件

## 要望

- プレビューで記録の文字（項目のタイトル・本文・値・スレッドのタイトル・書き込みなど、記録から取得した文字）を表示する全ての場所で、プレーンテキストの項目の ID（`A-14`・`D-1`・`T-1`・`R-1`・`L-1` など）とスレッドの ID（`TH-150`・書き込みの ID `TH-150-2`）を、リンクの記法を記載しなくても自動でその項目・スレッドを開くリンクにする
- 記録に無い ID は文字のままにする
- ID をリンクにする処理（本文・値の欄の `linkBody` と、スレッドの書き込みの `buttonizeItemIds`・`linkThreadIds`）を、記録の文字を描く 1 つの部品にまとめ、記録の文字を描く全ての部品がその部品を使用する
- 記録の文字をその部品を使用せずに描く部品を検出して失敗させる仕組みを持ち、今後追加する部品・欄でもリンクにならない場所が生まれないようにする
- ボタンの中など、リンクを入れ子にできない場所の ID は、その場所を押す操作を変えずに項目・スレッドを示す別の見せ方にし、どの場所をどの見せ方にするかを一覧で決める
- [#688](https://github.com/shuhei1101/mindstella/issues/688)（詳細パネルの値の欄の ID のリンク）で入れた振る舞いは、この作業でまとめた部品の上でも変えない

リンクを入れ子にできない場所（カード・行・検索の結果）の ID は、文字のままマーカーにし、ポインターを乗せると項目・スレッドのツールチップ（部品『本文のマーカーのツールチップ』の種類 `item`・`thread`）を出す。
マーカーの見た目は、等幅の文字に本文の用語のマーカーと同じ色・太さの点線の下線にする。
マーカーはフォーカスできる要素にせず、行のボタン（検索の結果は `option`）にフォーカスしたとき、行の中の ID の項目・スレッドのタイトルと状態を `aria-describedby` で読み上げ、ツールチップを出す。
移る操作は行を開いた先の詳細で行う。

呼び忘れは ESLint の `no-restricted-syntax` で、JSX の子に `title`・`summary` のメンバー式を `{...}` で直接描く記載を誤りにして検出する（規則はモジュール構成『プレビュー / React』の「記録の文字」）。

# 資料の本文のフォルダ docs/ をワークスペースの直下へ移し、残っている release/ を削除する

## 概要

利用者が、項目の本文をワークスペースの直下の `docs/` から直接開いて、ほかの用途に使用できるようになる。
納品物かどうかは資料のメタデータで持つため、`release/` のフォルダはなくし、資料のフォルダを 1 つにする。

## 背景

[Issue #144](https://github.com/shuhei1101/mindstella/issues/144) の要望。aituber のワークスペース（`tmp/261004_設計`）の話し合いで、画面から送信された要望（送信 S-39）。

- 項目の本文は記録のフォルダの中の `.mindstella/docs/` にあり、利用者がエディターやファイルの一覧からすぐに開けない
- `release/` の書き出しとゴール判定は [#565](https://github.com/shuhei1101/mindstella/pull/565) で削除済みで、新規作成するワークスペースは `release/` を持たない。移し替えた既存のワークスペースの `.mindstella/release/` は、v0.14.0 の手順が触らずに残している

## 計画書

| ファイル | 中身 |
| --- | --- |

| [サーバー](./サーバー.mark.md) | 本文の配置先・配信の設定・点検・変更の検知・移し替えの計画書 |
| [スキル](./スキル.mark.md) | エージェントフローが案内する本文とファイルの配置先の計画書 |

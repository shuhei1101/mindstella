## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信の待ち受け | ワークスペースごとの `ThreadingHTTPServer` をやめ、常駐サーバーの待ち受け（`MINDSTELLA_PORT`）に画面の経路を加える。削除していないワークスペースを全て配る（クローズしたワークスペースも、今のとおり配り続ける） | 常駐サーバーの Starlette のアプリに `server.custom_route` で `/w/{workspace}` の経路を登録し、同期の処理をスレッドで動かす（モジュール構成『serve.py』の `PreviewEndpoint`） |
| ワークスペースの区別 | 画面の全ての要求のパスでワークスペースを区別し、知らないワークスペース・削除したワークスペースは 404 を返却する | パスの形は要件の `未確定`（インターフェース定義設計） |
| `check_host`・`check_origin` | 照らすポートを常駐サーバーの待ち受けのポートにする。許可するホスト名（`MINDSTELLA_ALLOWED_HOSTS`）の扱いは今のまま | 常駐サーバーの API の `check_host`（api.py）は外のホスト名を受けない（MindStella の API を端末の外へ出さない）ため、まとめずに画面の経路だけが `serve.py` の `check_host`（`MINDSTELLA_ALLOWED_HOSTS` を受ける）を使う |
| 画面の URL の返却 | `preview_url`・`readme`・ワークスペースの作成と状態・起動のコマンド・常駐サーバーの状態・作業の完了と停止の通知は、常駐サーバーのポートの URL を返却する | |
| 配信の起動・終了のフック | ワークスペースごとのポートを渡す呼ばれ方を、1 つのポートで配る作りに合わせる。終了時のフックは、常駐サーバーが終わるときに加えて、今のとおりワークスペースを削除したときにも呼ぶ | 引数の構造はインターフェース定義設計で決める |
| `config.yaml` の `preview.port` | 要件の `未確定` の推奨（削除と移し替え）で進める | データ設計で reviewer の合格の後にユーザーへ確認する |
| 書き換えの通知 | `/api/events` の購読をワークスペースごとに分け、別のワークスペースの書き換えを通知しない | |
| 既存機能への影響 | 配る書き出し（`export`）は配信を使用しないため変えない | |
| セキュリティ | 1 つのポートで全てのワークスペースを配っても、`127.0.0.1` だけで待ち受けることと、Host・Origin の照合は変えない | |

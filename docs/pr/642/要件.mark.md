# 要件

## 要望

常駐サーバーが待ち受ける 1 つのポート（`MINDSTELLA_PORT`、無ければ 8784）で、全てのワークスペースの画面を配る。

- ワークスペースごとに空きポートで配信を起動する作り（`PreviewRegistry`）をやめ、常駐サーバーの待ち受けに画面の経路を加える
- 画面の要求（React の画面と今の画面の `/api/*`・`/spa`・ワークスペースのファイル・書き換えの通知）は、パスでどのワークスペースの要求かを区別する。別のワークスペースの記録を返却・記録しない
- `check_host`・`check_origin` は、常駐サーバーの待ち受けのポートと照らす
- 画面の URL を返却するもの（`preview_url`・`readme`・ワークスペースの作成・起動のコマンド・常駐サーバーの状態・作業の完了と停止の通知）は、常駐サーバーのポートの URL を返却する
- 配信の起動・終了のフック（`MINDSTELLA_PREVIEW_START_HOOK`・`MINDSTELLA_PREVIEW_STOP_HOOK`）の呼ばれ方を、1 つのポートで配る作りに合わせる
- 配る書き出し（`export`）は配信を使用しないため変えない
- ワークスペースの `config.yaml` の `preview.port` は削除し、既存のワークスペースの値はワークスペースの移し替えで削除する
- 配信のフックは、常駐サーバーのポート・ワークスペースの名前・画面のパスの 3 つを引数で受け取る

`未確定`: 画面のパスでワークスペースを区別する方法（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ワークスペースの ID をパスの先頭に配置する（`/w/{ID}/mindstella.html`・`/w/{ID}/api/records`） | 今の画面は `api/records` など相対のパスで呼ぶため、配置する場所を変えるだけで呼び出しが合う。ブラウザの保存の範囲もワークスペースごとに分かれる | React の画面の生成した呼び出しと `/spa` の基準のパスを、ワークスペースごとの先頭に合わせる必要がある |
| B | パスは今のまま、問い合わせの値（`?workspace={ID}`）で区別する | パスの定義（OpenAPI）を変えずに済む | 呼び出しに値を付け忘れると別のワークスペースへ届く。ファイル・画像のリンクにも値を付ける必要がある |

推奨: A

付け忘れで別のワークスペースへ届く失敗を、パスの作りで起こせなくする。

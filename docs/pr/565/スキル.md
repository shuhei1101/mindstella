## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| エージェントフロー | A-111・A-112・A-113 の YAML（`id`・`title`・`summary`・`condition`・`steps[].name`・`body`・`when`・`calls`・`refs`）を、プラグインの配下に 1 エージェントフロー 1 ファイルで新規作成する。`calls` の `server` は MindStella の MCP と project-index の MCP を指し、ツールの名前は今の MCP のツールにそろえる | 配置場所とファイルの形式は、モジュール構成設計で判定フローチャート『ドキュメント配置判定』『データ化判定』で決める |
| エージェントフローの前提 | セッションのエージェントの定義と起動の構成（A-107 の「（前提）」の行）は、MindStella のセッションの起動（[PR #531](https://github.com/shuhei1101/mindstella/pull/531)）が持つ起動の構成を使用し、エージェントの定義の `progress` は記載しない（D-330） | エージェントフローの索引の生成と `calls` の検査は、単一ユースケース設計で要否を決める |
| 記録の使い分け | 振り分けの先に、AI が利用者に聞くこと → 検討事項（スレッドでは聞かない）を含める。対象・カテゴリー・フェーズ・進め方ガイド・納品物は扱わない | D-481・D-261・D-269 C |
| コメントの取り込み | スレッドでは回答を求めず、回の最後に、追加した検討事項と反映した回答を新しいスレッド 1 件に表で通知する。検討事項への回答だけのスレッドには返信しない | D-481 |
| スキルの削除 | `setup`・`session`・`upgrade` のフォルダを削除し、プラグインのマニフェストと `files.yml` の行を合わせる | - |
| 文章と HTML の書き方 | knowledge の規約に任せ、プラグインに持たない | A-107 |

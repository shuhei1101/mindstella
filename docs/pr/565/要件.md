# 要件

## 要望

スキルとプレイブックをやめてエージェントフローにし、エージェントフローに残す中身と、削除する機能（ゴール判定・次の候補など）を作り直す（資料 A-107 の No 3）。
エージェントフローの中身は資料 A-111（起動と再開）・A-112（コメントの取り込み）・A-113（記録の使い分け）、削除するものは A-107 の `## 削除の候補` と `## MindStella の MCP のツールの行き先` の「削除」の行、構成は A-119・A-106 に従う。

<!-- table: {"kind": "data"} -->

| 要件 | 終わりの条件 |
| --- | --- |
| エージェントフロー | 起動と再開（`mindstella/startup`）・コメントの取り込み（`mindstella/on-comment`）・記録の使い分け（`mindstella/record`）を、A-111・A-112・A-113 の工程のとおりにプラグインに同梱する。project-index の `search_docs` で、どのセッションからも ID で参照できる |
| SessionStart の注入 | MindStella のセッションの SessionStart のフックが、起動の契機（起動・再開）と再開の状況（未読のコメント・前回参照した後に変わった項目の ID と要約・要見直しの検討事項・進行中の作業）を注入し、起動と再開のエージェントフローを先に進めるよう案内する。注入文は今の `references/起動時の指示.md` からプロンプトファイルに移す。前回参照した時点は常駐サーバーの状態のフォルダに持つ（D-326）。注入に収まらない分は `changes_since_read` で取得できる（D-342） |
| 要返信をやめる | スレッドで利用者に回答を求めない。利用者の回答が要ること（質問・確認・未決定の点・AI の解釈の確認・ワークスペースの外へ書き込む前の合意）は検討事項に挙げ、コメントの取り込みの最後に、追加した検討事項と反映した回答を新しいスレッド 1 件に表で通知する（D-481。A-112・A-113 の修正後の工程） |
| スキルの削除 | `setup`・`session`・`upgrade` のスキル（`plugins/mindstella/skills/{setup,session,upgrade}/`）を削除し、Claude Code の `/mindstella:*` のスキルの一覧に出ない |
| プレイブックと手引きの削除 | `playbooks/` と `references/`（質問の書式・リサーチの調べ方・文章の書き方・HTML の書き方）を削除する。記録の使い分けに要る分だけをエージェントフローへ移す |
| ゴール判定・次の候補・リリースの削除 | MindStella の MCP から `next`・`goal`・`write_release`・`clear_release` を削除する。`.mindstella/release/` を作らない |
| 再開時の状況 | MindStella の MCP の `status` を削除し、要見直しの判定を SessionStart の注入に移す（次の候補は返却しない） |
| 移し替え | MindStella の MCP の `migrate` を削除し、常駐サーバーがワークスペースを読み込むときに、記録のバージョンが古ければ移し替える（D-288） |
| 削除するキー | 設定の `goal`・`phases`・`playbooks`・`targets`・`target_label`・`categories`、項目の `phase`・`target`・`category`・`attrs`、資料の `deliverable`、検討事項の `weight`、調査の `angles`・`confidence` をスキーマから削除する。既存のワークスペースは移し替えで削除し、絞り込みはタグで行う（D-276 A）。要る属性は種類のスキーマのキーにする（D-277 A）。調査の観点と確かさは本文に記載する（D-278 A） |
| 設定の更新 | MindStella の MCP の `update_settings` と画面の設定の書き換えから、削除するキーと、フェーズ・対象・カテゴリーの付け替え（`phase_map`・`target_map`・`category_map`）を削除する |
| ワークスペースの点検 | `check` から、設定に無いフェーズの検査など、削除するキーに依存する検査を削除する |
| 概要の画面 | 概要を、未読の AI の書き込み・未決定の検討事項・要見直しの検討事項・確認中の資料だけを並べるトップにする。ゴールのタイル・次の候補のタイル・カテゴリー別の進み具合の表を削除する（D-279 A） |
| 検討事項のマップ | 対象 → カテゴリー → フェーズの木をやめ、削除するキーを使わずに根の下へ検討事項を平らに並べる。マップそのものは [#542](https://github.com/shuhei1101/mindstella/issues/542) で削除するため作り直さない（[確認ログ](https://github.com/shuhei1101/mindstella/pull/565#discussion_r4608530240)） |
| 資料の画面 | 納品物を先頭にしたカードの並びをやめる |
| README と MCP の案内 | ワークスペースの `README.md` と MindStella の MCP の instructions から、スキルの呼び方を削除し、エージェントフローを案内する |
| 公開ドキュメント | `docs/guide/` のスキル・話し合いの進め方・ゴールでリリースする・ワークスペースを今の版へ移し替える・ワークスペースの書式のページを、エージェントフローと削除したキー・機能に合わせて書き換える |

起動スクリプトの登録（`setup` のスキルの配下の `register.py`）は、起動のコマンドのサブコマンドへ移し、公開ドキュメントのインストールの手順から案内する（単一ユースケース設計で決定。単一ユースケース『起動スクリプトの登録』）。A-107 は「setup のスキルを無くすので、登録の手段をプラグインのインストールの手順に移す」とし、登録そのものはやめていない。

記録の種類ごとの使い方のガイド（D-502）は、task-planner の判断で別の Issue [#566](https://github.com/shuhei1101/mindstella/issues/566) に分けた（[判断のコメント](https://github.com/shuhei1101/mindstella/issues/518#issuecomment-6958283225)）。

### 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| URL の指定 | 利用者が、画面の URL の基底（`https://{名前}.{domain}` など）をホームの設定か環境変数で指定でき、指定が無ければ今のローカルの URL を使用する | 指定の方法は `未確定`（決める工程: インターフェース定義設計） |
| 通知 | 作業の完了の通知・停止の通知の URL を、指定があれば公開した URL にする | - |
| API と `preview_url` | ワークスペースの作成・状態の取得の `url` と `preview_url` の戻り値も、同じ指定で公開した URL にする | 合わせるかは単一ユースケース設計で確定する（推奨は合わせる。aituber の管理画面のリンクが同じ値を使用するため） |

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ホームの設定（`settings.yaml`）に画面の URL の基底を記載する | 全てのワークスペースが 1 つの基底で済む（全てのワークスペースは常駐サーバーの 1 つのポートの `/w/{workspace}/` で配る） | 設定のキーが増える |
| B | 配信の開始のフックの標準出力から公開 URL を受け取る | 利用者のスクリプトが決めた URL をそのまま使用できる | 常駐サーバーの 1 つのポートになった後は、ワークスペースごとのフックの出力が無い |

推奨: A

[#538](https://github.com/shuhei1101/mindstella/issues/538) で全てのワークスペースを 1 つのポートで配るようになり、公開の単位がワークスペースから常駐サーバーに変わったため、基底を 1 つ指定すれば足りる。

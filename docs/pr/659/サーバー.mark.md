### 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| データ | 検討事項に誰が決めたか（利用者・AI）のキーを追加する。値は英語の列挙にする。キーを持たない既存の検討事項はそのまま参照でき、誰が決めたかを表示しない | キー名と列挙の値はデータ設計で決める。記録の形式の移行の要否もデータ設計で決める |
| 編集機能 | AI が採用する案を切り替えるときと、記録を追加・修正して決定済みにするときに、誰が決めたかを AI として残す。利用者が画面から採用を変えて保存したときは利用者にする | 採用する案の切り替えのツールの引数はインターフェース定義設計で決める |
| 一括操作 | 画面から、未決定の検討事項の ID の並びを受けて、それぞれを推奨の案に決め、誰が決めたかを利用者にして 1 つの書き換えのまとまりにする。1 件でも決められない検討事項（推奨の案が無い・未決定でない・見つからない）があれば何も書き込まず、決められない検討事項と理由を全て返却する | 要件の `未確定`（通知の経路）の推奨 A の場合 |
| 通知 | まとめて決めた後、決めた検討事項の ID と件数を、『コメントをまとめて送信する』と同じく MindStella のセッションへ 1 回入力する | 要件の `未確定`（通知の経路）で決める |
| 生成機能 | エージェントフロー『記録の使い分け』を、方針（構成・責務・利用者の体験・費用・元に戻せないもの）は選択肢を作る前に論点と AI の理解をスレッドで聞き、細部（後から変えられるもの）は AI が決めて誰が決めたかを AI として記録する手順にする | 方針と細部の見分け方の目安をエージェントフローに記載する |
| 生成機能 | エージェントフロー『コメントの取り込み』に、まとめて決めた回答の通知を受けたときの取り込み（影響する項目の洗い出し）と、通知のスレッドに AI が決めた検討事項を並べる手順を追加する | 通知のスレッドの表の列はエージェントフロー・LLM 呼び出し設計で決める |
| バリデーション | 点検に、誰が決めたかを持つのに状態が決定済みでない検討事項を洗い出す規則を追加する | 規則の要否はインターフェース定義設計で決める |
| 既存機能への影響 | 話し合い「何でも会話」の `CLAUDE.md` の暫定の行（検討事項を複数挙げたときは 1 件のスレッドに ID を並べて通知する）を、仕組みに入った後に削除する | 反映作業『暫定のローカルルールの削除』 |

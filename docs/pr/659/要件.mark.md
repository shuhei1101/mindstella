子 Issue ごとの測れる基準は次のとおり。

| Issue | 基準 |
| --- | --- |
| #484 | AI は方針（構成・責務・利用者の体験・費用・元に戻せないもの）を選択肢を作る前にスレッドで聞き、細部（キーの名前・型・エラーの扱いなど後から変えられるもの）は自分で決めてスレッドで報告だけにする |
| #361 | 項目を並べる画面の絞り込みのドロワーの先頭に、AI が作ったプリセットが件数つきで並ぶ。プリセットを選ぶと、そのプリセットのタグの式がタグの条件に入る。チェックで表せる式は今のタグのチェックと組み合わせ方に入り、表せない式はドロワーのタグの条件を式で書く表示に入る（プリセットを解除する操作は持たず、タグの条件を外して解除する）。画面のタグの条件もプリセットと同じ式で書ける。状態・種類など今の絞り込みの条件は残る。該当する件数が 0 のプリセットには、ドロワーでマーカーを出す |

#361 の後続の「画面の今の絞り込みをプリセットとして保存する」は [#362](https://github.com/shuhei1101/mindstella/issues/362) が受け持つ。

プリセットの式（タグを含まない条件・`and`・`or`・`not` の束）は今のまま残し、画面のタグの条件も同じ式で書けるようにする（[回答](https://github.com/shuhei1101/mindstella/pull/659#discussion_r4653103209)）。チェックで表せる式は今のタグのチェックと組み合わせ方で、表せない式はドロワーで式として書いて直せる。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| スレッドの書き込み（#705） | 送信した書き込み・レビュー中の書き込み・削除した後の行から、外側のカードの中に重なるカードの見た目（枠・角丸・背景色の組）を除外し、書き手と種類は配置の側・背景色・線のどれかで見分ける | 検出が指す外側の要素を `detect_screen_issues` で確認してから決める |
| 音声の再生バー（#720） | 詳細パネル・詳細の全画面で描いた音声の入れ物の高さ・`overflow`・`line-height` を確認し、再生バーの高さを切らない規則にする | 原因の要素は描いた結果で確認して `## 実装` に記載する |
| タブのマーカー（#692） | 差分の表示の間、選んだ時点の追加・変更・削除の項目の種類から、画面の組み立てがタブごとの `marked` を計算してトップバーへ指定する | 概要のタブの扱いは画面設計で決める |
| 画面のスクロール（#692） | 資料を開いている間も画面の全体の高さを窓に収め、本文の区画とパネルの中だけをスクロールさせる | 記録の多いワークスペースで再現し、はみ出す要素を確認する |
| 差分の表示をやめるボタン（#692） | トップバーの `ClearDiffButton` を削除する | 部品設計『トップバー』とストーリーも削除する |
| 変更履歴の一覧（#156） | 先頭を「最新」にし、「前回開いてから」の行を削除して、まとまりを新しい順に並べる。差分の表示で開いたまとまりを既読にする | 「まだまとめていない変更」の行は残す |
| 未読のマーカー（#156） | 既読でないまとまりの行に未読のマーカーを付け、モーダルの上に「すべて既読にする」を配置する。トップバーの変更履歴のボタンに未読の件数を出す | 置き場所は要件の `未確定`（推奨は端末の保存領域） |
| 未読の増え方（#156） | 書き換えの通知で記録を再読み込みしたとき、増えたまとまりを未読として件数に加える | 既存の書き換えの通知をそのまま使用する |
| 案の選択（#363） | 検討事項の詳細の案のカードを押す領域にし、押すと一言の入力と確定を出して利用者の選択を記録する。選んだ案のカードには「選択済み」の状態を出し、選び直し・取り消しを配置する | 押す領域は縦横 24px 以上。AI の採用（決定済み）の見せ方と分ける |
| アクセシビリティ | 案のカードの選ぶ操作をキーボードで押せるボタンにし、選んだかを `aria-pressed` で、未読の件数をボタンの名前に含める | - |
| レスポンシブ対応 | 幅 390px でも案のカードの押す領域・一言の入力・変更履歴の未読のマーカーがはみ出さない | - |

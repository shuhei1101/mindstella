## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 利用者の選択の記録（#363） | 検討事項に任意のキーで利用者の選択（選んだ案の記号・日時・一言）を持たせ、`adopt` の採用（`決定済み`）とは別にする | 任意のキーの追加で、既存のワークスペースはそのまま参照できる。移し替えの手順が要るかはデータ設計で決める |
| 選択の書き込み（#363） | プレビューから利用者の選択を記録・選び直し・取り消しする配信の書き込みを追加し、記載したら開いている画面へ通知する | 記録の書き込みは変更の検知の対象になり、編集した人は利用者になる |
| AI の取得（#363） | 利用者が案を選んだ検討事項の一覧を MCP で返却し、再開の状況に件数を入れる | 方法は要件の `未確定`（推奨は MCP のツールの新設） |
| 選択の片付け（#363） | 『採用する案の切り替え』で採用したら、その検討事項の利用者の選択を片付ける | 一言はスレッドと同じ流れで取り込む |
| 前回開いた日時（#156） | 「前回開いてから」をやめるため、インターフェース定義『前回開いた日時』の用途を見直し、使用されなくなるなら廃止する | 既読の置き場所が端末なら、サーバーは既読を持たない |
| 既存機能への影響 | 書き換えのまとまりの連番・変更の検知は変えない | 単一ユースケース『書き込みを履歴に残す』は実行のみ |

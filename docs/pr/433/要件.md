# 要件

## 要望

プレビューの結合テストのうち、保存待ちの編集（`/api/edits`）を待つ判定が待ってから通り、コメントの一覧を開き直したときのスクロールの位置を確認するテストが毎回 pass するようにする。

| 子 | タイトル | 終わりの条件 |
| --- | --- | --- |
| [#383](https://github.com/shuhei1101/mindstella/issues/383) | 結合テストの保存待ちの編集を待つ helper が、判定を async 関数で書いていて待たずに通る | `tests/integration/preview/preview_edit_helpers.py` の `SAVED_EDIT_JS`・`NO_SAVED_EDITS_JS` と、`test_workspace_settings_screen.py` のゴールの中身を待つ判定が、同期の判定で保存待ちの編集を待ってから通る |
| [#428](https://github.com/shuhei1101/mindstella/issues/428) | 結合テスト test_reopen_restores_scroll が develop でも不安定に fail する（コメントの一覧を開き直したときのスクロールの位置） | 原因を突き止め、テストの待ち方か `plugins/mindstella/skills/mindmap/preview/app.ts` のスクロールの位置の戻し方を修正して、`test_reopen_restores_scroll` が毎回 pass する |

#383 の判定を同期にした後、待つようになって fail する呼び出し（`test_detail_panel_screen.py`・`test_workspace_settings_screen.py` の各 12 か所）は、同じ作業 PR で手当てする。
同じ構造の判定（`test_decisions_screen.py` の `_wait_added_options`・`_wait_added_value`、E2E の `test_item_add.py` の `_wait_added_options`）も、同じ helper に統一する。

#428 の原因はテストの読み方にあり、`app.ts` は変えない。
開き直した直後のスレッドの読み直しで一覧を描き直すと `.comments-body` の要素が差し替わり、`SETTLED_SCROLL_TOP_JS`（`preview_body_scroll_helpers.py`）が最初に取った差し替え前の要素（外れて `scrollTop` が 0）を読み続けて 0 を返す。
差し替え後の要素には位置 500 が戻っており、画面設計『コメントの一覧』の挙動どおり。

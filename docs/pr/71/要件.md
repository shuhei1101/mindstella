# 要件

## 要望

スクリプトのモードを残さず、サーバーと MCP を前提にした作りへ移す。
スクリプトの版は、出したときのタグで残る。

| 項目 | 要件 |
| --- | --- |
| MCP のツール | スクリプトのコマンド（`build` を除く）を MCP のツールへ移す。入力の検証・出力・終了の仕方は今のコマンドと同じ内容を返し、スキーマに合わない書き込みは何も書き換えない。`mindmap.py` のコマンドの入口は残さない。MCP サーバーは Python の公式の MCP SDK で作る |
| スキルの手順 | `setup`・`session`・`upgrade` の手順と `allowed-tools` を、MCP のツールを呼ぶ形へ書き換える。「ワークスペースを編集したら最後に `build` を流す」を除く。MCP のツールが使えない会話では、何も書き込まず起動スクリプトでの立ち上げを案内して止まる |
| プレビューの配信 | サーバーがワークスペースの YAML を直接読み、プレビューを HTTP で配る。YAML が書き換わったら、開いている画面へ再読み込みの操作なしで反映する（Server-Sent Events で知らせる）。待ち受けるのは端末の中（`127.0.0.1`）だけにする |
| 回答・意見の送信 | 詳細パネルから、項目の ID ごとに回答・意見を送る。送った内容はワークスペースに残り、サーバーを止めても消えない |
| 送信の取り込み | `session` の話し合いの最初に、取り込んでいない送信を拾い、取り込みのステップで記録してから取り込み済みにする |
| 起動スクリプト | tmux のセッションを立て、その中で mindstella の MCP サーバーを渡した Claude Code を起動し、そのセッションへつなぐ。プラグインのマニフェストには MCP サーバーを書かず、起動スクリプト以外で立ち上げた Claude Code には MCP のツールが載らない |
| 依存の確認 | 起動スクリプトが MCP サーバーを立てる前に、今の `check-env` と同じ内容（Python の版・依存のライブラリ）を確かめ、足りなければ足りないものとそろえるコマンドを示して止まる |
| 配る書き出し | `export`（#19）は残し、MCP のツールから呼ぶ |
| ワークスペースの移し替え | ワークスペースのファイルの形が変わる（送信の置き場所を足す 等）ときは、#43 の版ごとの移し替えの手順を足す |
| サブシステム | サブシステム「スクリプト」を「サーバー」に置き換え、MCP のツールとプレビューの配信を 1 つのプロセスで持つ。各プロセスが空きポートで自分のワークスペースを配る（[確認ログ](./確認ログ.md)） |
| 送信の置き場所 | ワークスペースに `submissions.yaml` を足す。初めて送ったときにサーバーが作り、無ければ送信 0 件として扱うため、移し替えの手順は足さない |

# 要件

## 要望

| 要件 | 終了の条件 |
| --- | --- |
| 設定の mdmark のバージョンが `latest` か未設定のとき、今の画面・React の画面・配る書き出し・Storybook が、mdmark の develop の最新の commit の配布物を読み込む | mdmark の develop に配布物を作成し直した commit が入った後、画面を開き直したときに読み込む `dist/index.js`・`dist/index.css` の SHA-256 が、mdmark の `origin/develop` の同じファイルと一致する。一致するまでの遅れの上限は、インターフェース定義設計で解決の仕方と合わせて決める |
| 設定の mdmark のバージョンがタグのとき、今と同じくそのタグの配布物を読み込む | タグの URL が今と同じ |
| 画面の CSS が、mdmark が描いた部品（表・差分・図・囲み）の見た目と動きを上書きしない | 上書きしている規則を洗い出して削除する。mdmark の使い方『テーマを上書きする』が定める CSS 変数の指定は残す。表の列の固定（複数の列を含む）と横スクロールが mdmark の動きのまま働く |
| 背景を透明にした `.mdmark` で、覆い・ツールチップ・全画面の図の背景が透けない（[#398](https://github.com/shuhei1101/mindstella/issues/398) から統合） | `--mdmark-color-bg` を透明にしている箇所と `:root` に `--mdmark-color-bg-opaque: var(--surface)`（React の画面は同じ役割のトークン）を指定する。表の左右の端に常に影が出ない・全画面の図の後ろの本文が透けない |
| プラグインのキャッシュの CSS の末尾に追記した暫定の `.mdmark { --mdmark-color-bg: var(--surface); background: transparent; }` が要らない | 暫定の規則を適用しない画面で、上の行の終了の条件を満たす |

`未確定`: `latest` の解決の仕方（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | サーバーが mdmark の develop の先頭の commit の SHA を GitHub に問い合わせ、画面には `gh/shuhei1101/mdmark@{SHA}` の URL で読み込ませる | MindStella だけで完結する。commit を指す URL は中身が変わらないので、CDN とブラウザのキャッシュが更新前のまま残らない | サーバーが GitHub へ問い合わせる。届かないときの扱いと、問い合わせた SHA を保持する時間を決める |
| B | mdmark の配布物を作成し直すたびに、mdmark の側で jsDelivr のキャッシュを削除する（mdmark へ起票し、依存に加える） | MindStella の読み込みは変わらない | ブラウザのキャッシュ（最大 7 日）は削除されない。mdmark の作業を待つ |

推奨: A

B ではブラウザに残った更新前の配布物を使用し続け、終了の条件を満たせない。

# 要件

## 要望

v0.12.1 以前のワークスペースを開いたとき、v0.13.0 の移し替えの手順 5（`mdmark_documents`）が mdmark の `upgrade` を成功させ、`pytest tests/integration/server/test_migrate.py::test_normal_when_mdmark_documents` が develop で pass する。

- 設定の `mdmark.version` が無いか `latest` のとき、移し替えの手順が呼ぶ mdmark の ref を、develop ではなく mdmark のタグに固定する
- 設定の `mdmark.version` がタグのときは、今のとおりそのタグを呼ぶ
- 画面が読み込む mdmark の既定（`latest`。develop の最新）は変えない
- インターフェース定義『記録の形式の移行』（IF-489-52）の `mdmark_documents` の呼ぶ ref の記述と、モジュール構成『サーバー / 移行 / mdmark_documents.py』（MOD-550-1）を合わせる

固定する mdmark のタグは、インターフェース定義設計で A（`v0.13.0`）に決めた。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `v0.13.0` | 手順が前提にした変換（`v0.11.0` のマーカーの JSON・`v0.13.0` の map）だけを適用し、[PR #551](https://github.com/shuhei1101/mindstella/pull/551) の PoC で確認した mdmark（`dist/` が v0.13.0 と同じ 73ca2603）と同じ変換になる | mdmark の `v0.14.0` の移行（ER 図の書き方の移行 `retired-er`）は適用しない |
| B | `v0.14.0` | 今出ている最新のタグの書き方まで移す | v0.13.0 の移し替えの手順が前提にしていない `v0.14.0` の移行まで適用し、手順を作った時点の書き方へ移すという目的からはみ出す |

推奨: A

移し替えはバージョンごとに、その手順を作った時点の書き方へ移すもので、`MDMARK_BASE_VERSION`（`v0.10.0`）から適用する手順も `v0.11.0`・`v0.13.0` の 2 つと決めて作られているため。

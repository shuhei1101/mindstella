## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 方針の質問（No 2・3） | 「利用者に聞くことを方針と細部に分ける」の方針の行を、AI の理解・案・推奨を持つ `未決定` の検討事項にする対応に書き換え、`new_thread` の `calls` を除外する | ワークスペースの外への書き込みと項目の削除の合意も検討事項で聞く |
| 返信の中身（No 2） | 「返信する」に、利用者に返信を求めず、回答が要ることは検討事項に挙げる決まりを加える | - |
| 報告のスレッド（No 1） | 「検討事項と回答を通知する」を、その回の AI の報告を新規のスレッド 1 件にまとめる工程にし、前の回の報告のスレッドをクローズにする | 今の工程も前の回の通知のスレッドをクローズにしている |
| 保留（No 4） | 「保留・取り下げにする」に、回答待ちの検討事項を保留にしない決まりを加える | - |
| 資料の状態（No 5） | 「発言を振り分ける」の資料の行に、`下書き`・`確認中`・`完成` の意味を加える | スキーマの値は変えない |
| 確認の依頼（No 6） | 資料の確認を依頼する工程を `record.yaml` に追加する（資料 1 件に検討事項 1 件、新規決定事項の表、確認中の資料に「この資料で完成でよいか」の未決定の検討事項） | - |
| 後で行う作業（No 7） | 「発言を振り分ける」のタスクの行に、その回のうちにタスクにする決まりを加え、「クローズにする」に書き込みの中の約束がタスクにあるかの確認を加える | - |
| タスクの状態（No 8） | タスクの行を、着手できるものは `進行中`、着手できない条件があるものは `保留` と `reason` の着手できる条件にする。回の最初に `保留` のタスクを `search_docs` で検索して見直す工程を `startup.yaml` と `on-comment.yaml` に追加する | 再開の状況の注入（IF-489-32）は変えない |
| 描画の確認（No 9） | 「記録を書き込む」に、図や mdmark の記法を持つ資料は書き込む前に mdmark の点検か書き出しで警告が無いことを確認する決まりを加える | コマンドとパスは記載しない |

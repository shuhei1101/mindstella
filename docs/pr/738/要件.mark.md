# 要件

## 要望

1. 詳細パネルと詳細の全画面の固定のヘッダーに、一覧の星（部品『お気に入りの星』）と同じ星のボタンを置き、押すと開いている項目をお気に入りに登録・解除する。カード・表の星と同じお気に入りを読み書きし、どちらで変えても他方の星が同じ状態になる
2. MindStella のセッションの AI が、利用者の指示で、ID で指した項目をお気に入りに登録・解除できる。AI が登録・解除した結果は、プレビューを開いている利用者の画面に、再読み込みせずに（書き換えの通知で）星として出る
3. 2 のため、お気に入りの登録の残り先を、端末の保存領域だけからワークスペースの側へ移す。端末の保存領域に残っている今のお気に入りは、移した後も失わない
4. 「お気に入りを一番上にする」「お気に入りだけを表示する」（表示の設定）は今のまま端末の個人の上書きとして残す
5. お気に入りはワークスペースに 1 つの共有のお気に入りにし、利用者ごとに分けない。星の登録・解除で項目の YAML・本文と `config.yaml` は変わらず、変更履歴に載らない

6. お気に入りは記録のフォルダ `.mindstella/` の `favorites.yaml` に持つ（[ER 図『ワークスペース』](https://docs.shuhdev.com/mindstella/docs/er/ER-489-1.yaml?rev=feat%2Fpreview%2Ffavorite-from-header-and-ai)の `favorites.yaml`）。AI は MCP のツールで、画面はサーバーの API で登録・解除する

<details>
<summary>残し先を決めた理由</summary>

| 案 | 内容 |
| --- | --- |
| A | 項目の YAML に `favorite: true` のキーを持たせる。AI は project-index の `write_docs` でキーを書き込む |
| B | ワークスペースの設定 `config.yaml` に `favorites`（項目の ID の並び）を持たせる |
| C | 記録のフォルダ `.mindstella/` に `favorites.yaml` を新設する |

C にした。
A は、AI が `write_docs` で書き込むたびに、変更の検知がそれを項目の変更として変更履歴に追加し、保持する回数（既定 5 回）を超えた内容の変更の履歴を押し出す。
B は、設定の検査と「最後に検査に通った設定」の差し替えに星の付け外しが巻き込まれる。

# 要件

## 要望

| 要件 | 終了の条件 |
| --- | --- |
| コメントの入力（詳細パネル・詳細の全画面・コメントの一覧の新しいスレッド）と返信の入力（スレッド）で「レビューに追加」（Ctrl+Enter を含む）を押して溜めた後に、入力欄へフォーカスを戻すかを設定に従わせる | 今の画面と React の画面の両方で、設定が戻すなら溜めた後に入力欄へフォーカスがあり、戻さないなら入力欄にフォーカスが無い |
| 音声入力の確定で溜めた・送信した後に、入力欄へフォーカスを戻すかを同じ設定に従わせる。挿入した（`insert`）後は、続けて書けるよう今と同じく入力欄へ戻す | 今の画面と React の画面の両方で、上の行と同じ |
| 設定を表示の設定で「自動（マウスは戻す・タッチは戻さない）・入力欄へ戻す・戻さない」の 3 つから選べ、この端末だけの個人の上書きとして残す | 選んだ値がページを開き直しても残り、「既定に戻す」で解除される |
| 設定を変えていない端末の既定は自動で、主な入力がマウスの端末（`pointer: fine`）では戻す、タッチの端末（`pointer: coarse`）では戻さない | 端末の保存領域が空のブラウザを、`pointer: fine` で開くと戻し、`pointer: coarse`（スマホの幅）で開くと戻さない |
| 入力欄へ戻さないときも、キーボードの操作と読み上げでフォーカスの場所が分かる | フォーカスが `body` に落ちず、溜めた結果の通知が読み上げられる |

`未確定`: 設定の項目名と選択肢の文言（決める工程: モック作成）

| 案 | 内容 |
| --- | --- |
| A | 項目名「レビューに追加した後のフォーカス」、選択肢「自動」「入力欄へ戻す」「戻さない」 |
| B | 項目名「追加した後に入力欄へ戻る」、選択肢「自動（スマホでは戻らない）」「戻る」「戻らない」 |

推奨: A

ボタンの文言「レビューに追加」と対応し、何の後の設定かが項目名から分かるため。

`未確定`: 入力欄へ戻さないときのフォーカスの移動先（決める工程: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 「レビューに追加」のボタン（押したボタン）にフォーカスを配置する | 押した場所から動かず、Tab で入力欄へ戻れる | 音声入力の確定の後は押したボタンが ✓ で、消えた後の配置先を別に決定する |
| B | 溜めた結果の行（「レビューに追加しました」）にフォーカスを配置する | 結果がそのまま読み上げられる | 結果の行をフォーカスできる要素にする |

推奨: A

ソフトウェアキーボードを開かずに、フォーカスを押した操作の近くに残せるため。音声入力の確定の後は、✓ の位置に戻る「レビューに追加」のボタンに配置する。

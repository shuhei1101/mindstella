# 要件

## 要望

mdmark の記法で記載する Markdown の拡張子を `.mark.md` にし、改名した文書を指すリンク・目次・配信元の行・コードのパスを修正する。
完了の条件は、改名の範囲のファイルに `mdmark check` の `plain_md_with_marks` が出ないことと、改名したファイルを指すパスが全て改名後のパスになっていること。

### リポジトリの文書

手で記載する `.md` のうち、mdmark の記法を含むものを `.mark.md` へ改名する。

| 範囲 | ファイル |
| --- | --- |
| 公開ドキュメント | `docs/guide/` のコマンド・セットアップ手順-ワークスペースを今の版へ移し替える・プレビューを見る・ワークスペースの書式・動作環境 |
| デザイン方針 | `docs/design-policy.md` |

- 改名したファイルを指すリンク（`docs/` の Markdown と YAML・Pages の設定とナビゲーション）と `files.yml` の行を改名後のパスに修正する
- 記法を含まない `.md` は `.md` のまま残す
- 改名したページの GitHub Pages の公開 URL は、改名前の URL（`{パス}.html`）のまま保つ。`docs/_config.yml` の `defaults` で、改名したページごとに `permalink` を改名前の URL にする（Jekyll はページの URL を拡張子の前までの名前から作るため、指定しないと `{パス}.mark.html` に変わる）

### ワークスペースの記録の本文

Markdown の本文は全て `docs/{ID}.mark.md` にする（HTML の本文は `docs/{ID}.html` のまま）。

- 本文を新規に記載するときのパス（MindStella の MCP・エージェントフローの案内）・スキーマの `body` の値のパターン・点検・変更の検知・配信・書き出し・画面が本文を取得するパスを、決めた拡張子に修正する
- 既存のワークスペースは、次のバージョンの移し替えの手順（`migrations/{バージョン}/steps.yaml`）で本文のファイルを改名し、`body` の値を書き換える。移し替えは、ワークスペースを開く前に『記録の形式の移行』が利用者に確認せずに適用する

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 本文のパス | Markdown の本文を記載するパスを `docs/{ID}.mark.md` にする | 確認ログのとおり案 A |
| スキーマ | 種類ごとのスキーマの `body` の `pattern` と説明を、決めた拡張子に修正する | スキーマの変更のため、移し替えの手順を加える |
| 本文の形式の判定 | `.mark.md` を Markdown の本文として判定する | `.html` の判定は変えない |
| 点検・変更の検知・配信 | 本文のファイルのパターンを、決めた拡張子のファイルに修正する | - |
| 移し替え | `migrations/v0.14.0/steps.yaml` に `call`（`markdown_bodies_to_mark_md`）を 2 手順目として加え、`docs/` の `*.md` を `.mark.md` へ改名し、項目の `body` と `history.yaml` の `before.body` を書き換える | 改名先が既にあれば StepFailedError で写しから戻す（『記録の形式の移行』） |
| 変更の検知 | 移し替えを当てたら、同じ鍵の中で前回の中身（`snapshot/` と、動いている変更の検知が持つ中身）を今の中身で作り直す | 改名を変更として記録しない（『変更の検知』の `rebase_snapshot`。ワークスペースの管理が呼ぶ） |
| release の書き出し | 変えない | `RELEASE_SUFFIXES` はどこからも参照されず、`.mark.md` も `.md` で終わるため、拡張子の判定（`body_format`・点検の `.endswith(".md")`・変更の検知の `*.md`）はそのまま `.mark.md` を Markdown として扱う |

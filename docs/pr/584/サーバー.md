## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 不具合 1 | Git 管理外のワークスペースへの `write_docs` の作成・更新・置き換えが検査に通るようにする | 配信の設定の各種類の行に `write_dates: false` を記載する。既存のワークスペースは、開くときに `write_dates` を持たない行に足す（IF-489-52『配信の設定の日時』） |
| 不具合 2 | 移し替えを適用した後と、ワークスペースのバージョンが最新で手順を適用しないときにも、スキーマの複製をプラグインのスキーマと比べて違うファイルを再配置する | 既に v0.14.0 に移し替えたワークスペースも、次に開いたときに一致させる |
| 不具合 3 | `body` を持たない項目を配信から除かない | project-index#195 の修正で解消する。MindStella の配信の設定は変えず、実際の project-index の結合テストで確認する |
| 既存機能への影響 | MindStella 自身の読み込み・検証（`validate_workspace`）も同じスキーマを使用するので、`created`・`updated` を持つ項目を読み込めることを単体テストで確認する | - |
| テスト | 結合テストに、Git 管理外のワークスペースへの project-index の `write_docs` の作成・更新、移し替えの後の書き込み、本文を持たない項目の検索を追加する。不具合 2 は、配信中の Git 管理外のワークスペースでスキーマの複製を更新前に戻して開き直し、`search_docs` の警告が消えることを実際の project-index で確認する | 実際の project-index を使用する結合テスト（`tests/integration/plugin/test_agent_flows.py` と同じ準備）で検出する。不具合 2 の実際の project-index の結合テストも、project-index#195 の完了後に不具合 1・3 と準備を共有して追加する（今は Mock で、読み直しの依頼を送ることまでを確かめる） |

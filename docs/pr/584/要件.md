# 要件

## 要望

v0.13.0 で記録の読み書きを project-index の MCP に移した後、MindStella のセッションが Git 管理外のワークスペースの記録を作成・更新・参照できない不具合 3 件を修正する。

| 不具合 | 完了の条件 |
| --- | --- |
| 1. `write_docs` の作成・更新が `created`・`updated` で検査に通らない | Git 管理外のワークスペースで、`write_docs` の `create`・`update`・`replace` が検査に通って書き込まれる |
| 2. v0.14.0 の移し替えがスキーマの複製を置き直さない | 移し替えの後、`.mindstella/schemas/` の複製がプラグインの `skills/mindmap/schemas/` と一致する。既に v0.14.0 に移し替えたワークスペースも、次に開いたときに一致する |
| 3. 本文のファイルを持たない項目が配信から除かれる | `body` を持たない項目（用語集・メモ・本文の無い検討事項とタスク）を `search_docs`・`trace_related` で参照でき、`write_docs` で更新でき、`search_docs` の結果に `missing_body_file` の警告が出ない |
| 4. テスト | 1〜3 を結合テストで検出できる（Git 管理外のワークスペースへの作成・更新、移し替えの後の書き込み、本文を持たない項目の検索）。このリポジトリに E2E は無い |

不具合 1・3 は project-index の設計書どおりの動きで、project-index の側の対応を [shuhei1101/project-index#195](https://github.com/shuhei1101/project-index/issues/195) で行う（Issue #583 の[追記](https://github.com/shuhei1101/mindstella/issues/583#issuecomment-6977926702)）。

| 不具合 | この作業 PR の範囲 | 着手 |
| --- | --- | --- |
| 1・3 | project-index#195 で修正する範囲が決まった後の残り（配信の設定・スキーマ・移し替え・テスト）。#195 で対応しない判断になったら MindStella の側で解決する | #195 の完了を待つ |
| 2 | 全て | #195 を待たずに設計・実装する |

不具合 1・3 の MindStella の側の残り（project-index#195 の修正 shuhei1101/project-index#196 が develop へ入った後に決定。Issue #583 の[報告](https://github.com/shuhei1101/mindstella/issues/583#issuecomment-6982035303)）:

| 不具合 | project-index の振る舞い | MindStella の側の残り |
| --- | --- | --- |
| 1 | 配信元の設定の `documents[].write_dates` が `false` の種類の文書には、Git 管理外の配信元でも `write_docs` が `created`・`updated` を付けない | 配信の設定（`build_source_config`）の各種類の行に `write_dates: false` を記載する。既に作ったワークスペースの `.mindstella/dev-docs.yaml` にも記載する。1 の結合テスト |
| 3 | `body_file` の列が無いか値が `null`・空の要素は、本文のファイルを持たない文書として配信し、`write_docs`・`delete_docs` で扱える | 3 の結合テスト（本文を持たない項目を検索・更新できる）。配信の設定は変えない |

効かせるには、利用する端末の project-index のサーバーを shuhei1101/project-index の 368b731 を含む版へ更新する。

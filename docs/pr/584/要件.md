# 要件

## 要望

v0.13.0 で記録の読み書きを project-index の MCP に移した後、MindStella のセッションが Git 管理外のワークスペースの記録を作成・更新・参照できない不具合 3 件を修正する。

| 不具合 | 完了の条件 |
| --- | --- |
| 1. `write_docs` の作成・更新が `created`・`updated` で検査に通らない | Git 管理外のワークスペースで、`write_docs` の `create`・`update`・`replace` が、project-index の追加する `created`・`updated` を持ったまま検査に通って書き込まれる |
| 2. v0.14.0 の移し替えがスキーマの複製を置き直さない | 移し替えの後、`.mindstella/schemas/` の複製がプラグインの `skills/mindmap/schemas/` と一致する。既に v0.14.0 に移し替えたワークスペースも、次に開いたときに一致する |
| 3. 本文のファイルを持たない項目が配信から除かれる | `body` を持たない項目（用語集・メモ・本文の無い検討事項とタスク）を `search_docs`・`trace_related` で参照でき、`write_docs` で更新でき、`search_docs` の結果に `missing_body_file` の警告が出ない |
| 4. テスト | 1〜3 を結合テストで検出できる（Git 管理外のワークスペースへの作成・更新、移し替えの後の書き込み、本文を持たない項目の検索）。このリポジトリに E2E は無い |

`未確定`: 不具合 1 の修正方法（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | MindStella の項目の共通のキー（`common.schema.json`）に、任意の文字列の `created`・`updated` を追加する | MindStella だけで完結し、project-index のリリースを待たない | 作成・更新の日時を `history.yaml` と項目の両方に持つ |
| B | project-index に、配信元の設定で日時の追加を止めるキーを追加する | 項目のスキーマが変わらない | project-index への起票と依存が要り、着手が遅れる |

推奨: A

利用者が超最優先と指定しており、記録を 1 件も書き込めない状態を MindStella だけで解消できる。

`未確定`: 不具合 3 の修正方法（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | project-index で、`records` の要素が `body_file` の値を持たないとき、除かずに要素の YAML を本文として配信する | 本文を持たない項目という今の記録の構造のまま参照できる。project-index の `_build` は本文の無い `records` の要素を既に想定している | project-index への起票と依存が要る |
| B | MindStella が全ての項目に本文のファイルを作成する（作成と移し替えの手順で） | MindStella だけで完結する | 本文を持たない用語集・メモにも空のファイルが並び、記録の構造が変わる |

推奨: A

本文を持たない項目は MindStella の記録の正しい構造で、配信の側で扱うのが筋になる。
A に決めたら、着手した planner が project-index へ起票し、この作業 PR の依存に加える。

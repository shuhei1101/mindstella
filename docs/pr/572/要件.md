要件として次を満たす。

| 対象 | 要件 |
| --- | --- |
| 配信元の追加（#554） | `POST /settings/sources` に、`GET /settings/sources` で引いた `version` を `expectedVersion` として送信する。バージョンが更新前（409）のときは、`patch_source` と同じく 1 回だけ再取得して再送信する |
| 配信元の追加のテスト（#554） | 配信元の行が無い状態からワークスペースを作る結合テストを追加し、project-index の Mock が `expectedVersion` の無い追加を 400 で拒否する |
| フォルダを移したとき（#554） | 移した先を開いたときに、前の ID の配信元の行が端末の設定に残り続けない |
| アカウントの指定（#556） | 依頼に `claude_config_dir` があり claude-balancer がある端末では、`claude-balancer exec --client mindstella --account {claude_config_dir} -- claude …` で起動する。指定が無いときは今と同じく `--account` を付けない |
| 借りられないとき（#556） | 指定したアカウントを借りられないときと、claude-balancer の設定にそのアカウントが無いときは、指定と違うアカウントで起動しない |
| 起動したアカウントの表示（#556） | 起動のコマンドの出力に、MindStella のセッションを起動したアカウントを表示する |
| 前のバージョンの形式の判定（#561） | `status="完了"` の検討事項の問題を前のバージョンの形式と判定しない。`is_legacy_problem` とモジュール構成『store.py』の記載を一致させる |

`未確定`: フォルダを移したときの前の ID の配信元の行の扱い（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ワークスペースの ID を記録の設定の `id` から読み、移した先を開いたら同じ ID の配信元の行のフォルダを移した先のパスへ変更する | ID と状態（`session.json` など）が移した後も同じで、前の行が残らない | #544・#525 の「ID をフォルダのパスから作る」前提が変わる |
| B | ID はフォルダのパスから作り直し、移した先を開いたら、同じ記録の前の ID の配信元の行と状態を削除する | ID の作り方を変えない | 前の ID の状態が削除され、移す前と後で別のワークスペースになる |

推奨: A

記録の設定は既に `id` を持ち（`workspace_id_of`）、移した後も同じワークスペースとして扱えるため。

`未確定`: 指定したアカウントを借りられないときの通知の方法（決める工程: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 起動を止め、503（`stage: account`）で claude-balancer が出力した理由を返却し、起動のコマンドはその理由を表示して終了コード 1 で止まる | 指定と違うアカウントで動かない | 指定したアカウントが空くまで使えない |
| B | claude-balancer が選んだほかのアカウントで起動し、指定と違うアカウントで起動したことを出力に表示する | すぐに使える | 指定したアカウントの利用枠を守れない |

推奨: A

今の 503（`stage: account`）の経路をそのまま使用でき、指定したアカウントを使用する意図から外れないため。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信元の追加（#554） | `add_source` は `get_settings` で `version` を取得し、`{"source": row, "expectedVersion": version}` を送信する。409 のうち `result: exists` でないもの（バージョンの不一致）は 1 回だけ再取得して再送信する | 外部 API『project-index の端末の設定の API と読み取り API』の `expectedVersion` を必須に修正する |
| フォルダを移したとき（#554） | 移した先を開いたときの前の ID の配信元の行の扱いを、要件の案 A・B から決める | `未確定`（決める工程: インターフェース定義設計）。案と推奨は[要件](./要件.md) |
| アカウントの指定（#556） | `build_command` に `claude_config_dir` を追加し、claude-balancer があり指定があるときは `exec --client mindstella --account {claude_config_dir} --` にする。`--account` は claude-balancer の設定のアカウント名か `config_dir` のパスを受ける | `build_env` の `CLAUDE_CONFIG_DIR` は claude-balancer が無いときだけのまま |
| 借りられないとき（#556） | 指定したアカウントを借りられない・設定に無いときの扱いを、要件の案 A・B から決める | `未確定`（決める工程: 単一ユースケース設計）。案と推奨は[要件](./要件.md) |
| 起動したアカウントの表示（#556） | MindStella のセッションの作成の応答に起動したアカウントを持たせ、起動のコマンドがその値を出力に表示する | アカウントの取得方法（`session.json` の設定のフォルダか claude-balancer の環境変数か）はインターフェース定義設計で決める |
| 前のバージョンの形式の判定（#561） | `is_legacy_problem` とテストの期待値のどちらが誤りかをモジュール構成『store.py』で照合し、誤っている側を修正する | 設計書の記載と食い違えば設計書も修正する |
| 既存機能への影響 | 指定が無い起動・claude-balancer が無い端末の起動は今と同じ | - |
| 外部ライブラリ | claude-balancer は `exec --account` を持つバージョン（develop の 353d665a 以降）が要る | タグは [shuhei1101/claude-balancer#358](https://github.com/shuhei1101/claude-balancer/issues/358) で待つ |

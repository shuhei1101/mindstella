## 変更方針

4 件とも、負荷の無い端末で単独に実行すると pass し、次の順序を強制すると fail することで原因を確認した。

<!-- table: data -->

| 対象 | 原因 | 方針 | 補足 |
| --- | --- | --- | --- |
| `test_body_scroll_restored`・`test_body_scroll_when_heading` | 画面は外部の Web フォント（Google Fonts）を読む。本文のスクロールの位置を決めた後にフォントが届くと本文の高さが変わり、ブラウザのスクロールの位置の補正で位置が 900 からずれ、ずれた位置が `sessionStorage` に記載される（フォントの CSS を 1 秒遅らせると、読み込み直した後の位置が 899 になる） | 位置を数で比べるテストでは Web フォントの要求を中断し、代わりのフォントで描かせる（`block_web_fonts`） | テストの側。同じ比べ方の `test_body_scroll_when_comment_location` にも適用する |
| `test_voice_input_when_service_stopped` | 「音声で入力」は操作の待ちを省いて（`force=True`）押すため、詳細パネルのすべり込み（0.45 秒の transition）の途中で押すとボタンが画面の外にある（すべり込みを 4 秒にすると毎回 fail する） | ボタンが画面に収まり、パネルのアニメーションが終わるのを待ってから押す（`assert_mic_blocked_after_click`） | テストの側。同じ関数を使う他の画面のテストにも効く |
| `test_reason_input` | `thread-view.tsx` の `closeReason` が、理由の入力を閉じる描き直しを待たずに `requestAnimationFrame` で「状態を変える」へフォーカスを移す。描き直しより先に次のコマが来るとボタンがまだ無く、フォーカスが失われる（`requestAnimationFrame` をマイクロタスクで走らせると毎回 fail する） | フォーカスを戻す印を立て、描き直した「状態を変える」のボタンの ref で印を見てフォーカスを移す | 画面の側。単体テスト `thread_view_when_close_focus` を追加した |

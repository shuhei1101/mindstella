# 要件

## 要望

外部のアプリと端末の起動のコマンドが、MindStella の API でワークスペースの設定を書き換えられるようにする（資料 A-119 の「MindStella の API」の表の「設定の書き換え」、資料 A-107 の No 9、検討事項 D-324）。
MindStella の MCP にも同じ処理を呼ぶツールを持たせる。

| 書き換えるもの | 記録する先 | 読めない指定のエラー |
| --- | --- | --- |
| 進め方の文書（`flow`） | ワークスペースの設定（`.mindstella/config.yaml`） | 『ワークスペースの作成』と同じ確認の方法で、文書を参照できなければ何も記録せずにエラーを返却する |
| 追加の MCP（`mcp_config`） | 状態のフォルダの `launch.json` | 『ワークスペースの作成』と同じ確認の方法で、読めなければ何も記録せずにエラーを返却する |
| プラグイン（`plugin_dirs`） | 状態のフォルダの `launch.json` | 同上 |

- 書き換えは、起動中の MindStella のセッションには反映しない。次に起動する・起動し直す MindStella のセッションから有効になる
- 起動中の MindStella のセッションに反映するときは、外部のアプリが既存の起動し直し（`POST /workspaces/{id}/sessions/{session}/restart`）を依頼する。起動し直しは、起動のたびに設定の進め方の文書と `launch.json` を参照し直す
- 指定しなかったキーは書き換えない。状態のフォルダに `launch.json` が無いワークスペースは、指定した値で記録を作る（作成の応答が指定を記録しなかったと示したときの指定し直し。D-341）
- クローズしたワークスペースも書き換えを受ける（状態のフォルダの記録はクローズで残るので、開き直した後の MindStella のセッションの作成から有効になる）。状態のフォルダの ID の一覧に無い ID は、ワークスペースが無いエラーにする。エラーの値（`stage` など）はインターフェース定義設計で決める
- 書き換えは、同じワークスペースの MindStella のセッションの作成・起動し直し・クローズと同じ順番で処理する（資料 A-119 の「ワークスペースごとに 1 つの順番を共有して依頼を処理する」）

`PATCH` は、進め方の文書・追加の MCP・プラグインに加えて、題名など設定のキー（既存の MCP の `update_settings` が記録するキー）も `settings` で受ける（インターフェース定義設計で案 A に決定。資料 A-119 の表の「題名などワークスペースの設定のキー」に合わせ、`update_settings` と同じ確認と置き換えの関数を使用する）。

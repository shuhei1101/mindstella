## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ユースケース | 単一ユースケース『ワークスペースの設定を書き換えて起動し直す』を資料 A-107 の No 9・資料 A-119・検討事項 D-324 の流れで新規作成し、『外部のアプリから起動する』『ワークスペースとMindStella のセッションの状態を取得する』の指定し直しから関連を張る | 起動し直しは既存の『MindStella のセッションを起動し直す』を使用する |
| 設定の書き換え | `PATCH /workspaces/{id}` と MCP のツールを追加する。`flow` は `config.yaml` に、`mcp_config`・`plugin_dirs` は `launch.json` に記録する。指定しなかったキーは残す | 受けるキーの範囲は `未確定`（要件.md）。起動中の MindStella のセッションには何もしない |
| バリデーション | `flow`・`mcp_config`・`plugin_dirs` を『ワークスペースの作成』と同じ関数で確認し、1 つでも読めなければ何も記録しない | 作成と同じ 422 と `stage` |
| エラー返却 | ID の一覧に無い ID は、ワークスペースが無いエラー（開き直し・削除と同じく 404・`stage` が `workspace` の見込み）。クローズしたワークスペースは受ける | エラーの値はインターフェース定義設計で決める。開き直し・削除と同じ problem+json |
| 排他 | ワークスペースごとの順番の中で処理する | 起動し直しが `launch.json` を参照する前後と重ならない |
| 公開ドキュメント | コマンドのリファレンスに `PATCH /workspaces/{id}` と MCP のツールを追加し、反映は起動し直しで行うことを記載する | - |

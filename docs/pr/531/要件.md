# 要件

## 要望

端末に 1 つの常駐サーバーと、ワークスペースと MindStella のセッションの作成・停止とクローズの API を作る（資料 A-107 の No 1。構成・API・フックは資料 A-119・A-106、シナリオは資料 A-115・A-116 に従う）。

| 要件 | 終わりの条件 |
| --- | --- |
| 常駐サーバー | 端末に 1 つの常駐サーバーを systemd --user で起動・停止でき、MindStella のセッションが落ちても常駐サーバーは止まらない |
| 古いコードの検出 | 常駐サーバーが読み込んだプラグインのフォルダ（コミットの SHA の名前）と、インストール済みのプラグインのフォルダが違うとき、起動の確認（SessionStart のフック・起動のコマンド）が、違いと再起動の手順を出す。バージョンの文字列が同じでも出す。並行するほかのセッションが使っているため、自動では再起動しない |
| ワークスペースの作成（`POST /workspaces`） | 許可するフォルダの下だけに作り、記録・設定の進め方の文書・状態のフォルダの追加の MCP とプラグイン・project-index の配信元の行・状態のフォルダのワークスペースの ID の一覧を揃えて、ワークスペースの ID と画面の URL を返す。記録が既にあるフォルダ・開いているワークスペース・クローズしたワークスペースのフォルダは A-115 の正常シナリオのとおりに開く（D-283・D-321・D-341）。許可するフォルダの外・読めない追加の MCP の定義・見つからないプラグイン・参照できない進め方の文書・配信元の登録の失敗は、記録も配信元の行も状態のフォルダの記録も残さずにエラーを返す |
| MindStella のセッションの作成（`POST /workspaces/{id}/sessions`） | tmux のペインの中で `claude-balancer exec` で Claude Code を起動し（claude-balancer が無い端末では既定のアカウント）、SessionStart のフックが状態に登録してから、MindStella のセッションの ID と画面の URL を返す。1 つのワークスペースに 1 つだけで、既にあるとき・クローズしたワークスペースは断る。空いたアカウントが無い・上限の時間までに準備ができないときは、ペインを閉じ、ワークスペースは開いたまま残してエラーを返す |
| MindStella のセッションの停止（`DELETE /workspaces/{id}/sessions/{session}`） | すぐに受け付けて返し、状態をクローズ待ちにし、応答の途中なら終わるまで待ってから止める。強制の指定では待たない。落ちていたときと強制で止めたときは、まとめていない変更を理由を添えて commit する。待つ上限を過ぎたら止めずに、待っている書き込みがあることを状態に記録する |
| MindStella のセッションの一覧（`GET /workspaces/{id}/sessions`） | 最後の MindStella のセッションの ID・状態（起動中・停止の途中・停止済み・落ちている）・応答の途中か・待っている書き込みがあるかを返し、停止の完了を確かめられる |
| ワークスペースのクローズ（`POST /workspaces/{id}/close`） | MindStella のセッションが無いとき（落ちたものを含む）だけ受け、配信元の行を `outside_read: false` にする。記録と状態のフォルダの追加の MCP・プラグインの記録は残す。クローズ待ちとクローズの後に届いたコメントはスレッドに残し、MindStella のセッションを起動しない |
| 依頼の順番 | ワークスペースの管理とセッションの管理は、ワークスペースごとに 1 つの順番を共有する（クローズと作成が同時に届いても、片方が終わってからもう片方を判定する） |
| 受ける Host | API と `/mcp` は `Host` が `127.0.0.1:{ポート}`・`localhost:{ポート}` の要求だけを受ける（D-304・D-340） |
| MCP のツール | MindStella の MCP に、上の API と同じ操作のツール（`create_workspace`・`create_session`・`sessions`・`stop_session`・`close_workspace`）を持たせる |
| フック | MindStella のセッションでだけ、SessionStart で状態に登録し進め方の文書の場所を注入し、SessionEnd で停止済みを、UserPromptSubmit・Stop・StopFailure で応答の始まりと終わりを状態に記録する。MindStella のセッションは、セッションの管理が起動のときに渡す環境変数で見分ける |
| 起動のコマンド | 端末の起動のコマンドが、常駐サーバーが立っていなければ起動し、同じ MindStella の API でワークスペース（進め方の文書・追加の MCP・プラグインを引数で指定）と MindStella のセッションを作る |

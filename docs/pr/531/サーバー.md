## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 常駐サーバーの起動 | systemd --user のユニットで常駐サーバーを 1 つ起動・停止する。起動の確認（SessionStart のフック・起動のコマンド）は、落ちていればユニットを起動する | ユニットの置き場所と入れ方（プラグインのインストールの後に誰が入れるか）は、インターフェース定義設計で決める |
| 古いコードの検出 | `GET /_admin/status` に常駐サーバーが読み込んだプラグインのフォルダを加え、起動の確認がインストール済みのプラグインのフォルダの名前と比べる。違えば違いと再起動の手順を出し、自動では再起動しない | Claude Code のプロファイル（`~/.claude`・`~/.claude-sub5` など）ごとにフォルダのパスが違うので、末尾のフォルダ名（コミットの SHA）で比べる。プロファイルごとに別のコミットを指すときの扱いはインターフェース定義設計で決める |
| MindStella の API | 常駐サーバーの同じポートに、`POST /workspaces`・`POST /workspaces/{id}/sessions`・`GET /workspaces/{id}/sessions`・`DELETE /workspaces/{id}/sessions/{session}`・`POST /workspaces/{id}/close` を足す。`Host` が `127.0.0.1`・`localhost` の要求だけを受ける | キーの名前と書式、エラーの形はインターフェース定義設計で決める |
| ワークスペースの管理 | 記録の作成・設定の進め方の文書・クローズを受け持ち、project-index の行の単位の API で配信元の行を登録・`outside_read: false` に変更する。状態のフォルダにワークスペースの ID の一覧を持つ | ワークスペースの ID は作成のときに MindStella が決めて設定に記録し、配信元の行の `id` にする |
| セッションの管理 | tmux のペインの中で `claude-balancer exec` で Claude Code を起動・停止し、状態のフォルダ（`~/.local/state/mindstella/`）に MindStella のセッションの ID・Claude Code の `session_id`・tmux のペイン・応答の途中か・クローズ待ちか・追加の MCP・プラグインを持つ。起動では `--mcp-config`・`--plugin-dir`・MindStella のセッションを見分ける環境変数・進め方の文書の場所の環境変数を渡す | 準備ができたかは SessionStart のフックの登録で判定する。待つ上限の値は規約『資源の値の決め方』で導く |
| 依頼の順番 | ワークスペースごとに 1 つの鍵を、ワークスペースの管理とセッションの管理で共有する。ワークスペースの作成はフォルダごと、ID の一覧の書き込みは全体で 1 つの鍵にする | - |
| コメントの通知 | 届いたコメントの貼り付けの宛先を、状態の MindStella のセッションのペインにする。クローズ待ち・クローズの後はスレッドに残すだけにする | MindStella のセッションが無いときの起動し直しは #520 |
| 起動のコマンド | `bin/mindstella` を、常駐サーバーを起動の確認で立ててから、MindStella の API でワークスペースと MindStella のセッションを作り、作った tmux のペインにつなぐコマンドにする。進め方の文書・追加の MCP・プラグインを引数で受ける | 引数の名前はインターフェース定義設計で決める |
| MCP のツール | `create_workspace`・`create_session`・`sessions`・`stop_session`・`close_workspace` を足し、API と同じ処理を呼ぶ | 既存の `init` は `create_workspace` に置き換え、`server_status`・`server_stop` は起動のコマンド（systemd --user）へ移す（A-107 のツールの行き先）。消すかは単一ユースケース設計で決める |
| 既存機能への影響 | 画面の配信はワークスペースごとのポートのまま。作成が返す画面の URL はその配信の URL にする | 1 つのポートへの切り替えはスコープ外（レビューで確定） |

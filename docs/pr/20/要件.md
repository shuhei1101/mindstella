# 要件

## 要望

利用者が Claude Code で話し合いながら、決め事・派生する問い・調べもの・資料をワークスペースに記録し、ゴールまで進められるスキルをプラグイン mindmap に同梱する。
ワークスペースへの記録は、[#11](https://github.com/shuhei1101/mindmap/pull/11) のスクリプトのコマンドを呼んで行う。

### スキルの分け方と形

- セットアップのスキルと話し合いを進めるスキルを分ける。セットアップは `setup`（`/mindmap:setup`）、話し合いを進めるスキルは `session`（`/mindmap:session`）で呼ぶ
- セットアップと話し合いの開始は引数で振り分けない（Issue の「引数なし・`config`・`setup` ならセットアップのモード」は、スキルの分割に置き換わった）
- 各スキルは `SKILL.md`（入力・ステップの表・コマンドと引数の一覧。ステップからはコマンド名で呼ぶ）を薄く保ち、場面ごとの手順を `steps/` に置く
- 2 つのスキルが共通で読む `references/`（質問の書式・文章の書き方・リサーチの調べ方）・`playbooks/`（分野ごとの進め方ガイド）・`README.md` は、既存の `schemas/`・`scripts/`・`preview/` と同じ `skills/mindmap/`（SKILL.md を持たない）に置く
- `README.md` に、はじめに・コアコンセプト・ユースケース（分野）・依存とインストール（マーケットプレイスの登録とプラグインのインストールのコマンド）・使い方を書く
- 他のスキルに依存しない。調べ方の中身は `references/` に写し、サブエージェントに渡す。スキルの中で AI Monitor の名前を出さない
- hooks を使わない。編集したら最後に `build` を流すことを手順に書く

### ステップ

| ステップ | 満たすこと |
| --- | --- |
| セットアップ | `check-env` で依存を確かめ、足りなければそろえるコマンドを示して止める。ワークスペースのフォルダが無ければ指定を求める。新規なら分野・最上位の軸の呼び名・フェーズ・カテゴリー・ゴールを決めて `init` する。既存なら `status` を流し、要見直し・進行中・再開可能・次の候補を出して続きを推奨する（利用者が話題を言っていればそこから） |
| 取り込み | 発言を対象・カテゴリー・フェーズに振り分けて記録する。決まったら進め方ガイドの観点と照らして派生の検討事項・未整理・タスクを積む。保留・解除・中止もここで行う。図や文書を出したら資料に残す。会話ログを書き足す |
| ヒアリング | 前提が揃った未決定（`next`）を選び、1 ラウンドにまとめて聞く |
| リサーチ | 「何を・どの観点で・何体で」を出して確認を取ってからサブエージェントを起動し、結果を調査に書いて検討事項に繋ぐ（利用者が自分から頼んだときは確認を省く） |
| 方針転換 | 採用する案を切り替え（`adopt`）、依存をたどって（`impact`）要見直しにし、見直しのタスクを積む。本文は今の正だけに直す。スコープが変わって成果物が要らなくなったら、その資料の `deliverable` を外して資料へ格下げする |
| プレビュー | `build` で書き出して開く |
| ゴール判定 | ゴールに届いていれば検討事項と成果物を見せて確定をもらい、`handoff/` に書き出す |

### 軸と進め方ガイド

- 記録の軸は 対象 > カテゴリー > フェーズ > 検討事項 の 4 段。細かいものは派生（`parent`）・依存・タグで表す
- 最上位の軸の呼び名は進め方ガイドが決める（システム開発: システム / 調査: 調査対象 / 資料作り: 資料 / 壁打ち: テーマ）
- 進め方ガイドは、フェーズの並び・フェーズごとの観点・必ず調べるもの・ゴールの候補・引き渡しの形を持つ。最初に作るのはシステム開発と調査の 2 つ
- システム開発: 目的 → 要件 → 構成 → インターフェース → コンテンツ。ゴールの候補は 要件まで / インターフェースまで（既定）/ モジュール構成まで
- 調査: 問い → 観点 → 事実 → 評価 → 結論

### 聞き方・調べ方・書き方

- 質問の書式: タイトル → 冒頭の文 → 選択肢があるときだけ案の表（案・内容・メリット・デメリット・備考）と推奨（記号＋理由）。選択肢が無い論点はたたき台を出す
- ヒアリングは前提が揃った問いを 1 ラウンドにまとめ、答えが他の問いに左右される問いは次のラウンドへ回す。事実は自分で調べ、決めることだけを聞く
- 用語集を会話の中で育て、ずれた言い方をその場で正す
- 外部ライブラリ・外部 API を決めるときは、ベストプラクティスと候補の調査を必ず積む
- 脱線した質問は、言葉は用語集、それ以外はメモに残し、タスクにはしない
- 文章の書き方は AI Monitor の規約『文章の追記』を写して改名し、語の選び方のうち文章全般に効くもの（呼び名の固定・造語を作らない・定番の操作語・値に軸の名前を添える）だけを足す
- 調べ方（公式の資料 / 実践者の知見 / 技術の選定）の写し元は、ローカルの `knowledge-intake`・`craft-intake` と AI Monitor の `tech-research`

### 設計書

- Claude Code のスキル・プラグイン・マーケットプレイスの仕組みを、外部ライブラリの設計書に書く（[#10](https://github.com/shuhei1101/mindmap/issues/10) でユーザーが依頼）

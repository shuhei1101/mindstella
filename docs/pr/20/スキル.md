結論: 成立。
1 つのプラグインに SKILL.md を持つフォルダを並べれば `mindmap:{フォルダ名}` で呼べ、SKILL.md の無い `skills/mindmap/` は共通の置き場所として残せる。
共通のファイルとスクリプトは、両方のスキルから `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/...` で指せる（作業ツリーでもインストールした形でも同じ書き方で通る）。
利用者の既定のモードでは、プラグインのフォルダが作業フォルダの外にあるため Read と Bash の両方に確認が要る。
スキルの front matter の `allowed-tools` で許すと確認は 0 件になり、その許可はスキルが起動したサブエージェントの Read・WebSearch・WebFetch にも及ぶ。
設計では、各スキルの `allowed-tools` に使うツールを並べ、Bash はスクリプトの起動だけに絞る（`Bash(python3 ${CLAUDE_PLUGIN_ROOT}/skills/mindmap/scripts/mindmap.py:*)` の 1 行）。
この 1 行で全コマンドを許すため、`mindmap.py` は `python3` で起動されると、`check-env` 以外のコマンドをスキル専用の仮想環境の Python で起動し直す形に変える（[スクリプト](./スクリプト.md)）。
`python3:*` は `python3 -c` まで許すため使わない。

最小再現の要点（[#22](https://github.com/shuhei1101/mindmap/pull/22) の `skills/setup-allowed/SKILL.md`・`skills/poc-session-allowed/SKILL.md`・`poc/run.sh`）:

```markdown
---
name: setup-allowed
allowed-tools: Read, Bash(python3:*)
---
PLUGIN_ROOT=${CLAUDE_PLUGIN_ROOT}
2. Read ツールで `${CLAUDE_PLUGIN_ROOT}/skills/mindmap/references/marker.md` を読む
3. Bash ツールで `python3 ${CLAUDE_PLUGIN_ROOT}/skills/mindmap/scripts/mindmap.py check-env` を実行する
```

```bash
claude -p "/mindmap:setup-allowed" --plugin-dir "$INSTALL_PATH" \
  --setting-sources project,local --permission-mode default --output-format stream-json --verbose
```

diff の見どころは、同じ本文で `allowed-tools` の有無だけを変えた `setup` / `setup-allowed`・`poc-session` / `poc-session-allowed` の組と、各ケースの判定に使った欄をまとめた `poc/results-summary.jsonl`。

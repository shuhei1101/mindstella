# 要件

## 要望

ワークスペースの記録を、配るための 1 枚の HTML（以下、配る書き出し）に書き出すコマンドを足す。
配る書き出しは、記録のデータ・画面の CSS・JavaScript・描画のライブラリ（marked・DOMPurify・elkjs・mermaid）を全て中に持ち、`<script>`・`<link>`・`<img>` の `src`・`href` に外のファイルや URL を持たない。
ネットにつながらない端末のブラウザで開いても、本文の Markdown・mermaid の図・検討事項のマップ・つながりを描き、読めなかったライブラリの知らせを出さない。

配る書き出しは見るだけの画面にする。
項目の追加・編集・削除、回答・コメントの送信、設定の保存など、ワークスペースへ書き込む操作は出さない（今のプレビューは書き込む操作を持たない）。
見るための操作（タブ・表示形式の切り替え・絞り込み・検索・詳細パネル・つながりの回転と拡大・ライトとダーク）は `build` の `preview.html` と同じに残す。

配る書き出しは、中に持つライブラリごとに名前・版・著作権の表示・ライセンスの名前と本文を持つ。
elkjs は EPL-2.0 を選び、ソースコードの入手先（リポジトリと版のタグの URL）も持つ。
DOMPurify は Apache-2.0 を選ぶ。
mermaid の配布ファイルが中に束ねた依存（d3・cytoscape・katex など）も、依存ごとに名前・版とライセンスの本文を持つ。

今の `build` が書き出す `preview.html` は変えない（描画のライブラリは jsDelivr から読むまま）。

書き出しの入口は新しいコマンド `export` にし、`--workspace` と書き出す先のパス `--out`（必須）を受ける（インターフェース定義『配る書き出し』）。
[#13](https://github.com/shuhei1101/mindmap/issues/13) で `build` を無くしても、配る書き出しはそのまま残る。
書き出す先は既定を持たない。ワークスペースの `release/` は `clear-release` が中身を消すため、既定の置き場所にしない。

ライブラリの配布ファイルとライセンスの本文は、`export` が書き出すときに jsDelivr から取る（リポジトリには同梱しない）。
書き出す側は Claude Code が動く端末でネットにつながっている。
取る URL と版は `template.html` の `<script src>` に揃え、配布ファイルは同じ `integrity`（sha384）と突き合わせる。
1 回の要求で接続と 1 回の読み取りをそれぞれ 30 秒まで待ち、取れなければ何も書かずにエラーで終える。
開く側は書き出した HTML だけで足り、通信しない。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 文字（Inter・Noto Sans JP・JetBrains Mono）の埋め込み | 要望が中に持つと挙げるのは描画のライブラリだけ。ネットにつながらないと端末の文字で描くが、読める。Noto Sans JP は数 MB あり、配る書き出しが大きくなる | 予定なし |
| `build` の `preview.html` へのライブラリの埋め込み | 要望は配る用途に限る。`build` の書き出しは記録を書くたびに作り直すため、小さいままにする | 予定なし |
| 書き込む操作を足すときの、配る書き出しでの出し分け | 今のプレビューは書き込む操作を持たない。書き込む操作を足す Issue の本文に、配る書き出しで出さない約束が入っている | [#16](https://github.com/shuhei1101/mindmap/issues/16) |
| サーバーで使うときの書き出しの廃止 | 別の Issue が扱う。配る書き出しは残す約束が本文に入っている | [#13](https://github.com/shuhei1101/mindmap/issues/13) |

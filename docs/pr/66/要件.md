# 要件

## 要望

プラグインの版を上げた利用者が、作ったワークスペースを、記録した版から今のプラグインの版まで、版ごとの手順を順に当てて移し替えられるようにする。
途中で失敗しても、ワークスペースは移し替える前の中身に戻る。

### 版の記録

- ワークスペースの直下に `mindstella-version.ini` を置き、1 行目に版（`v{メジャー}.{マイナー}.{パッチ}`。例 `v0.3.0`）を書く
- 書くのは、最後に整えたときのプラグインの版。`init` で作るときに書き、移し替えるたびに書き換える
- 版のファイルが無いワークスペースは、版を記録する前の形式として扱う
- ワークスペースの形を変える PR は、`migrations/{次の版}/` を足すのと同じ PR で、プラグインの版もその版へ上げる。次の版は計画の現在の Sprint の版で、この PR では `v0.3.0`。開発中も `init` が書く版・`migrate` が当てる手順・E2E が同じ版で揃う

- プラグインの版は `plugins/mindstella/version.ini` の 1 行目に持つ。インターフェース定義『プラグインの読み込み』の「`version` は持たない」を保ち、上げ忘れても狂うのは版の比較だけにとどめる

### 移し替えの手順

- 手順はプラグインが持ち、ワークスペースの形式を変えた版ごとに `plugins/mindstella/skills/mindmap/migrations/{版}/` を足す。フォルダの直下に `steps.yaml`、`call` で呼ぶ変換のスクリプトは `scripts/` に置く
- `steps.yaml` には 1 つ前の版からの操作を並べる。操作は `rename_file`・`move_dir`・`delete`（この 3 つが破壊的）と `rename_key`・`set_default`・`map_values`・`call` に限り、スキーマで点検する
- 今の `migrate` の中身（資料の `done` → `status`、設定に `summary` を足す）は、「版を記録する前の形式 → `v0.3.0`」の手順に移す。`summary` のように値が要るものは、機械的な手順の後の点検で利用者に聞く

### コマンド

- `migrate --from {版} --to {版}` で、`from` より後で `to` 以下の版の手順を版の順に当てる
- `--plan` を付けると当てずに、当てる手順を版の順に並べて返す。破壊的な操作に印を付ける
- MCP へ移るとき（[#13](https://github.com/shuhei1101/mindstella/issues/13)）も同じ入出力にする

### 移し替えのスキル

利用者が呼ぶ新しいスキル `upgrade`（`/mindstella:upgrade`）で、次の順に進める。

1. ワークスペースの版とプラグインの版を比べる
2. 当てる手順の一覧を見せる
3. 写しを取る（git の管理下ならコミット、そうでなければフォルダごと複製）
4. 破壊的な操作を含むときは、当てる前に確かめる
5. 機械的な手順を当てる
6. 今のスキーマで点検し、値が要るものだけ聞く
7. 版を書き換える

途中で失敗したら、写しから自動で元に戻し、どの手順で何が失敗したかを示す。

写しを取って戻すのは `migrate` が行い、スキルの `allowed-tools` は広げない。

### 話し合いを始めるとき

- セットアップのスキル（既存のワークスペース）と、話し合いを進めるスキルの準備で、ワークスペースの版とプラグインの版を比べる
- ワークスペースの版が古ければ、移し替えのスキルを案内する（勝手には当てない）
- 新しければ止めて、プラグインの更新を案内する

### 開発側の点検

- 最新のタグのスキーマと今のスキーマを比べ、変わっているのに `migrations/` に「最新のタグより新しく、プラグインの版以下」の版の手順が無ければ、テストで落とす

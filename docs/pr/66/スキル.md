## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 移し替えのスキル | 要件.md の 7 つの手順をステップの表にし、各ステップはスクリプトのコマンドで行う。`allowed-tools` は `setup`・`session` と同じく `Read` と `mindmap.py` の起動だけにする | 呼び名は `upgrade`（`/mindstella:upgrade`）。写しを取って戻す担い手が案 B に決まったときだけ `allowed-tools` を足す |
| 破壊的な操作の確認 | `--plan` の出力で破壊的な印が付いた手順があるときだけ、手順を並べて当ててよいかを確かめる。ないときは確かめずに当てる | - |
| 値が要るものを聞く | 当てた後の点検で値が無いと分かったもの（版を記録する前の形式の `summary` など）だけを聞き、`update` か `migrate` の引数で入れる | どの引数で入れるかはインターフェース定義設計で決める |
| 失敗したとき | 写しから戻った後、どの版のどの手順で何が失敗したかを、コマンドの出力から示して止まる | - |
| 話し合いを始めるとき | `setup` の既存のワークスペースと `session` の準備で、ワークスペースの版とプラグインの版を比べる。古ければ `/mindstella:upgrade` を案内して止まり、新しければプラグインの更新を案内して止まる。同じなら今までどおり進む | 版を比べる手段は [スクリプト](./スクリプト.md) の `## 変更方針` の「版の比較」。古い形式のまま書き込めるかは版ごとに違い、スキルの手順として決められないため、古いときも止まる |
| 新しいワークスペース | 変えない（`init` が版のファイルを書く） | - |

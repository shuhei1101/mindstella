# 要件

## 要望

- 常駐サーバーが、MindStella のセッションの次の出来事を、利用者の Discord のチャンネルへ Webhook で通知する

  | 出来事 | 通知に記載する内容 |
  | --- | --- |
  | 1 回の作業を終えた（応答の間に、AI がスレッドに書き込んだか commit した） | ワークスペースの名前・何が起きたか・スレッドの要約か commit の説明・プレビューの URL |
  | 止まった（エラー・終了） | ワークスペースの名前・止まった理由 |

- 1 回の作業（1 回の応答）で届く通知は 1 件にまとめる
- 利用上限・無操作の上限で止まったときの呼び出しは [#520](https://github.com/shuhei1101/mindstella/issues/520)・[#521](https://github.com/shuhei1101/mindstella/issues/521) が追加する。この PR は、どの停止の理由からも呼べる通知の仕組みを作る
- 常駐サーバーは、利用者が用意した Webhook の設定のファイル（中身は Webhook の URL の 1 行）を参照する。ファイルの場所は環境変数で指定し、指定が無い・ファイルが無いときは通知しない
- Webhook の URL は、ログ・応答・リポジトリ・Issue・PR に記載しない
- 通知の送信に失敗しても、出来事の記録・スレッドの書き込み・commit は失敗させない

`未確定`: 通知する出来事の範囲（決める工程: 単一ユースケース設計。規約『ユーザー確認が必須な事項』の「ユーザーの目に触れる語彙を決める」に該当するため、通知の文面と一緒に利用者へ確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 応答の終わりに、その応答の間のスレッドの書き込みと commit をまとめて 1 件にする | 1 回の作業で 1 件だけ届く。返事を求めるスレッドも、記録の書き換えも知れる | 応答の間の出来事を常駐サーバーが溜める処理が要る |
| B | commit だけを通知する | 溜める処理が要らない | スレッドで返事を求めただけで commit しない作業は届かない |
| C | スレッドの書き込みだけを通知する | 返事を求められたときに必ず届く | 記録を書き換えただけの作業は届かない |

推奨: A

要望の「1 回の作業を終えた」は応答の終わりに該当し、応答の終わりはフックの出来事で常駐サーバーが受けている。
応答の終わりで 1 件にまとめれば、スレッドの書き込みと commit の両方を落とさずに、通知が何件も届かない。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 単一ユースケース | 単一ユースケース『作業の完了を通知する』を新規作成する | - |
| 通知 | 新規のモジュールに、Webhook の設定のファイルを参照して Discord の Webhook へ JSON を POST する関数を配置する。HTTP は標準ライブラリで送信する | 送信の失敗は標準エラーに記録して返却し、呼ぶ側を失敗させない。記録に URL を含めない |
| 1 回の作業の完了 | 応答の始まり（`prompt_submit`）から終了（`stop`）までに、AI がスレッドに書き込んだか commit したかを MindStella のセッションごとに記録し、終了で 1 件の通知を送信する。書き込みが無い応答は通知しない | `stop_failure` で終わった応答の記録は、次の応答の始まりで削除する |
| 通知の文面 | `{ワークスペースの名前}: 作業が完了しました` とプレビューの URL の 2 行。絵文字を使用しない | 利用者が確認した文面（SC-568-1 の `notes`） |
| 設定 | 環境変数で Webhook の設定のファイルの場所を受ける。指定が無い・ファイルが無い・URL の形でないときは通知しない | 環境変数の名前はインターフェース定義設計で決める |
| 非機能 | Webhook の送信を待つ上限は、応答の終了のフックの処理を止めないよう、規約『資源の値の決め方』で導く | 送信は出来事の受け取りの応答を返却した後に行う |
| 外部 API | 外部 API『Discord』（Webhook の実行）の設計書を作る | 使用する範囲は `content` の送信（2000 文字以内）と、429・失敗の応答の扱い。投稿されたことを確認するため `wait=true` で送信する |

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 単一ユースケース | 単一ユースケース『作業の完了と停止を通知する』を新規作成する。『MindStella のセッションを止めてワークスペースをクローズにする』に止まったときの通知を追記する | シナリオは単一ユースケース設計で作り、影響するユースケースに追加する |
| 通知 | 新規のモジュールに、Webhook の設定のファイルを参照して Discord の Webhook へ JSON を POST する関数を配置する。HTTP は標準ライブラリで送信する | 送信の失敗は標準エラーに記録して返却し、呼ぶ側を失敗させない。記録に URL を含めない |
| 1 回の作業の完了 | 応答の始まり（`prompt_submit`）から終了（`stop`・`stop_failure`）までに、AI がスレッドに書き込んだ・commit した出来事を MindStella のセッションごとに溜め、終了で 1 件にまとめて通知する。溜めた出来事が無い応答は通知しない | `未確定`（[要件](./要件.md) の通知する出来事の範囲） |
| 停止 | `session_end` で停止済みにしたとき（`reason` が `clear`・`resume` 以外）と、`stop_failure`（エラー）のときに、止まった理由を通知する | 利用上限・無操作の上限は #520・#521 が同じ関数を呼ぶ |
| 通知の文面 | ワークスペースの名前・何が起きたか・スレッドの要約か commit の説明・プレビューの URL を記載する | `未確定`。単一ユースケース設計で文面の案を利用者へ確認する |
| 設定 | 環境変数で Webhook の設定のファイルの場所を受ける。指定が無い・ファイルが無い・URL の形でないときは通知しない | 環境変数の名前はインターフェース定義設計で決める |
| 非機能 | Webhook の送信を待つ上限は、応答の終了のフックの処理を止めないよう、規約『資源の値の決め方』で導く | 送信は出来事の受け取りの応答を返却した後に行う |
| 外部 API | 外部 API『Discord』（Webhook の実行）の設計書を作る | 使用する範囲は `content` の送信と、429・失敗の応答の扱い |

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 単一ユースケース | 単一ユースケース『作業の完了を通知する』を新規作成する | - |
| 通知 | 新規のモジュールに、Webhook の設定のファイルを参照して Discord の Webhook へ JSON を POST する関数を配置する。HTTP は標準ライブラリで送信する | 送信の失敗は標準エラーに記録して返却し、呼ぶ側を失敗させない。記録に URL を含めない |
| 1 回の作業の完了 | MindStella のセッションが `commit`・`new_thread`・`reply` を呼んで成功したときに、そのセッションに書き込みのマーカーを付け、応答の終了（`stop`）でマーカーがあれば 1 件の通知を送信する。マーカーは `prompt_submit`・`stop`・`stop_failure`・`session_end` で解除する | 停止の工程・画面の保存が作るまとまりは通知の対象にしない |
| 通知の文面 | `{ワークスペースの名前}: 作業が完了しました` とプレビューの URL の 2 行。絵文字を使用しない | 利用者が確認した文面（SC-568-1 の `notes`） |
| 設定 | 環境変数 `MINDSTELLA_DISCORD_WEBHOOK_FILE` で Webhook の設定のファイルの場所を受ける。指定が無い・ファイルが無い・1 行目が `http://` か `https://` で始まらないときは通知しない | - |
| 非機能 | Webhook の送信を待つ上限は 10 秒（非機能要件『Webhook の送信を待つ上限』） | 送信は出来事の受け取りの応答を返却した後に別のスレッドで行う |
| 外部 API | 外部 API『Discord』（Webhook の実行）の設計書を新規作成する | 使用する範囲は `content` の送信（2000 文字以内）と、429・失敗の応答の扱い。投稿されたことを確認するため `wait=true` で送信する |

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設定のキー | ワークスペースの設定に `mdmark`（`version`: `latest` かタグ）を足し、スキーマで検査する。無いときは `latest` | 置き場所は `未確定`（要件.md） |
| 設定の更新 | `update_settings` で `mdmark` を置き換えられる。『設定の再読み込み』の後に開いた画面から効く | - |
| 配信 | 雛形の mdmark の `link`・import map の URL を、設定の版の jsDelivr の URL（`latest` は `@develop`）にして配る | - |
| 配る書き出し | 設定の版の `dist/index.css`・`dist/index.js`・`THIRD_PARTY_LICENSES.txt` を取り、中に持つ。mdmark の LICENSE は、取った版のリポジトリにあればそれを、無ければ同梱のファイルを使う | 中身の確かめは `未確定`（要件.md） |
| ワークスペースの移し替え | 次の版の `migrations/v{版}/steps.yaml` に、資料の Markdown のマーカーを JSON の記載へ、flow・sequence を map へ移す手順を足す（mdmark の変換を呼ぶ）。破壊的な手順として扱う | mdmark の変換の呼び方（CLI・スクリプト）は PoC 検証で確かめる |

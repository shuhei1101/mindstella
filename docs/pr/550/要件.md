# 要件

## 要望

プレビューの画面（サーバーが配る今の画面・React の画面）・Storybook・配る書き出し・資料の HTML のエクスポートが読む mdmark の版を、設定 1 か所で決める。
既定は latest で、mdmark の develop の最新を読む。

| 要件 | 終わりの条件 |
| --- | --- |
| 設定のキー | 後から引数を足せるオブジェクトのキー（例: `mdmark: {version: latest}`）で版を指定でき、無いときは `latest` として扱う。`latest` 以外はタグ（`v{数字}.{数字}.{数字}`）だけを受け、ほかの値はスキーマに合わないエラーにする |
| latest の指す先 | `latest` は mdmark の develop のブランチの先頭を指す（jsDelivr の `gh/shuhei1101/mdmark@develop`）。mdmark を上げても MindStella の変更とリリースが要らない |
| 画面の読み込み | 今の画面と React の画面が、設定の版の `dist/index.css`・`dist/index.js` を読む。読めなかったときは今と同じく、そのライブラリを使う箇所に名前を出して本文を原文で出す |
| 配る書き出し | `export` が設定の版の配布ファイルとライセンスの本文を取り、書き出した HTML は通信せずに開ける |
| Storybook | Storybook の画面が、雛形と同じ版の mdmark を読む |
| ワークスペースの移し替え | プラグインを上げた後の `upgrade` で、既存のワークスペースの資料のマーカーを JSON の記載へ、flow・sequence の図を map へ移す（[mdmark#534](https://github.com/shuhei1101/mdmark/issues/534) の変換）。移した後のワークスペースを latest の画面で開くと、図とマーカーが描かれる |
| 外部ライブラリの設計書と単体テスト | 外部ライブラリの設計書『mdmark』（`LIB-489-13`）の版・読み方・`used_in` と、mdmark の版を見る単体テストを、設定で版を決める作りに合わせる（#475・#483 から統合） |
| 切り替えの前の確認 | 既定を latest に切り替える前に、[mdmark#620](https://github.com/shuhei1101/mdmark/issues/620) で develop の最新を jsDelivr から読めることを確かめる |

決定（案 A。インターフェース定義設計の合格 `5f419879` で確定）: 設定を持つ場所（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ワークスペースの `config.yaml` に持つ（`display`・`preview` と同じ並び） | 資料の書き方（マーカー・図）と読む版がワークスペースごとに揃い、移し替えとも対応する。`update_settings` で書き換えられる | 端末の全てのワークスペースを一度に固定するには、ワークスペースごとに書く |
| B | 端末の設定（project-index と共有するグローバルの設定の `mindstella`）に持つ | 端末で 1 か所を書けば全てのワークスペースに効く | ワークスペースの資料の書き方と読む版がずれても気づけない |

推奨: A

移し替えで資料の書き方を変える単位がワークスペースなので、読む版も同じ単位で持つと、書き方と版が食い違わない。

決定（案 A。インターフェース定義設計の合格 `5f419879` で確定）: タグを指定したときの中身の確かめ方（決める段: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | latest もタグも `integrity` を付けずに読む | 版ごとのハッシュの一覧を持たずに済み、どのタグでも指定できる | CDN の中身を確かめない |
| B | タグのときだけ、配信のたびにサーバーが配布ファイルを取ってハッシュを計算し、`integrity` を付けて雛形へ入れる | タグのときは今と同じく中身を確かめる | 配信のたびに CDN へ通信し、通信できないと画面を開けない |

推奨: A

既定の latest は中身が変わるので確かめられず、タグのときだけ確かめても既定の読み方の安全性は変わらない。配る書き出しは取った中身を中に持つため、書き出した後は変わらない。

決定（案 A。利用者の 👍 で確定。確認ログ）: 話し合いの決定 D-441 の C（常駐サーバーが mdmark のファイルを配信し、CDN から読まない。[#481 に追記](https://github.com/shuhei1101/mindstella/issues/481#issuecomment-6832375901)）の扱い（決める段: インターフェース定義設計。D-441 を変えるので利用者に確認する）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | C を取り下げ、設定の版を jsDelivr から読む作りを続ける。#481 の追記を取り下げる旨をコメントする | 常駐サーバーが mdmark を取得・保持する仕組みが要らない | 画面を開くたびに CDN へ通信する（今と同じ） |
| B | C を残し、#481 で常駐サーバーが設定の版を取得して配信する（この PR は jsDelivr から読む） | CDN へ通信しない画面にできる | #481 で取得・キャッシュ・更新の仕組みを作る |

推奨: A

設定で版を指定でき、latest で最新に追従できれば、C が解こうとした「上げるたびに MindStella を変える」状態は無くなる。

決定（案 A。インターフェース定義設計の合格 `5f419879` で確定）: 変換が追加する map の種類（`map.kinds`・`map.lines`）をワークスペースが持つ場所（決める段: インターフェース定義設計。PoC No 7 で、`mount` の `config.map` に指定しないとノードの種類の札とアイコンが消えると分かった）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ワークスペースの `config.yaml` の mdmark のキーの中（`mdmark.map`）に持つ。移し替えは一時の `mdmark.config.yaml` を作って変換を呼び、書き足された `map` を `config.yaml` へ移して一時のファイルを消す | 設定がワークスペースの 1 ファイルにまとまり、`update_settings`・スキーマの検査と同じ経路で扱える | 移し替えの手順で mdmark の設定と `config.yaml` の間の写し替えが要る |
| B | ワークスペースの `.mindstella/mdmark.config.yaml` を置いたままにし、画面と配る書き出しがそれを読む | mdmark の CLI（`check`・`upgrade`）をそのまま当てられる | 設定のファイルが 2 つになり、版の指定と map の種類が別のファイルに分かれる |

推奨: A

画面が読む版と map の種類はどちらも「画面が mdmark へ渡す設定」で、版の置き場所（推奨 A）と同じファイルに持てば読み込む経路が 1 つで済む。

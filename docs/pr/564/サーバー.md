## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| テストの準備 | `_make_workspace_with_set` の項目の追加と `commit` を、ツールを呼ぶ常駐サーバー（fixture `call_tool`）とは別の常駐サーバーで行い、`call_tool` の常駐サーバーではワークスペースの配信を起動していない状態で準備を終える | 別の常駐サーバーは fixture `start_server` で起動する。`commit` が MindStella のセッションを求める条件を満たせない場合は、テスト作成の段で別の準備の方法を決めて計画書に追記する |
| 製品のコード | 変更しない | `PreviewRegistry.start` の振る舞いは IF-489-17 のとおり |
| インターフェース定義 | IF-489-17 の 2 フローの setup の `make_workspace` に、ツールを呼ぶ常駐サーバーでは配信を起動していないことを書き足す | - |

## テスト結果

### ドキュメント修正

インターフェース定義『プレビューの URL』（`docs/interface/IF-489-17.yaml`）の 2 フローの setup の説明の書き足しだけで、期待値と製品のコードは変えないため、関係する単体・結合テストはなし。結合テスト `test_preview_url.py` の直しと実行は結合テスト作成の工程で行う。

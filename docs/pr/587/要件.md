# 要件

## 要望

動画・画像・音声などのファイルをワークスペースのファイルのフォルダに配置し、資料の本文に mdmark の `![キャプション](パス)` で埋め込むと、サーバーが配る画面（今の画面と React の画面）の詳細パネル・詳細の全画面で、動画・音声を再生でき、画像を表示できる。

| 項目 | 値 |
| --- | --- |
| 配置する人 | MindStella のセッション（動画作成ノードなど）と利用者 |
| 埋め込みの記法 | mdmark の `![キャプション](パス)`。動画・音声の再生バーとキャプションは mdmark@v0.10.0 の部品『動画と音声』が描く |
| 画面での確認 | ファイルのフォルダに置いた mp4 を資料に埋め込み、詳細パネルで開くと再生バーが出て再生できる。ファイルが無いときは、どのファイルが無いかが分かる |
| 点検 | 資料の本文が埋め込んだファイルがワークスペースに無いことを、ワークスペースの点検が参照切れとして返却する |
| 変更の検知 | ファイルのフォルダへの配置・差し替え・削除を、項目の変更として記録しない |
| 配信の範囲 | ファイルの配信は、ワークスペースのファイルのフォルダの中だけを返却し、フォルダの外のパスは返却しない |

`未確定`: ファイルのフォルダの場所と、資料から指すパスの書き方（決める段: インターフェース定義設計。技術の選択のため reviewer の判定で決める）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `.mindstella/files/` に配置し、資料（`.mindstella/docs/`）からの相対パス `../files/{名前}` で指す。画面は資料のフォルダを基準にパスを解決する | mdmark の CLI・VS Code のプレビューでも設定なしで同じパスが通る | 画面で資料のフォルダを基準に解決する処理が要る |
| B | `.mindstella/files/` に配置し、資料にはファイルのフォルダからの相対パス `{名前}` で記載し、`.mindstella/mdmark.config.yaml` の `assets.root` に `files` を記載する | 資料のパスが短い | mdmark の `mount` は `assets.root` を参照しないため、画面では別にパスを付け替える処理が要る |

推奨: A

ワークスペースの記録と同じ `.mindstella/` の下にまとまり、mdmark の書き出し・点検と画面で同じパスが通る。

`未確定`: ワークスペースの Git にファイルを含めるか（決める段: 単一ユースケース設計。手元の資産と容量に関わるためユーザーの判断に回す）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ファイルのフォルダも commit する（自動の commit を含む） | 資料と埋め込んだファイルが同じ履歴に残り、差分の時点に戻しても再生できる | 動画の分だけワークスペースのリポジトリが大きくなる |
| B | ファイルのフォルダを `.gitignore` で Git の外に配置する | リポジトリが大きくならない | 履歴の時点に戻したときや別の端末へ移したときに、ファイルが無く再生できない |

推奨: A

動画作成ノードの扱いの決定（mp4 をワークスペースのフォルダに配置して commit する）と同じで、記録として残すほうが資料の差分を読み返せる。

`未確定`: 埋め込んだファイルを持つ資料の書き出し（資料を書き出す・配る書き出し）の扱い（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mdmark の書き出しと同じく、画像は `data:` URL で HTML に埋め、動画・音声は HTML の隣の `{名前}_files/` へコピーする。ブラウザの資料を書き出すは HTML と `_files/` を 1 つの zip にしてダウンロードする | mdmark の書き出しと同じ構成で、書き出した先でも再生できる | 資料を書き出すのダウンロードが zip に変わる |
| B | 画像は `data:` URL で埋め、動画・音声は埋めずに、再生できないことを書き出しの警告で通知する | 書き出しの形が今と変わらない | 書き出した先で動画を再生できない |

推奨: A

資料 A-107 で、書き出しで埋め込んだ動画をコピーする（mdmark の書き出しと同じ）と決めている。

# サーバー

停止の API（DELETE `/workspaces/{id}/sessions/{session}`）は常駐サーバーが持ち、結合テストは常駐サーバーを子プロセスで起動して呼ぶため、この計画書に載せる。

## 現状

| 分類 | ページ / ファイル | 概要 | 補足 |
| --- | --- | --- | --- |
| ドキュメント | [docs/interface/IF-531-4.yaml](https://github.com/shuhei1101/mindstella/blob/develop/docs/interface/IF-531-4.yaml) | インターフェース定義『MindStella のセッションの停止』 | setup は「まとめていない変更がある」とだけ書き、作り方を指定しないため変更しない |
| テスト | [tests/integration/server/test_stop_session.py](https://github.com/shuhei1101/mindstella/blob/develop/tests/integration/server/test_stop_session.py) | 停止の API の結合テスト | `_add_pending` が無くなった MCP のツール `add` を呼び、2 件が fail する |
| テスト | [tests/integration/server/test_stop_notify.py](https://github.com/shuhei1101/mindstella/blob/develop/tests/integration/server/test_stop_notify.py) | 停止の通知の結合テスト | `_add_pending` が `write_items` で項目を足し、MindStella のセッションの起動の前に呼ぶ（`_running` の `before`）。今回の直し方の手本 |

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| テストの準備 | `_add_pending` を `write_items` で項目（メモ）を追加する形にする | `write_as_ai` がテストの MindStella のセッションの状態を書くため、`test_normal_when_forced` では MindStella のセッションを起動する前に呼ぶ。`test_normal_when_session_crashed` は今のとおり `write_session` の前に呼ぶ |
| 製品のコード | 変更しない | 停止の振る舞いは IF-531-4 のとおり |
| インターフェース定義 | 変更しない | setup の記載はまとめていない変更の作り方に触れていない |

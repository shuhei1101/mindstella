`未確定`: 画面の表の既定のピン止めの扱い（#639。決める工程: 部品設計。ユーザーに確認する）

| 案 | 内容 |
| --- | --- |
| A | mdmark の既定のまま、描いた直後にどの列も留めない。結合テストの期待値を「留めない」に合わせる |
| B | `mount` の `config.table.pin_default` に `true` を指定し、今までどおり行見出しの列（無ければ先頭の列）を留める |

推奨: A

mdmark#711 の依頼（MindStella の画面で毎回先頭の列が固定されるのをやめたい）が既定のままで満たせるため。

`未確定`: 確認済みを削除する範囲（#675。決める工程: データ設計。ユーザーに確認する）

| 案 | 内容 |
| --- | --- |
| A | 詳細パネルのボタン（部品『確認済みの切り替え』）だけを削除し、API・`history.yaml` の `confirmed`・コメントの送信で確認済みにする設定は残す |
| B | ボタンと、確認済みの設定と解除の API（IF-633-1）・`history.yaml` の `confirmed`・コメントの送信で確認済みにする設定まで削除し、既にある `confirmed` の値は移し替えで削除する |

推奨: B

画面から確認済みを付けられなくなると、残した API と記録のキーを使用する箇所がコメントの送信の設定だけになり、状態の完了と意味が重なるため。

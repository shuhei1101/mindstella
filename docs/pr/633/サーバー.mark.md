## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 確認済みの持ち方（#188） | 項目ごとの確認済みを、要件の案 A のとおり `history.yaml` の項目の行に持つ。キーが無い行は未確認として扱い、既存のワークスペースの移し替えは要らない | 確認ログで決定 |
| 確認済みの付け外し（#188） | 画面から項目の確認済みを設定・解除する API を追加する | インターフェース定義を新規作成 |
| AI の書き込みで解除（#188） | 変更の検知が項目の変更を記録するとき、編集した人が AI（MindStella のセッション）なら確認済みを解除する。利用者が画面から保存した変更では解除しない | - |
| コメントの送信で確認済み（#188） | コメントをまとめて送る・すぐ送るで送信した項目を、設定がオンなら確認済みにする | - |
| 設定（#188） | コメントの送信で確認済みにするかの設定を、ワークスペースの設定 `config.yaml` の `confirm_on_comment` に追加し、既定はオンにする。`update_settings` と設定の画面で書き換え、`settings.schema.json` にもキーを追加する | 確認ログで決定 |
| 記録の取得（#188） | 項目の確認済みを画面へ返却する | - |
| 状態のフォルダ（#624） | 403 の後に状態のフォルダを作る箇所（[#605](https://github.com/shuhei1101/mindstella/issues/605) の起動時の照合が候補）を特定し、製品とテストのうち誤っている側を修正する | 製品を修正する場合は IF-605-1・IF-531-1 の記載を修正する。起動時の照合（`startup.py` の `rebuild_ids_if_missing`）が `workspaces.yaml` を作るのは設計どおりのため、テストの期待を「403 の後に状態のフォルダへワークスペースの登録が増えない」に直す（製品と設計書は変えない） |
| 移し替えの手順の集め方（#628） | 同じバージョンに後から追加した手順も、ワークスペースが実行していなければ集めて実行する。実行済みの手順を記録するか、バージョンの付け方を変えるかはインターフェース定義設計で決める | 既に該当したワークスペースが、次の `migrate` で手作業なしで復旧する。バージョンのファイルの 2 行目に当て終えた手順の数を持つ（確認ログで決定）。`plan_migration` はワークスペースのバージョンの手順のうち数より後ろを先に集め、`record_version` と `init` は手順の数（`count_steps`）を書く |
| テストの常駐サーバーの後片付け（#629） | `McpServer` と `SessionWorld` が起動した常駐サーバーとブラウザを、pytest が後片付けの前に終了しても止める。常駐サーバーが親のプロセスの終了を検知するか、起動側で止めるかはモジュール構成設計で決める | 起動側（テスト）で止める。製品は変えない。`tests/` に、起動した常駐サーバーの PID と pytest の PID を受けて、pytest のプロセスが無くなったら常駐サーバー（とそのプロセスグループ）へ SIGTERM・続けて SIGKILL を送る見張りのプロセスを切り離して起動する補助を置く。`McpServer` は `Popen` の直後、`SessionWorld` の `systemctl` の Mock は `start()` の直後（`start_new_session=True` で親から外れるため PDEATHSIG は使えない）に見張りを起動する。Playwright のブラウザは pytest の子のドライバーが持ち、pytest が終わればドライバーと一緒に終わるため対象にしない |

# 要件

## 要望

| 要件 | 終了の条件 |
| --- | --- |
| `docs/` の Markdown の文書へ、タグを打った mdmark の CLI で `mdmark upgrade` を適用し、マーカーの今の書き方（`キー=値`・`+機能`・位置の値。例: `<!-- table: data -->`）の引数を JSON のオブジェクト（例: `<!-- table: {"kind": "data"} -->`）へ移す | `docs/` の Markdown に今の書き方のマーカーが残っていない |
| `index.yaml` から生成する目次の `README.md`（`docs/README.md`・`docs/interface/README.md`・`docs/scenario/README.md` ほか）は、手で書き換えず生成し直す | 生成し直した `README.md` と `index.yaml` の間に差分が出ない |
| 移行の報告に挙がった記載（拡張・`libraries` のマーカー、書き出さない記載）を、JSON のキーで記載し直すか、今も該当していない記載を削除する | 同じ CLI の `mdmark check` が `legacy_mark` を出さない |
| 完了したら [shuhei1101/mdmark#478](https://github.com/shuhei1101/mdmark/issues/478) にその旨をコメントする | #478 にコメントがある |

`未確定`: `mdmark upgrade` が前提にする設定ファイル `mdmark.config.yaml` の配置（決める段: 実装）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | リポジトリの直下に、`version` と点検する文書の範囲（`docs/` の Markdown）を持つ設定を配置して残す | 次のバージョンの `mdmark upgrade` と `mdmark check` を同じ範囲で実行できる | 設定ファイルが 1 つ増える |
| B | 移行のときだけ設定を配置し、移行の後に削除する | リポジトリのファイルが増えない | 次のバージョンへ上げるたびに設定を作り直す |

推奨: A

[shuhei1101/mdmark#479](https://github.com/shuhei1101/mdmark/issues/479) の後も mdmark の記法の変更は続き、そのたびに同じ範囲へ `upgrade` と `check` を実行するため。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ユースケース | 単一ユースケース『MindStella のセッションを起動し直す』に、しきい値での切り替えの正常シナリオと、空いたアカウントが無いときに今のアカウントで続けるシナリオを追加する | - |
| 利用枠の確かめ | 常駐サーバーが、起動中の MindStella のセッションごとに、一定の間隔で claude-balancer の `GET /accounts` を呼び、使用中のアカウントの `unavailableReason` がしきい値以上を表す値なら、起動し直しを契機（しきい値）で依頼する | 間隔とアカウントの当て方は `未確定`（[要件](./要件.md)） |
| 止め方 | 『MindStella のセッションの停止』と同じく、応答の途中なら終わるまで待ってから止める | 利用上限の契機と違い、応答が続けられるため待つ |
| アカウント | 起動し直しの `exec` は、しきい値以上のアカウントを claude-balancer の貸与の判定に除かせる。起動の前に、ほかに貸せるアカウントがあるかを `GET /accounts` で確かめ、無ければ起動し直さずに今のアカウントで続ける | 前回のアカウントを優先する `--resume` の貸与で、しきい値以上の前回のアカウントが除かれるかを claude-balancer の設計書『貸与』『貸与可否の判定』で確かめる |
| 停止の通知 | 止めた後・起動の前に『停止の通知』を、しきい値での切り替えを表す止まった理由で呼ぶ | - |
| 既存の契機 | 利用上限（`rate_limit`）の契機はそのまま残す | - |
| 動作環境 | claude-balancer が無い端末と、claude-balancer の常駐へつながらないときは、確かめずに今の動きのまま続ける | - |

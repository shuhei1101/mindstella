# 要件

## 要望

外部のアプリと端末の起動のコマンドが、MindStella の API でワークスペースと MindStella のセッションの状態を取得できるようにする（資料 A-119 の「MindStella の API」の表・「ワークスペースの状態」の表、資料 A-126）。
MindStella の MCP にも同じ処理を呼ぶツールを持たせる。

| 操作 | エンドポイント | MCP のツール | 返却する項目 |
| --- | --- | --- | --- |
| 状態の取得 | `GET /workspaces/{id}` | `workspace` | ワークスペースの管理から: ワークスペースの状態（`active` / `stopped` / `closed`）・画面の URL・利用者が読んでいない AI の書き込みの数・MindStella のセッションが取り込んでいない利用者のコメントの数・最後の更新の日時・クローズ済みか。セッションの管理から: 『MindStella のセッションの一覧』と同じ項目・クローズ待ちか・追加の MCP とプラグインの記録があるか |
| ワークスペースの一覧 | `GET /workspaces` | `workspaces` | 状態のフォルダの ID の一覧にあるワークスペースのうち、クローズしていないものの ID・題名・画面の URL・クローズ済みか。クローズしたものは指定したときだけ含める |

- 状態の取得・ワークスペースの一覧・『MindStella のセッションの一覧』は、記録・配信元の行・状態のフォルダを何も書き換えない
- 状態に起動中とあっても tmux のペインとプロセスの両方が合わなければ、落ちていると返却する（状態は書き換えず、『停止の通知』も呼ばない）。落ちたことの記録と通知は、落ちたことの見回りと、作成・クローズ・起動し直しが行う
- 追加の MCP・プラグインの記録は、有無だけを返却し、中身（MCP の定義・プラグインのフォルダ）は返却しない。指定が空の記録は「ある」とする
- クローズ済みかは、ワークスペースの管理がグローバルの設定のファイルの配信元の行を直接参照して `outside_read: false` で判定する（project-index の API を呼ばない）。クローズしたワークスペースも記録は残るので、未読の数と最後の更新を返却する
- 状態のフォルダの ID の一覧に無い ID（削除したワークスペースを含む）は、ワークスペースが無いエラー（404）にする
- 記録のフォルダ（`.mindstella/`）が無いときは、MindStella のセッションの状態と、フォルダのパスを含む警告を返却する。配信元の行は削除しない
- グローバルの設定のファイルを参照できないときは、画面の URL と MindStella のセッションの状態を返却し、未読の数・最後の更新・クローズ済みかは分からないとして警告を添える

`未確定`: 返却のキーの名前と、一覧でクローズしたワークスペースを含める指定のキー（決める工程: インターフェース定義設計。資料 A-126 の `notes.インターフェース定義で決めること`）

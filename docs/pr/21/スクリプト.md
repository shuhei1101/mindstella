## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 雛形の組み立て | 画面の HTML・CSS・JavaScript を `skills/mindmap/preview/` に分けて持ち、`build` が CSS・JavaScript を HTML の中へ差し込んでから、データを埋め込んだ 1 枚を書き出す | 書き出す `preview.html` は今と同じく、ワークスペースの他のローカルのファイルを指さない |
| 埋め込みのデータ | `settings`・7 種類・`bodies`・`built_at` に、画面に出す値 `derived`（次の候補・ゴールまで・カテゴリー別の進み具合）を足す。`next`・`goal` と同じ関数で `build` が計算し、画面では計算し直さない | トップバーの題名は `settings.summary` から出す |
| 設定の題名 | `mindmap.yaml` に題名 `summary`（必須）を足し、`init` で受け取る（[確認ログ](./確認ログ.md)） | 今のワークスペースは `migrate --summary` で足す |
| 埋め込みの安全 | 差し込む CSS・JavaScript が `</style>`・`</script>` を含まないことを、書き出しの側で確かめる | 含むときは同梱の雛形の誤りとしてエラーにする |
| 資料の状態 | 資料の `done`（真偽値）を `status`（下書き / 確認中 / 完成）に置き換え、ゴール判定は成果物の資料が `完成` かで見る | 今の `done` を持つワークスペースは、コマンド `migrate` で一度だけ移す（`done: true` → `完成`、`done: false` → `下書き`。[確認ログ](./確認ログ.md)）。他のコマンドが `done` でスキーマに合わないときは `migrate` を案内する |
| 設計書の対応テストファイル | モジュール構成『ビルド』『入口』『読み書きと検証』の `test_files` を外した（足した単体テストの名前が既存のテストファイルに無いと設計書の検証が通らないため） | 単体テストの作成で、元の `tests/unit/scripts/test_builder.py`・`test_mindmap.py`・`test_check_env.py`・`test_commands.py`・`test_kinds.py`・`test_store.py` を書き戻す |
| 既存機能への影響 | `build` の引数・標準出力・終了コード・エラーは変えない。設定に `summary`（必須）を足すため、ワークスペースを作るテストのデータ（`tests/workspace_fixtures.py`・`tests/e2e/単一ユースケース/test_workspace_create.py`・`tests/e2e/複合ユースケース/test_discussion_to_goal.py`）に題名を足す | `build` の引数・出力を確かめる既存の結合テストと E2E がそのまま通ること |

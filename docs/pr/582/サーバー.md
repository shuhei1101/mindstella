## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ユースケース | 単一ユースケース『MindStella のセッションを起動し直す』（契機ごとの正常・失敗）を新規作成し、複合ユースケース『話し合いを記録しながら進める』に、利用上限で止まった後に別のアカウントで話し合いを続ける流れを追加する | AI Monitor の利用上限時の代替先起動・エージェントセッションの再開起動のシナリオに合わせる |
| 起動し直しの API | `POST /workspaces/{id}/sessions/{session}/restart` と MindStella の MCP のツールを追加する。起動中なら停止と同じ待ち方で止めてから起動し、受けたときにクローズ待ちを解く | 強制の指定で最後の書き込みを待たない |
| 利用上限 | StopFailure のフックが `rate_limit` を送信すると、常駐サーバーが MindStella のセッションを止め、『停止の通知』を止まった理由「利用上限」で呼び、`claude-balancer exec` が終わるのを待ってから、前の会話を引き継いで起動し直す | 利用上限の到達の通知は `exec` が子プロセスの終了後に自分で行うため、MindStella からは `report-limit` を呼ばない。利用上限に達したアカウントは claude-balancer の貸与の判定で除外される |
| PreCompact | フックの依頼で、圧縮を止めた MindStella のセッションを止め、新規の会話で起動し直す。起動の契機の環境変数で、SessionStart の注入を再開として扱う | 前の会話を引き継がない（圧縮の後の文脈を記録と commit から戻す）。アカウントは指定しない |
| コメントが届いたとき | MindStella のセッションが無く（落ちた・無操作の上限で止めた）、クローズ待ちでもクローズ済みでもないとき、前の会話を引き継いで起動し直し、準備ができてからペインへ貼る | 起動し直しに失敗したら、コメントはスレッドに残す |
| 会話の引き継ぎ | 状態の `claude_session_id` を停止・落ちた後も残し、作成・起動し直しで `claude --resume {session_id}` を指定する。Claude Code が会話を参照できず起動直後に終わったときは、新規の会話で起動し直す | 記録の場所は `要件.md` の `未確定` |
| 作成の変更 | 『MindStella のセッションの作成』も、記録した会話があれば引き継ぐ（利用者が直接止めた後の起動のコマンドを含む） | 破壊的変更（新規の会話で起動していた作成の動きが変わる） |
| 失敗 | 空いたアカウントが無い・追加の MCP とプラグインを読み込めない・準備を待つ上限を過ぎたときは、状態の `last_error` に段階と理由を記録し、一覧で返却する。`launch.json` が無いワークスペースは指定なしで起動し、作成・起動し直しの応答に警告を記載する | 起動し直しの試行の上限・間隔は非機能要件で決める |
| 状態 | `session.json` の `status` に `restarting` を追加し、作成・停止・一覧のあるとみなす状態に含める | ER 図『常駐サーバーの状態』 |
| 公開ドキュメント | コマンドのリファレンス（起動し直しの API と MCP のツール）・話し合いを続きから再開する手順・Discord に通知する手順（利用上限の通知）を更新する | - |

# 要件

## 要望

MindStella のセッションを、次の契機で常駐サーバーが自動で起動し直す（資料 A-119 の「画面での MindStella のセッション」の表とフックの表）。

| 契機 | 起動し直し方 | 会話 | アカウント |
| --- | --- | --- | --- |
| 利用上限に達した（StopFailure のフックの `rate_limit`） | 常駐サーバーが MindStella のセッションを止め、『停止の通知』を止まった理由「利用上限」で呼び、`claude-balancer exec` が終わるのを待ってから起動し直す（利用上限の到達の通知は、子プロセスが利用上限で終わったときに `exec` が自分で行うため、MindStella からは呼ばない） | 前の会話を引き継ぐ（Claude Code の `session_id` で resume する） | 利用上限に達したアカウントは claude-balancer の貸与の判定で除外され、次のアカウントを借りる |
| PreCompact | フックが圧縮を止め、常駐サーバーへ起動し直しを依頼する | 新規の会話で起動し、起動と再開のエージェントフローで記録と commit から圧縮の前の作業に戻る | 指定しない（claude-balancer が選ぶ） |
| 落ちた・無操作の上限で止めた後にコメントが届いた | コメントをスレッドに残し、起動し直してから取り込み待ちとして届ける | 前の会話を引き継ぐ | 前回のアカウントを優先する |
| 起動し直しの API（`POST /workspaces/{id}/sessions/{session}/restart`。MindStella の MCP にも同じツール） | 起動中なら停止と同じく最後の書き込みが終わるのを待って止めてから起動する（強制の指定で待たない） | 前の会話を引き継ぐ | 前回のアカウントを優先する |

- 使用中の会話（Claude Code の `session_id`）を状態のフォルダに記録し、起動し直しはこの記録を参照して会話を引き継ぐ。`/clear`・圧縮で `session_id` が変わったら記録し直す
- 利用者が MindStella のセッションを直接止めた後に、そのワークスペースで MindStella のセッションを作成したとき（起動のコマンド・API・MCP）も、記録した会話があれば、その会話を引き継いで起動する。記録した会話を Claude Code が参照できないときは、新規の会話で起動する
- MindStella のセッションが落ちたことを、一覧・停止などで状態を参照されなくても常駐サーバーが見つけ、状態に記録して『停止の通知』を呼ぶ（PR [#571](https://github.com/shuhei1101/mindstella/pull/571) のスコープ外から引き取った分）
- クローズ待ち（API で停止を受けた）とクローズの後は、自動で起動し直さない。届いたコメントはスレッドに残す
- 起動し直しに失敗したとき（claude-balancer に空いたアカウントが無い・記録した追加の MCP やプラグインを読み込めない・準備を待つ上限を過ぎた）は、コメントをスレッドに残し、失敗した理由を『MindStella のセッションの一覧』の応答に記載する
- 状態のフォルダに追加の MCP・プラグインの記録（`launch.json`）が無いワークスペースは、指定なしで起動し、『MindStella のセッションの作成』と起動し直しの応答に、記録が無いことの警告を記載する
- 起動し直している間の状態（起動し直しの途中）を『MindStella のセッションの一覧』で返却する
- 利用上限の検知と借り直しは、AI Monitor の実装（利用上限時の代替起動・利用上限通知のフック）と claude-balancer の設計（利用上限に達したアカウントを通知して借り直す・別のアカウントで会話を再開する）に合わせる

使用中の会話は、状態のフォルダの `session.json` の `claude_session_id` に記録し、停止・落ちた後も削除せずに残す（インターフェース定義設計で確定。ワークスペースの記録に端末に固有の値を入れない）。

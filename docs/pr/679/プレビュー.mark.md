### 原因の測定（#677）

develop（04998dc2）の画面を結合テストの準備で開き、ブラウザの要求の経路で書き込みの要求の応答を 2 秒遅らせて、要求の回数を数えた。

| 操作 | 要求の回数 |
| --- | --- |
| まとめて送信をダブルクリック | 1 |
| まとめて送信を 2 回クリック（2 回目は押せない） | 1 |
| まとめて送信を再描画の前に 2 回押す（`button.click()` を同期に 2 回） | 2 |
| 詳細パネルのコメントで Ctrl+Enter を 2 回 | 1 |
| 詳細パネルの「レビューに追加」をダブルクリック | 1 |

再描画の前の 2 回目は `isPending`（React の state）では止まらないため、押した時点で同期に止める `useSingleFlight`（`MOD-679-1`）を足す。

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ボタンの部品（#677） | 書き込みのボタンが使う待つ間の状態（押せない・押したボタンの上の読み込み中のアイコン・`aria-busy`・幅を変えない）を、ボタンの部品の 1 か所で持つ | knowledge の規約『入力と文言』『表示の安定』 |
| 書き込みの mutation（#677） | 書き込みのボタンは、要求を送ってから記録に反映されるまでを待つ間とし、その間はもう一度実行しない | 反映の終了は案 B（[要件](./要件.mark.md)。インターフェース定義設計で確定） |
| 対象のボタン（#677） | 画面の全ての書き込み（送信・保存・更新・削除）のボタンに同じ決まりを当てる。楽観更新の操作は除く | 対象の一覧は画面設計で確定する |
| 結合テスト（#677） | 応答を遅らせた状態で書き込みのボタンを続けて押し、1 回だけ反映され、待つ間の見た目が出ることを確かめる | - |

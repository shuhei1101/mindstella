## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信の設定 | ワークスペースの作成で、記録のフォルダに配信元の設定を配置する。種類ごとの YAML を `records: items`・`body_file: body` で指し、スキーマは `schemas/` の種類のスキーマを指す。参照のキーを `related.types` に対応させる | ファイル名は要件の `未確定`。設定のスキーマは project-index のインターフェース定義に従う |
| 資料の本文 | 本文の Markdown を、項目の `body_file` か管理用の YAML の行で `search_docs` の本文の条件にヒットさせる | 項目の `body_file`（`body`）で配信する。`body_file` は YAML のファイルからの相対で解かれるため、`body` を `docs/{ID}.md` にする（移し替えの `body_to_docs_path`。『ワークスペースの作成』『記録の形式の移行』） |
| ツールの削除 | `find`・`show`・`add`・`update`・`remove`・`batch`・`tags`・`attrs`・`impact` の登録と、その処理だけが使用する関数を削除する | 画面の書き込み（保存待ちの編集をまとめて保存）が使用する書き込みと検証の処理は残す |
| 論点のツール | `edit_option`・`adopt`・`check` は MindStella の MCP に残す。`edit_option`・`adopt` は自分で履歴を記録して書き込み、変更の検知は二重に記録しない。`check` は MindStella に固有の決まりと重なった ID を洗い出す | 単一ユースケース設計で決めた（要件の表） |
| ID の採番 | `next_id` は種類を受け、ワークスペースの鍵を取って次の ID を返却し、返却した ID を予約として常駐サーバーの状態に持つ | 予約は常駐サーバーのメモリに種類ごとの最大の連番を 1 つ持ち、期限を設けない（『ID の採番』） |
| 変更の検知 | 配信が持つファイルの監視（『書き換えの通知』）で書き換えを見つけ、前回の中身と比べて項目の追加・変更・削除を履歴と通し番号に記録する。MindStella の MCP と画面の書き込みは、書き込んだときに自分で記録して二重に記録しない | 前回の中身は状態のフォルダの `snapshot/` とメモリに持ち、『書き換えの知らせ』と同じ 250ms の印で見る。読めない YAML の回は飛ばす。記録のファイルは書かず、履歴のキーは `history.yaml` に書く（『変更の検知』） |
| 外部の変更 | MindStella のセッションの応答の途中でない間に見つけた変更を、外部の変更のまとまりとして自動で commit する。状態が応答の途中でも、tmux のペインとプロセスが無ければ外部の変更とする | 外部の変更を最後に記録してから 60 秒（実測が無いため仮置き。結合テストで書き込みの間隔を測る。『変更の検知』） |
| Git の操作 | checkout・merge による書き換えを記録しない | `HEAD` とシンボリック参照の変化と、`.git/MERGE_HEAD`・`.git/index.lock` で見分ける（『変更の検知』） |
| 重なった ID | 変更の検知が同じ ID の項目を見つけたら、画面へ通知し、MindStella のセッションへ貼り付けで通知する | 通知の文面は画面設計とモックで決める |
| commit とスレッド | `commit` とスレッドの書き込みのツールは、`session_id` が状態の MindStella のセッションと一致する呼び出しだけを受け付け、違えばエラーを返却する | 読み取り（`threads`・`thread`・`pending`）は誰でも呼べる |
| `changes_since_read` | 外部の変更を含めて返却する | SessionStart のフックの注入（D-326）は #518 |
| instructions | 記録の検索と書き込みは project-index の `search_docs`・`write_docs`・`delete_docs` で行い、ID は `next_id` で取得することを案内する | - |
| 既存機能への影響 | 画面の配信・記録の取得（『記録の取得』）は変えない | - |

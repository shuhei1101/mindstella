## 要望

子 Issue ごとの終わりの条件は次のとおり（[Issue #528](https://github.com/shuhei1101/mindstella/issues/528) から写した）。

| Issue | 終わりの条件 |
| --- | --- |
| [#509](https://github.com/shuhei1101/mindstella/issues/509) | 設定「文字起こし後の挙動」の既定が、確定でレビュー中のコメントに追加する動作になっている。入力欄に入れるだけの動作は設定で選べるまま残っている。#499 の確認なしの送信には戻っていない |
| [#510](https://github.com/shuhei1101/mindstella/issues/510) | 録音中もほかの資料・スレッドを開ける。録音中はヘッダーに音声入力中の表示が出て、押すと録音中の入力欄へ移動する。音声入力は同時に 1 つだけで、録音中はほかの入力欄のマイクのボタンが無効になり、テキストの入力はできる |
| [#513](https://github.com/shuhei1101/mindstella/issues/513) | 録音の開始で Screen Wake Lock を取得し、終了・取り消しで解放して、録音中に端末の画面が暗くならない |

要件として次を満たす。今の画面と React の画面（`/spa/`）の両方に入れる。

- `transcription.action` に、文字起こしの結果を入力欄へ挿入した全文をレビュー中のコメントに追加する値を足し、`config.yaml` に値が無いときの既定をその値にする。`insert`・`send` は今の動作のまま選べる
- 追加する値は Claude Code へ送信しない。送信は今までどおり利用者が「送信」を押したときだけ
- レビュー中への追加に失敗したときは、挿入した全文を入力欄に残し、理由を画面に出す
- 録音中に、ほかの項目・スレッド・タブへ移っても録音を続ける。録音を捨てるのは利用者の「キャンセル」と、録音中の入力欄の行き先（項目・スレッド）が無くなったときだけ
- 録音中はトップバーに音声入力中の表示を出し、押すと録音を始めた入力欄の画面（スレッドの画面・項目の詳細）を開いて、その入力欄へフォーカスを移す
- 録音・文字起こし中は、録音中の入力欄のほかのマイクのボタンを押せない。ほかの入力欄のキーボードの入力は受け付ける
- 録音の開始で Screen Wake Lock を取得し、文字起こしへ進む・キャンセル・録音の失敗で解放する。取得できない端末・ブラウザでは録音をそのまま続け、エラーを出さない。録音中に画面が隠れて戻ったときは取得し直す

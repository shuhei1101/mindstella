# 要件

## 要望

コメントの入力・返信の入力の音声入力を、次のとおりにする（今の画面と React の画面の両方）。

| 対象 | 要件 |
| --- | --- |
| 文字起こしの結果 | 入力欄のカーソルの位置へ挿入するだけにし、スレッド・コメントとして投稿しない。カーソルが文字列の途中にあれば、その位置に挿入する |
| 送信 | 利用者が「レビューに追加」のボタンを押したときだけにする。キーボードで入力したコメントと同じく、レビュー中に入る |
| 既定の挙動 | `config.yaml` に `transcription.action` が無いときの既定を `insert` にする |
| 録音中の入力欄 | 入力欄へのキーボード入力を止め、入力欄の場所に入力している音声の波形を表示する。録音を終えたら（文字起こし・キャンセル・失敗）入力欄に戻し、録音を始める前の文字とカーソルの位置を残す |

`未確定`: 文字起こし後の挙動の `send` の扱い（決める段: 単一ユースケース設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `send` を廃止し、`transcription.action` を削除する。インターフェース『書き込みをすぐ送る』と、設定の画面の挙動の選択も削除する | 文字起こしの結果がレビュー中を経ずに送信される経路が無くなり、確認・修正してから送信する要件と食い違わない。挙動の分岐がなくなり、画面・サーバー・テストが減る | `config.yaml` に `action` を記載したワークスペースの読み込みを、スキーマで受けるか移し替えるかを決める必要がある |
| B | `send` を残し、既定だけを `insert` にする | 変更が既定の値と、録音中の表示・入力の停止にとどまる | 確認せずに送信する挙動が設定で選べるまま残り、要件の「スレッド・コメントとして投稿しない」と食い違う |

推奨: A

要件は、音声入力の結果を利用者が確認・修正してから送信することで、確認せずに送信する挙動を残す理由が Issue に無い。
`send` は未リリース（develop だけにある）で、公開済みのワークスペースの互換性は崩さない。

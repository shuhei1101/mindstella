Issue の実例のコピーを Linux の領域（`/tmp`）に配置して、origin/develop の実装で測った値。

| 計測 | 時間 |
| --- | --- |
| `run_update`（資料 1 件のタイトル） | 3.33 秒 |
| `run_thread`（スレッド 1 件） | 4.32 秒 |
| `run_set_thread_status`（スレッド 1 件のクローズ） | 1.44 秒 |
| `load_workspace` | 1.95 秒 |
| `validate_workspace` | 0.37 秒 |

<details markdown="1">
<summary>計測の内訳</summary>

- `run_update` のプロファイルでは、`yaml.safe_load`（純 Python の解析）が 9 回で処理時間の約 7 割を占める
- ファイルの読み取りそのものは、`/mnt/c` でも 1 ファイル 0.01 秒以下で、解析が支配的
- 同じ YAML を C 実装の `CSafeLoader` で読み込むと、`docs.yaml`（1.6MB）は 0.68 秒から 0.09 秒、`decisions.yaml`（1.2MB）は 0.85 秒から 0.16 秒、`threads.yaml`（1.6MB）は 0.79 秒から 0.10 秒になる
- `yaml.safe_dump` は 1 ファイル 0.4〜0.5 秒かかる

</details>

## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 計測 | 3 つの操作それぞれで、読み込み・検査・書き込みした種類の YAML と、処理ごとの時間を、Linux の領域と `/mnt/c` の両方で測り、モジュール構成に記載する | 原因の確定はモジュール構成設計で行う |
| YAML の読み込み・書き込み | 読み込みと書き込みの共通の経路で、解析・出力の処理を速いものに替える | 出力した YAML の中身は変えない |
| 読み込みの範囲 | 操作が使用しない種類の YAML を読み込まない。`run_thread` はワークスペース全体でなく、使用する種類だけを読み込む | - |
| 検査の範囲 | 書き込む種類だけを検査し、変更の無い種類の検査を省く | 種類をまたぐ参照の検査は残す |
| 速さの決定値 | 非機能要件に、要望の 3 つの操作の時間の上限と、測る条件（記録の件数・置き場所）を追加する | - |
| 速さのテスト | 結合テストで、要望の件数の記録を持つワークスペースを作り、3 つの操作が上限の時間に収まることを確認する | - |

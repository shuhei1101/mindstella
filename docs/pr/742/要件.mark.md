# 要件

## 要望

プレビューの次の箇所を、mdmark の部品のカスタム要素に置き換える。
調べた範囲の外にも置き換えられる箇所があれば含める。

| 箇所 | 今の実装 | 置き換え先 |
| --- | --- | --- |
| 一覧の共通の画面の表形式・表の部品・設定の画面の表 | `frontend/src/shared/components/list-screen.tsx`・`frontend/src/shared/components/table.tsx`・`frontend/src/features/settings/workspace-settings/workspace-settings-screen.tsx` | `<mdmark-table>` |
| ボードの部品・一覧の共通の画面のボード表示・検討事項の画面のボード | `frontend/src/shared/components/board.tsx`・`frontend/src/features/decisions/decisions/decisions-screen.tsx` | `<mdmark-view>` |
| 図の拡大 | `frontend/src/features/detail/diagram-viewer/diagram-viewer.tsx` | `<mdmark-map>` |
| 選んだ箇所へのコメント・コメントのマーカー | `frontend/src/shared/components/selection-comment.tsx`・`frontend/src/features/comments/` | `<mdmark-comments>` |

- 置き換えた画面の画面設計・部品設計の `component` を、置き換え先の部品に合わせる
- 表形式のビューの上の「項目の追加」「列の表示」を、ツールチップ付きのアイコンだけのボタンにして横に並べ、ピン止めのアイコンを見分けられるものにする
- 選んだ箇所へのコメント（選んだ範囲から元の Markdown の行を求める処理を含む）を mdmark の同じ機能へ移す
- コメント・下書き・スレッドの箇所（`loc`）を、mdmark の `{quote, prefix, suffix}` の形式へ移す
- 既存のワークスペースの記録の `loc` を、upgrade（『記録の形式の移行』）で新規の形式へ移し替える
- `loc` を参照するコメントの取り込みのエージェントフローと、公開ドキュメント（ワークスペースの書式・コマンドのリファレンス）を新規の形式に書き換える

### 置き換えの条件

- 今の画面の機能（列の固定・並べ替え・絞り込み・行の選択・キーボード操作・狭い幅での出し分け・独自の列の描き方 など）を 1 つも失わない
- 失われる機能が 1 つでもある箇所は置き換えを進めず、`議論中` を付けて利用者に通知し、mdmark 側の対応（オプションの機能として追加する・既定で持たせる）を利用者と決めてから進める
- 置き換えで増える機能（ピン止め・列の幅の変更・テーブル設定 など）は、そのまま使用する

### 未確定

`未確定`: 項目の値へのコメント（今の `{kind: value, key, text}`）の箇所の形式（決める工程: データ設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | mindstella 側の今の形式のまま残す | 値へのコメントの形式の変更と移し替えが要らない | 本文と値で箇所の形式が 2 つになり、取り込みのエージェントフローが両方を参照し分ける |
| B | 値のキーに mdmark の `{quote, prefix, suffix}` を加えた形式に合わせる | 本文と値の箇所を同じ照合で探し直せる | 値へのコメントも移し替えの対象になる |

推奨: B

値を描く要素を `<mdmark-comments>` で包めば本文と同じ選択とマーカーが使用でき、箇所の照合を 1 つにできるため。

`未確定`: コメントの一覧・スレッド・レビュー中の書き込みの画面のうち `<mdmark-comments>` へ置き換える範囲（決める工程: PoC 検証）

`<mdmark-comments>` は要素の中の本文への選択・マーカー・吹き出しを持ち、コメントを保存しない。
スレッドの一覧・レビュー中の書き込み・まとめて送信は mindstella の画面とサーバーに残し、本文の上の選択・マーカー・吹き出しを置き換える範囲を PoC 検証で今の機能と突き合わせて決める。

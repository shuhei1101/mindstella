## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| ユースケース | 単一ユースケース『ワークスペースを開き直して削除する』を資料 A-107 の No 8・資料 A-119・資料 A-116 の `notes.開き直し`・資料 A-132 の削除の流れで新規作成し、『MindStella のセッションを止めてワークスペースをクローズにする』から関連を張る | E2E は `tests/e2e/単一ユースケース/` に配置する。MindStella のセッションのエージェントは Mock にする |
| 開き直し | `POST /workspaces/{id}/reopen` と MCP のツールを追加する。クローズしたワークスペースは配信元の行を `outside_read: true` に戻し、クローズしていないワークスペースも受けて、どちらもクローズ待ちを解く | 『ワークスペースの作成』の `reopened` と同じ書き換えを 1 つの関数にまとめる |
| 削除 | `DELETE /workspaces/{id}` と MCP のツールを追加する。クローズしたワークスペースだけ受け、配信元の行を project-index の『端末の設定の配信元の 1 行の削除』で削除し、状態のフォルダの `workspaces/{ID}/` を削除し、最後に ID の一覧の行を削除する | 記録のフォルダは削除しない。配信元の行が既に無ければ削除済みとして続ける |
| 変更の検知 | 削除したワークスペースのフォルダの監視と前回の中身の持ち方を、配信元の行の削除に合わせて止める | 監視の止め方はモジュール構成設計で決める |
| エラー返却 | ID の一覧に無い ID は 404（ワークスペースが無い）。削除でクローズしていないワークスペースは 409。project-index の失敗は 502 | 区別する値は `要件.md` の `未確定` |
| 排他 | 開き直し・削除は、ワークスペースごとの順番の中で処理し、ID の一覧の書き込みはワークスペースをまたいだ 1 つの順番で処理する | 資料 A-119 の順番の取り決め |
| 公開ドキュメント | コマンドのリファレンスに 2 つの API と MCP のツールを追加し、コアコンセプト『ワークスペース』にクローズの後の開き直しと削除を記載する | - |

# 要件

## 要望

外部のアプリと端末の起動のコマンドが、MindStella の API でワークスペースを開き直し、削除できるようにする（資料 A-119 の「MindStella の API」の表・「ワークスペースの状態」の表、資料 A-116 の `notes.開き直し`、資料 A-107 の No 8）。
MindStella の MCP にも同じ処理を呼ぶツールを持たせる。

| 操作 | エンドポイント | 受ける状態 | 書き換えるもの |
| --- | --- | --- | --- |
| 開き直し | `POST /workspaces/{id}/reopen` | クローズしたワークスペースと、クローズしていないワークスペース | クローズしたワークスペースは配信元の行を `outside_read: true` に戻す。どちらもクローズ待ちを解く |
| 削除 | `DELETE /workspaces/{id}` | クローズしたワークスペースだけ | 配信元の行を削除し、状態のフォルダのそのワークスペースの記録（MindStella のセッションの状態・追加の MCP とプラグイン・変更の検知の前回の中身・前回参照した時点・移し替えの報告）と ID の一覧の行を削除する |

- 開き直した後は、状態の取得の `status` が `active` になり、MindStella のセッションの作成で、クローズの前と同じ進め方の文書・追加の MCP・プラグインで起動できる（状態のフォルダの追加の MCP・プラグインの記録はクローズで残っている）
- 開き直しは、クローズ待ちの間に届いたコメントで MindStella のセッションを起動し直さない（クローズ待ちを解くだけで、起動は MindStella のセッションの作成か起動し直しで行う）
- 削除は、記録のフォルダ（`.mindstella/`）を削除しない
- 削除の後は、同じ ID の状態の取得・開き直し・削除・MindStella のセッションの作成が、ワークスペースが無いエラー（404）を返却する
- 状態のフォルダの ID の一覧に無い ID の削除は、ほかのエラー（クローズしていない 409・project-index の失敗 502 など）と区別できる、ワークスペースが無いエラー（404）を返却する。aituber はこれを削除済みとして扱う
- 削除が途中で失敗したときは、ID の一覧の行を最後に削除し、同じ削除をもう一度依頼すれば残りを削除できるようにする。配信元の行が既に無いときは、削除済みとして続ける
- 開き直し・削除は、同じワークスペースの MindStella のセッションの作成・クローズと同じ順番で処理する（資料 A-119 の「ワークスペースごとに 1 つの順番を共有して依頼を処理する」）

`未確定`: ワークスペースが無いエラーを、ほかのエラーと区別する値（決める工程: インターフェース定義設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 今の API と同じ problem+json の 404 で、失敗した段階（`stage`）を `workspace` にする | 状態の取得・クローズの 404 と同じ構造で、外部のアプリは 1 通りの判定で済む | ステータスと段階の 2 つを確認する必要がある |
| B | 削除だけ、無いことを表す専用の値を応答に追加する | 削除の応答だけで判定できる | ほかの API の 404 と構造がずれる |

推奨: A

今の API は、ID の一覧に無い ID を全て 404・段階 `workspace` で返却しており、削除も同じ構造にすれば、外部のアプリが API ごとに判定を変えずに済む。

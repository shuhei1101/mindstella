# 要件

## 要望

常駐サーバーが起動したときに、待ち受けを始める前に次の 3 つを行う（資料 A-107 の No 10、資料 A-119 の「常駐サーバーが起動した」の行、検討事項 D-323）。

| 処理 | 内容 |
| --- | --- |
| 状態の照合 | 状態のフォルダの `session.json` が `running` の MindStella のセッションを、tmux のペインの ID と Claude Code のプロセスの ID の両方で照合し、どちらかが無いものを `crashed` として記録する。`running` から書き換えたものは、見回りと同じく『停止の通知』を `crashed` で呼ぶ |
| ID の一覧の作り直し | 状態のフォルダに `workspaces.yaml` が無いときだけ、project-index の端末の設定の配信元の行のうち、MindStella が作ったワークスペースの行から ID の一覧を作り直す。ワークスペースの行の見分け方はインターフェース定義設計で決める |
| エージェントフローの配信元のパスの確認 | project-index の配信元 `mindstella-agent-flows` の行の `config` が、起動した常駐サーバーのプラグインの `agent-flows/dev-docs.yaml` と違えば、行を今のパスへ書き換える。行が無いときは足さない（足すのは『ワークスペースの作成』のまま） |

- 3 つの処理のどれかに失敗しても、常駐サーバーの起動は止めない。失敗は常駐サーバーのログに記録する
- project-index が待ち受けていないときは、ID の一覧の作り直しとエージェントフローの配信元のパスの確認を飛ばし、ログに記録する。次の起動まで再試行するかはインターフェース定義設計で決める
- 状態の照合は、見回り（『落ちたことの見回り』）と同じ落ちたかの判定・書き換えの鍵・通知を使用する。`stopping`・`restarting` は書き換えない

# 常駐サーバーの起動時に、MindStella のセッションの状態を照合し、ワークスペースの ID の一覧を配信元の行から作り直し、プラグインの配信元のパスを確認する

## 概要

常駐サーバーが起動したときに、前の常駐サーバーの間に落ちた MindStella のセッションを落ちたものとして記録し、ワークスペースの ID の一覧が無くても配信元の行から作り直し、プラグインを更新してもエージェントフローを参照できるようにする。

## 背景

[Issue #525](https://github.com/shuhei1101/mindstella/issues/525) の要望（[#481](https://github.com/shuhei1101/mindstella/issues/481) の子。資料 A-107 の「シナリオを作る順」の No 10。資料 A-119 の「常駐サーバーが起動した」の行、検討事項 D-323）。

- 常駐サーバーは、落ちた MindStella のセッションを一定の間隔の見回り（『落ちたことの見回り』）で見つけるが、起動したときには照合しない。最初の見回りまでの間は、前の常駐サーバーの間に落ちた MindStella のセッションが起動中のまま残る
- MindStella の MCP と API は、状態のフォルダの `workspaces.yaml`（ワークスペースの ID の一覧）にある配信元の行だけをワークスペースとして扱う。ファイルが無いと、project-index に配信元の行が残っていても、どのワークスペースも扱えない（D-323）
- エージェントフローの配信元 `mindstella-agent-flows` は、『ワークスペースの作成』で行が無いときだけ、その時点のプラグインの `agent-flows/dev-docs.yaml` で足す。プラグインを更新してパスが変わっても登録し直さない

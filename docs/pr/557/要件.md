# 要件

## 要望

- 入力欄（コメント・返信・項目のキーと本文の編集）にカーソルがある間と録音中は、書き換えの知らせを受けても記録を読み直さず、更新があったことだけを持つ
- カーソルが入力欄から離れ、録音もしていないときに、溜めた更新を 1 回の読み直しで画面に反映する
- 更新が溜まっている間は、画面に「更新があります」を出す
- 読み直した後の描画で入力欄が作り直される・値が書き換えられる原因を調べて直す（反映を止めない場面でも入力欄の値とカーソルを保つ）
- 対象は React のプレビュー（`frontend/`）と今の画面（`plugins/mindstella/skills/mindmap/preview/`）

`未確定`: 「更新があります」の置き場所（決める段: モック作成）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 幅 1441px 以上でサーバーにつながらない表示が無いときだけトップバーの題名の右に出し、それ以外はトップバーの下に帯で出す | 広い幅では本文がずれない | 幅と接続の状態で置き場所が変わる。トップバーに幅が無く、出せるのは幅 1441px 以上だけ |
| B | 全ての幅でトップバーの下に帯で出す | 置き場所が幅と接続の状態で変わらず、文言を省かずに出せる | 帯の分だけ本文が下へずれる |
| C | 入力している欄の上に出す | 入力している本人の視線の先に出る | 入力欄ごとに置き場所が要り、録音中は入力欄が波形に替わる。録音中にほかの画面へ移ると出せない |

推奨: B

トップバーは接続の状態・音声入力中の表示と並ぶと幅 1440px 以下ではみ出し、案 A でもほとんどの幅で帯になる。置き場所を 1 つにしたほうが、利用者が探さずに済む。

帯を出す・消すときは、帯の高さの分だけ本文のスクロールの位置をずらし、入力欄の画面の上の位置を変えない。
